## 一、核心概念与定义

- **串(String，字符串)**：由**零个或多个**字符组成的**有限序列**，记为 s='a₁a₂…aₙ'（n≥0）。s 是串名，单引号括起的字符序列是串的**值**，aᵢ 可为字母、数字或其他字符；单引号本身不属于串，仅为区别于变量名/常量。
- **串的长度**：串中字符的数目 n；n=0 时即为空串。
- **空串(null string)**：长度为 0 的串（n=0），不含任何字符，记为 φ（教材用"∅"）。
- **空格串(blank string)**：由**一个或多个空格字符**组成的串 ' '，长度=空格字符个数，**长度≥1**，不是空串（高频辨析点）。
- **子串**：串中**任意个连续字符**组成的子序列（强调"连续"）；**主串**：包含子串的串。
- **字符位置**：字符在串序列中的序号（教材从 1 开始计数）；**子串位置**：以子串的**第一个字符在主串中的位置**表示，不是末尾字符位置或出现次序。
- **串相等**：当且仅当两串的**值相等**，即**长度相等**且**各对应位置字符都相等**；仅长度相等或仅字符集合相同都不算相等。
- 例：a='BEI'、b='JING'、c='BEIJING'、d='BEI JING'，长度分别为 3、4、7、8；a、b 都是 c、d 的子串；a 在 c、d 中位置均为 1，b 在 c 中位置为 4、在 d 中位置为 5；四个串彼此都不相等。
- **与线性表的区别**：串的逻辑结构与线性表极为相似，区别在于数据对象**约束为字符集**；更本质的差别在操作对象——线性表基本操作多以**单个元素**为对象，而串的基本操作通常以**串的整体**为对象（查找/取/插入/删除子串）。

### ADT String 最小操作子集

串有 13 种基本操作，其中 **StrAssign(串赋值)、StrCompare(串比较)、StrLength(求串长)、Concat(串联接)、SubString(求子串)** 五种构成**最小操作子集**：它们无法用其他串操作实现，反之其余操作（除 ClearString、DestroyString 外）都可由其实现。其中 StrCompare(S,T)：S>T 返正值、S=T 返 0、S<T 返负值；SubString(&Sub,S,pos,len)：取 S 第 pos 个字符起长 len 的子串（1≤pos≤StrLength(S)，0≤len≤StrLength(S)-pos+1）。

- `Index(S,T,pos)`（定位/模式匹配）：若 S 中第 pos 个字符之后存在与 T 相等的子串，返回其第一次出现位置，否则返回 0；可用最小操作子集实现（从 i=pos 起取等长子串与 T 比，相等返回 i，否则 i++ 继续）。

## 二、存储结构与分类

串有 3 种机内表示（存储）方法。

### 1. 定长顺序存储（SString）

- 类似线性表的顺序存储，用一组**地址连续**的存储单元存放串值字符序列；按预定义大小为每个串变量分配**固定长度**存储区。
- 定义：`#define MAXSTRLEN 255`，`typedef unsigned char SString[MAXSTRLEN+1]`，**0 号单元存放串的实际长度**。串长表示有两种方式：一是用下标 0 单元存实际串长（如 PASCAL）；二是在串值末尾加不计入串长的结束标记（如 C 用 `'\0'`），此时串长为隐含值，不便于某些串操作。
- **截断**：超过 MAXSTRLEN 的串值被舍去（截尾法）。Concat 时可能三种情形：S1[0]+S2[0]≤MAXSTRLEN（正常）；S1[0]<MAXSTRLEN 但和超限（S2 被部分截断）；S1[0]=MAXSTRLEN（S2 全被截去，T=S1）。
- 操作本质：**字符序列的复制**，时间复杂度基于被复制长度。缺点：串长受限（插入/置换等也可能截断），克服办法是动态分配——引出堆分配存储。

### 2. 堆分配存储（HString）

- 特点：仍以一组**地址连续**的存储单元存放串值，但存储空间在程序执行过程中**动态分配**而得。C 语言有一个称为"堆"的自由存储区，由 `malloc()`/`free()` 管理；用 malloc 为每个新串分配实际串长所需空间，成功则返回起始地址指针作为串的基址。
- 结构：`typedef struct { char *ch; int length; } HString;`，ch 若非空串则按串长分配存储区、否则为 NULL；length 存串长。操作仍基于"字符序列复制"，插入等需 `realloc` 重新分配（如 StrInsert 为 S 重新分配 S、T 长度之和的空间再复制）。
- **优点**：既有顺序存储处理方便、可随机访问的特点，串长又无任何限制，更灵活，是**实际串处理中最常选用**的存储结构。

### 3. 块链存储（LString）

- 与线性表链式存储类似，用链表存储串值。由于串的每个数据元素是**一个字符**，存在**"结点大小"问题**：每个结点可存 1 个或多个字符。结点大小>1 时，串长不一定是结点大小的整倍数，最后一个结点不一定被占满，通常补 `'#'` 或其他非串值字符（`'#'` 不属于串的字符集）。
- 一般只需从头到尾顺序扫描，故不必建双向链表。为便于**联结操作**，除头指针外附设**尾指针**指示最后结点并给出**当前串长**（结构 `LString{ Chunk *head,*tail; int curlen; }`，`Chunk{ char ch[CHUNKSIZE]; Chunk *next; }`）。
- **存储密度 = 串值本身所占存储位 / 实际分配的存储位**。结点大小=1 时密度最低但运算方便；结点增大可提高密度但操作变复杂；若需内外存交换，密度低会因交换过多影响总效率；字符集大小（机内编码长短）也影响存储方式选取。块链存储对联结等操作有一定方便之处，但总体不如前两种灵活，**占用存储量大、操作复杂**，实际较少用。

## 三、关键性质与结论

- 最小操作子集（StrAssign、StrCompare、StrLength、Concat、SubString）；三种存储的操作本质都是**字符序列复制**，定长存储有截断限制、堆分配串长无限最常用、块链存储存储密度问题突出。
- **BF 与 KMP 复杂度对比**：BF（算法4.5）最好/一般 O(n+m)、最坏 O(n×m)，实际执行时间通常近似 O(n+m)，至今仍被采用；KMP（算法4.6）恒为 O(n+m)（求 next 数组 O(m)、匹配 O(n)，因 m≪n 故额外开销值得）。
- KMP 最大特点：**指示主串的指针 i 不需回溯**，对主串仅需从头到尾扫描一遍，可**边读入边匹配**、无需回头重读，适合处理外设输入的庞大文件；但仅当模式与主串间存在许多**"部分匹配"**时才比 BF 快得多。
- BF 最坏典型：模式 '00000001' 配主串大量连续 '0' 后接 '1'，每趟都在模式末字符失配，导致 i 反复回溯（此类 01 串处理常见）。

## 四、核心算法思想

### 1. BF 暴力匹配（Brute Force，Index，算法4.5）

- **思想**：用计数指针 i、j 分别指示主串 S、模式串 T 中当前待比较的字符。从主串第 pos 个字符起与模式首字符比较：相等则继续逐个比较后续字符（i++、j++）；一旦失配，则将模式串整体右移一位，**主串指针 i 回溯**到 i-j+2、模式指针 j 重置为 1，重新比较；依次类推，直到模式每个字符与主串某连续子序列相等（匹配成功，返回 i-T[0]），否则返回 0。
- **本质**：模式串每次右移一格、从头重比，**已匹配过的前缀信息被丢弃**——这正是 BF 低效的根源。复杂度：i 的回溯导致最坏 O(n×m)，最好/一般 O(n+m)。

### 2. KMP 算法（Index_KMP，算法4.6）

- 由 D.E.Knuth、V.R.Pratt、J.H.Morris 同时发现，故称克努特—莫里斯—普拉特操作，可在 **O(n+m)** 数量级完成匹配。
- **核心改进（原理）**：每当一趟匹配出现字符比较不等时，**不回溯 i 指针**，而是利用已得到的"部分匹配"结果，将模式向右**"滑动"尽可能远**的距离后继续比较。
- **为什么 i 不回溯？** 失配时模式已匹配的那一段（前 j-1 个字符）已与主串相应位置对齐相等。若模式串内部存在"前缀=后缀"的重叠结构，则模式右滑后这段已知重叠部分无需再与主串比较，主串当前位置字符可直接与模式某个更靠后的字符对齐比较，因此 i 停在原地不动，只把 j 退回到合适位置即可。
  - 例（教材图4.3/4.4）：模式 'abcac' 与主串 'ababcabcacbab' 匹配，第三趟 i=7、j=5 失配时，BF 会退回 i=4、j=1 重比；但由第三趟部分匹配可推知主串第 4、5、6 个字符必为 'b'、'c'、'a'（即模式第 2、3、4 个字符），模式首字符是 'a'，无需再与这三个字符比较，只需将模式右滑 3 位、直接进行 i=7、j=2 的比较。整个过程 i 从不回溯。
- **一般化**：主串 s₁…sₙ、模式 p₁…pₘ，当 sᵢ≠pⱼ 失配时，问 i（不回溯）应与模式哪个字符 p_k（k<j）再比较。要求模式前 k-1 个字符 'p₁…p_{k-1}' = 主串 's_{i-k+1}…s_{i-1}'，结合已部分匹配 'p_{j-k+1}…p_{j-1}' = 's_{i-k+1}…s_{i-1}'，推出关键等式 **'p₁…p_{k-1}' = 'p_{j-k+1}…p_{j-1}'**（模式内部前 k-1 个字符 = 失配位置前的 k-1 个字符，且 k 尽可能大）。令 **next[j]=k**，它表明当模式第 j 个字符失配时模式需重新与主串该字符比较的位置。
- **匹配执行**：i 初值 pos、j 初值 1。若 sᵢ=pⱼ 则 i、j 各 +1；否则 i 不变、j 退到 next[j] 再比；若 j 退到 0（模式首字符即失配），则 i、j **同时 +1**，即从主串下一字符 s_{i+1} 起与模式重新开始匹配。形式上与 BF 极似，唯一差别就是失配时 i 不动、j 退回 next[j]。

### 3. next 数组（get_next，算法4.7）

- **定义（式4-5）**：
  - next[j] = max{ k | 1<k<j 且 'p₁…p_{k-1}' = 'p_{j-k+1}…p_{j-1}' }（集合非空时），
  - 其他情况 next[j] = 1；特别地 **next[1] = 0**（约定）。
  - **通俗理解**：next[j] = 模式串**前 j-1 个字符**组成的子串中，**最长相等前后缀的长度 + 1**。（"相等前后缀"指该子串的一个前缀与其一个后缀字符完全相同。）
- **递推求法**（此函数值仅取决于模式串本身，与主串无关）：
  - 起点：next[1]=0。
  - 设 next[j]=k（即 'p₁…p_{k-1}'='p_{j-k+1}…p_{j-1}'，k 为 1<k<j 中最大值），求 next[j+1]：
    - **(1) 若 p_k = p_j**：则 'p₁…p_k'='p_{j-k+1}…p_j'，故 **next[j+1]=k+1**，即 next[j+1]=next[j]+1。
    - **(2) 若 p_k ≠ p_j**：则前式不成立，把求 next 看成一次"模式串自身既是主串又是模式"的匹配问题，将模式右滑到用 **next[k]** 位置的字符再与 p_j 比较；若 next[k]=k' 且 p_{k'}=p_j，则 next[j+1]=k'+1，即 **next[j+1]=next[k]+1**。如此依次退（next[k]、next[k']…），直到某个位置字符与 p_j 相等，或退到 0，此时 **next[j+1]=1**。
  - 算法实现要点（get_next，代码见 代码总结.md）：i=1、next[1]=0、j=0；while(i<T[0])：若 j==0 或 T[i]==T[j]，则 ++i、++j、next[i]=j；否则 j=next[j]。时间复杂度 O(m)。
- **手算示例（逐位）**：模式串 **'abaabcac'**（教材图4.6），下标 j 从 1 开始：

  | j | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
  |---|---|---|---|---|---|---|---|---|
  | p_j | a | b | a | a | b | c | a | c |
  | next[j] | 0 | 1 | 1 | 2 | 2 | 3 | 1 | 2 |

  逐位推导（用直观法：前 j-1 个字符的最长相等前后缀长度+1）：
  - j=1：约定 next[1]=0。
  - j=2：前 1 个字符 'a' 无非空前缀，next[2]=1。
  - j=3：前 2 个 'ab'，前缀 'a'≠后缀 'b'，无相等前后缀，next[3]=1。
  - j=4：前 3 个 'aba'，最长相等前后缀 'a'='a' 长度 1，next[4]=2。
  - j=5：前 4 个 'abaa'，最长相等前后缀 'a'='a' 长度 1，next[5]=2。
  - j=6：前 5 个 'abaab'，最长相等前后缀 'ab'='ab' 长度 2，next[6]=3。
  - j=7：前 6 个 'abaabc'，无相等前后缀，next[7]=1（用递推验证：next[6]=3 对应 k=3，p₃='a'≠p₆='c'；退 next[3]=1，p₁='a'≠p₆='c'；退 next[1]=0，故 next[7]=1）。
  - j=8：前 7 个 'abaabca'，next[7]=1 对应 k=1，p₁='a'=p₇='a'，故 next[8]=1+1=2。
  - 结果 next = **0 1 1 2 2 3 1 2**。

### 4. nextval 修正（get_nextval，算法4.8）

- **动机（缺陷）**：原 next 定义在某些情况下仍有多余比较。例如模式 'aaaab' 与主串 'aaabaaaab' 匹配，i=4、j=4 时 s₄≠p₄，按 next[j] 还需再做 i=4、j=3 / j=2 / j=1 三次比较；但因模式中第 1、2、3、4 个字符都相等，这些比较必然也失配，毫无意义，可直接将模式一气右滑到 i=5、j=1 比较。
- **修正规则**：若按定义求得 next[j]=k，而 **p_j = p_k**（即模式第 j 与第 k 个字符相等），则 s_j 与 p_j 失配时也不必再与 p_k 比，应直接与 p_{next[k]} 比，即 **nextval[j]=nextval[k]**；若 **p_j ≠ p_k**，则 **nextval[j]=k（=next[j]）**。
  - 一句话：**p_j = p_{next[j]} 时 nextval[j]=nextval[next[j]]；否则 nextval[j]=next[j]**。修正可**链式传递**（连续相等时一路退到最前）。
- 算法实现要点（get_nextval）：在原 get_next 基础上，当 j==0 或 T[i]==T[j] 时 ++i、++j，再判断：若 T[i]!=T[j] 则 nextval[i]=j，否则 nextval[i]=nextval[j]；失配时 j=nextval[j]。**匹配算法不变，仅把 next 换成 nextval 即可。**
- **手算示例**：模式 **'aaaab'**：

  | j | 1 | 2 | 3 | 4 | 5 |
  |---|---|---|---|---|---|
  | p_j | a | a | a | a | b |
  | next[j] | 0 | 1 | 2 | 3 | 4 |
  | nextval[j] | 0 | 0 | 0 | 0 | 4 |

  推导：next=[0,1,2,3,4]。j=1 nextval=0；j=2：p₂='a'=p_{next[2]}=p₁='a'，故 nextval[2]=nextval[1]=0；j=3：p₃='a'=p₂，nextval[3]=nextval[2]=0；j=4：p₄='a'=p₃，nextval[4]=nextval[3]=0；j=5：next[5]=4，p₅='b'≠p₄='a'，故 nextval[5]=next[5]=4。结果 nextval=**0 0 0 0 4**，比较次数显著减少。

## 五、易错点与常考辨析

| 易错点 | 正确理解 |
|--------|----------|
| 空串 vs 空格串 | 空串长度=0（不含字符）；空格串 ' ' 由空格字符组成，长度≥1，二者不等价 |
| 子串 vs 子序列 / 子串位置 | 子串必须是**连续**字符；子串位置以**首字符**在主串中的位置表示，非末尾字符或出现次序 |
| 串相等 | 需长度相等**且**各对应位置字符都相等，缺一不可 |
| next[1] 的值 | 恒为 0（约定），表示模式首字符就失配，需 i、j 同时+1、模式整体右移一格 |
| next 数组下标 | 教材从 j=1 开始计数（非 0），手算时注意与模式字符对齐 |
| next 递推 | p_k=p_j 时 next[j+1]=next[j]+1；p_k≠p_j 时退到 next[k] 再比，直到相等或退到 0（则=1） |
| nextval 计算 | 必须先求 next 再修正；p_j=p_{next[j]} 时 nextval[j]=nextval[next[j]]（可链式传递），否则=next[j] |
| nextval 与匹配 | 修正只改跳转值，**匹配算法本身不变**，把 next 换成 nextval 即可 |
| BF 最坏复杂度 | O(n×m) 出现在模式与主串有大量部分匹配时（如全 0 串），最好/一般为 O(n+m) |
| KMP 指针行为 | **i 永不回溯**（与 BF 本质区别，常考判断/选择）；失配时 j 退到 next[j]，j 退到 0 时 i、j 同时 +1 |
| 串比较 StrCompare | 按字典序逐字符比较，遇不等返回两字符差值；全等则返回长度之差 |

> 备注：next / nextval 的**手算是高频填空考点**，务必练熟"前 j-1 个字符最长相等前后缀长度+1"直观法与递推法，并能对任意模式串快速写出结果。完整代码见 知识笔记/代码总结.md。
