# 讲稿对照：C2-A-01 首例（2026-09-20）

> 对照材料：视频《答题格式与复杂度分析》转写稿（37.4min，约 1 万字）vs `课件/C2/C2-A-01/C2-A-01-讲稿.md`（现行版）。
> 方法：逐页定位（按讲稿标志性语句在转写稿中锚定时间段），提取四类差异：照念（含微调）/ 改写 / 自发新增 / 删减跳过。
> 这是首例对照，提炼的规律供分析轮验证；单例结论需在其余课节复验。

## 一、逐页差异

### P1 封面 / P2 课段定位 —— 基本照念
几乎逐句照讲稿念，只加口头语（"那么""呢"）。一处微调：讲稿"跟代码直接相关的是这么几块"，主讲说"**这么三块**"——口头表达倾向给具体数字。

### P3 课段目录 —— 照骨架，自发补考情判断
讲稿按节报目录。主讲在讲稿之外**自发补了三条具体考情判断**：
- "广义表呢，其实也在近几年基本上绝迹了，也不怎么考"；
- "串的代码是明确不考的"；
- "数组考的是一些公式的计算"。
讲稿只有一句"它以手算为主，几乎不考具体代码"。**主讲口中的考情比讲稿具体、直接、敢下判断。**

### P5 学习要求 —— 照念 + 自发补充
- 自发承认过程："像视频里面我会给出 PPT 里的定义，**或者是我自己会有时候手写定义**"；
- 自发加判断："手写当然会更加的记忆深刻一点""（答案页）**自己给自己纠错**"。

### P6 伪代码格式 —— 照念 + 一大段完全自发的考场经验
讲稿说"三样不能省……除这三样，头文件、main 都能省"。主讲讲完照念部分后，**现场补了一整段讲稿没有的内容**：
- "有些同学用 C++ 写会加一些头文件，string.h、math.h 这些……**如果说你要用的话，那我还建议你写一下，不然老师会认为这些函数是凭空冒出来的**；但是我不太建议用其他方法写，老师可能会认为你有点投机取巧，毕竟这是手写题，还是要看你思路、看你自己手写的能力。"
这是主讲从阅卷/考试经验里长出来的实操建议：**有立场（"我不太建议"）、有理由（"凭空冒出来"）、有具体例子（string.h/math.h）**——整段没有任何"AI 味"可言，因为它是内容先于表达。

### P7 三件套 —— 照念 + 自发补充"复杂度可以画图""代码可以写注释"
- "比较复杂的情况下，你可能要多分析一些情况，**甚至画图也可以去写的**"；
- "**对代码题，代码里面也可以写点注释**，跟老师说明清楚这个代码究竟怎么运行的"。
两条都是讲稿没有的实操建议，主讲随手就补出来了——说明这类内容在他脑子里是"活的"。

### P8 三件套样例 —— 自发补充两条关键考场细节
- "（思想）这边是以注释的形式写的，**但实际上最好还是以文本形式：你在写代码之前，单独找一块区域，写一段完整的、单独的算法思想**，让老师能够看清楚"；
- "int findMax(int a, int n) **这个基本上是题目会给你的，它会写清楚输入是什么、输出是什么、函数签名是什么，不需要你自己写；没有的话，那就可以自己定义**"。
讲稿 P8 只说"思想写在代码前面"。这两条是更高价值的实操细节，讲稿反而没写——**主讲肚子里的货比讲稿多，讲稿只承载了骨架**。

### P9 时间复杂度 —— 自发改动：把翻倍循环的推导提前完整讲了
讲稿 P9 结尾只有一句"等下的模仿题里就有一段是这样的"。主讲现场把 `for(i=1;i<n;i*=2)` 的 logn 推导**完整展开讲了**（"从1走到n需要乘logn次的2"）。
另外自发补了"这段单独讲几页，**后面可能就不会再提及了**"与"这是教材书里面最开始的那部分内容，考的不会很难，但会作为基本的附加部分考察"——主讲习惯交代内容的"地位"和"后续出现策略"。

### P10 内层跟外层变 —— 自发换了一个反例并完整推导
讲稿的反例是"三层循环、最内层只执行固定几次"。主讲现场**换成了 `i=1;i<=n;i*=2` 双层循环求和得 O(N) 的完整推导**，还指导"大家能够画一个图去把它算出来"。这个反例更贴近 802 考法，是他临场做的教学决策。

### P11 递归树 —— 自发表达个人立场
讲稿"这个逐层累加的办法比背公式靠谱得多"。主讲现场具体化："我记得有些教材里面会给出一些公式，直接根据公式去算，**但是我认为呢，公式比较抽象，我更喜欢用这种方法去算**"。
——"我记得有些……但是我认为……我更喜欢……"是典型的真人立场句式：有记忆的不确定、有偏好、有第一人称。

### P12 空间复杂度 —— 病句现场被主讲"顺"成了人话（重要证据）
讲稿 P12 首句是病句："空间复杂度数的定义是为了把这件事做完，你额外开了多少辅助空间"（负例 N2）。
主讲实际说的是：**"空间复杂度跟时间复杂度其实有点不太一样，它的定义是什么呢？是额外开的辅助空间。为什么说是额外开呢？因为像输入数据本身就占了一部分……那它是不是就 100% 是 O(n) 了？实际上不对，我们要算的是额外的空间。"**
——他用"自问自答+反问否定"把这件事讲得非常顺。**证明病句是改稿残留：一念就别扭，主讲自然说成了人话。反过来说，讲稿里的病句不是主讲的表达习惯，是生产环节的缺陷。**

### P13 小结 —— 同样的病句证据
讲稿首句"这一讲结尾一下"（负例 N1）。主讲实际说的是"**好，那我们现在来小结一下**"。病句再次被现场修正。

### P14 课后任务 —— 大幅压缩口播
讲稿约 2 分钟的课后任务（含"别只在脑子里过""三件要齐"等叮嘱），主讲 40 秒讲完：题目是什么、按什么格式写、答案在后面自己对照。末尾还有口误："发到朋友圈"（应为 QQ 群）——正常口播现象。

## 二、系统性规律（首例提炼，待其余课节复验）

### 2.1 主讲的口头语指纹
- 高频衔接词：**"那么"（极高频，几乎每2-3句一个）、"然后"、"就是/就是说"、"这样"、"嘛"、"对不对/对吧"、"呢"**；
- 主语习惯：大量用**"我们"**包住动作（"我们要去数这个我们的基础基本操作"），讲稿多用"你/大家"——主讲实际是"带着一起做"的视角；
- 句子形态：短句、破碎、语序松散，一句话里主语反复出现；信息靠重复推进，不靠单句精确。

### 2.2 自发内容的类型学（"有人味"的来源）
主讲自发补充的内容全部属于五类，且没有一类是"表达层"的：
1. **具体考情判断**（广义表绝迹、串代码明确不考、数组考公式）——敢下结论、给具体章节；
2. **考场实操建议**（思想单独划区域、函数签名题目会给、代码可写注释、不建议借 C++ 特性、复杂度可画图）——从阅卷视角出发；
3. **完整推导展开**（翻倍循环提前讲、O(N) 反例完整推）——教学临场决策；
4. **个人立场**（"我认为公式比较抽象，我更喜欢画树"）——第一人称、有偏好；
5. **自问自答式澄清**（空间复杂度为什么不把输入算进去）——反问、否定、再立论。

**共同点：这五类都是"内容增量"，不是"表达修饰"。主讲从来不把一句普通的话换个花样再说一遍；他要么念稿，要么补充新信息。**

### 2.3 讲稿与实讲的角色分工（从对照倒推）
- 讲稿实际承担的是**骨架与顺序**（讲什么、按什么顺序、哪页停顿），主讲照骨架走；
- 讲稿中写得最"满"的叮嘱句、总结句（课后任务段、小结段）往往被主讲压缩或跳过——**写得越满的段落，照念率越低**；
- 病句、"绕"句在实讲中都被自然顺成人话——**这些不是主讲的毛病，是写稿环节的毛病**。

### 2.4 对负例台账的验证
- N1（"这一讲结尾一下"）：实讲为"来小结一下"——**确认是写稿残留，非主讲习惯**；
- N2（"空间复杂度数的定义是"）：实讲为流畅的自问自答——**同上**；
- Z2（"那句话的真实含义，用今天学的东西翻译"，C1-B-02 现行稿）：待做 C1-B-02 对照后验证；
- 主讲自发部分未发现任何负例型表述——**负例全部集中在写稿层**。

## 三、对后续分析轮的初步启示（假设，非结论）

1. **AI 味的病根可能在"生产顺序"**：现在的流程是"写完整讲稿→主讲照着讲"，主讲被迫把书面句式念出来，再加"那么/然后"去消化书面结构。如果反过来——**用主讲的骨架（页+要点+他自发的经验条目）让主讲自己长出话来**，讲稿的角色可能应该从"口播参考"退到"内容清单+顺序单"。
2. **讲稿里的"人味"不是写出来的，是主讲自己带的**：自发内容五类型（考情/实操/推导/立场/自问自答）可以作为讲稿的新骨架——写稿时把这些"活内容"列成条目，而不是把话写成句子。
3. 口头语（那么/然后/对不对）不是病，是主讲的呼吸节律；讲稿**不需要**模仿它们（念稿时主讲自己会加），但更不该写得比口语更"整齐"。
4. 需要复验的问题：C1-B 系列的对照是否同样成立（B1 是主讲亲改稿，他的亲改稿与实讲的重合度是否更高）；课后任务压缩、小结压缩是否普遍。
