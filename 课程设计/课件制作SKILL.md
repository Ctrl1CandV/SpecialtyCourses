# 课件制作 SKILL（802代码课程）

> 本 Skill 定义**每节课课件的生产流程与质量标准**。
> 架构分工（重要）：
> - **内容生成**：产出 `deck.yaml`（结构化幻灯片内容）与 `讲稿.md`，规范见 `tools/CONTENT-SPEC.md` 与本文档第五节；
> - **PPT 渲染**：由 `tools/render-pptx.js` 统一执行，样式唯一权威在渲染引擎内，内容 AI 不得在 deck.yaml 中写任何布局/颜色/字号。

---

## 一、产出物与目录约定

每节课一个目录，三个文件：

```
课件/
├── C1/C1-A-01/
│   ├── deck.yaml              # 幻灯片内容规格（内容AI产出）
│   ├── C1-A-01.pptx           # 渲染产物（工具生成，不手改）
│   └── C1-A-01-讲稿.md        # 讲稿（内容AI产出）
```

命名：课段目录按 `C{n}` 组织（C0 为总先导，C1/C2/C3 为三门课）；每节目录名 = 节次编号（如 `C1-A-01`）。

## 二、生成工作流（AI执行步骤）

制作 C2/C3 时按 README 的最短阅读路径取材；当前节设计是备料清单，相关笔记、缺口与勘误要核对，不必通读全部课节或语料转写。本文是生产流程权威，`授课技法指南.md` 只供遇到具体问题时解释参考，不另设先交大纲等待确认的流程。

1. **内部整理内容卡**：从当前节设计提取五项——最多 3 个核心结果、各自要解决的具体问题、一个重点过程、1—2 个错误或边界、两道课后题；不新增交付文件。若设计中的例子不足，按当前考点从 `题库数据库/README.md` 指向的题库找少量候选；逐题核对题面、答案或独立推导、配图、存疑备注与原始页，确认适合本节且可对学生展示。题集分档和入库状态不等于题目已核准；版权不明时只用自己编写的数字实例，不照搬原题或原图。C2 可将已核对题意匿名化、缩短或改写来讲知识，C3 才讲完整真题。每个核心知识点要说清用途；用现有页型安排问题页、展示真实状态变化的过程页、让学生预测一步、补关键代码或判断边界的检查页。原理或小实例先于完整代码，同一结论只完整解释一次。
2. **一次生成三件套**：按 `tools/CONTENT-SPEC.md` 写 deck.yaml，按第五节写逐页讲稿，再用 `node tools/render-pptx.js 课件/<课程>/<节次>/deck.yaml` 渲染 PPT（逐条动画仍需录制前手工添加）；不强制先交页码大纲等待确认。
3. **AI 自检后交付**：先顺着引题、关键过程和最难的一页模拟讲一遍：学生会先想什么、下一页新增了什么、录制时关键一步是否有依据；只修缺口页，不做全篇统一润色。再核对知识和代码、题源与缺口勘误、重复解释及第六节表达规则；用 PowerPoint/WPS 检查页数、底图、溢出与重复元素，对未封存课节运行第八节的单节检查。`check.js` 会重渲染目标 PPT，不对封存课节运行。主讲审稿或录制后若有反馈，只把其明确认可或否定的一两处实例用于下一节校准；不要求逐句转写或另建反馈交付物。

> 交付物 = **deck.yaml + .pptx + 讲稿**（三件套）。不再产出 HTML/PDF。

## 三、页型与标准结构

### 3.1 常规课（非先导类）组织参考（按内容估时）

以下是可调整的讲解顺序，不按步骤分配固定分钟数；内容有限时缩短计划时长，不为填满步骤重复解释。问题页、展示状态变化的过程页和学生检查页仍按第二节落实。

1. **引题**：C2 用简化任务或具体问题，C3 可用完整真题；先呈现问题不提前给答案；
2. **思想先行**：自然语言或表格描述思想，先不展示完整代码；
3. **推演示意**：按需展示关键状态变化（沿用 content 页＋要点逐条动画，不用 `board` 页，录制不手写，学员拿纸跟画）；
4. **代码精讲**：围绕关键代码与边界讲解，重点行可用 bullets 放大，不逐行复述屏幕代码；
5. **复杂度收尾**：适用的算法讲复杂度和易错点（无算法课可省）；
6. **课后任务**：1道跟练题+1道变式题（A阶段变式降为模仿题），题面进 deck.yaml；**参考答案放PPT末尾两页，一题一页**（单页塞两题会溢出；PPT随课发给学生自行对照，不口播），答案要点用bullets不用note，讲稿附录一同步一份。

### 3.2 特殊课型

**代码班总先导课**（唯一，10分钟，独立成片 C0）：封面→真题引题→试卷结构→考察形式→伪代码示例→能力阶梯→课程全景→分层选课→学习方法→时间轴→总结→下一站（transition 收尾）。

**课段导学**（每课段首节开头5分钟）：课段位置（分值地位）→课段目录（表格）→适合人群（表格）→学习要求→衔接下一课段→transition 进入正课。

## 四、样式规范（渲染引擎权威，此处仅供理解）

- 16:9（13.333×7.5英寸），机构底图 `assets/底图.jpg` 每页 cover 铺满；
- 三色制：黑 1F2329（正文/标题）、蓝 1F4E9C（kicker/要点符）、红 C0392B（角标）；灰 8A9099 为次要色；
- 字体：微软雅黑（正文）+ Consolas（代码）；
- 顶部安全区 1.05 英寸（避开底图顶部色带），内容左对齐；**页脚仅页码，不打机构/课程标签**（底图自带宣传）；
- 每页正文 ≤6 行 bullets / ≤6 行表格 / ≤10 行代码，超了拆页（渲染器有自动缩放兜底，但内容侧应主动控制）。

## 五、讲稿规范

1. **定位**：讲稿是逐页口播参考，不是逐字稿；可以详略不均。优先写 PPT 没有的原因、推导、易错点、有依据的考场建议和学生动作。PPT 上已写清的定义、列表与代码不完整复述；
2. **逐页对应**：`## P{n} 页名（约Xmin）` 小节，与 deck.yaml 页序一致，时长取整分钟；不口播的页（如末页参考答案）也建占位小节并标注"（不口播）"，保持页数对应；
3. **语言**：术语直接、例子具体、判断有依据；句子自然可朗读，不模仿主讲口头禅，也不虚构其亲历或个人立场。写完通读，念着不像说话的段落重写；
4. **格式降档**（基础阶段复盘后新增）：
   - 口播正文**禁用Markdown表格**，对比内容用口语列举；
   - **加粗每节≤10处**，只标需要重读的词；
   - 舞台指令只保留【板书】【停顿】两种；
   - 不追求段落工整，一段一个意思即可；
5. **悬念管理**（基础阶段复盘后新增）：每个"后面会讲"式钩子登记进本节悬念台账；同一钩子全课段只铺垫一次，铺垫语只进讲稿不进deck；小结页不重提钩子清单。跨课段钩子的埋设/兑现位置见框架3.1清单与3.2登记表；
6. **时长估计**：逐页估算口播、演示、停顿及练习时间，页级标注合计与 `meta.duration` 一致；字数只是粗略估时参考，不是质量下限。时间不足先核对是否缺具体例子、状态变化过程或学生练习；没有合适增量就调短计划时长，不重复解释凑字数；
7. **附录**：一、课后题参考答案（与PPT末页同步）；二、本节代码合集（与笔记一致，笔误须修正并记入勘误）；三、勘误位；
8. **固定开场白**（第八轮起）：封面页小节问候语之后独立一段："在开始之前先简单介绍一下，伴梦研途是专门做重邮考研的机构，想要获取更多课程资料、答疑以及后续的课程安排，都可以在伴梦研途的QQ群里获取，需要的同学可以加一下。"；
9. **代码一致**：所有代码与 `知识笔记/代码总结.md` 全局约定一致（下标两套、带头结点、top=-1 等），明显笔误修正后记勘误；
10. **表达校准**：执行第六节五条规则；需要例子时从 README 指向的主讲笔记正例和消极案例中各取一个相关样本。两份讲稿对照报告、技法指南 §4.7 仅在具体问题出现时查阅，不读完整转写。

> `课程设计/授课技法指南.md` 是解释性资料，需要具体方法时查阅；若其旧流程或字数表与本节冲突，以此处流程与估时规则为准。

## 六、反"AI味"硬约束（内容与样式双侧）

写作校准五条：①普通教学动作直接说，不包装；②不用一次性比喻替代术语；③相邻页不重复同一结论；④删去无新信息的铺垫、总结和鼓励；⑤不虚构主讲经历、个人立场、考情或阅卷规则。正向标准是**术语直接、例子具体、判断有依据**，不模仿“那么”“然后”“对不对”等口头语。

| 常见弊病 | 约束 |
| :--- | :--- |
| 口号式标题 | 禁止"一条路走到底""记住X条铁律"；标题只陈述内容 |
| 营销腔 | 不用"放心跟""稳稳拿下"；陈述事实、给数字、给判断标准 |
| "一句话总结"句式 | 列表结尾禁止总结句 |
| 卡片堆叠/装饰框 | 目录对比一律用表格；正文不用彩色装饰框 |
| 一页塞满 | 每页 ≤6 bullets / ≤6 行表格 / ≤10 行代码，超了拆页 |
| 夸张图标emoji | 一律不用；要点符仅用渲染器内置圆点 |
| 逐行注水注释 | 代码注释只注关键行 |
| 铺垫钩子复读 | "记住就行，后面强化阶段会说"类语句全课段每个钩子至多1次（check.js检测） |
| 格式过度 | 讲稿加粗每节≤10处、口播正文无表格（check.js检测加粗密度） |
| AI高频句式 | "不是X，而是Y""这不仅是…更是…"、空洞衔接语（值得注意的是/某种意义上）、商务套话（赋能/旨在/不可或缺）一律改写 |
| 超纲符号曝光 | 代码示例逐符号审查，学员此刻解释不了的符号不上屏（框架2.6审查二） |
| 比喻替代术语 | 能换成学员该学的术语就必须换；只用一次、之后不复用的新比喻当装饰删掉（技法指南§4.7型一） |
| AI专用词/生造说法 | "路线报一下""盘点问题""立一个规矩""数学基础""设计哲学""自由翻译""按现在的值办事"一律改平实（§4.7对照表，check.js禁语表扫描） |
| 把简单内容讲复杂 | 一段的核心信息能一句话说完就砍到那一句；与相邻页重复的论证删；时长缺口用真厚度补（§4.7型三） |

## 七、机构物料边界（2026-08 事故复盘后新增）

**凡机构提供的物料，一律谨慎更改**：

1. 机构给的PPT（含底图、logo、机构页文案）不得擅自改动；确需调整时，只动我方内容页的正文文字，底图、logo、版式、机构页面一个字都不动；
2. 直播分享类合作课件的可改范围是固定的：**只有我方产出的内容页可以修改**（802备考经验分享场为第12—40页）；机构的封面、目录、数据统计、课程广告、收尾页都是不可改的；
3. 我方deck.yaml/渲染产物只作为内容源与备份，**不得覆盖机构版PPT**；需要产出最终版时，在机构原件的副本上只替换我方页的文字；
4. 讲稿涉及机构页面（数据统计、课程广告）时，**按PPT原文的意思写，不删减、不过度扩充**；
5. 任何"重新生成/统一风格"的冲动都先停一下：机构物料的第一原则是保持原样。

## 八、自检清单

以下只核对机器检查不了的风险与交付硬要求；第六节的五条表达规则只需定向看引题、核心过程和最难一页，命中疑点再扩查，不逐项遍历旧词表。

- [ ] deck.yaml 通过 `node tools/render-pptx.js` 渲染无报错；
- [ ] pptx 页数 = deck.yaml slides 数，PowerPoint/WPS 打开正常；
- [ ] 每页文字无溢出、无与底图顶部横幅重叠；
- [ ] 无重复元素（尤其 transition/cover 页）；
- [ ] 讲稿与 deck.yaml 逐页对应，时长按口播、演示与练习估计；字数低仅提醒复核估时；
- [ ] 代码与笔记全局约定一致；完整真题的年份、分值和评分讲解留在 C3，C2 仅可使用匿名化、缩短或改写的教学任务；
- [ ] 三类页面承担不同任务：引题有具体问题，过程展示关键状态变化，检查页要求学生预测、补代码或判断边界；逐页模拟讲解后，只有缺口页被修订；
- [ ] 使用的题目或改写实例已核题面、答案/推导、配图、存疑及来源；不照搬未确认可分发的版权题；
- [ ] 第六节五条表达规则在引题、核心过程和最难页没有明显问题；若主讲已有明确审稿反馈，仅借用被其确认的正负例，不臆造经历；
- [ ] 悬念台账：本节新埋钩子已登记，全课段无同钩子二次铺垫；
- [ ] 首次出现的新符号有解释；学生当前阶段必须用到的概念与边界没有遗漏；
- [ ] 推演页与课后题各有用途，不重复展示已讲过的样板步骤；
- [ ] 讲稿朗读顺畅，口播正文无表格；加粗只标需要重读的词；
- [ ] deck 无制作备注：动画登记、录制方式、"配合讲稿"类说明只在讲稿课前准备（check.js 第13项；CONTENT-SPEC 第五节第6条）。
- [ ] deck 第n页与讲稿P{n}逐页对应：尤其动画页/演示页的页号（check.js只比页数比不出错位，需人工对标题）。
- [ ] 讲稿页级估时合计 = deck.meta.duration；按口播、停顿、跟画与练习综合核对，不强制按字数配额分摊（见CONTENT-SPEC第六节）。
- [ ] PPT末尾含课后题参考答案（一题一页，学生自行对照；讲稿每题有对应的不口播占位小节）；
- [ ] 讲稿封面页含固定开场白（机构介绍，见第五节第8条）；
- [ ] 演示页已在课前准备中登记"录制前手工加逐条动画"；
- [ ] 自检用单节 `node tools/check.js 课件/<课程>/<节次>`，**不跑全量**（全量会重渲染封存课节的pptx，见CONTENT-SPEC自检命令注意事项）。
