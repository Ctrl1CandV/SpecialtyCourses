# 802 题库数据库建设方案（第四问详细设计）

> 用途：把散在 PDF/图片/网页里的 802 题目与知识，转成**集中、结构化、AI 一读就懂**的题库数据库，供 C2/C3 讲课时随时取用大量题目。
> 定位：这是 C2/C3 优化补充的**前置基建**。基建不成，后面讲题就是无米之炊（现状：AI 能读到的完整题目几乎为零）。
> 定稿：2026-09-06，主讲四项决策已确认（见第二节）。

---

## 一、背景与目标

### 1.1 为什么必须做

主讲判断："目前真题资料里的内容远远不够，后面讲知识、尤其后面阶段要讲大量题目。"经探查证实：

- 3 个真题 PDF **有文本层**，题面、代码、答案都在，但**从未转成结构化数据**，AI 每次要用都得重新翻 PDF；
- 331 页《数据结构题集》是**纯扫描版**，上一轮 MinerU 只留下"题号＋2 行摘要＋分档"（`真题资料/题集筛选工作稿/`），**完整题面、选项、答案、图全部丢失**，MinerU 中间产物与复现脚本也已不在；
- 外部题库（408、辅导书）**完全没有搜集**。

结论：现有 AI 可读的"完整题目"接近于零。C2-B 讲算法要例题、C3-B 讲 17 道真题要题面与解析、后续要"讲大量题目"——都指向同一个缺口：**没有题库**。

### 1.2 目标

建一个题库数据库，做到：

1. **全**：真题 2020—2026、题集九章全部题目、408 与辅导书补充题，应收尽收；
2. **准**：题面、选项、代码、图、答案、解析完整，来源可回溯到原 PDF 页；
3. **好取**：AI 用一条命令就能按章节/题型/考点/难度/来源/模板筛出题目并拿到完整内容；
4. **可用**：直接服务 C2/C3——讲某个算法时，一键拉出该考点的全部相关题（真题＋题集一档＋408）。

## 二、四项决策的落定（2026-09-06 主讲确认）

| 决策点 | 结论 | 理由 |
| :--- | :--- | :--- |
| 题集识别引擎 | **本地部署 MinerU** | 本机 RTX 4070 Ti SUPER 16GB 显存，远超 MinerU 推荐的 8GB；免费、无需 token、无页数限制、可离线反复用 |
| 数据库形式 | **SQLite 主库 ＋ 查询 CLI ＋ Markdown 导出**（三层） | 主讲："Markdown 保底，若文件数据库配套工具不复杂就发挥数据库优势"。SQLite 发挥检索统计优势，配一个简单 CLI 让 AI 直接查，Markdown 导出保底人读 |
| 外部搜集范围 | 408 历年真题 ＋ 严蔚敏教材正文 ＋ 王道/天勤题库 | 主讲多选确认，扩充题量与知识体系 |
| 外部获取方式 | **先尽量抓全存临时区，版权后续再筛** | 主讲确认；临时区与正式库分离，未过版权筛选的不进主库 |

## 三、数据库设计

### 3.1 三层存储形态

```
① SQLite 主库 tiku.db        —— 唯一的结构化真相源，所有题目入这里
② 查询 CLI 工具 tiku.py       —— AI 与人取数的唯一入口，命令简单
③ Markdown 导出 导出/*.md     —— 从主库生成的人读视图（保底），可随时重导
```

- **为什么 SQLite 做主库**：题目要多维检索（章节×题型×考点×难度×来源×模板×真题同源），SQL 天然擅长；去重、统计、关联一次查询搞定；单文件便于备份。
- **为什么还要 Markdown 导出**：AI 直接 Read markdown 仍是最省事的；主讲也要能翻着看。导出是主库的**只读投影**，改数据只改主库再重导，不手改导出文件。
- **AI 取数不复杂的保证**：tiku.py 只暴露 6 个动词（list/get/search/stats/export/import），常用查询一条命令，输出纯文本或 markdown，AI 跑完直接读。

### 3.2 目录结构

```
题库数据库/
├── README.md               # 数据库说明、schema、tiku.py 用法、来源登记台账
├── tiku.db                 # SQLite 主库（结构化真相源）
├── schema.sql              # 建表 SQL（可重建库）
├── images/                 # 所有抽取的图片，按源分子目录
│   ├── 真题/  题集/  外部/
├── 导出/                    # Markdown 人读视图（从主库生成，只读投影）
│   ├── 真题/  题集/  408/  王道天勤/
├── 工具/
│   ├── tiku.py             # 查询 CLI（唯一取数入口）
│   ├── extract_zhenti.py   # P0 真题：fitz 抽取 → 入库
│   ├── extract_tiji.py     # P1 题集：MinerU 结果后处理 → 入库
│   ├── import_external.py  # P2 外部：搜集内容 → 入库
│   └── requirements.txt    # 依赖锁定
└── 临时区/                  # P2 外部搜集的原始文件（版权/质量未筛，不进主库）
    ├── 408/  教材/  王道天勤/  其他/
```

- `临时区/` 与主库严格分离：抓来的原始 PDF/网页/图片先落临时区，过版权与质量筛选后才转化入主库。
- MinerU 识别的中间产物（切片 PDF、markdown、content_list.json）落 `_tmp/mineru_out/`，识别完成、入库校对后即可清理（不像上轮那样丢在半路）。

### 3.3 SQLite Schema（核心表）

**questions（题目主表）**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | TEXT PK | 唯一 ID，命名见 3.5 |
| source | TEXT | 来源：真题2026/真题2025/…/题集/408/王道/天勤/教材 |
| source_detail | TEXT | 来源细节，如"26回忆版""严蔚敏题集第2版第7章" |
| chapter | TEXT | 802 知识章节：绪论/线性表/栈队列/串/数组广义表/树/图/查找/排序 |
| qtype | TEXT | 题型：选择/填空/解答/算法设计/程序阅读/综合应用 |
| number | TEXT | 原卷/原书题号，如"程序阅读1""7算3" |
| difficulty | TEXT | 难度：题集①—⑤ / 王道星级 / 空 |
| tier | TEXT | 题集分档：一档/二档/三档（复用分档表），非题集为空 |
| stem | TEXT | 题干（markdown，代码用 ``` 围栏） |
| options | TEXT | 选项（选择题），markdown |
| answer | TEXT | 答案 |
| analysis | TEXT | 解析 |
| kaodian | TEXT | 考点标签，逗号分隔，如"复杂度分析,循环频度" |
| template | TEXT | 关联 15 模板编号（框架 2.5），如"模板3-断链拼接" |
| figures | TEXT | 图引用，JSON 数组，相对 images/ 路径 |
| pdf_page | INTEGER | 原 PDF 页码，回溯用 |
| real_related | TEXT | 真题同源标注，如"同2025倒数第k" |
| raw_text | TEXT | 原始识别文本（未清洗），备查校对 |
| notes | TEXT | 备注（回忆版缺漏、识别存疑等） |

**辅助表**：`chapters`（章节＋高频/中频标注）、`sources`（每个源文件的转化状态台账）、`figures`（图片登记，可选 VLM 描述）。
**索引**：chapter、qtype、tier、source、template、kaodian。

### 3.4 查询工具 tiku.py（AI 取数入口）

| 命令 | 作用 | 示例 |
| :--- | :--- | :--- |
| `list` | 按条件列题（id＋题干首行） | `tiku.py list --chapter 图 --tier 一档` |
| `get` | 输出某题完整内容 | `tiku.py get 题集-07-算3` |
| `search` | 全文搜题干/答案/考点 | `tiku.py search 拓扑排序` |
| `stats` | 多维统计 | `tiku.py stats --by chapter` |
| `export` | 导出 markdown 视图 | `tiku.py export --source 题集 --chapter 图` |
| `import` | 从 jsonl 批量入库 | `tiku.py import 待入库.jsonl` |

筛选参数统一：`--source --chapter --qtype --tier --template --kaodian --difficulty --limit`。输出默认纯文本，`--md` 输出 markdown。AI 讲课备料时的典型用法：`tiku.py list --chapter 图 --qtype 算法设计` 拉出图的所有算法题，再 `get` 逐题取全文。

### 3.5 题目 ID 命名规范

`{源}-{章/年}-{题型简写}{序号}`，全库唯一、可反查来源：

- 真题：`真题-2026-阅读1`、`真题-2025-算法2`
- 题集：`题集-07-算3`（第7章算法设计第3题）、`题集-01-选13`
- 408：`408-2023-选择5`
- 王道/天勤：`王道-06-例题2`、`天勤-05-选择3`

## 四、转化流水线

### 4.1 P0 真题（fitz 直抽，本地免费，已验证）

```
真题PDF ──fitz──▶ 逐页文本 + 逐页图片
                    │
                    ├─ 文本：按题型标题（一、程序阅读 / 二、算法分析…）与题号切分
                    ├─ 图片：抽到 images/真题/，记录 page 归属
                    └─ 答案：2026答案PDF 单独抽，按题号对齐到题目
                    ▼
              清洗为 questions 记录（stem/options/answer/analysis/kaodian）
                    ▼
                 import 入库
```

- 3 个真题 PDF 均有文本层，fitz 抽取质量高（已验证：DFS 生成树、共享栈、链表交集的代码与答案都能完整抽出，填空位保留 `________`）。
- 24-25 是"OCR 文本层＋扫描图"双层 PDF，文本可直接用，整页扫描图存档备校对。
- **回忆版固有缺漏**（如 26 回忆版注明"红色部分并未给出"）如实记入 notes，不臆造补全。
- 真题是 C3-B 的核心弹药，优先做、马上出成果、验证 schema 与 CLI。

### 4.2 P1 题集（MinerU 本地 + GPU，工程大头）

```
① 环境：conda 建 mineru 专用环境，pip install "mineru[all]"，下载模型（GPU 后端）
② 切片：448MB/331页超单文件限制，用 pypdf 按 9 章登记页码区间切小片
        （复用《题集筛选工作流》第二节的章-PDF页台账：全书 PDF页=书页+9）
③ 识别：mineru -p 切片.pdf -o _tmp/mineru_out/ --backend vlm（GPU）
        产出 markdown + content_list.json（含逐块 page_idx）+ images/
④ 后处理：按题号规则（选N/答N/算N）从 markdown 切分逐题
        复用已有 9 章分档表 → tier 字段直接回填
        图按 page_idx 归到对应题
⑤ 校对：题号连续性用第0章交叉引用复核；抽查识别质量；存疑记 notes
⑥ 入库：import → 导出 markdown 视图
```

- **已有资产复用**：`题集筛选工作稿/` 的 9 章题单（题号＋摘要＋PDF页）与分档表（一档/二档/三档）直接作为题集库的**骨架与 tier 来源**，MinerU 识别只是往骨架里填完整题面/选项/答案/图。
- **答案来源**：题集答案在书末或另册，识别时确认答案区页码；若扫描版不含答案，答案字段留空并记 notes，后续人工或外部补。
- **不臆造**：工作流铁律"不许凭记忆编题"照旧——识别不清的记 notes 待人工核，不猜。
- 331 页 GPU 识别约 1—2 小时，切片与后处理是主要人工/脚本工作量。

### 4.3 P2 外部搜集（联网抓全 → 临时区 → 筛选 → 转化）

```
① 搜集（先抓全）：
   - 408 历年真题（数据结构部分）：公开统考真题，版权风险低，优先
   - 严蔚敏《数据结构》教材正文：知识体系原文，补概念讲解
   - 王道/天勤题库：题量大、贴近考试，版权敏感
   → 原始文件（PDF/网页/图片）落 临时区/{408,教材,王道天勤,其他}/
② 登记：sources 表记录每个来源的获取方式、版权状态、质量评估
③ 筛选：过版权与质量关的，才进转化；不过关的留临时区不入主库
④ 转化：文本型直抽，扫描/图片型走 MinerU（复用 P1 环境）→ 结构化 → 入库
```

- **版权边界（主讲确认"先抓全后筛"）**：抓取阶段不设限，但**入主库前必须过版权筛**——408 公开真题可入库；教材正文入库仅作内部备课引用；王道/天勤等付费版权内容，抓来存临时区备选，是否入主库由主讲定夺，默认不公开分发。
- **质量优先**：外部题质量参差，入库时标注来源可信度；与真题/题集重复的题做去重（按 stem 相似度）。

| 阶段 | 内容 | 依赖 | 产出 |

## 六、与 C2/C3 的衔接（数据库怎么服务讲课）

- **C2-B 讲算法**：讲某模板时，`tiku.py list --template 模板3` 拉出该模板全部题（真题＋题集一档＋408），选最典型的当课堂例题、其余当课后题。
- **C3-B 讲真题**：17 道真题的题面、代码、答案、解析已在库，`get 真题-2026-算法1` 直接取，不用再翻 PDF。
- **课后题布置**：`list --chapter 图 --tier 一档` 拉出图的一档题作为强化练习。
- **补缺口**：现有 C2/C3 设计文档里"课后题＝题集X选Y"的引用，可升级为"从库中按考点动态选题"，题量不再受限于手头 PDF。
- **反哺设计**：题库建成后回头审视 C2/C3 逐节设计，凡"内容干瘪"的节，从库里补真题/408 题做例题，落实"内容充实"。

## 七、风险与边界

1. **回忆版真题不完整**：26 回忆版有"红色部分未给出"等缺漏，如实记 notes，不臆造；答案以 2026 答案 PDF 为准，缺答案的题 answer 留空标注。
2. **MinerU 识别质量**：扫描版题集识别可能有误（公式、图、代码缩进），后处理阶段抽查校对，存疑记 notes；题号连续性用交叉引用复核（工作流已验证的方法）。
3. **题集答案缺失**：若扫描版不含答案区，答案字段留空，后续人工或外部补，不编造。
4. **版权**：临时区抓全不设限，但入主库前过版权筛；付费版权内容默认不公开分发，由主讲定夺。
5. **去重**：408/王道题可能与真题/题集重复，入库按 stem 相似度去重，保留来源最全的一条。
6. **存储体积**：题集 331 页图＋外部资料可能几百 MB，images/ 与临时区/ 的大文件按需 gitignore（见第八节）。

## 八、Git 与存储策略

| 内容 | 进 Git？ | 理由 |
| :--- | :--- | :--- |
| schema.sql、tiku.py、各 extract 脚本 | ✅ 进 | 代码资产，可复现 |
| README.md、导出/*.md | ✅ 进 | 人读视图，diff 友好，是主库的可读快照 |
| tiku.db | ⚠️ 主讲定 | 二进制、diff 差；但它是真相源。建议进（数据资产），或只进导出 md＋脚本、db 靠脚本重建 |
| images/（真题小图） | ✅ 进 | 体积可控 |
| images/（题集 331 页图）＋临时区/ | ❌ gitignore | 体积大、版权未定，本地留存即可 |
| _tmp/（MinerU 中间产物） | ❌ gitignore | 临时，已加入 .gitignore |

> 待主讲定：tiku.db 是否进 Git。默认按"进"处理（数据资产优先保全），若仓库体积敏感则改为 gitignore + 靠脚本从导出 md 重建。
