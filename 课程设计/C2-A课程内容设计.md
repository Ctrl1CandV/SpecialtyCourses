### 知识点与关键内容

**802 的作答形式**（框架 1.2、1.3、2.4）：写伪代码，不要求可编译的严格 C。可以省掉 `#include` 与 `main`，直接写函数；评分重思路轻语法，思路对、边界全，语法小错照样给分。但三样不能省：结构体定义（用到的结构要写出类型定义）、函数签名（参数与返回值）、边界判断（空表、越界、n 的合法性）。用 `countNegative`（统计数组负数个数）当例子，光秃秃一个函数就是合格写法。

**答题三件套**（框架 1.2）：① 算法思想（文字说清分几步、每步干什么）② 代码（伪代码，结构体定义与边界完整）③ 复杂度（时间与空间各一个结论，各配一句理由）。三件各有分值，缺一件扣一件；思想那一件还能在代码没写完时救分。样例用求数组最大值 `findMax`，思想写在代码前、复杂度写在代码后，完整演示三段式（不用链表等超纲结构）。

**复杂度分析**（三件套的第三件，最容易丢分）：

- 时间：数基本操作的执行次数，只保留最高阶、去掉系数与低阶。三种数法——① 单层循环直接数（`sum+=a[i]` 跑 n 次即 O(n)）；② 循环变量翻倍（`x*=2` 到超过 n，圈数是 logn，即 O(logn)）；③ 内层范围依赖外层时先求和（`for(i)for(j=i)` 总次数 n(n+1)/2，即 O(n²)）。别数循环层数，要数最里面那句基本操作真正跑了几次。
- 递归式展开：`T(n)=2T(n/2)+O(n)` 画递归树逐层累加。第 0 层 1 个问题代价 O(n)，第 1 层 2 个问题各 O(n/2) 合计还是 O(n)，每层都 O(n)，共 logn 层，所以 O(nlogn)。记法：每层代价乘层数。归并排序、快排的复杂度就是这么来的。
- 空间：辅助数组的大小加递归栈的最大深度。原地算法的 O(1) 指额外空间不随 n 增长，不是一点内存不占。**递归的空间不是 O(1)**，栈深度要算（树的递归遍历是 O(树高)，单支树最坏 O(n)）。

### 推演与动画

P11 递归树跟画页：以 T(n)=2T(n/2)+O(n) 为例，① 画第 0 层 1 个问题代价 O(n)；② 第 1 层拆 2 个各 O(n/2) 合计 O(n)；③ 点出每层翻倍又减半、层层代价都是 O(n)；④ 规模减半到 1 共 logn 层，每层 O(n) 合计 O(nlogn)。学员拿纸跟着画。这是本节唯一的跟画页。

### 设问清单

1. 802 的代码题要不要写 `#include` 和 `main`？（不用，写伪代码，直接写函数）
2. 伪代码里哪三样不能省？（结构体定义、函数签名、边界判断）
3. 一道算法题的三件套是哪三件？（思想、代码、复杂度）
4. 看到两层循环能不能直接写 O(n²)？（不能，要数最里面基本操作的次数，内层依赖外层先求和）
5. 一个递归函数没开任何数组，空间复杂度是 O(1) 吗？（不是，要算栈深度）

### 易错与误解破除

- 以为要写能编译的完整 C 程序：802 写伪代码即可，省头文件与 main。
- 只写代码不写思想和复杂度：三件缺一件扣一件的分。
- 复杂度只写结论不给理由：阅卷要看理由，光有结论拿不全分。
- 以为复杂度就是数循环层数：三层循环里若最内层只执行常数次，总体可能是 O(n)。
- 以为递归没开数组空间就是 O(1)：栈深度必须算进去。

## A2 顺序表（40min，14页）

### 核心结果与用途（≤3）

1. **能默写顺序表定义与五个基本操作**（静态/动态两版定义、InitList、LocateElem、ListInsert、ListDelete）。用途：顺序表是第一个正式结构，也是全课段“学一个结构怎么走”的样板；不熟则后面每个结构的定义与操作都要重新卡壳。
2. **能写对插入/删除的合法范围与挪动方向**（插入位序 1..length+1、从后往前挪；删除位序 1..length、从前往后挪）。用途：这是顺序表最易错、程序阅读题最爱挖的点；方向写反会覆盖数据，上界写错会越界。
3. **会算平均移动次数与复杂度**（插入 n/2、删除 (n-1)/2，均 O(n)）。用途：填空与综合应用常直接问平均移动次数；也说明顺序表插删贵在哪，为链表铺垫。

### 重点过程

P8 插入逐格挪动：一个存 10、20、30、40、50 的表（length=5），在第3位插25。四步——① 画 data[0..4] 与 length=5；② 两个合法范围检查通过；③ j 从5到3逐格后移（data[5]=data[4]、data[4]=data[3]、data[3]=data[2]），每步画数组状态；④ 写 data[2]=25、length 变6。配一句“从后往前才不会覆盖没搬走的数”。P10 检查页用同一个小表走一遍删除（删第2个）做方向对照，先让学生预测再给答案。

### 关键代码与材料出处

**静态与动态定义**（材料原文）：

```c
#define MaxSize 1000
typedef struct{ int data[MaxSize]; int length; }SqList;          // 静态
typedef struct{ int *data; int MaxSize, length; }SeqList;         // 动态
```

两者的差别：静态版 MaxSize 是编译期常量写死在宏里；动态版 MaxSize 是一个字段，运行时由 InitList 的参数决定，所以结构体里必须存它，data 是指针，指向 malloc 出来的那片连续内存。

**初始化两版**：静态版循环清零加 `length = 0`；动态版 `L.data = (int *)malloc(sizeof(int) * InitSize);` 后必须判空，失败返回 false，成功则 `length = 0; MaxSize = InitSize;`。呼应 C1-B-04 的 malloc 与判空。

**LocateElem**：`for(i=0; i<L.length; i++) if(L.data[i]==key) return i+1;` 找不到返回 -1。**为什么返回 i+1**：题目问的是"第几个"，位序从 1 起，下标从 0 起。这是约定 1 的直接体现，也是程序阅读题的常考陷阱。

**ListInsert**（三个动作，次序不能乱）：

```c
bool ListInsert(SqList &L, int i, int elem){
    if(i < 1 || i > L.length + 1) return false;   // 位序合法范围
    if(L.length >= MaxSize) return false;          // 容量判断
    for(int j = L.length; j >= i; j--) L.data[j] = L.data[j - 1];
    L.data[i - 1] = elem;
    L.length++;
    return true;
}
```

三个要点：合法范围是 `1 ≤ i ≤ length+1`（可以插在最后面，所以上界是 length+1 不是 length）；挪动必须**从后往前**，从前往后会把还没挪走的数覆盖掉；写进的位置是 `data[i-1]`，因为位序 i 对应下标 i-1。

**ListDelete**：合法范围 `1 ≤ i ≤ length`；`elem = L.data[i-1]` 用引用把删掉的值带出去（约定 6 的用途）；挪动从前往后 `for(j=i; j<L.length; j++) L.data[j-1] = L.data[j];`。

**移动次数**：插入到第 i 位要挪 length-i+1 个元素，等概率下平均 n/2；删除第 i 位要挪 n-i 个，平均 (n-1)/2。所以顺序表的插入删除是 O(n)，这是它在 B 段与链表对比时的关键数据（只给数字，不做优劣论述，那是专业课的事）。

### 关键代码与材料出处

**定义**（材料原文）：

```c
typedef struct LNode{
    int data;
    struct LNode *next;
}LNode, *LinkList;
```

`LNode` 与 `LinkList` 是同一个结构的两个名字：前者指一个结点，后者指指向结点的指针，也就是"一条链"。C1-B-03 讲过 typedef，这里是它的正式用武之地。定义里写 `struct LNode *next` 是自引用，C1-B-06 已讲过为什么合法（必须隔一层指针），一句话带过不复述。

**头结点的价值**（两句话讲透）：插入删除时第一个数据结点的位置和其他位置处理完全一样，因为头结点永远存在，"第 i-1 个结点"在 i=1 时就是头结点；空表判定变成 `L->next == NULL`，与非空表用同一个式子。

**初始化**：`L = (LNode *)malloc(sizeof(LNode)); if(L == NULL) return false; L->next = NULL; return true;`

**头插法建表**（缺口 1 补写）：

```c
void CreateByHead(LinkList &L, int n){
    L = (LNode *)malloc(sizeof(LNode));
    L->next = NULL;                       // 先成空表
    for(int i = 0; i < n; i++){
        LNode *s = (LNode *)malloc(sizeof(LNode));
        scanf("%d", &s->data);
        s->next = L->next;                // 新结点接在原第一个之前
        L->next = s;
    }
}
```

关键两句的次序不能换：先 `s->next = L->next` 再 `L->next = s`。反过来写，原来的第一个结点就找不到了。结果是**输入次序的逆序**，因为每次都插在头部。

**尾插法建表**（缺口 1 补写）：

```c
void CreateByTail(LinkList &L, int n){
    L = (LNode *)malloc(sizeof(LNode));
    LNode *r = L;                         // r 始终指向当前尾结点
    for(int i = 0; i < n; i++){
        LNode *s = (LNode *)malloc(sizeof(LNode));
        scanf("%d", &s->data);
        r->next = s; r = s;               // 接在尾部，r 后移
    }
    r->next = NULL;                       // 尾结点的 next 必须置空
}
```

rear（这里叫 r）的价值：不留它，每插一个都要从头走到尾找尾巴，n 个结点是 O(n²)；留着它，每次插入 O(1)，整体 O(n)。循环结束后 `r->next = NULL` 不能忘，否则尾结点的 next 是垃圾值（C1-B-04 讲过 malloc 不清零）。

**GetElem 与 LocateElem**（材料原文）：

```c
LNode *GetElem(LinkList L, int i){
    if(i < 0) return NULL;
    LNode *p = L; int j = 0;              // p 从头结点起，j 从 0 起
    while(j < i && p != NULL){ p = p->next; j++; }
    return p;
}
LNode *LocateElem(LinkList L, int elem){
    LNode *p = L->next;                   // 按值查找从第一个数据结点起
    while(p != NULL && p->data != elem) p = p->next;
    return p;
}
```

口径要点：`GetElem(L, 0)` 返回头结点，`GetElem(L, i)` 返回第 i 个数据结点。两个函数起点不同（一个从 L，一个从 L->next），要对比着讲。

**ListInsert 与 ListDelete**（材料原文）：

```c
bool ListInsert(LinkList &L, int i, int elem){
    LNode *p = GetElem(L, i - 1);         // 找前驱
    if(p == NULL) return false;
    LNode *s = (LNode *)malloc(sizeof(LNode));
    if(s == NULL) return false;
    s->data = elem;
    s->next = p->next;                    // 先接后面
    p->next = s;                          // 再接前面
    return true;
}
bool ListDelete(LinkList &L, int i, int &elem){
    LNode *p = GetElem(L, i - 1);
    if(p == NULL) return false;
    if(p->next == NULL) return false;     // 第 i 个结点不存在
    LNode *s = p->next;
    elem = s->data;
    p->next = s->next;
    free(s);
    return true;
}
```

插入找的是**第 i-1 个结点**（前驱），这是链表与顺序表最大的思路差别：顺序表直接按下标访问，链表必须从前往后走到前驱。删除要判两次：前驱存在（p != NULL）、第 i 个结点存在（p->next != NULL）。

**求表长与销毁**（缺口 1 补写）：

```c
int ListLength(LinkList L){
    int n = 0; LNode *p = L->next;
    while(p != NULL){ n++; p = p->next; }
    return n;
}
void DestroyList(LinkList &L){
    LNode *p = L, *q;
    while(p != NULL){ q = p->next; free(p); p = q; }   // 先存后继再 free
    L = NULL;
}
```

销毁的关键：必须先存下一个结点的地址再 free 当前结点，否则 free 之后 `p->next` 读的是已回收内存（C1-B-04 的悬空指针）。只 free 头结点会漏掉全部数据结点，是典型的内存泄漏。

### 知识点与关键代码

**双链表定义**（材料原文）：

```c
typedef struct DNode{
    int data;
    struct DNode *prior, *next;
}DNode, *DLinkList;
```

**双链表插入**（材料原文，四条赋值的次序是本节重点）：

```c
bool ListInsert(DLinkList &L, int i, int elem){
    DNode *p = GetElem(L, i - 1);
    if(p == NULL) return false;
    DNode *s = (DNode *)malloc(sizeof(DNode));
    if(s == NULL) return false;
    s->data = elem;
    s->next = p->next;                        // ①
    s->prior = p;                             // ②
    if(p->next != NULL) p->next->prior = s;   // ③ 插在表尾时 p->next 为 NULL
    p->next = s;                              // ④
    return true;
}
```

次序的讲法：① 和 ② 是安置新结点自己，先后无所谓；**③ 必须在 ④ 之前**，因为 ④ 一执行，`p->next` 就指向 s 了，再写 `p->next->prior` 改的是 s 自己，原来的后继就丢了 prior。③ 的判空是因为插在表尾时没有后继。

**双链表删除**（材料原文）：

```c
bool ListDelete(DLinkList &L, int i, int &elem){
    DNode *p = GetElem(L, i - 1);
    if(p == NULL) return false;
    if(p->next == NULL) return false;
    DNode *s = p->next;
    elem = s->data;
    p->next = s->next;
    if(s->next != NULL) s->next->prior = p;   // 删的是尾结点时无后继
    free(s);
    return true;
}
```

**循环单链表**：与单链表的三处差别，一处一处对比着讲。

| 动作 | 单链表 | 循环单链表 |
| :-- | :-- | :-- |
| 建表结束 | `r->next = NULL` | `r->next = L`（指回头结点） |
| 判空 | `L->next == NULL` | `L->next == L` |
| 遍历终止 | `p != NULL` | `p != L` |

头插法建循环单链表：每插一个都 `s->next = L->next; L->next = s;`，最后 `r->next = L`。材料的“循环单链表的原地逆置”（B1 讲）用的就是这个终止条件。

**循环双链表**：判空要两个条件 `L->next == L && L->prior == L`。只判一个不够，因为插入过程中可能出现 next 已成环而 prior 还没接好的中间状态。

**静态链表**（缺口 2 补写，完整版见缺口代码文档）：

```c
#define MaxSize 100
typedef struct{
    int data;
    int next;            // 游标：下一个元素的下标，-1 表示结束
}SLinkList[MaxSize];
```

讲清三件事：下标 0 通常当头结点用；`next` 存的是下标不是地址，所以叫游标；插入删除只改游标不搬数据，这一点和链表一样。它存在的理由是在没有指针的语言里模拟链表，以及某些题目要求用数组实现链表操作。

**四种链表怎么选**（一张对比表收尾）：

| 需求 | 选哪种 | 理由 |
| :-- | :-- | :-- |
| 只在尾部操作、要顺序 | 单链表加 rear | 尾插 O(1) |
| 要频繁找前驱或双向走 | 双链表 | prior 直接给前驱 |
| 要循环报数、轮转 | 循环单链表 | 走到尾自动回头，约瑟夫环就是这个 |
| 要频繁在头尾两端操作 | 循环双链表 | 头尾都是 O(1) |
| 题目要求用数组 | 静态链表 | 游标代替指针 |

### 推演与动画

P5 双链表插入四步动画：① s->next 指向原后继；② s->prior 指向 p；③ 原后继的 prior 改指 s；④ p 的 next 改指 s。每步画一次，第四步之前插一帧“如果先做第四步会怎样”的对比。

### 设问清单

1. 双链表插入的四条赋值里，哪两条的次序绝对不能换？（③ 与 ④，③ 必须在 ④ 前）
2. 插入时为什么要有 `if(p->next != NULL)`？（插在表尾时没有后继）
3. 循环单链表怎么判空？遍历终止条件是什么？（`L->next == L`；`p != L`）
4. 循环双链表判空为什么要两个条件？（插入过程中可能只有一边成环）
5. 静态链表的 next 里存的是什么？（下一个元素的下标，即游标）

### 易错与误解破除

- 双链表插入先做 `p->next = s`：原后继的 prior 再也改不到，链断了。
- 循环链表还用 `p != NULL` 做终止条件：死循环，因为永远遇不到 NULL。
- 静态链表当成顺序表用：它的插入删除不搬数据，只改游标。
- 以为双链表一定比单链表好：多一个指针就多一份空间，只在需要找前驱时才值得。

### 知识点与关键代码

**顺序栈定义与五个操作**（材料原文）：

```c
typedef struct{ int data[MaxSize]; int top; }SqStack;

bool InitStack(SqStack &S){ S.top = -1; return true; }
bool IsEmpty(SqStack &S){ return S.top == -1; }
bool IsFull(SqStack &S){ return S.top == MaxSize - 1; }
int  GetLength(SqStack &S){ return S.top + 1; }
bool Push(SqStack &S, int elem){
    if(S.top == MaxSize - 1) return false;
    S.data[++S.top] = elem;               // 先移 top 再放
    return true;
}
bool Pop(SqStack &S, int &elem){
    if(S.top == -1) return false;
    elem = S.data[S.top--];               // 先取再移 top
    return true;
}
bool GetTop(SqStack &S, int &elem){
    if(S.top == -1) return false;
    elem = S.data[S.top]; return true;    // 只读不移
}
```

讲 `++S.top` 与 `S.top--` 的位置：top=-1 表示栈空，所以入栈必须先把 top 加 1 再放（前缀自增），出栈必须先取再减 1（后缀自减）。这个次序是由约定决定的，不是随便写的。

**top=0 约定的对比**（只对比不展开）：入栈写 `S.data[S.top++] = elem`，出栈写 `elem = S.data[--S.top]`，判空 `S.top == 0`，判满 `S.top == MaxSize`，长度就是 `S.top`。四个式子全变了，所以约定必须先说清。

**循环队列定义与四个操作**（材料原文）：

```c
typedef struct{ int data[MaxSize]; int rear, front; }SqQueue;

bool InitQueue(SqQueue &Q){ Q.front = 0; Q.rear = 0; return true; }
bool IsEmpty(SqQueue &Q){ return Q.rear == Q.front; }
bool IsFull(SqQueue &Q){ return (Q.rear + 1) % MaxSize == Q.front; }
int  GetLength(SqQueue &Q){ return (Q.rear - Q.front + MaxSize) % MaxSize; }
bool EnQueue(SqQueue &Q, int elem){
    if((Q.rear + 1) % MaxSize == Q.front) return false;
    Q.data[Q.rear] = elem;
    Q.rear = (Q.rear + 1) % MaxSize;      // 先放再移 rear
    return true;
}
bool DeQueue(SqQueue &Q, int &elem){
    if(Q.rear == Q.front) return false;
    elem = Q.data[Q.front];
    Q.front = (Q.front + 1) % MaxSize;    // 先取再移 front
    return true;
}
```

**假溢出**：不取模的话，rear 走到 MaxSize 就到头了，可前面因为出队腾出的空间用不上。取模让下标绕回去，这就是“循环”的含义。

**判满三策略**（本节重点，一张表讲完）：

| 策略 | 判空 | 判满 | 代价 |
| :-- | :-- | :-- | :-- |
| 牺牲一单元（本课程默认） | `rear == front` | `(rear+1)%MaxSize == front` | 少存一个元素 |
| 加 size 字段 | `size == 0` | `size == MaxSize` | 多一个字段，入队出队都要维护 size |
| 加 tag 字段 | `front == rear && tag == 0` | `front == rear && tag == 1` | 多一个字段，只有入队让 rear 追上 front 时 tag 置 1 |

问题的根源：`rear == front` 既可能是空也可能是满，三种策略就是三种消歧办法。牺牲一单元最简单（不加字段），所以教材与本课程都用它。`GetLength` 为什么要 `+MaxSize`：`rear - front` 可能是负数（rear 绕回了前面），加 MaxSize 再取模就得到正确长度。

**链栈与链队**（缺口 3 补写，一页带过）：链栈用单链表，栈顶就是表头，入栈等于头插，出栈等于删第一个结点，不需要判满（内存够就能压），只需判空 `L->next == NULL`。链队要同时有 front 和 rear 两个指针，入队在 rear 后面接，出队从 front 摸；材料提到链队一般默认不带头结点，此时队空的条件是 `front == NULL && rear == NULL`，出队到只剩一个结点时要同时更新 rear。

**栈与递归**：C1-B-06 画过 fact(3) 的调用栈，四层层层展开再层层收回。那一节讲的是“函数调用为什么会有栈”，这一节讲的是“怎么自己用一个栈”。A7 的非递归遍历就是把递归的栈搬到代码里显式管理，这是 B4、B5 大量算法的工具。

### 推演与动画

P9 是核心动画：一个 MaxSize=5 的循环队列（牺牲一单元，实际最多存 4 个），依次做五次入队和三次出队，每一步画出 data[0..4] 的内容与 front、rear 的位置。要让学生亲眼看到三件事：rear 从 4 绕回 0；当 `(rear+1)%5 == front` 时明明还有一格空着却判满，这就是牺牲的那一单元；出队后 front 追上 rear 就是队空。

### 设问清单

1. top=-1 时，入栈为什么写 `S.data[++S.top]` 而不是 `S.data[S.top++]`？（top 指向栈顶元素，-1 表示空，必须先移再放）
2. 循环队列不牺牲一单元会怎样？（队空与队满都是 rear==front，无法区分）
3. 加 size 和加 tag 各是怎么消歧的？（size 直接记个数；tag 记最后一次是入队还是出队）
4. `GetLength` 里为什么要 `+MaxSize`？（rear-front 可能为负）
5. 链栈需要判满吗？（不需要）
6. EnQueue 是先放数据还是先移 rear？（先放，rear 指向的是下一个空位）

### 易错与误解破除

- 把栈的判满写成 `S.top == MaxSize`：top=-1 约定下应该是 `MaxSize-1`。
- 入队不判满就放：覆盖掉还没出队的元素。
- 出队先移 front 再取：取到的是下一个元素。
- 混用两种约定：同一道题里 top 的初值与判空判满式子必须配套。
- 以为链队只有一个指针：必须 front 和 rear 两个，否则入队要走到尾。

### 知识点与关键代码

**三种存储**（材料原文）：定长顺序存储 `typedef struct{ char ch[MaxSize]; int length; }SString;`（考察串的基本概念时用，不涉及 malloc）；堆分配存储 `typedef struct{ char *ch; int length; }String;`（本节四个基本操作全部基于这一种）；块链存储（一个结点存多个字符，一句带过）。

**必须记住的易错点**（材料原文的【易错】标注）：两种定义不能混用。定长数组 `char ch[MaxSize]` 不能 free，也不能被赋值为 NULL。凡是出现 `str.ch = (char*)malloc(...)` 的操作，其结构体的 ch 必须是指针。

**strassign**（材料原文，命中勘误 B7，用修正版）：

```c
int strassign(String &str, char *ch){
    if(str.ch){ free(str.ch); str.ch = NULL; }   // 修正：free 后置 NULL
    int len = 0; char *c = ch;
    while(*c){ len++; c++; }
    if(len == 0){ str.ch = NULL; str.length = 0; return 1; }   // 修正：成功返回 1
    str.ch = (char*)malloc(sizeof(char) * (len + 1));          // +1 是为了存 '\0'
    if(str.ch == NULL) return 0;                               // 失败返回 0
    c = ch;
    for(int i = 0; i <= len; i++){ str.ch[i] = *c; c++; }      // <= 才存到 '\0'
    str.length = len;
    return 1;
}
```

两个数字要讲透：`len+1` 是留给结束符的空间；循环写到 `i <= len` 是为了把 '\0' 也拷进去。勘误 B7 的两处修正（free 后置 NULL、返回值统一为成功 1 失败 0）要在页面上说明一句“笔记里是简写，这里统一约定”。

**strcompare**（材料原文，命中勘误 B6）：

```c
bool strcompare(String s1, String s2){
    for(int i = 0; i < s1.length && i < s2.length; i++)
        if(s1.ch[i] != s2.ch[i]) return false;
    return (s1.length - s2.length) == 0;
}
```

明确告诉学生：这个函数名叫 compare，实际做的是**判等**——遇到第一个不同字符就返回 false，最后比长度。它不返回大小关系。如果题目要字典序比较，需要另写返回 int 的版本（第一个不同字符决定正负，全同则比长度）。这是勘误 B6 的处置。

**concat**（材料原文）：申请 `str1.length + str2.length + 1`；第一个循环 `while(i < str1.length)` 只拷 str1 的有效字符（不拷它的 '\0'）；第二个循环 `while(j <= str2.length)` 多拷一个，把 str2 的 '\0' 一起拷过来当结果的结束符。两个循环边界的差别是本段的讲解重点。

**substring**（材料原文）：合法性判断 `pos < 0 || pos >= str.length || len < 0 || pos + len > str.length`；len==0 时结果是空串（ch 置 NULL）；否则申请 len+1，拷完补 `substr->ch[j] = '\0'`。

**BF 匹配**（材料原文）：

```c
int index(String str, String substr){
    if(str.length == 0 || substr.length == 0) return 0;
    int i = 0, j = 0, k = i;
    while(i < str.length && j < substr.length){
        if(str.ch[i] == substr.ch[j]) { i++; j++; }
        else{ j = 0; i = ++k; }           // 失配：模式串回开头，主串从下一位重来
    }
    if(j == substr.length) return k + 1;  // 返回位序
    return 0;
}
```

三个指针的分工：i 扫主串当前位置，j 扫模式串当前位置，k 记住本轮匹配的起点。失配时 j 归零、i 回到 k+1，这就是“回溯”。返回 k+1 是位序（和 LocateElem 一个口径）。最坏时间复杂度 O(nm)。

**KMP 的思想与 next 手算**：BF 的问题是主串指针要回溯，已经比对过的字符又比一遍。KMP 让主串指针 i 永不回溯，失配时只把模式串的 j 退到 next[j]。next[j] 的含义：模式串前 j-1 个字符里最长相等前后缀的长度加 1。nextval 是 next 的优化：如果 `substr[j] == substr[next[j]]`，那么退到 next[j] 还是会失配，所以直接取 `nextval[next[j]]`。

**不写匹配代码的理由**要说清：802 考的是 next 与 nextval 的手算（题集 4选18、4选20、4答7、4答8 全是手算），七年真题里没有一道要求写 KMP 匹配代码。所以本节把思想讲透、把手算练熟，代码不写。这是框架 2.7 “主线与辅线分界”的一个具体例子。

**数组地址计算**（一页）：行优先下 `a[i][j]` 的地址 = 基址 + (i×列数 + j) × 每元素字节数；列优先把 i 与 j 的角色换过来。三维同理。这是填空题常考点（题集 5选2—5选7、5答1—5答3），代码课只讲清它就是下标换算，代码里体现为多维数组的存储次序。

**三对角矩阵**（一页）：n 阶三对角矩阵的非零元素集中在 |i-j| ≤ 1 的区域。压缩到一维数组后，推导思路是数一下 `a[i][j]` 前面有多少个非零元素：前 i-2 行满行各 3 个，第 i-1 行有 i-1 个，本行前面有 j-i+1 个，加起来就是下标（按材料给的口径写式子，课堂上把推导走一遍而不只给结论）。

**广义表**（一页）：head 取第一个元素（可以是原子也可以是子表），tail 取除第一个之外剩下的**表**（一定是表，哪怕只剩一个元素也带括号）。这两个口径是题集 5选15—5选22、5答13、5答14 的全部考点。代码课只给一页，说明它在代码里就是递归定义的结点结构（材料有广义表存储结构的图）。

### 知识点与关键代码

**两种定义**（材料原文）：

```c
typedef struct BiTNode{
    ElemType data;
    struct BiTNode *lchild, *rchild;
}BiTNode, *BiTree;

typedef struct CSNode{
    ElemType data;
    struct CSNode *firstchild, *nextbro;
}CSNode, *CSTree;
```

孩子兄弟链表这里只给定义并说一句“它是把一般树存成二叉树的办法，A8 展开”，不讲用法，避免超前一页。

**三种递归遍历**（材料只给了先序，中序后序补全，差别只在 visit 位置）：

```c
void PreOrder(BiTree T){                  // 先序：根 左 右
    if(T == NULL) return;
    visit(T);
    PreOrder(T->lchild);
    PreOrder(T->rchild);
}
void InOrder(BiTree T){                   // 中序：左 根 右
    if(T == NULL) return;
    InOrder(T->lchild);
    visit(T);
    InOrder(T->rchild);
}
void PostOrder(BiTree T){                 // 后序：左 右 根
    if(T == NULL) return;
    PostOrder(T->lchild);
    PostOrder(T->rchild);
    visit(T);
}
```

三个函数摆在一页上，让学生看到只有 visit 的位置在动。这一页是本节的核心认识：**遍历方式的区别就是访问根的时机**。时间复杂度三个都是 O(n)（每个结点访问一次），空间是 O(树高)（递归栈深度），最坏 O(n)（单支树）。

**非递归先序**（材料原文，类型名按勘误 B4 改为 SqStack）：

```c
void PreOrder2(BiTree T){
    if(T == NULL) return;
    SqStack s; InitStack(s);
    Push(s, T);
    BiTree p;
    while(!IsEmpty(s)){
        Pop(s, p); visit(p);
        if(p->rchild != NULL) Push(s, p->rchild);   // 先压右
        if(p->lchild != NULL) Push(s, p->lchild);   // 再压左
    }
}
```

为什么先压右再压左：栈是后进先出，后压的左孩子先弹出，所以访问顺序是根、左、右。

**非递归中序**（材料原文，类型名同上改）：

```c
void InOrder2(BiTree T){
    if(T == NULL) return;
    SqStack s; InitStack(s);
    BiTNode *p = T;
    while(!IsEmpty(s) || p != NULL){
        while(p != NULL){ Push(s, p); p = p->lchild; }   // 一路压左到底
        if(!IsEmpty(s)){
            Pop(s, p); visit(p);                          // 弹出即访问（根）
            p = p->rchild;                                // 转向右子树
        }
    }
}
```

两个要点：外层循环条件是 `!IsEmpty(s) || p != NULL`，两个条件缺一不可（栈空但 p 非空说明还有右子树要处理，p 空但栈非空说明还要回退）；内层 while 在做什么——把从当前结点往左的一整条链全压进栈，这就是递归版里“先一路往左走”的显式版本。

**非递归后序**（材料原文，命中勘误 A4 缺判空，补上）：

```c
void PostOrder2(BiTree T){
    if(T == NULL) return;                    // 勘误 A4：材料缺这一句
    SqStack s1, s2; InitStack(s1); InitStack(s2);
    BiTNode *p;
    Push(s1, T);
    while(!IsEmpty(s1)){                     // 用先序变体“根右左”遍历，结果压入 s2
        Pop(s1, p); Push(s2, p);
        if(p->lchild) Push(s1, p->lchild);
        if(p->rchild) Push(s1, p->rchild);
    }
    while(!IsEmpty(s2)){ Pop(s2, p); visit(p); }   // 逆置读出即“左右根”
}
```

双栈法的思路要讲清：s1 里按“根、左、右”的压栈方式得到“根、右、左”的弹出序列，把这个序列全部压进 s2，再从 s2 弹出就是“左、右、根”，正是后序。这是模板 14（辅助栈逆序）的一个实例。

**层序遍历**（材料原文）：

```c
void LevelOrder(BiTree T){
    if(T == NULL) return;
    SqQueue Q; InitQueue(Q);
    EnQueue(Q, T);
    BiTNode *p;
    while(!IsEmpty(Q)){
        DeQueue(Q, p); visit(p);
        if(p->lchild != NULL) EnQueue(Q, p->lchild);
        if(p->rchild != NULL) EnQueue(Q, p->rchild);
    }
}
```

为什么必须用队列不能用栈：层序要按“先进先出”的顺序访问，同一层的结点先入队先出队，用栈会变成深度优先。这就是约定 4 的用处：队列里存的是 BiTree（结点指针），不是 int，答题时要说明一句。

**由先序与中序建树**（材料真题 2026 第 2 题原文）：

```c
BiTree Build(BiTree &T, int A[], int B[], int preL, int preR, int inL, int inR){
    if(preL > preR) return NULL;                 // 区间为空
    T = (BiTNode*)malloc(sizeof(BiTNode));
    T->data = A[preL];                           // 先序第一个是根
    int k = inL;
    while(B[k] != A[preL]) k++;                  // 在中序里定位根
    int leftLen = k - inL;                       // 左子树结点个数
    Build(T->lchild, A, B, preL + 1, preL + leftLen, inL, k - 1);
    Build(T->rchild, A, B, preL + leftLen + 1, preR, k + 1, inR);
    return T;
}
```

四步讲：① 先序的第一个元素是根；② 在中序里找到根的位置 k，k 左边是左子树、右边是右子树；③ 算出左子树结点个数 leftLen，用它把先序也切成两段；④ 递归建左右子树。四个下标边界是本节的难点，要对着一个具体例子（先序 1 2 4 5 3，中序 4 2 5 1 3）走一遍。

### 易错与误解破除

- 非递归中序的外层条件只写 `!IsEmpty(s)`：右子树没进栈时会提前结束。
- 层序里 EnQueue 前不判孩子非空：把 NULL 入队，出队时 visit(NULL) 会崩。
- 建树的边界写成 `preL >= preR`：会漏掉只有一个结点的子树，正确是 `preL > preR`。
- 以为递归遍历的空间是 O(1)：递归栈要算，是 O(树高)。
- 后序遍历用“中序加标志”的写法与双栈法混用：本课程统一用双栈法，因为它不需要额外的标志位。

### 知识点与关键代码

**结构定义**（材料原文）：

```c
typedef struct BiThrNode{
    int data;
    struct BiThrNode *lchild, *rchild;
    int ltag, rtag;          // 0 表示指向孩子，1 表示线索
}BiThrNode, *BiThrTree;
```

**中序线索化**（材料原文）：

```c
void InThread(BiThrTree &p, BiThrTree &pre){
    if(p != NULL){
        InThread(p->lchild, pre);
        if(p->lchild == NULL){ p->lchild = pre; p->ltag = 1; }        // 建前驱线索
        if(pre != NULL && pre->rchild == NULL){ pre->rchild = p; pre->rtag = 1; }  // 回填后继线索
        pre = p;
        InThread(p->rchild, pre);
    }
}
void CreateInThread(BiThrTree &T){
    BiThrNode *pre = NULL;
    if(T){
        InThread(T, pre);
        if(pre != NULL){ pre->rchild = NULL; pre->rtag = 1; }   // 最后一个结点的后继置空
    }
}
```

**pre 的作用是本节的核心**，要讲透：pre 始终指向中序序列里刚刚访问过的结点。线索化需要两类信息：当前结点 p 的前驱（就是 pre），以及 pre 的后继（就是 p）。前者在 p 的左链域为空时直接建；后者要等到下一步才能回填，因为遍历到 p 时还不知道 p 的后继是谁。这就是代码里两个 if 分开写的原因。

**为什么 CreateInThread 结束后要单独处理 pre**：循环结束时 pre 指向中序序列的最后一个结点，它的右链域是空的且没有后继可指，所以置 NULL 并把 rtag 设为 1（表示“这是线索，指向空”），与前面的约定保持一致。

**线索树上找后继**（材料原文在 `重邮数据结构.md`，代码总结缺）：

```c
BiThrNode *Nextnode(BiThrNode *p){
    if(p->rtag == 1) return p->rchild;          // 右链域是线索，直接就是后继
    BiThrNode *q = p->rchild;                    // 否则进右子树
    while(q->ltag == 0) q = q->lchild;           // 找右子树的最左下结点
    return q;
}
BiThrNode *Firstnode(BiThrNode *T){              // 中序第一个结点
    while(T->ltag == 0) T = T->lchild;
    return T;
}
```

两种情况要对比着讲：rtag==1 时后继已经存好了，O(1) 拿到；rtag==0 时要进右子树找最左下，最坏 O(树高)。

**中序线索树的遍历**（材料原文）：

```c
for(BiThrNode *p = Firstnode(T); p != NULL; p = Nextnode(p)) visit(p);
```

一句话讲完它的价值：不用栈、不用递归、不用额外空间，空间复杂度 O(1)。这是线索化存在的全部理由。

**树的孩子兄弟存储与转化三步**：树转二叉树的画法是① 兄弟之间连线；② 每个结点只保留与第一个孩子的连线（抹去其他孩子的线）；③ 以根为轴心把整棵树顺时针旋转 45 度。结果是：原来的第一个孩子变成左子树，原来的下一个兄弟变成右子树，正好对应 CSNode 的 firstchild 与 nextbro。

森林转二叉树：先把每棵树各自转成二叉树，再把后一棵树作为前一棵树根的右子树，依次接下去。

**遍历对应关系**（一张表，这是题集 6选45 的考点）：

| 树的遍历 | 对应二叉树的遍历 |
| :-- | :-- |
| 先根遍历 | 先序遍历 |
| 后根遍历 | **中序**遍历 |

后根对应中序而不是后序，这是学生最容易错的一条。理由：孩子兄弟表示法里，一个结点的兄弟全部挂在右子树上，后根遍历“先孩子后自己”在二叉树上就成了“先左子树、再自己、再右子树（兄弟们）”，正是中序。

**求树的度**（材料原文，写法巧妙，要逐行讲）：

```c
int degree = 0;                     // 全局变量
int Post(CSNode *p){
    if(p == NULL) return 0;
    Post(p->firstchild);            // 递归进子树，只为更新全局 degree，不用返回值
    int d = 1 + Post(p->nextbro);   // 自己加所有兄弟，就是一个父结点的孩子数
    degree = max(degree, d);
    return d;
}
```

两件事要讲清：一是 `Post(p->firstchild)` 的返回值被丢开了，它的作用只是让递归走到子树里去更新全局变量；二是 `1 + Post(p->nextbro)` 数的是“自己加上后面的兄弟”，而一条兄弟链恰好对应一个父结点的孩子，所以 d 就是那个父结点的度。这是模板 5（递归三件套里“遍历中维护全局变量”）的一个实例，B4 会反复用这个套路。

### 易错与误解破除

- ltag、rtag 的 0 与 1 含义记反：0 是孩子指针，1 是线索。
- 以为线索化之后就不能再插入结点：可以，但要重建线索，所以线索树适合静态场景。
- 把树的后根遍历对应到二叉树的后序遍历：错，是中序。
- 森林转二叉树时把后一棵树接到左子树：应该接右子树。
- 求度的函数里把 `Post(p->firstchild)` 写成用返回值：它返回的是子树里的兄弟链长度，与当前度无关。

#define MaxVertexNum 100
// 邻接矩阵
typedef struct{

**字段名统一规则**（勘误 B1、B2、B3 的处置，本页是全课程的一次性交代）：

- 边表结点的下一指针统一叫 `nextarc`。材料里 2024 与 2025 两道真题的解答用的是 `p->next`，因为那两年的题面自己给的结构体字段就叫 next。**规则：以题目给出的定义为准，答题时抄题目的字段名**；课件正文统一用 nextarc。

- 顶点数上限统一叫 `MaxVertexNum`。材料里出现过 `MAX_VERTEX_NUM` 与 `MAXV` 两种写法，课件不用。

**求所有顶点入度与邻接表转矩阵**（材料原文）：

```c
void Indegree(ALGraph G, int indeg[]){
    for(int i = 0; i < G.vexnum; i++) indeg[i] = 0;
    for(int i = 0; i < G.vexnum; i++)
        for(ArcNode *p = G.vertices[i].firstarc; p != NULL; p = p->nextarc)
            indeg[p->adjvex]++;
}
```

要讲清为什么必须遍历所有顶点的边表：入度是“指向它的弧有多少条”，而这些弧分散在各个顶点的边表里，只看一个顶点的边表只能得到它的出度。这个函数是 B6 拓扑排序的第一步，也是 2026 真题的第一步。

邻接表转矩阵：双重循环，外层遍历顶点，内层遍历它的边表，`A[i][p->adjvex] = 1`；无向图还要对称地写 `A[p->adjvex][i] = 1`。

**DFS**（材料原文，常量名统一）：

```c
bool visited[MaxVertexNum];
void DFS(ALGraph G, int v){
    visit(v);
    visited[v] = true;
    for(ArcNode *p = G.vertices[v].firstarc; p != NULL; p = p->nextarc)
        if(!visited[p->adjvex]) DFS(G, p->adjvex);
}
void DFS_Traverse(ALGraph G){
    for(int i = 0; i < G.vexnum; i++) visited[i] = false;   // 复位
    for(int i = 0; i < G.vexnum; i++)
        if(!visited[i]) DFS(G, i);
}
```

两个要点：visit 与标记的先后（先访问再标记，不能反）；Traverse 里为什么要先把 visited 全部复位（它是全局数组，上一次遍历的标记会残留）与为什么要外套一层 for（非连通图要从每个未访问顶点各走一次）。

**BFS**（材料原文，常量名统一）：

```c
bool visited[MaxVertexNum];
SqQueue Q;
void BFS(ALGraph G, int v){
    visit(v); visited[v] = true; EnQueue(Q, v);
    while(!IsEmpty(Q)){
        DeQueue(Q, v);
        for(ArcNode *p = G.vertices[v].firstarc; p != NULL; p = p->nextarc){
            int k = p->adjvex;
            if(!visited[k]){ visit(k); visited[k] = true; EnQueue(Q, k); }
        }
    }
}
```

**入队时就标记而不是出队时标记**，这是本节最重要的一个设问：如果出队时才标记，同一个顶点可能被多个邻居重复入队， visit 会输出多次，队列也会变长。入队时标记保证每个顶点最多入队一次。

**复杂度对比**（一张表）：

| 存储 | DFS 与 BFS 时间 | 空间 |
| :-- | :-- | :-- |
| 邻接矩阵 | O(n²)：每个顶点都要扫一整行 n 个元素 | O(n)：visited 加栈或队列 |
| 邻接表 | O(n+e)：n 个顶点加 e 条边各访问一次 | O(n) |

邻接表的空间是 O(n+e)（无向图 2e 条边表结点），邻接矩阵是 O(n²)。所以稀疏图用邻接表，稠密图用矩阵。

**并查集一页**（埋钩子）：给定义（一个数组 parent，parent[i] 是 i 的父结点，根的 parent 指向自己）、两个操作（Find 沿父结点往上找到根、Union 把一棵树的根接到另一棵树的根下）、一句话用途（判断两个顶点是否已在同一集合，Kruskal 靠它判环）。本节只理31这些，B7 讲 Kruskal 时兑现。

5. 非连通图为什么要外套一层 for？（每个连通分量要从自己的某个顶点走一次）
6. 邻接矩阵下 DFS 为什么是 O(n²)？（每个顶点要扫一整行）
7. visited 是全局数组，会带来什么问题？（上次遍历的标记会残留，Traverse 里必须先复位）

### 易错与误解破除

- BFS 出队时才标记 visited。
- 忘记在 Traverse 里复位 visited，第二次调用时结果错。
- 邻接表的边表遍历写成 `p = p->next`（应为 `nextarc`，除非题目自己给的字段叫 next）。
- 以为 BFS 队列里存的是顶点本身：存的是顶点编号（约定 4）。
- DFS 递归版里忘记判 `!visited[...]` 就直接递归：有环的图会无限递归。
