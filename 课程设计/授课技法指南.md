# 授课技法指南（802代码课程）

> 本文档回答一个问题：**怎么把课讲得最好**——大纲与内容怎么设计、PPT和讲稿怎么写、录制怎么录。
> 依据：翁恺《C语言程序设计》、鹏哥C语言、郝斌C语言、哈佛CS50（David Malan）的教学方法拆解；梅耶多媒体学习认知理论；BOPPPS与加涅九段教学法；edX/斯坦福视频时长实证研究；讲稿写作与录制技法资料。来源清单见文末附录。
> 本文档是持续迭代的工作文档：每录完一节课，把新踩的坑和新发现的好做法回写进对应章节。

## 一、三个核心病灶与总药方

当前课件的三个问题，各有病根：

| 病灶 | 病根 | 总药方 |
| :--- | :--- | :--- |
| 有效内容不足（35分钟的课录不满25分钟） | 讲稿只写了"结论"，没写"过程"：缺少推导、演示、设问、跟练、重复 | 每个知识点按"厚度公式"展开（§2.2）；讲稿字数按语速预算硬约束（§2.1） |
| AI味重 | 三个独立来源：**平均化**（措辞过于标准、内容过于全面、同一结论反复论证）、**绕**（比喻替代术语、AI专用词、把简单内容讲复杂、层次越界）、**读者负担**（自造词当术语用、电报句、名词标签当标题、口播正文列表化） | 讲稿只讲PPT上没有的东西（§4.1）；备料先行、先说后写（§4.2、§4.8）；过一遍去AI味清单（§4.4）；过“绕”三型自查（§4.7）；分诊三个来源并守住防过度修正的五条边界（§4.8） |
| 内容干瘪 | 缺少激活旧知、练习、反馈、迁移环节；没有"事件"，全是"陈述" | 按BOPPPS补齐环节（§2.3）；每节设计一个"难忘时刻"（§2.4） |

**本项目的最高判据（2026-09-06 主讲申明）**：去 AI 味是手段，不是目的。这个项目的验收标准只有一条：**听者能不能跟上逻辑，听完能不能自己写出来**。所以判断一处表述要不要改，问的不是“它命中了哪条病理”，而是“改了之后学生是不是更容易懂”。命中词表但改了反而更难懂的，不改（术语该长就长，宁可多花十秒解释也不换成模糊的说法）。

本项目实际出现过的两个真病，都不在 AI 味清单里，只能靠内容设计治：

- **内容干瘪**（C1-A：35 分钟的课录不满 25 分钟）。病根是只写结论不写过程。药是厚度公式（§2.2）与备料先行（§4.8）。
- **语言膨胀**（C1-B-05：字数与时长标注都达标，但同一个结论讲了五遍）。病根是一个结论摊到多页。药是“一个结论只论证一次”（§4.4）与“本节几个结论、各在哪页论证”的结构自查（§4.7）。

三者的关系是：**内容干瘪与语言膨胀是主病，AI 味是并发症**。把内容做实、把逻辑理顺，大半 AI 味自动消失；反过来只清词表不补内容，会得到一份“读着顺但学不到东西”的稿子。

## 二、课程大纲与内容设计

### 2.1 时长与字数的硬预算

- 中文授课语速基准：**160—180字/分钟**（智慧树平台讲稿模板的折算标准；教培类内容可放慢到120—140字/分，难点处更慢）。
- 据此，讲稿正文字数（不含附录）的下限：

| 计划时长 | 讲稿字数下限（按160字/分） | 建议区间 |
| :--- | :--- | :--- |
| 30min | 4800字 | 4800—5400字 |
| 35min | 5600字 | 5600—6300字 |
| 40min | 6400字 | 6400—7200字 |
| 10min（先导） | 1600字 | 1600—1800字 |

- **写稿完成后先数字数**：字数不达标 = 有效内容必然不足，先补内容再谈其他。
- 板书页、停顿、跟练留白不占字数预算，但每处要在讲稿里显式写出（"【停顿】半分钟"），否则录制时会被无意识跳过。

### 2.2 知识点的"厚度公式"

一个知识点讲不出时长，是因为只给了"结论层"。每个核心知识点按下面六层展开，能自然撑起时间，且每一层都是有效内容：

```
① 问题：旧手段解决不了什么（制造需求）
② 土办法：先用笨办法做一遍（翁恺式：先给土办法，再引导挑毛病）
③ 挑毛病：土办法哪里不好（让学员"帮"老师发现问题）
④ 新工具：语法/概念登场（此时它是救星，不是空降的定义）
⑤ 演示：现场敲代码/画图/跑结果（看见它工作）
⑥ 跟练+变式：学员动手，改一个条件再做一遍
```

示例——"循环"可以这样展开：
- ①问题：打印1到100，用100行printf写吗？
- ②土办法：真写前5行给大家看，写到第6行停下；
- ③挑毛病：改个需求（打印到1000）就要重写，而且容易抄错；
- ④新工具：while的三要素登场；
- ⑤演示：现场敲，跑出来，故意把条件写错演示死循环（反直觉时刻）；
- ⑥跟练：暂停，自己敲一遍；变式：改成打印偶数。

示例——"分号"可以这样展开（而不是一句话带过）：
- 为什么C要分号（一句话结束的标志，类比中文句号）；
- 漏分号时编译器真实报错截图/现场演示；
- 反直觉点：**报错行号往往不是漏分号的那一行**（编译器只能发现"这里不对劲"，指不准是谁的错），展开讲这个现象；
- 对比：Python不用分号，靠换行——顺带一句即可，帮学员建立"C的规矩是设计选择"的认知。

### 2.3 单节课结构：六步 × BOPPPS 对照

课程框架已有六步结构（引题→思想先行→板书推演→代码精讲→复杂度收尾→课后任务）。用BOPPPS六环节对照检查，**缺的环节就是内容干瘪的位置**：

| BOPPPS环节 | 对应六步 | 零基础课常见缺失 | 补齐方式 |
| :--- | :--- | :--- | :--- |
| B 导入 | 引题 | 只给题不给冲突 | 用反差/悬念/提问钩子（§2.5） |
| O 目标 | （常缺） | 学员不知道学完能干嘛 | 引题后一句话："学完这节你能……"（动词+技能） |
| P 前测 | （常缺） | 默认学员有基础 | 一个口头小问题摸底（"上一节的XX还记得吗？"） |
| P 参与式学习 | 板书推演+代码精讲 | 单向灌输 | 设问+暂停指令+预测输出（§4.3） |
| P 后测 | （常缺） | 讲完就总结 | 课后跟练题就是后测，课上先给30秒自测 |
| S 总结 | 复杂度收尾 | 罗列知识点 | 串成网+预告下节的钩子 |

加涅九段中最常被跳过、恰好对应"干瘪"的三段：**激活旧知**（零基础学员没有背景，必须显式回顾上一节）、**提供学习指导**（给了信息要紧接着示范怎么用）、**促进迁移**（明确说"这个东西在802哪里用"）。每节课讲稿自查这三段是否存在。

### 2.2b 知识链完整性与阶段适配（基础阶段复盘后新增）

内容厚度的反面有两个坑，都出在C1-A录制复盘里：

**坑一：知识链缺角**。讲while完全不提do-while（取证：全课段0命中），讲`&&`短路不提`||`也短路——学员拿到的是缺角的知识地图。规则：每个知识点在大纲中标注它的兄弟知识点，兄弟可以不展开但**必须被点名**（一句"它存在、什么场景用、为什么本课不重点练"即可）。交付前自查清单：本节每个新概念，相邻概念提到没有。

**坑二：超纲符号提前曝光**。`SqList &L`在讲变量的课里出现4次且从未解释（学员连函数都没学）。取证修正了一个直觉：问题往往不是"细讲了超纲内容"，而是"携带超纲符号的代码被直接搬上屏幕"。规则：任何代码示例上屏前逐符号审查——有没有学员此刻解释不了的东西？有则换例子或删符号；确需展示真题原文时口头降级且全课不超过1处。

两个方向的共同判据：**知识要适合当前阶段**——不提前展开后面的机制，也不把后面的符号拖进来。

### 2.4 每节课一个"难忘时刻"

CS50的核心方法：每节课至少设计一个戏剧化/反直觉的瞬间，学员记住这个瞬间就记住了知识点。候选形式：

- **反直觉演示**：死循环现场跑、`0 < x < 10` 永远为真、`int x = 3.9` 打印出3、忘写break的switch穿透；
- **现场翻车再救回**：故意写错→编译报错→带大家读报错→修正（报错教学本身就是难忘时刻）；
- **实物/动作类比**：撕纸演示二分、盒子演示变量、排队演示队列；
- **调试器揭秘**：单步看变量变化（C1-B讲指针时的主力手段）。

设计讲稿时先定"本节的难忘时刻是什么"，再围绕它组织内容。

### 2.5 导入钩子（前90秒）

三类可用钩子（微课设计通用分类）：
1. **提问法**："为什么1米=100厘米？"式的追根问底——C语言版："为什么printf后面要加分号？"；
2. **悬念法**："今天有个谜题：这段代码打印出来的结果，90%的人猜错"；
3. **反差法**：预期与结果的反差——"数学老师看了要摇头：一个数怎么会等于自己加5？"（score = score + 5，A-02已用，是好例子）。

导入之后必须抛出本节要解决的具体问题，把情绪引向任务。

### 2.6 注意力节奏

- 成人对新信息单元的有效专注约**5—10分钟**；每5—10分钟必须有一次节奏变化：换例子、提问、演示、板书、小结、玩笑。
- 30—40分钟微课不必砍短，但要按"学习单元"内部分段，单元之间用变化重置注意力（CS50的立场：长度不是问题，单位时间内有没有"事件"才是问题）。
- 约每2.5分钟应有一次视觉切换、提问或明确过渡（录制层面的检查点）。

### 2.7 C1-A课段的内容取舍依据

以《C Primer Plus》第1—10章为蓝本（已调研确认章节结构）：
- A1 对应第1—2章（程序骨架、编译流程）；A2 对应第3—4章（类型、printf/scanf、'\0'首现于4.2.1）；A3 对应第5章（运算符）；A4 对应第6—7章（循环、分支、break/continue）；A5 对应第9—10章（函数、数组）。
- 两个教材事实需要注意：
  1. 教材第6章先讲循环、第7章才讲分支；本课程A4按"分支→循环"顺序讲（先易后难），是有意调整，讲稿不必提；
  2. 教材第8章（字符I/O与缓冲区）是scanf %c回车坑的真正出处；A2只讲现象埋悬念是对的，但讲稿要把"这个坑的救法在后面讲"这句话落到具体节次，避免悬空。
- 每节只立一个核心概念（框架既定原则）；凡需要地址/指针才能解释的，只讲用法埋悬念。

## 三、PPT设计

### 3.1 有实证支撑的原则（梅耶多媒体学习理论）

1. **冗余原则**：图+讲解 优于 图+讲解+屏幕全文。讲稿要念的内容原样打在PPT上，学习效果反而下降。**PPT和讲稿重叠越少越好**。
2. **模态原则**：画面留给图和代码，解释交给耳朵（讲解）。
3. **一致性原则**：删掉一切与目标无关的装饰。
4. **信号原则**：用高亮、加粗、箭头引导注意力到当前讲的那一行/那一格。
5. **空间邻近**：解释紧贴对应的代码行/图，不分页。
6. **个性化原则**：对话式表述（"我们来看""你会发现"）优于书面腔——这是PPT侧去AI味的依据。

### 3.2 密度与版式标准（沿用并细化既有规范）

- 每页 ≤4—6 个要点；每页只承载**一层**信息，讲完才翻页；
- 表格用于目录/对比/数据；代码块 ≤10 行，超了拆页或用"骨架+填空"两页；
- 代码页必须配"一句话目标"（这段代码在干嘛），代码旁结论紧贴（空间邻近）；
- 重点行用加粗/变色放大（信号原则），不靠口头说"注意第3行"；
- 网课PPT正文字号不小于24磅（录制规范），本项目渲染器正文18pt起步、自动缩放兜底，内容侧仍应主动控制密度。

### 3.3 代码呈现

- 等宽字体；只展示核心逻辑，避免满屏代码；
- 长代码用"先骨架后填空"：一页给框架（挖空），下一页给完整版——对应板书推演与代码精讲两步；
- 讲到哪块亮哪块：deck侧用加粗标记重点行（渲染器已支持 `**加粗**`）。

### 3.4 反面模式清单（禁止）

1. 教材搬家：一页超百字、整段文字上屏；
2. 照念PPT：页面上的字读得懂，讲稿又把同样的字念一遍；
3. bullet堆砌：屏幕文字+口头语言+图像三重叠加；
4. 特效堆砌：转场、多重动画、无关音效；
5. 长句上屏：手机观看看不清，句短、字大、字少。

### 3.5 板书与习题的增量原则（基础阶段复盘后新增）

板书推演和课后习题的模式本身保留（这是课程的有效结构），但每一处书写都要过价值关：

> **第八轮修订（2026-08-25）**：板书推演一律改为PPT动画呈现（要点逐条出现），录制不手写，学员拿纸跟画。下述"只写新增内容"的精神保留：演示页只呈现本节的推理步骤，不夹带已学过的样板。

- **板书只写本节课新增的东西**。程序骨架（头文件、`int main(){`、`return 0`）在课段首节写一次建立习惯，之后口头带过（"还是老骨架，头文件main不变"），不再书写。C1-A实测：A-02~A-05板书结论里样板行占比33%—50%，全部属于重复劳动；
- 板书的真实成本比想象高：触屏书写慢、容易出误触，每节板书总时长按8分钟封顶，超了砍内容，不赶书写；
- **价值三问**（每处板书、每道习题过一遍）：①练的是不是本节核心？②能不能用更少笔画达成？③删掉它对学习有没有损失？一问答"否"就删；
- 同一份完整代码在deck板书结论页、讲稿正文、讲稿附录已出现三次，不再增加第四次出现的位置；
- 课后习题同理：跟练题练本节核心动作，模仿题换一个数/场景即可，不为凑数加第三题。

## 四、讲稿写作

### 4.1 讲稿与PPT的分工（去"逐页复述"的总原则）

- **PPT给眼睛看结构**：关键词、表格、代码、图；
- **讲稿给耳朵听判断**：PPT上没有的——为什么、怎么想到的、踩坑经验、数据背后的判断、过渡与设问。
- 自检：随机抽一页，讲稿里该页内容如果删掉PPT上的文字后没有增量，这页讲稿就是复述，重写。

### 4.2 先说后写（最重要的写作流程）

1. 对着deck.yaml，**用嘴把这节课讲一遍**，录音或语音转文字；
2. 把转录整理成稿：保留口语结构，补上遗漏的环节（设问、停顿、跟练指令）；
3. 对照厚度公式（§2.2）检查每个知识点是否六层齐全；
4. 数字数（§2.1），不够就回到第1步重讲补内容——**不是靠写字凑数，是靠多讲一层**。

> AI协作时的用法：AI产出的讲稿初稿只能当"素材"，必须经过主讲人口语重述这一环；直接照AI稿录，必然AI味重。

### 4.3 为耳朵写（口语化技术）

- 句子读起来喘不上气，就太长——拆短；
- **口头路标**替代书面小标题："接下来看第一个""现在说说为什么会这样"（听众看不到标题，必须说出来）；
- **计划性重复**：关键观点说一遍→展开→换个说法再说一遍。这不是注水，是听觉吸收的机制；
- 设问+暂停指令制造伪互动："大家猜输出是什么？（停顿）……按暂停，自己先写一遍"；
- 交稿前测试：以实际语速通读全稿，同一句卡两次就重写，念着别扭的段落删掉重构。

### 4.4 去AI味清单（逐项过）

AI味的可辨识特征与对策：

| 特征 | 对策 |
| :--- | :--- |
| "首先、其次、最后""一方面、另一方面""总而言之" | 换成具体表述或口头路标 |
| 句子长度均匀、逻辑链过于顺滑 | 段落长短错落；允许插话和补充（"对了，这里还有个坑"）；长句之后必须跟短句（2—6字），禁止连续三句长度相近 |
| 定义式开头（"XX是指……"） | 改用例子、提问、故事开头 |
| 过度拔高（"不仅仅……而是……"） | 删掉，给事实、给数字、给判断标准 |
| 没有犹豫、没有自我校正 | 加个人化评论（"我当年第一次也搞错了""说实话这个写法有点丑"） |
| 每段结尾总结句 | 列表结尾禁止总结句（既有规范，继续执行） |
| 营销腔（"稳稳拿下""放心跟"） | 既有规范，继续执行 |
| "不是X，而是Y""这不仅是……更是……"二元对比句式 | AI高频句式，出现即改写为直接陈述 |
| 空洞衔接语（"值得注意的是""某种意义上""此外"） | 删除或换成具体内容 |
| 商务套话（"赋能""深度剖析""旨在""不可或缺""双刃剑"） | 禁用 |
| **铺垫钩子复读**（"记住就行，后面强化阶段会说"多页重复） | 悬念台账制：每个钩子全课段只铺垫一次，deck与讲稿不重复铺垫（C1-A实测：同一钩子跨节出现13次） |
| **格式过度**（加粗每节40+处、口播段里嵌Markdown表格） | 加粗每节≤10处；口播正文禁表格；见§4.6 |
| 形容词堆砌（"很难""很重要"） | 换成具体场景或数字（"改了三遍还是错"） |
| **赠予句式**（"给你一个/再给你/带你把/给你个"高频开头） | 第八轮新增：换成"这里有个/再看/还有个"或直接陈述；同一句式每节至多出现1次 |
| **口号式短句**（"规矩立住/关键来了/神奇的地方来了/这就是…的一幕"） | 第八轮新增：删掉或换成平实过渡（"重点是/接下来看"） |
| **模板化个人故事**（虚构的"我当年…"经历） | 第八轮新增：除非主讲提供真实素材，否则不用；需要共情时用"很多人第一次都会…"替代 |
| **比喻替代术语**（该给术语的地方只给比喻） | 第十轮新增：术语先行，比喻只做辅助；能直接换成学员该学的术语就必须换（§4.7型一） |
| **AI专用词与生造说法**（"路线报一下""盘点问题""设计哲学""自由翻译"） | 第十轮新增：按§4.7替换对照表改为平实说法；check.js 禁语表扫描 |
| **把简单内容讲复杂**（一件事换三个角度反复论证） | 第十轮新增：砍到核心，省下的时长预算移到真正需要厚度的页，不靠绕撑时间（§4.7型三） |
| **同一结论跨页重复论证**（一个机制在引题页、机制页、失败版页、解法页、落点页各讲一遍） | 第十一轮新增：全节只论证一次，后续页只用一句话引用结论；写稿前先列"本节几个结论、各在哪页论证"（C1-B-05取证：值传递在5页重复，"复印件"出现16次） |
| **非收官课做课段串网**（"把六节课串一遍"出现在倒数第二节） | 第十一轮新增：课段串网只放在最后一节的小结页，前面的节只预告下一节 |
| **工具性语法当主体展开**（为读代码服务的语法讲成主角） | 第十一轮新增：按"是什么＋怎么用＋两条规矩＋点名兄弟"讲完即止，不做"为什么不都用它"式延伸论证 |
| **课程定位越界：工具课讲成专业课预习**（第十二轮新增） | C1-B-06 的综合实战用 3 页教顺序表的 length 语义、insert 算法与容量防御，还花整页做“顺序表 vs 链表优劣对比”，这些都是 C2-A-02/A-03 的内容 | 综合实战课只练工具组合（结构体、指针、动态内存、引用传参），载体结构的正式内容归对应专业课；开写前先问“这一页教的是语法还是数据结构” |
| **自造词当术语用**（给常见概念起外号，之后不再解释：“落点”“底座”“弹药库”） | 第十三轮新增：学生看得到的 deck 与讲稿一律不用；内部设计文档可用已定义的简称，但首次出现必须解释（§4.8） |
| **电报句**（冒号、破折号、斜杠堆碎片，整句没有动词） | 第十三轮新增：补回主语与动词；斜杠列举改顿号加“和”；破折号每页至多一处 |
| **名词标签当标题**（kicker 与 title 短到不像话，如“选型”“单链表推演”） | 第十三轮新增：改成问句或直陈，以念得出来为准 |
| **讲稿口播正文列表化**（整段是半句堆叠，念不下去） | 第十三轮新增：deck 的 bullets 保持要点式，讲稿同一段写成完整句子（两种文本两套判据，§4.8） |

> 判定标准的总纲：**AI味的本质是"平均数"**——挑不出毛病但读完什么都没留下。人味来自具体、来自波动、来自讲稿里"只有这个主讲人才会这么说"的句子。第十轮补充：AI味的另一半是**"绕"**——不造口号、不堆格式，但每句话都要拐个弯才说到事，具体形态与对策见§4.7。

### 4.5 讲稿结构模板（单节课）

六段式节奏，与六步结构对应：

```
Hook    引题：问题+结果承诺（"学完你能……"）        1—2min
Context 为什么现在学这个（802哪里用、和上节的关系）   并入引题或思想先行
Teach   核心内容：3—5个要点，每个按厚度公式展开       主体
Show    演示：板书推演+代码精讲（现场敲/画图/跑结果） 主体
Do      跟练指令：暂停、自己写、对答案               板书页+课后任务
Recap   总结串网+下节钩子                           1—2min
```

最简口诀：**写一个目标，教一个概念，给一个例子，留一个动作**。

### 4.6 讲稿格式约定（基础阶段复盘后降档）

**总原则：讲稿是口播参考，不是逐字稿，也不是交付文档。** 主讲人不会照念，写稿的目标是让他"扫一眼就知道这页讲什么、思路怎么接"。格式越多的讲稿，口播时越抓不住主线——C1-A的教训：六份讲稿正文加粗最多到49处/节，口播段落里嵌着Markdown表格，每页标题带精确到0.5分钟的时长，这是AI生成文档的形态，不是人写讲稿的形态。

格式硬规则：

1. 逐页对应 `## P{n} 页名（约Xmin）`，时长取整分钟；
2. 舞台指令只保留【板书】【停顿】两种，设问后的停顿必须标注；
3. **口播正文禁用Markdown表格**（表格念不出来），需要对比的内容用口语列举写；
4. **加粗每节≤10处**，只标真正需要重读的词；check.js会对加粗密度告警；
5. 正文一段一个意思，短句分行，标点即停顿；不追求段落工整；
6. 附录三件套（题答案/代码合集/勘误位）继续执行；勘误位发现即填；
7. 写完必须朗读一遍（§4.3交稿测试），念着不像说话的段落重写；
8. **Markdown 星号转义**（第十轮新增）：讲稿正文里表示指针与解引用的 `*` 一律写成 `\*`。同一段落里出现两个裸 `*` 会被 Markdown 当成斜体标记配对，预览与渲染后星号消失、代码就读错了（如 `*(a+i)` 与后文的 `*p` 被配成一对）；只有一个裸 `*` 时也统一转义，免后续改稿时踩坑。代码围栏内不转义。check.js 第 12 项会扫正文未转义的裸星号。

### 4.7 "绕"的三种形态与替换对照表（第十轮新增）

**背景**：前九轮的去AI味规则主要治口号、营销腔、格式过度与结构词，但主讲人审读 C1-B-02 讲稿时指出还有一类没被规则覆盖：表述"绕"——读着不舒服，但挑不出具体错词。本轮把它拆成三型，每型给可操作的判据，并把已取证的实例固定成替换对照表（证据链见 `授课反思与改进清单.md` 第七节）。

**三型判据**

| 型 | 表现 | 自查问句 | 对策 |
| :--- | :--- | :--- | :--- |
| 型一 比喻替代术语 | 该给术语的地方只给比喻，学员记住的是比喻不是术语 | 这个比喻能不能直接换成一个学员该学的术语？ | 能换就必须换；术语先行，比喻只做辅助 |
| 型二 AI专用词与生造说法 | 把平常的事包上一层书面腔或自创名词 | 这句话我在教室里会这么开口吗？ | 换成平实动词与名词，对照下表改 |
| 型三 把简单内容讲复杂 | 一件事换三四个角度反复论证，或给不相干的延伸 | 这段的核心信息能不能一句话说完？ | 能就砍到那一句；时长不够去补真厚度（§2.2），不靠绕撑 |

**替换对照表（实例取证自 C1-B-02，同型表述在其他讲稿出现即改）**

| 禁用型表述 | 改为 |
| :--- | :--- |
| "路线报一下""先盘点今天要解的问题" | "这节课的顺序是""先把今天要解决的问题说清楚" |
| "立一个规矩""规矩就一条""规矩记住一条" | "只有一条要记住""记一条"（PPT页名已有的"规矩"不改） |
| "这个换算关系是后面所有内容的数学基础" | "后面讲数组全靠这一条" |
| "试图在脑子里构建这个画面" | "脑子里要有这么一幅图" |
| "i++是先按现在的值办事，办完再加" | "先用当前的值，用完再加1" |
| "两套写法完全互通，你能自由翻译，才算真懂" | "两种写法你要能互相改写" |
| "%c的脾气是不管三七二十一" | "%c不做任何跳过" |
| "C语言的设计哲学是把这份自由交给程序员" | "C语言把这个责任交给程序员" |
| "a像钉在地上的路标，p是拿着路标地址到处走的快递员" | "a是固定地址不能改，p是变量可以换指向" |
| "骨子里都是指针在走路""把这层窗户纸捅破" | "本质上都是指针在移动" |
| "都是在这张图上添加新家具""下一节学一个新零件" | "都是往这张图上加内容""下一节学一个新东西" |
| "回车的编号" | "回车的ASCII码"（该用术语用术语） |
| "看懂和会用的分界线就在笔头上" | "看懂和会用的差别就在画图这一步上" |
| "养成走完这一遍再交手的习惯" | "写完边界，代入走一遍再往下做" |

**比喻的使用边界（不是一律禁比喻）**：课程既有的核心比喻体系——内存是带编号的格子、变量是盒子、指针画箭头、越界是踩进别人的地盘——**保留并全程一致使用**，它们是零基础学员的脚手架，也服务于知识链的前后衔接。禁的是临时造一个只用一次的新比喻去替代本该给的术语。判据：**比喻如果只在这一句出现、之后不再复用，大概率是装饰，删。**

**型三的标准处置流程（P8案例）**：原稿用9段1310字讲"两种遍历"，内含与后两页重复的越界事故段、与本页前文重复的观察段。处置：砍到4段516字（图推演→两种写法对比与边界→考法与选型→遍历加加工骨架），同时把页时长标注从约5分钟改为约4分钟；省下的字数预算不留在本页，而是补到当节偏薄的页上去（前测摸底、上机验证动作、常见误解破除、易混对比）。**时长不够不是把现有内容讲绕的理由。**

**交付前自查三问**（加入每节朗读一遍的流程）：
1. 本节有没有只用一次的新比喻？有就删或换成术语；
2. 有没有一句话在教室里不会这么开口的表述？有就按对照表改；
3. 有没有哪段的核心信息可以一句话说完？有就砍，把时长预算还给真正需要厚度的知识点。

**型三的节级形态：整节内容膨胀（第十一轮新增，C1-B-05 取证）**：段落级的绕是"一件事换三个角度说"，节级的绕是"一个结论摊到五页各说一遍"。判据同样是一句话：**本节有几个结论？每个结论在哪一页论证？**答案必须是一页一个。C1-B-05 原稿只有"值传递为何改不动＋两种解法"三件事，却摊成 15 页 40 分钟；**注意它的字数与时长标注都是达标的**（口播 5831 字、权重 38.1 分钟），膨胀不在数字上，而在内容里：其中约 1890 字（32%）是把同一个结论换页重讲。重构为 12 页 28 分钟（口播 3941 字）后，反而补进了两个原先没有的真知识点（数组做参数看着像值传递却能改外面、函数不能返回局部变量的地址）。**内容少不是注水的理由，字数达标也不等于不啰嗦。**完整取证与处置见 `授课反思与改进清单.md` 第八节。

**另一种节级偏差：课程定位越界（第十二轮新增，C1-B-06 取证）**：这一类不重复也不绕，问题是**讲的层次不对**。综合实战课的任务是把本阶段学过的工具接起来用，载体可以是一个表、几块用指针串起来的内存，但载体的正式内容（插入删除、头结点、查找、优劣对比）属于后面的专业课。自查问句：**这一页教的是语法工具，还是数据结构本身？**一页里出现“这个成员是整个表的命根子”“每次插入要搬多少元素”这类论述，就已经越界。C1-B-06 原稿 8 页综合实战里有 3 页在教 C2 的内容，压到 6 页、删掉优劣对比后，反而把 C 语言侧最有价值的自引用语法（为何合法、必须隔一层指针、struct 不能省）讲得更完整。**删越界内容不会降低含金量，只会把它拉回本阶段的位置。**完整取证见 `授课反思与改进清单.md` 第九节。

### 4.8 AI味的三个来源、词表三级与防过度修正（第十三轮新增）

**本项目怎么用这一节**（主讲申明后补）：下面这套病理来自通用的文稿 AI 味研究，是可用的诊断线索，**不是本项目的验收标准**。本项目的标准见 §一 的最高判据：听者能不能跟上逻辑。所以这一节的用法是“写完之后拿它扫一遍，找出妨碍理解的地方”，不是“写的时候逐条对着规避”。逐条对着规避会写出另一种病：为了不像 AI 而故意写得不清楚。

前十二轮治的是看得见的病：格式、结构词、绕。这一节把病理补全，因为三种病要用三种药，先分诊再动手。

**三个来源与分诊**

| 来源 | 读者的感受 | 主要特征 | 药 |
| :--- | :--- | :--- | :--- |
| 平均化 | 挑不出错，但读完什么都没留下 | 措辞过于标准，情感过于克制，逻辑过于工整，内容过于全面；同一结论反复论证撑篇幅 | 具体化（人物、事件、数字、矛盾）；一个结论只论证一次（§4.4） |
| 绕 | 读着不舒服，说不出哪句错 | 比喻替代术语、AI专用词、把简单内容讲复杂、讲的层次越界 | §4.7 三型判据与替换对照表 |
| 读者负担 | 每句都要先破译，再把碎片拼回句意 | 自造词当术语用、电报句、名词标签当标题、口播正文列表化 | 本节“读者负担四形态” |

前两种在本项目已经治过。第三种是盲区，它的危险在于信息可以很具体（编号、百分比俱全），但读者仍然要逐句解码才能拼出意思。“能追问到具体”不能豁免这一型。

**读者负担四形态**

1. **自造词当普通名词用**。给常见概念起外号，之后不再解释，直接当大家都懂来用。本项目的设计文档里就有这类词：“弹药清单”“种模板”“厚度公式”“钩子台账”。规则是分场景的：学生看得到的 deck 与讲稿一律不用；内部设计文档可以用已经定义过的简称，但首次出现必须解释；自造词只许出现在代码标识符里。自查问句：这个词第一次出现时，学生能不能从上下文猜出意思？
2. **电报句**。为了显得信息密度高，把句子拆碎，用冒号、破折号、斜杠连接碎片，整句没有动词。改法是给句子补回主语和动词，斜杠列举改成顿号加“和”，破折号每页至多一处。自查问句：这句话有主语、动词、宾语吗？能不能用“先……然后……”讲清？
3. **名词标签当标题与正文**。短本身没错，错在短到不像话。deck 的 kicker 与 title 要念得出来：“选型”改成“三种传参怎么选”，“单链表推演”改成“三个结点怎么串起来”。
4. **列表替自然段**。整页全是 bullet，每条不超过一行半，条条靠分号排比。这一条对 deck 与讲稿要分开判：PPT 是屏幕媒介，要点式呈现是正常的，deck 的 bullets 允许半句；讲稿是口播文本，念出来的必须是完整句子。自查问句：讲稿这一段能不能顺着念下来不卡壳？卡壳就说明它是列表不是话。

**翻译腔**（读者负担的一种，口播稿里少见，但要认得）：多层“在……背景下”“基于……”“通过……”叠加，谓语迟迟不出现；“它、该、其”指代不明；定语超过两层。自查问句：这句话的主干（谁做了什么）能不能提到前 15 个字？

**词表是线索，不是判官**

check.js 的违禁词表与禁语表有两种确定的失效。一是误伤：技术文体里合法的“证明”“展示”“探索”被当成拔高词。二是漏检：通篇绕、信息近零的稿子，词表命中可以为零。所以命中词表只意味着“值得用判据复核一遍”，复核通过就保留。这也是 check.js 把这些项设成 WARN 而不是 ERROR 的原因：工具负责提示，人负责判断。

**防过度修正的五条边界**（与上面任何单条规则冲突时，以本节为准）

1. **看密度不看单例**。排比、三短语并列、“不是A而是B”，单个出现都不是病，连篇出现才是。为内容服务的并列不动。
2. **三种文本三套判据**。讲稿是口播文本，判据是“会不会在教室里这么开口”；deck 是屏幕文本，判据是“学生扫一眼能不能抓住要点”；设计文档是工作文本，判据是“接手的人能不能照着做”。不共用一套。
3. **服务理解的修辞保留**。贯穿全课程的核心比喻体系是脚手架，留：内存是带编号的格子、变量是盒子、指针画箭头、malloc 是借、free 是还。只用一次的新比喻是装饰，删。
4. **人类惯例保留**。设问、停顿、口语的语气词、刻意的重复（“记住这一句”）都不是 AI 味。
5. **不为去 AI 味牺牲准确**。术语该长就长，“平衡二叉树”不能改成“两边一样高的树”。主讲本人的口头表述是最高优先级语料，与本节任何规则冲突时以主讲为准。

**生成侧的纪律：备料先行**

AI 味的一大半是“没有内容硬要成篇”时用套话填出来的。所以写新讲稿之前，先把这一节必须承载的具体内容列出来：本节有几个结论、每个结论的推导步骤、要用的数字与实例、要破除的误解、课后题。列不出来的部分向主讲要，或者在稿子里标注缺口，不许编。内容齐了，大半个词表自动用不上。这是十二轮修订里最省力的一味药，也是 §4.2“先说后写”往前推一步。

**改完必须显式回查的一项**：连续三句长度相近吗？这一段有没有一句 6 字以内的短句？句长节奏靠生成时自觉不可靠，实测改写后仍会残留，必须回查。

## 五、录制

### 5.1 语速与节奏

- 基准120—140字/分（教培类），难点处刻意放慢，宁慢勿快；紧张会加速，录制时自我监控；
- 语调起伏的最简做法：**重读关键词**——每句最重要的一两个词加重、放慢（"这个知识点/经常考"）；
- 断句：逗号轻停约1秒、句号停约2秒、重点前停顿加长。

### 5.2 停顿

- 停顿不是事故，是"让观点沉下去"的工具；
- 抛出思考题或练习指令后，不留长空白，说"按暂停键自己先做"——既不浪费时长又给了思考时间；
- 每2.5分钟左右一次视觉切换/提问/明确过渡。

### 5.3 口头禅

- 口头禅是大脑找词时的缓冲，**内容不熟时更多**——录前把讲稿读到脱口而出是根本解法；
- 对策是替换不是压抑：想说"嗯"时闭嘴，用静默替代（停顿被解读为从容，填充音被解读为紧张）；
- 量化红线：填充音 ≤5个/分钟无影响，≥12个/分钟专业可信度显著下降；
- **录完回听计数**是最有效的反馈（翁恺从2005年起给自己所有课录音回放改进）。

### 5.4 在场感与跟练感

- 把镜头当成一个具体的学生（"刚跨考、第一次碰C语言的同学"），一对一讲给他听，不对"一群人"广播；
- 情绪比日常抬高一档：镜头吃掉表现力，你觉得略夸张，观众看着刚好；
- 看镜头，不扫提词器文字（扫字是念稿感的最大暴露点）；提词器紧贴镜头正下方，字号调到扫一眼即回；
- 跟练感设计：指令式语言（"现在暂停，自己敲一遍"）、设问+等待（"输出是什么？（停顿）对，是0"）；
- 同一段至少录三遍，前两遍当热身，挑最松弛的一条；开头第一句单独练到脱口而出；
- 录前试拍几十秒小样回看；按教学环节分段录（每段5—10分钟），保证质量也便于重录。

### 5.5 录制后自检（发布前）

1. 回听一遍：数口头禅、查语速失控点、查"念稿感"段落；
2. 对照讲稿查：设问后有没有真停顿、跟练指令有没有给足时间；
3. 时长核对：实际时长 vs 计划时长，偏差>10%时复盘是内容问题还是语速问题，写进勘误位；
4. 抽3个随机时间点静音看画面：PPT是否自明（不看讲解能否看懂这页在干嘛）。

## 六、单节课生产流程（升级版，替代SKILL第二节的工作流）

1. **读**：框架对应节次要求＋知识笔记对应内容＋（C2起）真题对应题目；
2. **定事件**：先写一句话——"本节的难忘时刻是什么"；
3. **列大纲**：页码清单（页型+一句话内容），每个核心知识点标注厚度公式的哪几层；与调用者确认；
4. **写 deck.yaml**：按CONTENT-SPEC，只管讲什么；
5. **写讲稿**：按§4流程（先说后写），数字数（§2.1），过BOPPPS自查（§2.3）与去AI味清单（§4.4）；
6. **渲染**：`node tools/render-pptx.js 课件/<课程>/<节次>/deck.yaml`；
7. **验收pptx**：页数、底图、无溢出、无重复元素；
8. **一致性自检**：`node tools/check.js 课件/<课程>/<节次>`——自动检查页数对应、字数预算、违禁词、内部代号、image路径、YAML合法性；ERROR必须修，WARN评估后处理；
9. **录制**：按§5执行；
10. **发布后自检**：§5.5，问题记入讲稿勘误位。

## 八、C1-A制作实战经验沉淀

> 本章是实际制作 C1-A-02~05 四节课过程中踩过的坑与验证有效的方法，供后续 C1-B、C2、C3 制作直接复用。

### 8.1 讲稿字数与有效内容

- **字数是有效内容的下限指标**：按160字/分预算，35分钟课需5600字、40分钟需6400字。字数不够 = 有效内容必然不足，先补内容再谈其他。
- **补字数的正确方式是补"厚度"不是凑话**：每个知识点按"问题→土办法→为什么→802落点→对比延伸"展开。例如"整数除法丢小数"补一句"这个脾气在折半查找 mid=(low+high)/2 里正好是要的行为"，既是有效内容又自然加长。
- **板书页与停顿不占字数但占时长**：板书页现场书写约4—5分钟、每处【停顿】约30秒，这些在字数预算之外，实际录制时长 = 字数对应时长 + 板书/停顿时长。
- **C1-A 各节实测字数**（板书页除外）：A-02约5500字、A-03约4600字、A-04约5800字、A-05约6200字，均在计划时长可接受范围。

### 8.2 802连接是内容厚度的金矿

- 每个语法点都追问"这个在802哪里用"，把真题场景写进讲稿：
  - `%`取余 → 2021删除正偶数（判偶数）
  - `&&`短路 → 链表查找 while(p!=NULL && p->data!=elem)（顺序决定安全）
  - `for`遍历 → 顺序表遍历、打擂台求最值
  - `++`自增 → L.length++（插入后维护表长）
  - 整数除法 → 折半查找 mid=(low+high)/2
- 这些连接让学员持续看到"学的东西考试用在哪"，既是有效内容，也是学习动机。
- **频度克制（第七轮补充）**：802挂钩集中在课段导学页与小结页，知识点正文每节至多2处。基础阶段复盘：每个知识点都挂考题会制造焦虑、稀释知识本身，学员反馈"基础课老在说考试"。挂钩是顺手提一句，不是句句不离。同理，"这个后面课会讲"式前瞻铺垫除台账登记的一次性兑现句外一律不写。

### 8.3 制作中踩过的坑（务必避免）

| 坑 | 原因 | 对策 |
| :--- | :--- | :--- |
| board页用了blocks字段，任务文字不显示 | 渲染器board页只读task字段 | board页一律用task字段，不用blocks |
| scanf读double用%f（应为%lf） | printf用%f、scanf用%lf，易混 | 讲稿明确区分："printf打double用%f，scanf读double用%lf" |
| bool未提stdbool.h | 标准C需#include才能用bool | 讲稿补一句"上机加#include <stdbool.h>" |
| 讲稿"下一节讲"表述失实 | 写稿时与实际编排不一致 | 跨节引用要核对实际页序，用"后面讲"比"下一页讲"安全 |
| 板书结论省略花括号与教学规矩冲突 | 省空间写了简写，但前面强调过花括号不能省 | 讲稿加说明，或板书结论也写全花括号 |
| YAML中单引号开头字符串解析失败 | 'X'被当作引号标量 | 用双引号包裹："..." |
| 答案页单页塞两题＋灰底note，内容溢出屏幕（第九轮实测） | 答案页未走正文密度规则；旧版渲染器代码块高度不随自动缩放，缩字号后盒子仍按原高占位 | 答案页一题一页，要点用bullets；渲染器代码块高度已随缩放联动（render-pptx.js code case），密集页不再溢出 |

### 8.4 每节课的标准结构（C1-A验证有效）

```
封面 → 引题（回顾上节+本节问题） → 知识点1（厚度公式展开）
→ 知识点2 → … → 本节难忘时刻 → 板书推演 → 板书结论
→ 总结 → 课后任务（跟练+模仿）
```

- 每节15—18页（含封面和课后任务）；
- 知识点之间用"先看一个问题"/"再讲一个"过渡，不用"首先其次"；
- 总结页不超过5条 bullets，每条对应一个知识点；
- 课后任务固定"跟练+模仿"两题，A阶段不设变式题。

### 8.5 去AI味的实操要点

- **先说后写**：对着deck讲一遍再整理成稿，口语结构自然就出来了；
- **删结构词**：把"首先/其次/最后"换成"先看X"/"再说Y"/"最后一点"；
- **加个人化评论**："我当年第一次也搞错了""说实话这个写法有点丑"——模拟真人思维流；
- **设问+停顿**：每个知识点至少一个"你猜结果是什么？（停顿）"；
- **check.js自动扫描违禁词**：交付前跑一遍，比人工查可靠。

### 8.6 C1-A录制复盘：四个坑与对策（2026-08）

> C1-A全部录制封存后，主讲人反馈与封存课件逐文件取证的四类问题。完整证据链与推理见 `课程设计/授课反思与改进清单.md`；对应规则已并入2.2b、2.6（框架）、3.5、4.4、4.6与课件制作SKILL。

| 坑 | 取证要点 | 对策落点 |
| :--- | :--- | :--- |
| 铺垫钩子复读 | "地址/&→强化阶段"一个钩子跨节铺垫13次以上，C1-A-02单节7次；deck与讲稿还同页重复 | 悬念台账制：每个钩子全课段只铺垫一次，铺垫语只进讲稿不进deck |
| 知识链缺角 | do-while全课段0命中；`||`短路未提；讲for只认for是while的"兄弟" | 大纲标注兄弟知识点，可以不展开但必须点名（2.2b） |
| 超纲符号提前曝光 | `SqList &L`在讲变量的课出现4次且从未解释（学员尚未学函数） | 代码示例逐符号审查，不允许"展示而不解释"（2.2b） |
| 板书样板重复 | A-01~05板书task固定"六步"含3个样板步；板书结论样板行占33%—67% | 板书增量原则：首节写骨架建立习惯，之后只写新增（3.5） |

附带发现：讲稿格式AI化是逐节加重的（正文加粗数0→27→49→40），说明格式问题会自我繁殖——必须用check.js的加粗密度告警打断这个趋势。

### 8.7 语感对齐：向真人讲师学习

AI味的根治不是删几个词，而是让讲稿的语言向真人课堂靠拢。四位参照讲师的可借鉴点（调研来源见文末附录）：

- **翁恺**：慢而稳、留足思考时间；用通俗词先解释再引术语；从2005年起对每节课录音复盘——我们的对应做法是"录完回听，下一节写稿前修正一处"；
- **鹏哥**：直接对话感（"你/大家"）、痛点先行的开场、细致逐行带练；
- **郝斌**：先讲为什么（本质）再讲怎么做，语言接地气；
- **韩顺平/李治军**（同批调研的补充样本）：敲代码前先把概念捏清楚、一定举例；每节课先回顾上一节，遇到问题先给初级解法再逐步优化；
- **Malan（CS50）**：把抽象概念变成可见的事件（撕电话簿演示二分查找）——对应我们的"难忘时刻"设计。

优先级声明：**主讲人本人的口述习惯是最高优先级语料**。讲稿初稿给到主讲人后，他改回来的表述方式要积累成语料；如果有录音转写，按转写的风格校准，而不是按书面语校准。判断标准只有一个："这话我在教室里会这么开口吗？"
