# 题集筛选工作流（严蔚敏《数据结构题集（第2版）》）

> 本文档定义"题集三档筛选"任务的完整工作流：从 PDF 提取到三档分级，到最终交付一份简单的筛选指南 PPT。
> 任务来源：机构附加任务。目的：为 802 考生筛掉不值得做的题、标出特别有价值的题，减少刷题时间、提高刷题质量。
> 本工作流产出的 PPT 属于面向学生的交付物，遵守 `tools/CONTENT-SPEC.md` 全部硬约束与课件制作 SKILL 的反 AI 味规则。

---

## 一、任务背景与目标

学生手头有严蔚敏版教材配套题集，全书刷完成本过高且大量题目与 802 考情无关。本任务按章产出一份"刷题导航"PPT：

- **一档（重点做）**：对 802 特别有参考意义的题目，逐题简标价值所在（考什么、对应什么题型/真题）；
- **二档（不用做）**：基本不会考或超出 802 考纲的题目，列出范围与跳过理由；
- **三档（巩固做）**：其余在纲内的题目，定位为巩固基础，列表带过。

原则：**只做筛选，不做题解**。PPT 不承载完整解答；学生需要题解时回看教材与知识笔记。

## 三、题目提取（步骤1）

1. **环境准备**：本机 Python 尚未安装，**已验证无需安装**——用 `uv run --no-project --with pypdf` 即可跑切片脚本，mineru 走 skill 的 `uv run` 方案（2026-08-23实跑固化）；
2. **提取方式（2026-08-23实跑固化）**：题集PDF为331页扫描版、无文本层且470MB超过mineru云端200MB上限，标准流程为——①`uv run --with pypdf` 按登记页码区间切出小PDF（含目录区）；②mineru skill 解析切片（Standard API，VLM模型，66页约1分钟）；③从 mineru 的 `content_list.json`（含逐块 page_idx）做逐题页码归属，题号连续性用第0章的交叉引用（"第2章算法设计题第39题"等）复核。原 PyMuPDF 文本层方案对本书无效；仍不可行则转人工拍照录入，不许凭记忆编题；
3. **题单格式**：每题一条记录——题号（书本原题号）、题干摘要（≤2行）、小问拆分、书本页码、PDF 页码；
4. 提取完成后与用户核对题目总数是否与书本目录一致（题集每章习题数固定），数量对不上先查页码区间再往下走。

## 四、考纲边界（分档依据）

分档只依据以下四样，不允许凭感觉：

1. **802 试卷结构**（框架 1.1）：程序阅读约20分、填空约30分、综合应用约70分、算法分析3题30分；
2. **手算考点清单**（框架 1.1/1.2）：KMP next/nextval、数组地址计算、哈夫曼与哈夫曼编码、广义表、堆调整、出栈序列、散列 ASL、BST/AVL、Floyd/Dijkstra、AOE/关键路径、判定树、拓扑排序、复杂度分析等；
3. **13 个算法大题模板**（框架 2.5）：头插法、快慢指针、断链拼接、条件删除、递归三件套、层序+last、DFS回溯、BFS/多源BFS、二分改判定、归并计数、循环链表模拟、递归建树、入度表法；
4. **知识笔记章结构**（重邮数据结构.md 八章：绪论、线性表、栈队和数组、串、树与二叉树、图、查找、排序）与其中的高频/中频标注。

**802 考纲之外的典型内容**（二档候选，逐题核对后认定，不预设立场）：纯 C 语言语法细节、数据结构教材中偏理论的证明、外部存储与文件细节、超纲的算法复杂度数学推导、教材附录类内容等。哪些真超纲，以框架考情与知识笔记为准，拿不准时按第六节保守原则处理。

## 五、三档定义与判定规则

### 5.1 档位定义

| 档位 | 名称 | 定义 | PPT 中的呈现 |
| :--- | :--- | :--- | :--- |
| 一档 | 重点做 | 与 802 题型直接对应、或与真题同源/变式、或考 2.5 模板的题 | 逐题列出：题号＋考点＋价值一句话 |
| 三档 | 巩固做 | 在考纲内，但考频低、属基本理解与基本运算的题 | 按知识点分组的题号列表 |
| 二档 | 不用做 | 基本不会考，或超出 802 考纲的题 | 题号区间＋跳过理由一句话 |

### 5.2 一档判据（满足其一即一档）

- **真题同源**：与 2020—2026 任一真题同考点同形态，注明年份（如"同2025倒数第k"）；
- **题型直接对应**：可改写为程序阅读/填空/综合应用/算法分析任一题型的标准形态（如出栈序列判断、next 数组手算、散列 ASL 表、哈夫曼编码过程）；
- **模板训练**：练的是 13 模板之一，注明模板名（如"头插法·逆置"）；
- **复杂度分析**：绪论章的时间/空间复杂度分析题一律高一档对待（算法分析题 30 分的前置技能）。

### 5.3 二档判据（满足其一即二档）

- 知识点不在知识笔记八章范围内，或笔记中明确不展开的内容；
- 802 自 2024 年题型调整后不再出现的形态（以框架 1.2 命题规律为准）；
- 纯数学推导、纯语法细节、与数据结构考点无链路关系的题。

### 5.4 三档判据

- 不满足一档判据、知识点又在纲内的其余全部题目。三档是**兜底档**：凡是归不了档的题一律落三档，不许悬空。

### 5.5 边界与冲突规则

1. **保守原则**：一档/二档拿不准时，一律落三档。宁可多留，不可错杀——筛错一道真题同源题的代价远大于多刷几道基础题；
2. **一档宁缺毋滥**：一档的价值在于"每一道都值得做"，数量失控说明判据松了。经验上限：每章一档题不超过该章题数的三分之一，超了先复查判据；
3. **大题拆判**：一道大题含多个小问时按小问分档，标注如"x.3(a)一档、(b)三档"；
4. **代码题口径**：题集中的算法设计题凡涉及 13 模板即一档；只要求写类型定义/基本操作的基础代码题落三档；
5. **分档表留痕**：每题的档位与理由先写入工作底稿 `{章名}-分档表.md`（题号/档位/考点/理由），PPT 从分档表生成，不允许跳过底稿直接写 PPT。

## 六、单章执行流程（步骤2—8）

按课件制作 SKILL 的工作流改造：

1. **页码标定**：按第二节核对章首尾页，登记台账；
2. **提取题单**：按第三节产出 `{章名}-题单.md`，题号连续性用第0章交叉引用或章内引用复核；
3. **逐题分档**：对照第四节依据与第五节判据，产出 `{章名}-分档表.md`；一档题必须写明价值点（考点＋题型/真题/模板），二档题必须写明跳过理由；
4. **subagent 二次核查**（2026-08-23增设，用户不再逐题审核后的替代机制）：每批分档表完成后，派发独立 subagent（每3章一个）做对抗式复核——①逐条验证一档题的价值声明：声称的"同XXXX真题/模板"是否真实存在、形态是否真的对应；②逐条验证二档题的跳过理由：知识点是否真的不在知识笔记与2020—2026真题范围内；③抽查三档是否有误埋的高价值题。subagent 只读材料、给结论（维持/改判＋依据），改判由主流程落笔并记录；
5. **应用改判**：主流程核对 subagent 的每条改判建议，接受则更新分档表并注明"二审改判"；
6. **生成 deck.yaml 与讲稿**：按第七节模板；
7. **渲染与自检**：`node tools/render-pptx.js` 渲染，`node tools/check.js` 自检（本类产物有讲稿，ERROR/WARN 全部清零）；
8. **交付与归档**：pptx＋讲稿交机构；台账与底稿留存。

## 七、输出规范（勾画微课：PPT＋讲稿，2026-08-23与机构确认改版）

每章一份 5—10 分钟录制的勾画微课：deck.yaml＋pptx＋讲稿三件套，讲稿供主讲照读录制。用现有渲染链（deck.yaml → render-pptx.js），页型只用 cover/content。

**底图（本类产物专用，与课程底图不同）**：`assets/题集勾画底图.png`——取自《802备考经验分享-最终版.pptx》末页，去掉祝语文本、保留底部通栏群图与左上角校徽校名（白底）。deck.meta 写 `background: assets/题集勾画底图.png` 与 `topSafe: 1.3`（左上角校徽占位至约1.19in，标题区下移避让）。课程类产物继续用默认 `assets/底图.jpg`，不受影响。

**固定开场白（机构原话，逐字照读，每章讲稿开头）**：

> 重邮考研802数据结构习题集题目勾画，因为了解到绝大部分学弟学妹都会使用这本习题集去强化巩固基础，学长也给大家勾画一下习题，分为有价值必做，可做可不做，完全不做三个方向，最大化提高专业课的复习时间，大家也可以进一下（引导到最下面的群），学长学姐都在里面答疑，有啥问题都可以问。

**面向学生的三档名称**（对外口径，与内部档位的对应）：有价值必做＝一档；可做可不做＝三档（巩固）；完全不做＝二档（跳过）。PPT 与讲稿一律用对外名称，"一档/二档/三档"只出现在工作底稿。

**页序模板**（每章约8—12页）：

| 页 | 页型 | 内容 |
| :--- | :--- | :--- |
| 1 | cover | 习题集题目勾画 · 第X章 章名；meta 行注明依据（802考情＋真题2020—2026） |
| 2 | content | 本章勾画总览：table 三方向题数与占比＋题号口径说明（选N/答N/算N＝原书选择题/解答题/算法设计题第N题） |
| 3—N | content | 必做题详单：每页≤5题，每题一行——题号＋考点＋价值一句话（table）；超一页拆页 |
| N+1 | content | 可做可不做清单：按知识点分组列题号（table） |
| N+2 | content | 完全不做清单：题号＋原因一句话（table） |
| 末 | content | 使用建议（必做精做并对照真题、可做可不做限时过、不做直接跳）＋回看指引（知识笔记对应章）＋一句群指引（答疑群见页面底部） |

**讲稿规范**：逐页对应 `## P{n} 页名`；P1 先照读固定开场白再口播封面信息（含动作提示"指向底部群图"）；每页60—90秒；全稿≥1300汉字（8分钟×160字/分，check.js 字数检查依据）；开头引导句（群答疑）按 CONTENT-SPEC 第四节写法融入。

**写作硬约束**：

- 遵守 CONTENT-SPEC 第五节：陈述式标题、无口号、无营销腔、无 emoji、页脚仅页码；
- **禁止内部代号**：deck 与讲稿不出现 C1-A/C2-B 等编号（meta.id 用 `TS-{章}` 作渲染元数据）；
- 价值描述**只给事实不给情绪**：写"考散列ASL，2024综合应用同型"，不写"超级重要一定要做"；固定开场白为机构原话，不受此条约束；
- 题号一律用原书题号并注明对应 PDF 页（方便学生翻书）；页内题号口径在总览页统一说明后，正文用"选12/答3/算16"简写；
- 每页≤6行表格的密度规则照旧，超了拆页；
- meta 写 `duration: 8min`（讲稿字数检查依据）。
