## 一、核心概念与定义

- **查找表(Search Table)**：由同一类型的数据元素（或记录）构成的集合。由于"集合"中数据元素之间只存在完全松散的关系（仅"同属一个集合"），查找表是一种非常灵便的数据结构。对查找表经常进行的操作有四类：①查询某个"特定的"数据元素是否在表中；②检索某个"特定的"数据元素的各种属性；③在表中插入一个数据元素；④从表中删去某个数据元素。

- **关键字(Key)**：数据元素（或记录）中某个数据项的值，用它可以标识（识别）一个数据元素。
  - **主关键字(Primary Key)**：能唯一标识一个记录的关键字（不同记录的主关键字互不相同）；
  - **次关键字(Secondary Key)**：用以识别若干记录的关键字（不唯一）。
  - 当数据元素只有一个数据项时，其关键字即为该数据元素的值。

- **查找(Searching)**：根据给定的某个值，在查找表中确定一个其关键字等于给定值的记录或数据元素。若表中存在这样的记录，称**查找成功**，结果为给出整个记录的信息或指示该记录在表中的位置；若表中不存在关键字等于给定值的记录，称**查找不成功**，结果给出一个"空"记录或"空"指针。查找方法取决于表中数据元素依何种关系组织在一起（这种关系是人为加上的）。

- **静态查找表(Static Search Table)**：对查找表只作前两种统称为"查找"的操作（查询/检索），不改动表结构。基本操作：Create、Destroy、Search、Traverse。对应方法：顺序查找、折半查找、分块查找、静态树表查找。

- **动态查找表(Dynamic Search Table)**：查找过程中同时插入表中不存在的数据元素，或删除已存在的某个数据元素，表结构本身在查找过程中**动态生成**。基本操作：InitDSTable、DestroyDSTable、SearchDSTable、InsertDSTable、DeleteDSTable、TraverseDSTable。对应结构：BST、AVL、B-树/B+树、键树、散列表。

- **平均查找长度 ASL(Average Search Length)**：为确定记录在查找表中的位置，需和给定值进行比较的**关键字个数的期望值**，是衡量查找算法好坏的主要依据（查找算法的基本操作是"将记录的关键字和给定值进行比较"）。对含 n 个记录的表：

\[ ASL=\sum_{i=1}^{n}P_iC_i \]

其中 \(P_i\) 为查找表中第 i 个记录的概率且 \(\sum_{i=1}^{n}P_i=1\)；\(C_i\) 为找到表中其关键字与给定值相等的第 i 个记录时，和给定值**已进行过比较**的关键字个数（\(C_i\) 随查找过程不同而不同）。ASL 分**查找成功**与**查找不成功**两种，需分别讨论；查找不成功时的平均查找长度定义为：查找不成功时需和给定值进行比较的关键字个数的期望值。

> 关键字类型可为整型、实型或字符串型；对两个关键字的比较约定用宏 EQ(a,b)（相等）、LT(a,b)（小于）、LQ(a,b)（小于等于）实现。

## 二、存储结构与分类

### 静态查找表的表示与对应查找方法

| 表的表示 | 适用查找方法 | 前提条件 |
|---------|------------|---------|
| 顺序表 / 线性链表 | **顺序查找** | 对表结构无要求，有序无序皆可 |
| 有序顺序表 | **折半查找**（及斐波那契查找、插值查找） | 必须**顺序存储**，链表无法有效折半 |
| 索引顺序表 | **分块查找（索引顺序查找）** | 表分块有序 + 建立索引表 |
| 静态树表 | 静态最优查找树 / **次优查找树** | 记录查找概率不等时用 |

- **有序表**：表中所有记录关键字满足 `ST.elem[i].key ≤ ST.elem[i+1].key`（i=1,…,n-1），称记录按关键字有序。
- **斐波那契查找 / 插值查找**（了解）：均为折半查找的改进。斐波那契查找按斐波那契数 \(n=F_u-1\) 分割（分割只需加减、平均略优于折半但最坏略差）；插值查找按给定值在区间中的比例定位（仅适合**关键字均匀分布**的表）。

### 动态查找表的表示

以各种树结构表示：**二叉排序树 BST**、**平衡二叉树 AVL**、**B-树 / B+树**（平衡多路查找树，用于文件系统外存索引）、**键树（数字查找树）**（含双链树、Trie 树两种存储）、**散列表 Hash**。动态查找表的特点是：对给定值 key，若表中存在则查找成功返回，否则插入关键字等于 key 的记录。

### 散列表存储

- 地址集为 0~m-1 的连续区间，通过哈希函数 H(key) 将关键字**直接映射**为存储地址（以"像"作存储位置）。与线性表/树建立在"比较"基础上不同，散列表建立在"直接映像"基础上，理想情况一次存取即得所查记录。
- **冲突(collision)**：不同关键字可能得到同一哈希地址（key₁≠key₂ 而 f(key₁)=f(key₂)），具有相同函数值的关键字称该哈希函数的**同义词(synonym)**。哈希函数是从关键字集到地址集的**压缩映像**，冲突一般不可避免，故建表既要设"好"的哈希函数，又要设处理冲突的方法。

## 三、关键性质与结论

### 顺序查找

- **查找过程**：从表中最后一个记录开始，逐个进行记录关键字和给定值的比较；若某记录关键字与给定值相等则查找成功，反之直至第一个记录都不等则查找不成功。
- **带哨兵改进**：查找前先令 `ST.elem[0].key=key`（0 号单元作**监视哨**），从后往前 `for(i=ST.length; !EQ(ST.elem[i].key,key); --i)`，找到时返回 i，找不到时 i 为 0。作用是**免去查找过程中每一步都要检测整个表是否查找完毕**。这是程序设计技巧上的改进，实践证明当 `ST.length≥1000` 时，进行一次查找所需平均时间几乎减少一半。监视哨也可设在高下标处。
- **成功 ASL 推导**：\(C_i\) 取决于所查记录在表中的位置，查最后一个记录只需比较 1 次，查第一个记录需比较 n 次，一般 \(C_i=n-i+1\)。等概率（\(P_i=1/n\)）时：

\[ ASL_{ss}=\sum_{i=1}^{n}P_iC_i=\frac{1}{n}\sum_{i=1}^{n}(n-i+1)=\frac{1}{n}\cdot\frac{n(n+1)}{2}=\frac{n+1}{2} \]

- **不成功比较次数**：不论给定值 key 为何值，查找不成功时和给定值进行比较的关键字个数均为 **n+1**（n 个记录各比一次，再与哨兵比一次）。
- **成败各半时**：假设查找成功与不成功可能性相同、每个记录查找概率相等，则 \(P_i=1/(2n)\)，\(ASL=\frac{3}{4}(n+1)\)。
- **不等概率优化**：ASL 在 \(P_n≤…≤P_2≤P_1\) 时取极小值，故若预知查找概率应按概率由小至大重排记录；概率无法预知时可附设**访问频度域**保持记录按频度非递减有序，或每次查找后将命中记录移至表尾。
- **优缺点**：优点是算法简单、适应面广，对表结构无要求（有序无序皆可），且对**线性链表同样适用**；缺点是平均查找长度较大，n 很大时效率低。

### 折半查找（二分查找）

- **适用前提**：只适用于**有序表**，且**限于顺序存储结构**（对线性链表无法有效折半，因无法 O(1) 定位中点）。
- **查找过程**：先确定待查记录所在范围（区间 [low,high]），逐步缩小范围直到找到或找不到。指针 low、high 指示范围下界和上界，\(mid=\lfloor(low+high)/2\rfloor\) 指示中间位置。
- **判定树**：描述折半查找过程的二叉树，每个结点表示表中一个记录，结点值为该记录在表中的位置。查找某记录的过程恰是走一条从根结点到相应结点的路径，**和给定值进行比较的关键字个数恰为该结点在判定树上的层次数**。
- 判定树是**平衡二叉树**（叶子结点所在层次之差最多为 1），但**不一定是完全二叉树**；n 个结点的判定树深度与 n 个结点的完全二叉树深度相同，为 \(\lfloor\log_2 n\rfloor+1\)。成功时比较次数最多不超过树的深度。
- **成功 ASL 推导**：设有序表长 \(n=2^h-1\)（则 \(h=\log_2(n+1)\)），判定树是深度为 h 的满二叉树，层次为 j 的结点有 \(2^{j-1}\) 个，每个记录查找概率 \(P_i=1/n\)，找到层次为 j 的结点需比较 j 次：

\[ ASL_{bn}=\sum_{i=1}^{n}P_iC_i=\frac{1}{n}\sum_{j=1}^{h}j\cdot 2^{j-1}=\frac{n+1}{n}\log_2(n+1)-1 \]

对任意 n，当 n 较大（n>50）时有近似结果 \(ASL_{bn}\approx\log_2(n+1)-1\)。可见折半查找效率比顺序查找高。
- **不成功走外部结点**：在判定树所有结点的空指针域上加指向方形结点的指针，称方形结点为**外部结点**（圆形为内部结点）。查找不成功的过程是走一条从根到外部结点的路径，和给定值比较的关键字个数**等于该路径上内部结点个数**，最多也不超过 \(\lfloor\log_2 n\rfloor+1\)。

### 分块查找（索引顺序查找）

- 是顺序查找的一种改进方法。除表本身外，尚需建立一个**索引表**：将表分成若干子表（块），对每块建一个索引项，含**关键字项**（值为该子表内最大关键字）和**指针项**（指示该子表第一个记录在表中的位置）。索引表按关键字有序。
- **分块有序**：第二块中所有记录关键字均大于第一块最大关键字，第三块所有关键字均大于第二块最大关键字，依次类推。即**块间有序、块内无序**。
- **ASL 结构**：\(ASL_{bs}=L_I+L_S\)，其中 \(L_I\) 为查找索引表确定所在块的平均查找长度，\(L_S\) 为在块中查找元素的平均查找长度。
- **均分 b 块、每块 s 个记录**（\(b=\lceil n/s\rceil\)），等概率时每块查找概率 1/b、块中每记录查找概率 1/s：
  - 用**顺序查找确定所在块**：\(ASL_{bs}=L_I+L_S=\frac{b+1}{2}+\frac{s+1}{2}=\frac{1}{2}\left(\frac{n}{s}+s\right)+1\)。给定 n 时 s 可选，当 \(s=\sqrt{n}\) 时 ASL 取最小值 \(\sqrt{n}+1\)（比顺序查找有很大改进，但远不及折半查找）。
  - 用**折半查找确定所在块**：\(ASL_{bs}\approx\log_2(\sqrt{n}+1)+\frac{\sqrt{n}}{2}\)。
- 因索引表按关键字有序，确定块可用顺序查找或折半查找；块中记录任意排列，块内**只能顺序查找**。

### 静态树表与次优查找树（了解）

折半查找的等概率最优性在各记录查找概率**不等**时未必成立。使**带权内路径长度** \(PH=\sum_{i=1}^{n}w_i h_i\)（\(w_i=c\cdot p_i\)、\(h_i\) 为结点层次）最小的判定树称**静态最优查找树**；因其构造代价高，实用中用近似算法构造**次优查找树**（取 \(\Delta P_i=\left|\sum_{j<i}w_j-\sum_{j>i}w_j\right|\) 最小的记录作根、递归构造）。次优查找树 ASL 与 log n 成正比、也是一棵 BST，但属静态树表、**不能在查找过程中插入结点生成**。

### 二叉排序树 BST

- **定义**：或为空树，或为具有下列性质的二叉树：①若左子树不空，则左子树上所有结点的值均**小于**根结点的值；②若右子树不空，则右子树上所有结点的值均**大于**根结点的值；③左右子树也分别为二叉排序树。（即左<根<右）
- **中序遍历二叉排序树得到关键字的递增有序序列**（由定义决定）。一个无序序列可通过构造 BST 变成有序序列，构造树的过程即为排序过程。
- BST 既拥有类似折半查找的特性，又采用链表作存储结构，插入新结点只需改某结点指针由空变非空（不必移动其他结点），相当于在有序序列上插入记录而不移动其他记录，是动态查找表的适宜表示。
- **ASL 与树的形态有关**：查找过程恰是走一条从根到该结点的路径，比较关键字个数等于路径长度加 1（或结点所在层次数），不超过树的深度。含 n 个结点的 BST 不唯一：
  - **平衡时**（形态同折半判定树），ASL 与 \(\log_2 n\) 成正比，为 \(O(\log n)\)；
  - **退化单支树时**（先后插入的关键字有序），树深为 n，\(ASL=\frac{n+1}{2}\)（与顺序查找相同），为最差情况。
  - 随机情况下平均查找长度与 log n 等数量级（\(P(n)\approx 2(1+\frac1n)\ln n\)），但出现不平衡的概率约 46.5%，故需"平衡化"成 AVL。

### 平衡二叉树 AVL

- **定义**：或为空树，或为具有下列性质的二叉树：左右子树都是平衡二叉树，且**左子树和右子树的深度之差的绝对值不超过 1**。
- **平衡因子 BF(Balance Factor)**：定义为该结点的**左子树深度减去右子树深度**，则平衡二叉树上所有结点的平衡因子只可能是 **-1、0、1**。只要有一个结点的平衡因子绝对值大于 1，则该二叉树不平衡。
- **最小结点数（斐波那契关系）**：设 \(N_h\) 为深度 h 的 AVL 所含**最少结点数**，则 \(N_0=0,N_1=1,N_2=2\)，且 \(N_h=N_{h-1}+N_{h-2}+1=F_{h+2}-1\)（类斐波那契）。故含 n 结点的 AVL 最大深度约 \(1.44\log_2(n+2)\)，与 log n 同数量级，**查找时间复杂度 O(log n)**。

### B-树（m 阶平衡多路查找树）

一棵 m 阶的 B-树，或为空树，或为满足下列特性的 m 叉树：

1. 树中每个结点至多有 **m 棵子树**；
2. 若根结点不是叶子结点，则至少有 **2 棵子树**；
3. 除根之外的所有非终端结点至少有 **\(\lceil m/2\rceil\) 棵子树**；
4. 所有非终端结点包含信息 \((n,A_0,K_1,A_1,K_2,A_2,\dots,K_n,A_n)\)：\(K_i\) 为关键字且 \(K_i<K_{i+1}\)；\(A_i\) 为指向子树根结点的指针，且 \(A_{i-1}\) 所指子树中所有结点关键字均小于 \(K_i\)，\(A_n\) 所指子树中所有结点关键字均大于 \(K_n\)；n 为关键字个数，满足 \(\lceil m/2\rceil-1\le n\le m-1\)，**子树个数 = 关键字个数 + 1 = n+1**；
5. 所有**叶子结点都出现在同一层次**上，且不带信息（可看作外部结点或查找失败的结点，实际上不存在，指向它们的指针为空）。

- **最大深度**：含 N 个关键字的 m 阶 B-树，第 l+1 层至少有 \(2\lceil m/2\rceil^{l-1}\) 个结点、叶子（失败结点）数为 N+1，故 \(N+1\ge 2\lceil m/2\rceil^{l-1}\)，反解得最大深度 \(l\le\log_{\lceil m/2\rceil}\frac{N+1}{2}+1\)（即查找一个关键字最多涉及这么多个结点）。
- **查找效率**：B-树通常存于磁盘，"找结点"在磁盘、"结点内找关键字"在内存进行；磁盘查找远比内存耗时，故**磁盘上查找次数（待查关键字所在结点的层次数）是决定 B-树查找效率的首要因素**。3 阶 B-树又称 2-3 树。

### B+树（B-树的变型，m 阶）

B+树是应文件系统所需而出的一种 B-树变型。一棵 m 阶 B+树与 m 阶 B-树的**三点差异**：

1. 有 n 棵子树的结点中含有 **n 个关键字**（B-树为 n-1 个）；
2. 所有**叶子结点包含全部关键字的信息**及指向含这些关键字记录的指针，且叶子结点本身依关键字大小**自小而大顺序链接**（链成有序链表）；
3. 所有**非终端结点可看成索引部分**，结点中仅含有其子树（根结点）中的最大（或最小）关键字。

- B+树通常有**两个头指针**：一指根结点、一指关键字最小的叶子结点，故可从最小关键字起**顺序查找**、也可从根**随机查找**。随机查找/插入/删除基本同 B-树，但**查找时即使非终端关键字等于给定值也不终止，继续向下直到叶子**（成败都走根到叶的路径）。
- **插入/删除仅在叶子结点进行**：插入后关键字个数大于 m 则分裂为 \(\lceil m/2\rceil\) 和 \(m-\lceil m/2\rceil\) 两结点，双亲同时含两结点最大关键字；删除后关键字数少于 \(\lceil m/2\rceil\) 时与兄弟合并（同 B-树）。叶子中最大关键字被删时其非终端值可作"分界关键字"保留。**B+树更适合范围查找与顺序查找**。

### 键树（数字查找树，了解）

键树是度≥2 的**有序树**，结点只含**组成关键字的符号**（数值含一个数位、单词含一个字母，结束符 $ 小于任何字符）。两种存储：**双链树**（孩子兄弟链表，域 symbol/first/next）；**Trie 树**（多重链表，含 d 个指针域，d 为基：单词 d=27、数值 d=11）。查找时间依赖树的深度。

### 散列表

- **装填因子** \(\alpha=\dfrac{\text{表中填入的记录数}}{\text{哈希表的长度}}=\dfrac{n}{m}\)，标志哈希表的装满程度。α 越小发生冲突可能性越小，α 越大再填记录时冲突可能性越大、比较次数越多。
- **哈希表平均查找长度是 α 的函数，而不是 n 的函数**。故不管 n 多大，总可选合适装填因子将 ASL 限定在一定范围内。查找过程中需比较的关键字个数取决于三因素：**哈希函数、处理冲突的方法、装填因子**（对均匀哈希函数可不考虑其对 ASL 的影响）。
- **查找成功时 ASL**（可证明）：
  - 线性探测再散列：\(S_n\approx\frac{1}{2}\left(1+\frac{1}{1-\alpha}\right)\)
  - 随机探测再散列、二次探测再散列、再哈希：\(S_{nr}\approx-\frac{1}{\alpha}\ln(1-\alpha)\)
  - 链地址法：\(S_{nc}\approx 1+\frac{\alpha}{2}\)
- **查找不成功时 ASL**：
  - 线性探测再散列：\(U_n\approx\frac{1}{2}\left(1+\frac{1}{(1-\alpha)^2}\right)\)
  - 伪随机探测再散列等：\(U_{nr}\approx\frac{1}{1-\alpha}\)
  - 链地址法：\(U_{nc}\approx\frac{\alpha}{2}+e^{-\alpha}\)

## 四、核心算法思想（分步骤与过程）

### 顺序查找

从表尾（或表头）逐个比较关键字与给定值，配哨兵简化边界判断。代码见代码总结.md。

### 折半查找（分步骤）

1. 置区间初值 `low=1; high=ST.length;`
2. 当 `low<=high` 循环：`mid=(low+high)/2;`
   - 若 `EQ(key, ST.elem[mid].key)` → 找到，返回 mid；
   - 否则若 `LT(key, ST.elem[mid].key)` → 在前半区间继续，`high=mid-1;`
   - 否则 → 在后半区间继续，`low=mid+1;`
3. 循环结束（low>high）说明表中不存在待查元素，返回 0。

> 例：有序表 (05,13,19,21,37,56,64,75,80,88,92) 查 21——mid=6（64>21）→high=5、mid=3（19<21）→low=4、mid=4（21=21）成功，共比较 3 次。查 85——最终 low>high 失败。代码见代码总结.md。

### 分块查找

分两步：①先在索引表中确定待查记录所在的块（顺序查找或折半查找索引表的最大关键字）；②再在该块中顺序查找。因块内无序只能顺序查找。代码见代码总结.md。

### 二叉排序树 BST：查找 / 插入 / 删除

- **查找步骤**（递归）：树空或给定值等于根关键字则返回根（结束）；否则小于根则左子树继续、大于则右子树继续。查找失败时返回路径上最后一个结点，即为插入位置。
- **插入步骤**：新结点一定是新添的**叶子**，且是查找不成功时路径上最后一个结点的左/右孩子：空树则作新根，否则按大小挂作 p 的左/右孩子。从空树出发经一系列查找插入可生成 BST（构造即排序）。
- **删除三情况详解**（设被删结点 *p、双亲 *f）：
  1. ***p 为叶子**（PL、PR 均空）：删叶不破坏结构，只需修改双亲指针。
  2. ***p 只有左子树 PL 或只有右子树 PR**：令 PL 或 PR 直接成为 *f 的左（右）子树即可，不破坏 BST 特性。
  3. ***p 左右子树均不空**：两种做法——其一，令 *p 左子树为 *f 左子树、*p 右子树挂到左子树最右结点（前驱）的右子树上；其二（常用），令 *p 的**直接前驱（或直接后继）替代 *p**，再删去该前驱/后继（前驱=左子树最右、后继=右子树最左；以前驱 *s 替代时 *s 只有左子树 SL，删 *s 后令 SL 为 *s 双亲 *q 的右子树）。
  - 实现要点：右子树空则重接左子树，左子树空则重接右子树，均不空则转左后向右到尽头找前驱 s（q 记其双亲），`p->data=s->data` 后重接 q 的子树再释放 s。代码见代码总结.md。

### 平衡二叉树 AVL：插入失衡四型与旋转过程

- **失衡定位**：由于插入结点而失去平衡的**最小不平衡子树**的根结点 a（即离插入结点最近、且平衡因子绝对值超过 1 的祖先结点）。旋转处理后新子树深度与插入前相同，故不影响插入路径上所有祖先结点的平衡度，仅需对最小不平衡子树作平衡旋转即可。
- **四种失衡类型与调整**（旋转正确性可由"保持中序遍历关键字自小至大有序"证明）：
  1. **LL 型（单向右旋平衡）**：在 *a 的**左子树根结点的左子树**上插入结点，*a 的平衡因子由 1 增至 2。进行一次**向右的顺时针旋转**（右单旋）。
  2. **RR 型（单向左旋平衡）**：在 *a 的**右子树根结点的右子树**上插入结点，*a 的平衡因子由 -1 变为 -2。进行一次**向左的逆时针旋转**（左单旋）。
  3. **LR 型（双向旋转，先左后右）**：在 *a 的**左子树根结点的右子树**上插入结点，*a 平衡因子由 1 增至 2。需**先对左子树左旋、再对 *a 右旋**两次旋转。
  4. **RL 型（双向旋转，先右后左）**：在 *a 的**右子树根结点的左子树**上插入结点，*a 平衡因子由 -1 变为 -2。需**先对右子树右旋、再对 *a 左旋**两次旋转。
  - (1)与(2)对称，(3)与(4)对称。
- **单旋操作（指针修改）**：
  - **右旋 R_Rotate(p)**：lc=p->lchild（左子树根）；p->lchild=lc->rchild（lc 的右子树挂为 p 的左子树）；lc->rchild=p；p=lc（p 指向新根，即原左子树根）。
  - **左旋 L_Rotate(p)**：rc=p->rchild；p->rchild=rc->lchild；rc->lchild=p；p=rc。
- **插入后平衡因子调整规律**（以插在左子树、左子树"长高"为例）：原 bf=-1（右高）→改 0、树高不变；原 bf=0→改 1、树高增 1；原 bf=1（左高）→失衡，作左平衡：左孩子 bf=1 作单右旋（旋后根与右子树根 bf 置 0）；左孩子 bf=-1 作先左后右双旋（旋后按新结点位置改 bf）。插在右子树的处理与之对称。代码见代码总结.md。

### B-树的查找 / 插入 / 删除

- **查找过程**：是一个**顺指针查找结点**和**在结点内关键字中查找**交叉进行的过程。从根开始，在结点内确定给定值落在哪两个关键字之间（或等于某关键字），顺相应指针下到子结点，直至找到关键字（成功）或到达叶子结点（失败）。返回结果 (pt, i, tag)：tag=1 成功，pt 所指结点第 i 个关键字等于给定值；tag=0 失败，给定值应插在 pt 所指结点第 i 与第 i+1 个关键字之间。
- **插入（分裂过程）**：B-树的生成从空树起逐个插入关键字而得。因结点关键字数必须 ≥⌈m/2⌉-1，插入不是简单添加叶子，而是**首先在最低层的某个非终端结点中添加一个关键字**：
  - 若该结点关键字数不超过 m-1，则插入完成；
  - 否则（超过 m-1）产生结点**分裂**：设 *p 已有 m-1 个关键字，插入后含 m 个关键字，将 *p 分裂为 *p 与 *p′ 两结点——*p 保留前 \(\lceil m/2\rceil-1\) 个关键字，*p′ 保留后 \(m-\lceil m/2\rceil\) 个关键字，**中间关键字 \(K_{\lceil m/2\rceil}\) 和指针 *p′ 一起插入到 *p 的双亲结点中**。双亲若也因此超过 m-1 则继续分裂，可逐级向上，直至根分裂生成新根、树长高一层。
- **删除过程**：首先找到被删关键字所在结点并从中删除。
  - 若被删关键字为**非终端结点**中的 \(K_i\)，则以指针 \(A_i\) 所指子树中的**最小关键字 Y（或直接前驱/后继）替代 \(K_i\)**，然后在相应结点中删去 Y——从而转化为删除最下层非终端结点中的关键字。
  - 删除最下层非终端结点关键字后，分三种情况：
    1. 被删关键字所在结点关键字数**不少于 \(\lceil m/2\rceil\)**（即 ≥⌈m/2⌉）：只需从该结点删去关键字 K 和相应指针 \(A_i\)，树的其他部分不变，删除完成。
    2. 所在结点关键字数等于 \(\lceil m/2\rceil-1\)，而相邻的右（或左）兄弟结点关键字数**大于** \(\lceil m/2\rceil-1\)（兄弟"够借"）：作**借位（旋转）**——将兄弟结点中最小（或最大）关键字**上移至双亲结点**，将双亲结点中小于（或大于）且紧靠该上移关键字的关键字**下移至被删关键字所在结点**，使两结点关键字数均不少于 \(\lceil m/2\rceil-1\)，双亲结点关键字数不变。
    3. 所在结点与相邻兄弟结点关键字数**均等于** \(\lceil m/2\rceil-1\)（兄弟也"不够借"）：作**合并**——删去关键字后，将所在结点剩余的关键字和指针，加上双亲结点中相应的分隔关键字 K，一起合并到相邻兄弟结点中（有右兄弟则并入右兄弟，否则并入左兄弟）。若合并后使双亲结点关键字数小于 \(\lceil m/2\rceil-1\)，则对双亲结点依次类推作借位或合并处理，可能逐级上溯至根，使树变矮。

### 散列表：造表 / 哈希函数 / 冲突处理 / 查找

**造表思想**：根据设定的哈希函数 H(key) 和处理冲突的方法，将一组关键字映像到有限连续的地址集（区间 0~m-1）上，以关键字在地址集中的"像"作为存储位置（称哈希造表/散列，所得位置称哈希地址）。**"好"的哈希函数**是均匀的(Uniform)：任一关键字映像到地址集中任一地址的概率相等，使哈希地址均匀分布以减少冲突。

**六种哈希函数构造方法**：

1. **直接定址法**：\(H(key)=key\) 或 \(H(key)=a\cdot key+b\)（a、b 为常数，又称自身函数）。地址集与关键字集大小相同，**对不同关键字不会冲突**，但实际能用的情况很少。
2. **数字分析法**：设关键字以 r 为基且**全部可能关键字事先已知**，分析全体关键字后取**分布均匀、避冲突的若干数位**组成地址（可取几位或几位叠加舍进位）。
3. **平方取中法**：取关键字**平方后的中间几位**为地址（中间几位与每一位都相关，使随机关键字得随机地址），取位数由表长决定。**较常用**。
4. **折叠法(folding)**：将关键字分割成位数相同的几部分（末部分可不同），取叠加和（舍进位）作地址。两种叠加：**移位叠加**（各部分最低位对齐相加）、**间界叠加**（沿分割界来回折叠后对齐相加）。适用于**位数很多、且每位分布大致均匀**时。
5. **除留余数法**：\(H(key)=key\bmod p,\ p\le m\)。**最简单也最常用**，可直接取模也可在折叠/平方取中后取模。**p 的选择很重要**：一般取 p 为**不大于 m 的质数**或**不含小于 20 质因数的合数**（p 取不好易生同义词，如 p 取 2 的幂会忽略高位）。
6. **随机数法**：\(H(key)=random(key)\)，取关键字的随机函数值为地址，通常在**关键字长度不等**时采用。

> 选择哈希函数需考虑：计算哈希函数所需时间、关键字长度、哈希表大小、关键字分布情况、记录查找频率。

**处理冲突的四种方法**：

1. **开放定址法**：\(H_i=(H(key)+d_i)\bmod m\quad(i=1,2,\dots,k,\ k\le m-1)\)，其中 H(key) 为哈希函数，m 为表长，\(d_i\) 为增量序列，三种取法：
   - **线性探测再散列**：\(d_i=1,2,3,\dots,m-1\)。优点：只要哈希表未填满，总能找到一个不冲突的地址；缺点：易产生**"二次聚集"（堆积）**——两个第一个哈希地址不同的记录争夺同一个后继哈希地址，即在处理同义词冲突过程中又添加了非同义词的冲突，对查找不利。
   - **二次（平方）探测再散列**：\(d_i=1^2,-1^2,2^2,-2^2,\dots,\pm k^2\ (k\le m/2)\)。只有在**表长 m 为形如 4j+3（j 为整数）的素数**时才可能找到，可克服线性探测的堆积。
   - **伪随机探测再散列**：\(d_i=\) 伪随机数序列，取决于伪随机数列。
2. **再哈希法**：\(H_i=RH_i(key)\ (i=1,2,\dots,k)\)，\(RH_i\) 均是不同的哈希函数，即在同义词产生地址冲突时计算另一个哈希函数地址，直到冲突不再发生。**不易产生"聚集"，但增加了计算时间**。
3. **链地址法（拉链法）**：将所有关键字为同义词的记录存储在同一线性链表中。设哈希地址在 [0,m-1]，建指针向量 ChainHash[m]（初始为空指针），凡地址为 i 的记录都插入头指针为 ChainHash[i] 的链表中（插入位置可在表头、表尾或中间以保序）。**不发生二次聚集**（哈希地址不同的记录在不同链表中），删除方便。
4. **公共溢出区**：设 HashTable[0..m-1] 为基本表（每分量存一个记录），另设 OverTable[0..v] 为溢出表。所有与基本表中关键字为同义词的记录，一旦发生冲突，都填入溢出表。

**散列查找步骤**（与造表过程基本一致）：给定 K 值，①按造表设定的哈希函数求得哈希地址；②若表中此位置没有记录则查找不成功；③否则比较关键字，若与给定值相等则查找成功；④否则按造表设定的处理冲突方法找"下一地址"，直至表中某位置为"空"或所填记录关键字等于给定值为止。

> **删除标记**：若要在**非链地址**处理冲突的哈希表中删除一个记录，需在该记录位置填入一个**特殊符号（删除标记）**，以免断链后找不到在它之后填入的"同义词"记录。链地址法删除则无需此标记。

## 五、易错点与常考辨析

- **折半查找只能用于顺序存储的有序表，不能用于链表**（无法 O(1) 定位 mid）；顺序查找对链表适用。
- 判定树是**平衡二叉树但不一定完全二叉树**（叶子层次差≤1），深度 \(\lfloor\log_2 n\rfloor+1\)；成功 ASL 用 \(\frac{n+1}{n}\log_2(n+1)-1\approx\log_2(n+1)-1\)，不成功走**外部结点**（比较次数=路径上内部结点数），两者别混淆。顺序查找不成功比较次数恒为 **n+1**（含哨兵）；带哨兵从后往前只为免每步检测表尽，非改比较逻辑。
- 分块查找**块间有序、块内无序**，块内只能顺序查找；定块可顺序可折半。**最佳分块 \(s=\sqrt{n}\)**，此时 \(ASL_{min}=\sqrt{n}+1\)。
- BST **中序有序**；ASL 取决于形态：平衡 O(log n)、顺序插入退化单支树 O(n)（\(ASL=\frac{n+1}{2}\)）——退化正是引入 AVL 的原因（不平衡概率约 46.5%）。删除**双孩子**用直接前驱（左子树最右）或直接后继（右子树最左）替代再删之，勿直接删两个孩子；单孩子用孩子顶替；叶子直接删。
- AVL 平衡因子 = **左子树深度 − 右子树深度**，只取 **-1/0/1**；旋转看失衡结点"哪侧孩子的哪侧子树"插入：**LL→右单旋、RR→左单旋、LR→先左后右、RL→先右后左**（LL/RR 单旋、LR/RL 双旋），方向别记反。旋转只对**最小不平衡子树**进行，处理后子树深度不变、不影响祖先。深度 h 的 AVL **最少结点** \(N_h=N_{h-1}+N_{h-2}+1=F_{h+2}-1\)（\(N_0=0,N_1=1,N_2=2\)），类斐波那契。
- B-树 m 阶：根非叶≥2 子、非根非终端 ≥\(\lceil m/2\rceil\) 子，关键字数 \([\lceil m/2\rceil-1,\ m-1]\)，**子树数=关键字数+1**，叶子同层且为失败结点（不带信息、实际不存在）；3 阶又称 2-3 树。插入只在**最下层非终端结点**，超 m-1 则分裂（中间关键字上移）；删除"够借"用**借位**（兄弟上移、双亲下移）、"不够借"用**合并**（并入兄弟+双亲分隔关键字），可逐级上溯。
- **B+树 vs B-树**：B+树 n 子对应 **n 个关键字**、关键字**全在叶**、叶**链成有序链表**、非终端**只索引**、查找**必到叶**、有根与最小叶两个头指针；B-树 n 子对应 **n-1 关键字**、非终端也含关键字、命中即停。B+树更适合范围/顺序查找。
- 散列 **\(\alpha=n/m\)**，α 越大冲突越多；**ASL 只与 α 有关、与 n 无绝对关系**。除留余数 **p 取 ≤m 的最大质数**（或不含小于 20 质因子的合数）最好。**线性探测易"二次聚集"（堆积）**、链地址法不会；链地址删除无需标记、**开放定址删除须填删除标记防断链**；二次探测需表长 m 为 4j+3 型素数才能探遍。
- 802 一般不考**红黑树**（了解为一种自平衡二叉查找树即可）；键树（双链树/Trie）、次优查找树、斐波那契/插值查找了解思想即可，重点在顺序/折半/分块/BST/AVL/B-树/B+树/散列表。
