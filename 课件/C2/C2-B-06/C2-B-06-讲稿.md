## P3 判两点连通（约4分钟）

第一个算法，判两点连通：给定图里两个顶点 i 和 j，问 i 能不能到 j。代码 Pathitoj 是材料原文，九行。

走一遍。开头是终止：i 等于 j，说明走到了，返回 1。然后把自己的 visited 置 1，逐个邻居试：邻居 k 没访问过，就递归问 k 能不能到 j；任何一个邻居递归返回 1，这一路就返回 1。所有邻居都试完还没返回，说明从 i 出发到不了 j，返回 0。

【停顿】设问：这题的 visited 打了标记就再没清过，为什么可以不复位？想一下场景：从 i 出发把整片可达的区域都探了一遍，没探到 j；后来换一条路又走到这个区域里的某个顶点 x——x 已经被探过了，从 x 出发的所有路当时都没通到 j，现在再走一遍结果一样。所以标记留着不是错误，是剪枝：探过的区域不再重复探。

但这个写法有一个隐患必须说清：visited 是全局数组，这个函数一旦返回，标记全留着。同一个程序里调第二次 Pathitoj，visited 还是上一次的残留，直接出错。所以要么每次调用前手动清零，要么把它当一次性函数用——判一次就完事。后面几页会看到这个隐患在路径题里怎么爆掉。

拿个小例子把函数走一遍：图 4 个顶点，边 0-1、0-2、1-3、2-3，问 0 能不能到 3。调用 Pathitoj(G, 0, 3)：0 不等于 3，标记 0；邻居 1 没访问，递归进 1；1 标记自己，邻居 0 已访问跳过，邻居 3 没访问，递归进 3；3 等于 j，返回 1；一层层传回去，答案是 1。要是问 0 到 4，图里根本没有 4，所有递归走到头返回 0，答案是 0。整个过程没有撤销任何标记。

复杂度：每个顶点和每条边最多访问一次，时间 O(|V|+|E|)，递归栈空间 O(|V|)。

## P4 经过 k 的路径（约5分钟）

第二个算法是路径类真题的匿名化版本：判断从 u 到 v 是否存在一条经过 k 的路径。页面上标了年份，题面、分值和评分点到真题阶段再展开，这里只拿它当教学载体。

讲代码之前先说思路，这题的解题关键就一句：**u 到 v 经过 k，拆成两段——u 能到 k，并且 k 能到 v，两段都是刚才的判连通**。两段都通，答案就是 true。为什么要拆？因为"经过 k"这个条件卡在路中间，整体搜很难写；拆成两段之后，每一段都是你会写的东西。

看代码，两段函数。checkPath 和 Pathitoj 骨架几乎一样，差别在倒数第二行：所有邻居试完返回 false 之前，多了一句 visited[u] 等于 false。这一句就是回溯——从 u 往下走的路全失败了，u 的标记清掉，让别的路还能再经过 u。第二个差别：成功的时候直接 return true，不清标记。为什么成功不清？已经找到一条路了，后面不用再试，清不清都不影响结果；这是 2025 年题的写法，下一页的 2024 年题成功分支里也清了，两种都对，你自己写的时候统一一种。

再看外壳 IsExistPathGoBy。三段：先边界守卫，顶点数或边数为 0 直接 false；然后第一段 checkPath(G, u, k)，不通就返回 false；中间用一个循环把 visited 全部复位；最后第二段 checkPath(G, k, v)。

【停顿】设问：中间的复位循环能不能省？想清楚再往下听。不能省，而且这是本题最容易错的地方。第一段搜索留下的标记是"从 u 出发探过的区域"，第二段要从 k 重新出发，这些残留标记会把第二段的路堵死——明明 k 能到 v，也返回 false。下一页末尾的动画会把这一刻画出来。

还有一处和材料不同要交代：材料的 visited 声明是变长数组带初始化，按全局约定改成固定长度数组加等于 {false}，行为一样，写法更稳。

## P5 长度 k 的路径（约5分钟）

第三个算法，路径类第二种形态：判断无向图里是否存在一条长度恰好为 k 的路径。长度指边的条数。

思想是在 DFS 里多带一个参数 depth。数据结构基础阶段第7节写树递归、上一节写最长路径时都用过同一个套路：递归中携带额外信息。这里 depth 记"从起点已经走了几条边"，每往下一层加 1，进函数先判 depth 等于 k——走到了，返回 true。标记、递归、失败复位，和上一题同一个骨架。

【停顿】设问：k 的合法范围是什么？看外壳第一行：k 小于 1 或 k 大于 G.vexnum 减 1，直接 false。下界好懂，长度至少是 1 条边。上界推一下：这题要求简单路径，顶点不重复，k 条边要经过 k+1 个不同顶点，图里一共只有 vexnum 个，所以 k 最大是 vexnum 减 1。写题时把这个不等式写在代码里，阅卷时它就是边界分的依据。

外壳还有一处要看：每个起点各试一遍，换起点之前内层循环把 visited 全部清 0。为什么？这次搜索可能从任意顶点出发，上一个起点留下的标记不能让下一个起点带着走。

最后说成功分支。这个版本的成功分支里也写了 visited[i] 等于 0 再返回 true，和上一题"成功不清"不一样。两种写法都对——成功了就不再继续搜索，清不清都不影响结果——但你自己的代码里要统一，不能一题一种。

复杂度：每个起点一次 DFS，最坏 O(|V|) 个起点，每次 O(|V|+|E|)，总时间 O(|V|乘(|V|+|E|))；空间 O(|V|)。

## P6 两种 visited 处理对比（约4分钟）

这一页是全节最重要的一页，把 P3 和 P4 两段代码并排放在屏幕上，左边判连通，右边找路径，就差倒数第二行。

左边：标记打了就不撤，失败返回时标记保留。右边：失败返回前把 visited[u] 清回 false。左边用在只问"能不能到"的题；右边用在问路"怎么走"的题、要拆成几段搜的题、要输出全部路径的题——这些题里，一条路走不通之后，顶点还要让别的路再用，标记必须清。

【停顿】现在回答这一页的判断题：你拿到一道图的路径题，怎么决定写哪种？看题目问什么。只问可达性，写不复位版，简单还不会错；要还原路径、要经过某个点、要数出全部走法，写回溯复位版。判断错了代价很大：该复位没复位，典型症状是"明明有路却返回 false"，上一页中间的复位循环就是这个病。

屏幕上还有一张五行对比表，四列内容口播念一遍：失败返回时，左版标记保留当剪枝，右版清除让别的路再试；成功返回时，左版保留，右版清或不清都对，统一即可；隐患，左版是二次调用前要手动清零，右版是忘了复位会误判 false。

基础阶段留的问题到这一页正式还账：visited 只在找路径类题目里要清，而且清的位置固定——写在失败返回之前。连通性判断永远不需要清。

## P7 过程页：两种写法对比动画（约4分钟）

拿纸跟着画，PPT逐步放。左右是同一个图：6 个顶点，边是 0-1、0-2、1-3、2-3、1-4、4-5，注意 0-1-3-2-0 是一个环，5 是尾巴上的端点。任务是找从 0 到 5 且经过 3 的路径，按上一节的讲法拆成两段。

左半屏，写法一标记从不复位。第一段 0 到 3：从 0 出发，先试邻居 1，1 的邻居里 3 没访问过，走进去，3 就是目标，成功。此刻标记留在 0、1、3 三个顶点上，谁也没清。第二段从 3 出发到 5：3 的邻居按顺序是 1 和 2，先看 1——visited[1] 是 1，被挡住，跳过；走 2，2 的邻居是 0 和 3，全有标记，死路。返回 false。错在哪一行，看清楚：不是第二段写错了，是第一段的残留标记把第二段的路堵死了。

右半屏，写法二回溯复位。第一段一模一样，0 到 1 到 3 成功；区别在两段之间，visited 全部复位。第二段从 3 重新出发：邻居 1 没标记了，走进 1；1 的邻居里先试 0，0 再走到 2，死路，回退；再试 4，4 走到 5，成功，返回 true。

【停顿】两幅轨迹在哪一个顶点开始不同？顶点 1。第二段从 3 选邻居那一刻，左版的 1 走不了，右版的 1 能走。把这一帧画在纸上，比背两段代码管用。

## P8 拓扑排序（约5分钟）

后半节转拓扑类。先讲拓扑排序本身：有向无环图里，把顶点排成一个序列，使每条弧都从排在前面的顶点指向排在后面的顶点。

代码 TopoLogicalSort 四步，对应屏幕上的四段。开头先判 G.kind 不等于 1 直接返回 false：kind 记的是图的类型，等于 1 表示有向图；不是有向图就没有拓扑序这个概念，直接拒绝。第一步求入度表：遍历每个顶点的边表，它指向谁，谁的入度加一——这一段就是数据结构基础阶段第9节的 Indegree，原样照抄。第二步，入度为 0 的全部入栈，栈是第3节的基本操作。第三步，循环出栈：弹出一个 u，写进 print 数组，count 加一。第四步，u 的每个后继入度减一，减到 0 的立刻入栈。

【停顿】设问：最后为什么 return count 等于 G.vexnum？反过来想：什么情况下 count 会不够？图里有环。环上的每个顶点都指着环内另一个顶点，它的入度永远减不到 0，永远进不了栈，永远输出不了。所以输出个数不足顶点数，等价于有环。这一句同时是拓扑排序的判环手段，记住。

还有一个判断题先押答案：栈换成队列，输出还是合法拓扑序吗？是。因为入栈和入队的都是"当前入度为 0、可以输出"的顶点，先输出哪一个都合法；所以栈版和队列版得到的序列可能不同，但都合法。这一句话是下一题"判唯一"的引子，先记住结论。

复杂度：求入度表过一遍所有边，主循环每个顶点出入栈一次、每条边被减一次，时间 O(|V|+|E|)，空间 O(|V|)。

## P9 过程页：拓扑排序推演（约4分钟）

还是拿纸跟着画。图在屏幕上：5 个顶点的有向无环图，边是 0→1、0→2、1→3、2→3、3→4，每个顶点下方的格子里写着初始入度：0、1、1、2、1。

初始只有顶点 0 入度为 0，入栈，栈里一个元素。第 1 轮：出 0，输出 0；0 的后继是 1 和 2，1 的入度 1 减到 0，入栈；2 的入度 1 也减到 0，入栈。栈里底是 1 顶是 2。第 2 轮：出 2，输出 2；2 的后继是 3，3 的入度 2 减到 1，不够 0，不入栈。第 3 轮：出 1，输出 1；1 的后继也是 3，3 的入度再减到 0，入栈。第 4 轮：出 3，输出 3；3 的后继是 4，4 的入度 1 减到 0，入栈。第 5 轮：出 4，输出 4，栈空，结束。

输出序列是 0、2、1、3、4，count 等于 5，等于顶点数，无环。注意一个细节：栈版输出的是 0 2 1 3 4，不是按编号排。上一页的判断题在这里兑现——把栈换成队列，1 先于 2 出队，序列变成 0 1 2 3 4，也合法。

## P10 判给定序列是否拓扑序列（约4分钟）

拓扑类第二题，也是一道真题的匿名化版本：题目给一个序列，问它是不是这张图的一个拓扑序列。

关键认识先说：**不需要真的做一遍拓扑排序再比较**。如果先自己排序，再把两个序列逐位比，既慢又绕。正确做法：按给定序列的顺序模拟一遍——序列说先输出谁，就先检查谁。检查的方法还是入度表：每检查一个顶点 u，先看它的入度是不是已经变成 0；不是 0，说明还有前驱没在它前面出现过，序列不合法，返回 false；是 0，就把 u 的所有后继入度减一，继续检查下一个。

【停顿】设问：为什么入度不为 0 就能断定不合法？因为拓扑序列的定义就是每条弧从前指后，u 的前驱必须全部排在 u 前面；轮到 u 时入度还没减到 0，意味着某个前驱还在后面排着，矛盾。

看代码 IsTopoSeq，十行出头。前两段和拓扑排序共用：边界守卫加求入度表。主循环按 seq 的顺序走：取出 u，判入度，减后继。循环走完没返回 false，就是合法序列。

复杂度：求入度表 O(|V|+|E|)，主循环每个顶点查一次、每条边减一次，也是 O(|V|+|E|)；空间 O(|V|)。这一题和拓扑排序共用同一个入度表框架，背一份代码答两道题。

拿推演的图走一遍：给序列 0 2 1 3 4。先求入度表 0、1、1、2、1。检查 0：入度 0 合法，后继 1、2 减一，表变 0、0、0、2、1。检查 2：入度 0 合法，后继 3 减一。检查 1：入度 0 合法，后继 3 再减一到 0。检查 3：入度 0 合法，后继 4 减一。检查 4：入度 0 合法。全过，返回 true。换一个序列 0 1 2 3 4 也同样合法——合法拓扑序不止一个，这正是下一题要判的事。若把 3 排到 1 前面，轮到 3 时入度还是 1，当场返回 false。

## P11 判拓扑序列是否唯一（约3分钟）

拓扑类第三题：判断一张图的拓扑序列是否唯一。

思路一句话：任何一轮里，入度为 0 的顶点只能有一个。为什么？某一轮同时有两个入度为 0 的顶点，它们之间没有路径相连——有路的话后一个的入度不可能减到 0——谁也不约束谁，谁前谁后都合法，序列至少有两种。反过来，每一轮恰好只有一个可选顶点，顺序就被一步步唯一确定了。这就是充要条件，也是本页的算法。

代码 uniquely 十二行，和拓扑排序同一个骨架，差别在计数：初始统计入度为 0 的个数 num0，不等于 1 直接返回 0；主循环每出队一个顶点，把这一轮新变成 0 的个数再数一遍，超过一个返回 0。队列在这里只用来按轮推进，换成栈不影响结果。

【停顿】这题材料原题给的是邻接矩阵和另一套字段名，页面下方有一行字段对应，念一遍：numVertices 就是 vexnum，顶点数；numEdges 就是 arcnum，边数；VerticesList 就是 vex，顶点表；Edge 就是 edge，邻接矩阵。答题时以题目给的定义为准，抄题目给的字段名；本课程正文统一用基础阶段第9节那一套，页面上的代码就是按统一写法改成的邻接表版，逻辑和材料原题逐行对应。

复杂度同拓扑排序：时间 O(|V|+|E|)，空间 O(|V|)。

拿两张图对比感受判据。第一张：只有两条边 0→2、1→2，初始 0 和 1 同时入度为 0，num0 等于 2，第一句就返回 0——拓扑序 0 1 2 和 1 0 2 都合法，不唯一。第二张就是推演那张图：第一轮只有 0，出 0 之后 1、2 同时变 0，第二轮 num0 等于 2，返回 0——对应 0 1 2 3 4 与 0 2 1 3 4 两个合法序列。什么时候唯一？每一轮恰好一个入度为 0 的顶点，比如把边改成 0→1、0→2、1→2，第一轮只有 0，出 0 只有 1，出 1 只有 2，序列被唯一锁定。

## P13 小结与课后任务（约2分钟）

六个算法一张表，对着屏幕收一遍。判两点连通：标记后从不复位，最容易错的是二次调用前忘了清零。经过 k 的路径：回溯复位，两段之间再清零，最容易错的是中间忘了复位、第二段误判。长度 k 的路径：回溯复位，每个起点前清零，最容易错的是 k 的上界写成 vexnum。拓扑排序：不用 visited、用入度表，最容易错的是先输出后减后继入度、次序写反——减入度必须在输出之后立刻做。判给定序列：入度表加按序模拟，最容易错的是忘了先求入度表。判唯一：入度表加每轮计数，最容易错的是拿着另一套字段名写代码。

一句主线串起来：visited 怎么处理，取决于题目问的是"能不能到"还是"路怎么走"；拓扑类三题共用一张入度表，改的只是每轮干什么。

```c
// 判两点连通：visited 全局、从不复位（一次性函数）
int visited[MaxVertexNum] = {0};
int Pathitoj(ALGraph G, int i, int j){
    if(i == j) return 1;
    visited[i] = 1;
    for(ArcNode *p = G.vertices[i].firstarc; p != NULL; p = p->nextarc){
        int k = p->adjvex;
        if(!visited[k] && Pathitoj(G, k, j)) return 1;
    }
    return 0;                       // 注意：这里不复位 visited
}

// 经过 k 的路径：DFS 回溯 + 两段调用（2025 年题，visited 声明按勘误 A6 修正）
bool checkPath(ALGraph G, int u, int v, bool visited[]){
    if(u == v) return true;
    visited[u] = true;
    for(ArcNode *p = G.vertices[u].firstarc; p != NULL; p = p->nextarc)
        if(!visited[p->adjvex] && checkPath(G, p->adjvex, v, visited)) return true;
    visited[u] = false;             // 回溯：失败返回前复位
    return false;
}
bool IsExistPathGoBy(ALGraph G, int u, int k, int v){
    if(G.vexnum == 0 || G.arcnum == 0) return false;
    bool visited[MaxVertexNum] = {false};
    if(!checkPath(G, u, k, visited)) return false;          // 第一段：u 到 k
    for(int i = 0; i < G.vexnum; i++) visited[i] = false;   // 两段之间复位
    return checkPath(G, k, v, visited);                     // 第二段：k 到 v
}

// 长度 k 的路径：DFS 带 depth 参数（2024 年题）
bool DFS(ALGraph& G, int i, int depth, int k, int visited[]){
    if(depth == k) return true;
    visited[i] = 1;
    for(ArcNode* e = G.vertices[i].firstarc; e != NULL; e = e->nextarc){ int v = e->adjvex;
        if(!visited[v] && DFS(G, v, depth + 1, k, visited)){ visited[i] = 0; return true; } }
    visited[i] = 0;                 // 回溯
    return false;
}
bool existsKSimplePath(ALGraph& G, int k){
    if(k < 1 || k > G.vexnum - 1) return false;
    int visited[MaxVertexNum];
    for(int i = 0; i < G.vexnum; i++){ for(int j = 0; j < G.vexnum; j++) visited[j] = 0;
        if(DFS(G, i, 0, k, visited)) return true; }
    return false;
}

// 拓扑排序：入度表加栈
bool TopoLogicalSort(ALGraph G, int print[]){
    if(G.kind != 1) return false;
    int indegree[MaxVertexNum] = {0};
    for(int i = 0; i < G.vexnum; i++)
        for(ArcNode *p = G.vertices[i].firstarc; p != NULL; p = p->nextarc) indegree[p->adjvex]++;
    SqStack S; InitStack(S);
    for(int i = 0; i < G.vexnum; i++) if(indegree[i] == 0) Push(S, i);
    int count = 0;
    while(!IsEmpty(S)){ int u; Pop(S, u); print[count++] = u;
        for(ArcNode *p = G.vertices[u].firstarc; p != NULL; p = p->nextarc)
            if(--indegree[p->adjvex] == 0) Push(S, p->adjvex); }
    return count == G.vexnum;
}

// 判给定序列是否拓扑序列（2026 年题）
bool IsTopoSeq(ALGraph G, int seq[], int n){
    if(G.vexnum == 0) return false;
    int indegree[MaxVertexNum] = {0};
    for(int i = 0; i < G.vexnum; i++)
        for(ArcNode *p = G.vertices[i].firstarc; p != NULL; p = p->nextarc) indegree[p->adjvex]++;
    for(int i = 0; i < n; i++){ int u = seq[i];
        if(indegree[u] != 0) return false;
        for(ArcNode *p = G.vertices[u].firstarc; p != NULL; p = p->nextarc) indegree[p->adjvex]--;
    }
    return true;
}

// 判拓扑序列是否唯一：按勘误 B2 改写为邻接表版，逻辑与材料邻接矩阵版对应
bool uniquely(ALGraph G){
    int indegree[MaxVertexNum] = {0}, num0 = 0;
    for(int i = 0; i < G.vexnum; i++)
        for(ArcNode *p = G.vertices[i].firstarc; p != NULL; p = p->nextarc) indegree[p->adjvex]++;
    SqQueue Q; InitQueue(Q);
    for(int i = 0; i < G.vexnum; i++) if(indegree[i] == 0){ num0++; EnQueue(Q, i); }
    if(num0 != 1) return 0;                     // 第一轮入度为 0 的必须只有一个
    while(!IsEmpty(Q)){ int v; DeQueue(Q, v); num0 = 0;
        for(ArcNode *p = G.vertices[v].firstarc; p != NULL; p = p->nextarc)
            if(--indegree[p->adjvex] == 0){ num0++; EnQueue(Q, p->adjvex); }
        if(num0 > 1) return 0;                  // 任何一轮新出两个就不唯一
    }
    return 1;
}
```
