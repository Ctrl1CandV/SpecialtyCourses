## P2 引题：为什么要限制操作端（约2分钟）

那么先想一个问题。顺序表和链表，哪个位置都能插入删除，很灵活。为什么还要专门搞出栈和队列这种只让在一端操作的结构？

因为很多问题的天性就是只在一端操作，你给它全方位的灵活反而用不上、还容易乱。举两类。第一类是后进先出的场景：你调用一个函数，它里面又调用别的函数，最先调用的最后才返回，这就是一层压一层、再一层弹一层，天然符合"最后进去的最先出来"，这就是栈。括号匹配、表达式求值也是这个道理。第二类是先进先出的场景：排队买票，先来的先走；二叉树一层一层地遍历、图的广度优先搜索，都要按到达的先后顺序处理，这就是队列。

所以栈和队列不是把简单东西搞复杂，而是把"只在一端操作"这件事用结构固定下来，让代码写清楚、不出错。栈只在一端进出，叫栈顶，后进先出；队列一端进另一端出，先进先出。记住这两个本质，后面所有操作都围绕它们。

## P3 顺序栈定义与 top=-1 约定（约3分钟）

先看顺序栈的定义。就是一个数组 data 加一个 top：typedef struct，里面 int data[MaxSize] 存元素，int top 记栈顶位置，起个名叫 SqStack。初始化 InitStack 只做一件事，把 top 置成 -1。

这里要正式定一个约定，我们叫它约定3：**本课程 top=-1 表示栈空**。也就是说，top 指向的是当前栈顶那个元素本身，栈里一个元素都没有的时候，top 是 -1。为什么用 -1 而不是 0？因为数组下标从 0 开始，第一个元素放在 data[0]，如果 top 指向栈顶元素，空栈时它就该指到"第一个元素的前一个"，也就是 -1。

你先把这个约定记死，因为它决定了后面每一个操作的式子。还有一种常见的约定是 top=0，让 top 指向栈顶元素的下一个空位，空栈时 top=0。两种约定都对，但式子不一样，混用就全错。我们这一节全程用 top=-1，第6页专门对比 top=0 会怎么变。

还有一个约定顺带说一下，约定4：栈和队列里存的元素类型，我们这里写的是 int，但它当工具用的时候，里面存的可以是结点指针、顶点编号，按题目需要换，操作逻辑一模一样。

## P4 Push 与 Pop（约4分钟）

那么定义和约定清楚了，看入栈 Push 和出栈 Pop，重点是自增自减的位置。

先看 Push，入栈。第一句判满，if top == MaxSize-1 就返回 false。为什么判满是 MaxSize-1？因为 top 指向栈顶元素，栈装满时 top 指到最后一个下标 MaxSize-1，再进就溢出了。判满过了，S.data[++S.top] = elem，注意是 ++S.top，前缀自增，先把 top 加 1、再往这个新位置放元素。

【停顿】为什么入栈是先 ++top 再放？因为 top=-1 表示空，第一个元素要放在 data[0]，所以得先把 top 从 -1 加到 0，再放 data[0]。top 指向的是栈顶元素，那要放一个新元素在它上面，自然得先移 top 再放。这个次序是 top=-1 这个约定决定的，不是随便写的。

再看 Pop，出栈。第一句判空，if top == -1 返回 false，空栈没法出。然后 elem = S.data[S.top--]，注意是 S.top--，后缀自减，先取出 data[top] 这个栈顶元素、再把 top 减 1。为什么出栈是先取再减？因为 top 正指着栈顶元素，你要的就是它，先取出来，然后 top 往下退一格，指向新的栈顶。

你把 Push 和 Pop 对着记：入栈 ++top 先移后放，出栈 top-- 先取后移。方向正好相反，都是因为 top 指向栈顶元素本身。

## P5 GetTop、判空判满、求长度（约2分钟）

剩下几个操作都由 top=-1 这个约定直接推出来，很快。

GetTop 取栈顶元素但不弹出，跟 Pop 的区别就在它不动 top：判空之后，elem = S.data[S.top]，取出来就完了，top 不变。

判空 IsEmpty，栈空就是 top == -1。判满 IsFull，栈满就是 top == MaxSize-1。求长度 GetLength，因为 top 指向栈顶元素的下标，下标从 0 开始，所以元素个数是 top + 1；空栈 top=-1，长度正好是 0。

你看，判空、判满、长度这三个式子，全是从"top 指向栈顶元素、空栈 top=-1"推出来的，不用死记，理解了约定自然就写对了。

## P6 检查页：top=0 约定五个式子怎么变（约3分钟）

这一页你先自己推，别急着看答案。刚才我们全程用 top=-1。现在换一种约定：top=0，让 top 指向栈顶元素的下一个空位，栈空的时候 top=0。请你推一推，在这个新约定下，判空、判满、入栈、出栈、求长度这五个式子分别怎么写？

【停顿】对一下答案。判空，空栈 top=0，所以是 top == 0。判满，top 指向下一个空位，装满时 top 指到 MaxSize，所以是 top == MaxSize。求长度，top 正好就是元素个数，长度 = top。入栈，top 指的是空位，直接放进去再后移，写 S.data[S.top++] = elem，先放后移。出栈，栈顶元素在 top-1，要先移再取，写 elem = S.data[--S.top]，前缀自减。

你对比一下两套约定：top=-1 时入栈是 ++top 先移后放、判满 MaxSize-1；top=0 时入栈是 top++ 先放后移、判满 MaxSize。五个式子全变了。所以做栈的题，第一件事是看清题目用的是哪种约定，或者自己先声明用哪种，然后所有式子配套着写。混用两套约定，是这里最典型的错。

## P7 队列定义与假溢出（约3分钟）

那么栈讲完了，看队列。队列是一端进、另一端出，进的那端叫队尾 rear，出的那端叫队头 front。定义也是一个数组加两个指针：typedef struct，int data[MaxSize]，int rear 和 front，起名 SqQueue。初始化 front=0、rear=0。

用数组存队列，会遇到一个麻烦，叫假溢出。你想，入队往 rear 放、rear 往后移，出队从 front 取、front 往后移。用着用着，front 和 rear 都往数组后面跑，前面出队腾出来的格子空着却用不上。等 rear 走到数组末尾 MaxSize，明明前面还有一大片空位，却没地方放了，这就叫假溢出——不是真的满了，是下标到头了。

解决办法是让下标绕回去：rear 走到末尾，就让它回到 0，接着用前面腾出的空间。这就是循环队列，实现上靠取模，rear = (rear + 1) % MaxSize，一到 MaxSize 就自动归 0。把数组想成首尾相接的一个圈，就是这个意思。

## P8 判满三策略（约5分钟）

循环队列有一个绕不过去的问题，也是本节最重要的考点：怎么判满、怎么判空。

问题的根源在这：队空的时候，front 和 rear 相等；队满的时候，绕一圈 rear 又追上 front，front 和 rear 也相等。同样是 rear == front，一个是空一个是满，光看这两个指针分不出来。这就是循环队列的核心矛盾。

有三种办法消除这个歧义，你都要会写。第一种，牺牲一单元，这是我们课程和大多数教材的默认做法：约定 rear 在 front 前面一格就算满，也就是判满写成 (rear+1) % MaxSize == front，判空还是 rear == front。代价是数组有一格永远不用，MaxSize 的数组只能存 MaxSize-1 个。第二种，加一个 size 字段记元素个数：判空 size==0，判满 size==MaxSize，这样就不靠 front、rear 判空满了，代价是每次入队出队都要维护 size。第三种，加一个 tag 标志位：只有入队让 rear 追上 front 时把 tag 置 1，出队让 front 追上 rear 时把 tag 置 0，判满就是 front==rear 且 tag==1，判空是 front==rear 且 tag==0，代价是多一个字段、多两处维护。

这三种是填空题的常考点，题目会问你某种约定下判满怎么写，或者给你一个结构体问它能存多少个。你要能一眼认出它用的是哪种策略。我们课程统一用第一种牺牲一单元，因为它最简单、不用加字段。

## P9 过程页：循环队列走一圈（约5分钟）

这一页你拿纸跟着画，PPT一步步放。我们拿一个 MaxSize=5 的循环队列，用牺牲一单元法，所以它实际最多存 4 个。

第一步，初始 front=rear=0，队空。你画一个 0 到 4 共五格的数组，front 和 rear 都指在 0。

第二步，依次入队 a、b、c、d。每入一个，放在 data[rear]，rear 再 (rear+1)%5。放 a 时 rear=0，放完 rear=1；放 b，rear=2；放 c，rear=3；放 d，rear=4。现在 a、b、c、d 占着下标 0、1、2、3，rear=4。判满看一下，(rear+1)%5 = (4+1)%5 = 0，正好等于 front=0，满了。你注意，下标 4 那一格还空着，但因为牺牲一单元，它不能再用，这就是被牺牲掉的那一格。

第三步，出队 a、b。每出一个，取 data[front]，front 再 (front+1)%5。出 a，front 从 0 到 1；出 b，front 从 1 到 2。现在队里剩 c、d，front=2、rear=4。再判满，(rear+1)%5=0，不等于 front=2，不满了，又能入队了。

第四步，再入队 e。放进 data[rear=4]，然后 rear=(4+1)%5=0，绕回开头。现在 front=2、rear=0，队里是 c、d、e。

【停顿】你刚才亲眼看到三件事：rear 从 4 绕回了 0，这就是循环；(rear+1)%5==front 的时候明明还空一格却判满，那格就是牺牲的一单元；front 一直追 rear，追上（rear==front）就是队空。这三件事把循环队列的判空判满讲全了。

## P10 EnQueue 与 DeQueue（约3分钟）

有了前面的铺垫，入队出队的代码就顺了。

EnQueue 入队：第一句判满，if (rear+1) % MaxSize == front 返回 false，这就是牺牲一单元的判满式。判满过了，Q.data[Q.rear] = elem，先放在 rear 指的格子；然后 Q.rear = (Q.rear + 1) % MaxSize，rear 后移一格并取模。注意顺序是先放再移，因为 rear 指的是下一个空位。

DeQueue 出队：第一句判空，if rear == front 返回 false。然后 elem = Q.data[Q.front]，先取出 front 指的队头元素；再 Q.front = (Q.front + 1) % MaxSize，front 后移取模。也是先取再移，因为 front 指的是队头元素本身。

你把入队和出队对着记：入队 rear 指空位、先放再移；出队 front 指队头、先取再移。两个移动都要 % MaxSize，不然绕不回去。还有个 GetLength，长度 = (rear - front + MaxSize) % MaxSize，为什么要 +MaxSize？因为 rear 可能绕到了 front 前面，rear-front 是负数，加一个 MaxSize 再取模就修正过来了。

## P11 链栈与链队（约2分钟）

栈和队列也能用链表实现，这一页带过。

链栈用单链表，把栈顶放在表头：入栈就是在表头插入一个结点，等于头插法；出栈就是删掉第一个结点。链栈有一个好处，它不需要判满，因为结点是 malloc 出来的，只要内存够就能一直压；它只需要判空，L->next == NULL 就是空栈。这一点和顺序栈不同，顺序栈要判满。

链队用链表做队列，要 front 和 rear 两个指针：front 指队头负责出队，rear 指队尾负责入队，入队在 rear 后面接、出队从 front 删。为什么要两个指针？因为如果只有 front，每次入队都得从头走到尾找队尾，太慢；有了 rear，入队直接 O(1)。链栈链队 802 考得不多，你理解"栈顶在表头、入栈即头插、链栈不判满"就够了。

## P12 栈与递归（约2分钟）

最后说一下栈和递归的关系，把这一节和前面串起来。

C 语言强化阶段我们画过 fact(3) 的调用栈，fact(3) 调 fact(2)、fact(2) 调 fact(1)，一层层压进去，到 fact(1) 返回了，再一层层弹出来。那个栈是系统自动帮你管理的，你写递归，系统在背后用一个栈记录每层调用。

这一节讲的是你自己手动用一个栈。这两件事是相通的：后面讲二叉树的非递归遍历，本质就是把递归时系统帮你管的那个栈，搬到代码里自己用显式的栈来管。所以栈是强化阶段大量算法的工具，括号匹配、表达式求值、非递归遍历都靠它；队列是另一类工具，层序遍历、广度优先搜索、拓扑排序都要用队列来排队。这两个结构你现在写熟了，后面算法阶段会反复用到。

## P13 小结（约2分钟）

这一节收一下。

顺序栈，top=-1 约定下：入栈 data[++top]、出栈 data[top--]、判空 top==-1、判满 top==MaxSize-1、长度 top+1。这五个式子全由 top=-1 推出来。换成 top=0 约定，五个式子全变，两套不能混用。

循环队列，牺牲一单元：判空 rear==front、判满 (rear+1)%MaxSize==front、长度 (rear-front+MaxSize)%MaxSize。判满三策略——牺牲一单元、加 size、加 tag——是填空常考点，根源都是 rear==front 分不清空和满。

链栈入栈即头插、不判满只判空；链队要 front 和 rear 两个指针。栈和队列是强化阶段算法的工具。

这一节你把 top 约定和循环队列判满这两处吃透，就抓住了它全部的考点。

## 附录一：课后题参考答案

跟练题：默写 SqStack、SqQueue 定义与全部基本操作，并写出判满三策略。

```c
#define MaxSize 100
typedef struct{ int data[MaxSize]; int top; }SqStack;
bool InitStack(SqStack &S){ S.top = -1; return true; }
bool Push(SqStack &S, int elem){ if(S.top==MaxSize-1) return false; S.data[++S.top]=elem; return true; }
bool Pop(SqStack &S, int &elem){ if(S.top==-1) return false; elem=S.data[S.top--]; return true; }
bool GetTop(SqStack S, int &elem){ if(S.top==-1) return false; elem=S.data[S.top]; return true; }
// 判空 top==-1；判满 top==MaxSize-1；长度 top+1

typedef struct{ int data[MaxSize]; int rear, front; }SqQueue;
bool InitQueue(SqQueue &Q){ Q.front=0; Q.rear=0; return true; }
bool EnQueue(SqQueue &Q, int elem){ if((Q.rear+1)%MaxSize==Q.front) return false;
    Q.data[Q.rear]=elem; Q.rear=(Q.rear+1)%MaxSize; return true; }
bool DeQueue(SqQueue &Q, int &elem){ if(Q.rear==Q.front) return false;
    elem=Q.data[Q.front]; Q.front=(Q.front+1)%MaxSize; return true; }
// 判空 rear==front；判满 (rear+1)%MaxSize==front；长度 (rear-front+MaxSize)%MaxSize
// 判满三策略：牺牲一单元 (rear+1)%MaxSize==front；加size size==MaxSize；加tag front==rear且tag==1
```

模仿题（3算15 同类）：循环队列牺牲一单元、MaxSize=6，front=1、rear=0。

- 元素个数 = (rear-front+MaxSize)%MaxSize = (0-1+6)%6 = 5，队里有 5 个元素。
- 判满：(rear+1)%MaxSize = (0+1)%6 = 1 == front，成立，队已满（牺牲一单元最多存 5 个）。
- 已满，再入队 EnQueue 返回 false，front、rear 不变，仍是 front=1、rear=0。

## 附录二：本节代码合集

顺序栈与循环队列，均用 `知识笔记/代码总结.md` 批次一修正后的版本（数组存储、判满 top==MaxSize-1）。

```c
// 顺序栈（top=-1）
#define MaxSize 100
typedef struct{ int data[MaxSize]; int top; }SqStack;
bool InitStack(SqStack &S){ S.top = -1; return true; }
bool IsEmpty(SqStack S){ return S.top == -1; }
bool IsFull (SqStack S){ return S.top == MaxSize - 1; }
int  GetLength(SqStack S){ return S.top + 1; }
bool Push(SqStack &S, int elem){ if(S.top==MaxSize-1) return false; S.data[++S.top]=elem; return true; }
bool Pop (SqStack &S, int &elem){ if(S.top==-1) return false; elem=S.data[S.top--]; return true; }
bool GetTop(SqStack S, int &elem){ if(S.top==-1) return false; elem=S.data[S.top]; return true; }

// 循环队列（牺牲一单元）
typedef struct{ int data[MaxSize]; int rear, front; }SqQueue;
bool InitQueue(SqQueue &Q){ Q.front=0; Q.rear=0; return true; }
bool IsEmpty(SqQueue Q){ return Q.rear == Q.front; }
bool IsFull (SqQueue Q){ return (Q.rear+1)%MaxSize == Q.front; }
int  GetLength(SqQueue Q){ return (Q.rear-Q.front+MaxSize)%MaxSize; }
bool EnQueue(SqQueue &Q, int elem){ if((Q.rear+1)%MaxSize==Q.front) return false;
    Q.data[Q.rear]=elem; Q.rear=(Q.rear+1)%MaxSize; return true; }
bool DeQueue(SqQueue &Q, int &elem){ if(Q.rear==Q.front) return false;
    elem=Q.data[Q.front]; Q.front=(Q.front+1)%MaxSize; return true; }
```
