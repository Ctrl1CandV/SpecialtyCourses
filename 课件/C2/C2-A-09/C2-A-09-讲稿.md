## P2 引题：一张图两种存法（约3分钟）

那么先建立一个整体认识。图和我们前面学的结构比，复杂在哪？线性表是一对一，树是一对多，图是多对多——任意两个顶点之间都可能有关系，还可能有环。这么复杂的关系，计算机里怎么存？

主流有两种办法。第一种邻接矩阵，用一个二维数组，行和列都是顶点，edge[i][j] 这个格子记顶点 i 和 j 之间有没有边。第二种邻接表，用一个顶点表加边表，每个顶点挂一条链，链上记着它连向哪些顶点。

这两种存法各有优劣，一种费空间但查两点之间有没有边快，一种省空间但查起来要顺链走。这一节我们把两种都讲清楚，你知道各自存了什么、什么时候用哪个。

再说一句分量：图是 802 三大重点章之一，2020 到 2026 考了 5 道大题。所有的图算法，最小生成树、最短路径、拓扑排序，全都建立在这两件事上——图怎么存、图怎么走。这一节就是把这两件事讲透，后续所有图算法都是在它上面加东西。

## P3 邻接矩阵（约4分钟）

先看邻接矩阵。定义 MGraph：一个 char 数组 vex 存顶点信息，一个二维 int 数组 edge 就是邻接矩阵，再加 vexnum 顶点数、arcnum 边数。

edge[i][j] 存什么？无权图里，存 1 表示顶点 i 到 j 有边，存 0 表示没边。

【停顿】这里有个要理解的点：无向图的邻接矩阵是对称的，也就是 edge[i][j] 一定等于 edge[j][i]。为什么？因为无向图的边没有方向，i 和 j 之间有一条边，就是 i 连 j、也是 j 连 i，所以两个格子同时为 1。而有向图就不对称了，edge[i][j]=1 表示一条从 i 指向 j 的弧，它不等于 edge[j][i]。

带权图怎么办？把那个 1 换成权值，也就是边的权重。那不可达的位置，就是两个顶点之间没有边，存什么？存一个很大的数 INF，表示"无穷大、走不通"。为什么不用 0？因为权值 0 可能是一条真实的、权重为 0 的边，用 0 表示不可达会和它混淆，所以用一个足够大的 INF。这个 INF 在求最短路径、最小生成树时到处要用，你先有个印象。

邻接矩阵的空间是 O(n²)，n 是顶点数。不管图里有多少条边，它都要开 n 乘 n 个格子。所以边很少的稀疏图，用邻接矩阵会浪费一大片 0。

## P4 邻接表（约4分钟）

邻接矩阵稀疏图浪费空间，邻接表就是来解决这个的。它只存真实存在的边。

看定义，分两部分。第一部分是边表结点 ArcNode：adjvex 记这条边连到哪个顶点，weight 是带权时用的权值，nextarc 指向下一条边。第二部分是顶点表 VNode：data 存顶点信息，firstarc 指向这个顶点的第一条边。所有顶点表组成一个数组 AdjList，再包一层 ALGraph 记顶点数边数。

说白了，邻接表就是：每个顶点挂一条单链表，链上每个结点记着"我连向哪个顶点"。顶点 0 连向 1、2，那 0 的边表就是 1、2 两个结点串起来。

它为什么省空间？因为它只存实际有的边。一条边对应一个边表结点，无向图每条边在两个顶点的边表里各出现一次，所以边表结点一共 2e 个，加上 n 个顶点表，空间是 O(n+e)。稀疏图 e 远小于 n²，这就比邻接矩阵省多了。

这里的 weight 字段，材料里原本是注释掉的，我们把它放出来，因为带权图求最小生成树要用到边的权值，现在放出来，代码才自洽。

有向图的邻接表要注意：一个顶点的边表，存的是从它出发的出边。所以顺着边表能查到它的出度，但要查它的入度，就得看有多少条边指向它，这些边分散在别的顶点的边表里，得遍历所有顶点才数得出来。这就引出下一页的求入度。

## P6 求所有顶点的入度（约4分钟）

看一个邻接表的典型应用，求所有顶点的入度。这个动作是 2026 年拓扑排序真题的第一步，很重要。

看代码 Indegree，参数是图 G 和一个 indeg 数组，用来存每个顶点的入度。第一段，先把 indeg 全部清零，因为要在上面累加。第二段是双层循环：外层遍历每一个顶点 i，内层顺着顶点 i 的边表走，边表里每个结点的 adjvex 就是 i 指向的那个顶点，那个顶点的入度加一。

【停顿】这里要理解一个点：为什么求入度必须遍历所有顶点的边表，不能只看一个顶点？因为入度是"有多少条边指向它"，而这些指向它的边，是分散在各个顶点的边表里的。你看顶点 j 自己的边表，只能看到 j 指向谁，也就是 j 的出度；要知道谁指向 j，必须把每个顶点的边表都扫一遍，看谁的边表里出现了 j。所以这个双层循环，外层遍历所有顶点、内层遍历它的边表，每遇到一条边就给它的终点入度加一，扫完所有边，每个顶点的入度就都数出来了。

这个求入度是拓扑排序的准备工作，拓扑排序的第一步就是它，你现在把 Indegree 写熟。

## P7 图的遍历为什么需要 visited（约3分钟）

那么图存好了，接下来是怎么走，也就是遍历。图的遍历有两种，DFS 深度优先和 BFS 广度优先，思路和树的遍历相通，但图多了一个必须处理的东西——visited 标记。

为什么图必须用 visited，树却不用？因为树没有环，你从根往下走，走到底自然就结束了，不会重复访问。但图有环，还可能多对多，你要是不标记哪些顶点访问过了，就会顺着环绕圈、重复访问同一个顶点，甚至无限循环下去。

所以用一个 visited 数组，visited[i] 记顶点 i 访问过没有。遍历到一个顶点，先看它 visited 是不是 true，是就跳过，不是才访问它、并把它标记成 true。这样每个顶点最多访问一次，不会绕圈。

这里有个坑要提前说：visited 通常写成全局数组。全局数组的问题是，它的值在一次遍历结束后不会自动清掉。所以如果你要对同一张图做多遍遍历，或者写一个完整的遍历函数，必须在开始之前把 visited 全部复位成 false，否则上一遍的标记还留着，这一遍就会漏掉顶点。这个复位后面 Traverse 函数里会看到。

## P8 DFS 深度优先（约4分钟）

先看 DFS，深度优先搜索。它的思路是尽量往深里走：从起点出发，走到一个邻居，再从那个邻居继续往深走，走到没有没访问过的邻居了，再回头换一条路。这个"一路深入、走不通再回退"，天然就是递归。

看代码 DFS，参数是图 G 和当前顶点 v。第一句 visit(v) 访问 v，紧接着 visited[v]=true 标记它访问过了。然后一个 for 循环，顺着 v 的边表走，p 从 firstarc 开始、每次 p=p->nextarc，对每个邻居 p->adjvex，如果它还没访问过 !visited，就递归 DFS 进去。

【停顿】这里有两个要点你要注意。第一，visit 和标记的次序，是先 visit(v) 再 visited[v]=true。这个次序本身影响不大，但两个都得有，漏了标记就会重复访问。第二，也是更关键的，递归进去之前必须判 !visited[p->adjvex]，只递归没访问过的邻居。如果不判就直接递归，遇到有环的图，它会顺着环无限递归下去，栈溢出。所以这个 !visited 的判断是 DFS 不死循环的保证，绝对不能漏。

DFS 的递归版和树的先序遍历递归结构很像，都是"访问自己、再递归孩子"，只不过图要先判 visited。你把这个类比记住，DFS 就不难写。

## P9 BFS 广度优先（约4分钟）

再看 BFS，广度优先搜索。它的思路是一层一层扩：先访问起点，再访问起点的所有邻居，再访问邻居的邻居，一层层往外扩。这个"按层、先进先出"的顺序，天然要用队列，和上一节层序遍历用队列是一个道理。

看代码 BFS。开头 visit(v)、标记 visited[v]=true、把 v 入队。然后 while 队列不空：出队一个顶点 v，顺着 v 的边表遍历它的每个邻居，对没访问过的邻居，访问它、标记它、把它入队。

这里队列里存的是顶点的编号，是个 int，不是别的，这就是约定4——当队列当工具用时，里面存的元素类型按需要定，这里存顶点编号。

【停顿】现在讲本节最重要的一个设问：BFS 里，为什么是在入队的时候就标记 visited，而不是等出队的时候再标记？你想一下，如果出队时才标记会怎样？一个顶点 k，它可能同时是好几个已入队顶点的邻居。如果入队时不标记，那么这几个顶点出队时，都会发现 k 还没被标记，就会把 k 重复入队好几次。结果 k 会被 visit 输出好几遍，队列里也塞了一堆重复的 k，又浪费又出错。而在入队时就标记，k 第一次被发现就标记上，后面别的顶点再看 k 已经是 visited，就不会重复入队。所以入队时标记，保证每个顶点最多入队一次。这个点是 BFS 最容易错、也最爱考的地方，你务必理解透。

## P10 过程页：同一张图 DFS 与 BFS 对比（约5分钟）

这一页你拿纸跟着画，我们在同一张图上把 DFS 和 BFS 各走一遍，对比两个序列。

图是这样：5 个顶点 0、1、2、3、4，边有 5 条，0-1、0-2、1-3、2-4、3-4。邻接表里每个顶点的邻居按顶点号从小到大排。你先把这张图画出来。

先走 DFS，从 0 开始。访问 0，标记 0。0 的邻居是 1、2，先看 1，没访问过，递归进 1。访问 1，标记 1。1 的邻居是 0、3，0 访问过了，看 3，没访问过，进 3。访问 3，标记 3。3 的邻居是 1、4，1 访问过，看 4，进 4。访问 4，标记 4。4 的邻居按升序是 2、3，先看 2，没访问过，进 2。访问 2，标记 2。2 的邻居 0、4 都访问过了，回退到 4；4 的下一个邻居 3 也访问过了，继续回退。一路退回来，所有顶点都访问完了。DFS 序列是 0 1 3 4 2。你看，它是一路往深走：0→1→3→4→2。

再走 BFS，从 0 开始。访问 0、标记、入队，队列是 [0]。出队 0，看 0 的邻居 1、2，都没访问过，访问 1、标记、入队，访问 2、标记、入队，队列是 [1,2]。出队 1，看 1 的邻居 0、3，0 访问过，3 没有，访问 3、标记、入队，队列 [2,3]。出队 2，邻居 0、4，0 访问过，4 没有，访问 4、标记、入队，队列 [3,4]。出队 3，邻居 1、4 都访问过。出队 4，邻居都访问过。队列空，结束。BFS 序列是 0 1 2 3 4。你看，它是一层层扩：先 0，再 0 的邻居 1、2，再下一层 3、4。

【停顿】同一张图，DFS 得 0 1 3 4 2，BFS 得 0 1 2 3 4，完全不同。DFS 深、BFS 广。你把 visited 数组和队列的状态在纸上一步步标出来，这两种走法的差别就看得清清楚楚。这个"给一张图写出 DFS、BFS 序列"是选择题、画图题的常考形态，你多练几张图就熟了。

## P11 非连通图的 Traverse（约3分钟）

刚才的 DFS、BFS 都是从一个顶点出发，那只能走遍它所在的那个连通分量。如果图是非连通的，有好几个分开的部分，从一个顶点走不到所有顶点，怎么办？这就要外面再套一层，叫 Traverse。

看代码 DFS_Traverse。第一段，一个 for 循环把 visited 全部复位成 false，这就是上一页说的那个复位，因为 visited 是全局数组，得先清干净。第二段，又一个 for 循环，遍历每个顶点 i，如果 i 还没被访问过 !visited[i]，就从 i 启动一次 DFS。

【停顿】为什么要外套这一层 for？因为非连通图有多个连通分量，从一个顶点出发只能走遍它自己那个分量。你从顶点 0 走一遍，走完 0 所在的分量；然后 for 继续往后找，遇到第一个还没访问过的顶点，它一定属于另一个还没走过的分量，从它再启动一次 DFS，走完那个分量。这样每个分量都从一个顶点走一次，才能把整张非连通图走遍。

还有一个容易错的点：那个复位。如果你写一个函数要多次遍历，或者第一次遍历完再调第二次，visited 里全是上次留下的 true，第二次就会以为所有顶点都访问过了，一个都不走，结果全错。所以每次完整遍历前，第一件事是把 visited 复位。BFS 的 Traverse 也是一样的结构，先复位、再外套一层 for 启动 BFS。

## P12 两种存储下的复杂度（约2分钟）

遍历的复杂度，跟用哪种存储直接相关，我们对比一下。

先说时间。邻接矩阵下，DFS 和 BFS 都是 O(n²)。为什么？因为在矩阵里，要找某个顶点的所有邻居，你得扫它那一整行，一行有 n 个格子，逐个看是不是 1。每个顶点都要扫一整行 n 个，n 个顶点就是 n 乘 n，O(n²)。而邻接表下是 O(n+e)，因为你顺着边表走，只访问真实存在的边，n 个顶点加 e 条边各走一次，就是 O(n+e)。

再说空间。两种存储下，遍历本身用的辅助空间都是 O(n)，就是 visited 数组，加上 DFS 的递归栈或 BFS 的队列，最多 O(n)。

还有一个是存储本身占的空间：邻接矩阵是 O(n²)，邻接表是 O(n+e)。所以你记住这个选择：稀疏图，边少，用邻接表省空间、遍历也快（O(n+e)）；稠密图，边多接近 n²，用邻接矩阵，查两点之间有没有边是 O(1)，而且矩阵实现简单。

## P13 生成树与生成森林（约2分钟）

遍历的时候，你走过的边会连成一棵树，这叫生成树。

具体说，对一个连通图做遍历，从起点出发，每访问一个新顶点，都是顺着某条边走过去的，把这些"走过的边"收集起来，正好构成一棵树，包含图的所有顶点。用 DFS 走出来的叫 DFS 生成树，用 BFS 走出来的叫 BFS 生成树。

如果图是非连通的，那遍历完每个连通分量各得到一棵生成树，这些树合起来叫生成森林。

有两个点你记一下：生成树的边数一定是顶点数减一，因为 n 个结点的树有 n-1 条边；还有，同一张图，DFS 和 BFS 生成的树通常不一样，因为走法不同、经过的边就不同。求生成树是画图题的常考点，你按遍历的走法，把经过的边画出来，就是那棵生成树。

## P14 并查集（约2分钟）

最后介绍一个工具，并查集，这一节先认个脸，讲最小生成树的时候正式用。

并查集是干嘛的？它维护一堆不相交的集合，支持两个操作：查一个元素属于哪个集合，以及把两个集合合并。它的实现很巧，用一个数组 parent，parent[i] 记 i 的父结点，每个集合是一棵树，根结点的 parent 指向它自己。

两个操作：Find，找一个元素所在集合的代表，就是顺着 parent 一路往上走，走到根（parent 指向自己的那个）；Union，合并两个集合，就是把一棵树的根，接到另一棵树的根下面。

它有什么用？在图里，并查集常用来判断两个顶点是不是已经在同一个连通块里。强化阶段讲 Kruskal 最小生成树，每要加一条边，就用并查集查这条边的两个端点是不是已经连通，如果已经连通，再加就会成环，这条边就不能要。所以并查集是 Kruskal 判环的核心工具。这一节你先理解它的结构和两个操作，代码我们到强化阶段再展开。

## P15 小结与课后任务（约2分钟）

这一节收一下，也是数据结构基础阶段的收尾。

图的两种存储：邻接矩阵用二维数组，O(n²)，适合稠密图，无向图对称、带权不可达存 INF；邻接表用顶点表加边表，O(n+e)，适合稀疏图。求入度要遍历所有顶点的边表，这是拓扑排序的第一步。

图的两种遍历：DFS 递归、一路往深走到底再回退，递归前判 !visited 防环；BFS 用队列、一层层扩，入队时就标记 visited，队列存顶点编号。非连通图外套一层 Traverse，先复位 visited、再从每个未访问顶点各启动一次。复杂度矩阵 O(n²)、邻接表 O(n+e)。遍历走过的边构成生成树或生成森林。

图是三大重点章之一，这一节的存储和遍历是后面所有图算法的地基，你务必写熟。

## 附录一：课后题参考答案

跟练题：默写邻接表定义、DFS、BFS、Indegree；5顶点图写存储与遍历序列。

```c
typedef struct ArcNode{ int adjvex; int weight; struct ArcNode *nextarc; }ArcNode;
typedef struct VNode{ VertexType data; ArcNode *firstarc; }VNode, AdjList[MaxVertexNum];
typedef struct{ AdjList vertices; int vexnum, arcnum; int kind; }ALGraph;

bool visited[MaxVertexNum];
void DFS(ALGraph G, int v){
    visit(v); visited[v] = true;
    for(ArcNode *p = G.vertices[v].firstarc; p != NULL; p = p->nextarc)
        if(!visited[p->adjvex]) DFS(G, p->adjvex);
}
void BFS(ALGraph G, int v){
    visit(v); visited[v] = true; EnQueue(Q, v);
    while(!IsEmpty(Q)){
        DeQueue(Q, v);
        for(ArcNode *p = G.vertices[v].firstarc; p != NULL; p = p->nextarc)
            if(!visited[p->adjvex]){ visit(p->adjvex); visited[p->adjvex]=true; EnQueue(Q, p->adjvex); }
    }
}
void Indegree(ALGraph G, int indeg[]){
    for(int i = 0; i < G.vexnum; i++) indeg[i] = 0;
    for(int i = 0; i < G.vexnum; i++)
        for(ArcNode *p = G.vertices[i].firstarc; p != NULL; p = p->nextarc)
            indeg[p->adjvex]++;
}
```

5顶点图（边 0-1、0-2、1-3、2-4、3-4）从0出发：DFS = 0 1 3 4 2，BFS = 0 1 2 3 4。邻接矩阵对称，edge[0][1]=edge[0][2]=edge[1][3]=edge[2][4]=edge[3][4]=1 及其对称位置，其余为 0。

模仿题（7选21、7选22 同类）：判断合法的 DFS/BFS 序列。

- 拿遍历规则去卡每个选项：照着 DFS（一路深入、走不通回退）或 BFS（按层扩、队列先进先出）模拟一遍。
- DFS 合法关键：每步要么走到未访问的邻居、要么回退，不能凭空跳到不相邻的未访问顶点。
- BFS 合法关键：先访问顶点的邻居要先出队，不能乱序。
- 邻接表里邻居顺序会影响具体序列，合法序列可能不止一个。

## 附录二：本节代码合集

图的存储与遍历，均用 `知识笔记/代码总结.md`，字段名按课件统一，weight 字段按勘误放出。

```c
#define MaxVertexNum 100
typedef struct{ char vex[MaxVertexNum]; int edge[MaxVertexNum][MaxVertexNum]; int vexnum, arcnum; }MGraph;  // 邻接矩阵

void DFS_Traverse(ALGraph G){                 // 非连通图 DFS
    for(int i = 0; i < G.vexnum; i++) visited[i] = false;   // 先复位
    for(int i = 0; i < G.vexnum; i++) if(!visited[i]) DFS(G, i);
}
// 复杂度：邻接矩阵 DFS/BFS 时间 O(n²)、邻接表 O(n+e)；辅助空间都是 O(n)
// 邻接表转矩阵：外层遍历顶点 i、内层遍历边表，A[i][p->adjvex]=1；无向图再对称写 A[p->adjvex][i]=1
```
