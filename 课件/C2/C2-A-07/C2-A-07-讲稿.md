## P2 引题：二叉树为什么不用数组存（约2分钟）

那么先想一个问题。上一节数组我们讲得很熟，二叉树能不能也用数组存？

答案是：特殊的能，一般的不能。完全二叉树和满二叉树可以用数组存，因为它们的形态是规整的，结点 i 的左孩子固定在 2i、右孩子固定在 2i+1，一个空位都不浪费。但一般的二叉树形态千奇百怪，可能是一棵斜树，也可能缺枝少叶，你要是硬用数组按完全二叉树的下标去存，中间就得补一大堆空位，浪费得厉害。

所以一般二叉树用链式存储：每个结点带上两根指针，一根指左孩子、一根指右孩子，这就是二叉链表。它不要求形态规整，有多少结点就 malloc 多少，孩子没有就指 NULL。这一节我们就用二叉链表来讲遍历。

先把话说在前头，遍历为什么这么重要？因为后面强化阶段那些树的算法，求高度、数结点、找路径、判断平衡，全都建立在"能把这棵树走一遍"这个动作上。遍历就是那个最基础的"走一遍"。这一节把四种遍历方式讲到位，后面就都是在遍历上做文章。

## P3 二叉链表与孩子兄弟链表（约3分钟）

看两种链式存储的定义。

第一个是二叉链表，typedef struct BiTNode，里面一个 data 存数据，两个指针 lchild 和 rchild 分别指左孩子和右孩子。起两个名字，BiTNode 是一个结点，BiTree 是指向结点的指针、代表一棵树。你以后看到 BiTree T，就知道 T 是指向这棵树根结点的指针，T 为 NULL 就是空树。

第二个是孩子兄弟链表，typedef struct CSNode，一个 data，两个指针 firstchild 和 nextbro，分别指第一个孩子和下一个兄弟。这个结构是用来把一般的树（不是二叉树，是每个孩子可以有任意多个的那种树）存成二叉树形式的。它的用法我们下一节讲树和森林的时候展开，这一节你先认得这个定义、知道它是干嘛的就行，不展开。

这里 data 的类型写成 ElemType，是个占位的类型名，代表"元素类型"。这就是约定4：当树里存的是整数，ElemType 就是 int；存别的就换成别的，遍历的逻辑一点不变。

## P4 三种递归遍历（约4分钟）

那么进入本节的核心，遍历。先看三种递归遍历，我特意把它们放在一页上，你一眼就能看出规律。

先序遍历 PreOrder，顺序是根、左、右：如果 T 是空就返回，否则先 visit(T) 访问根，再递归遍历左子树 PreOrder(T->lchild)，再递归遍历右子树 PreOrder(T->rchild)。

中序遍历 InOrder，顺序是左、根、右：空的判断一样，然后先递归左子树，再 visit(T) 访问根，再递归右子树。

后序遍历 PostOrder，顺序是左、右、根：先递归左子树，再递归右子树，最后 visit(T) 访问根。

【停顿】你把三个函数对着看，会发现它们的框架一模一样：都是判空返回、都是两次递归调用加一次 visit，唯一的区别就是 visit(T) 这一句放在哪。放最前面是先序，放中间是中序，放最后是后序。所以三种遍历不是三件事，是同一件事的三个变体，区别只在访问根的时机。这个认识很重要，强化阶段讲递归算法的时候还会直接用到它。

这里 visit(T) 是个抽象动作，代表"访问这个结点"，具体是打印 data 还是别的，看题目。三种遍历的时间复杂度都是 O(n)，每个结点访问一次；空间是 O(树高)，因为递归要用栈，栈的深度等于树的高度，最坏情况单支树是 O(n)。

## P5 检查页：三种序列先自己写（约5分钟）

这一页你先自己写，别急着看答案。屏幕上这棵树你拿纸画下来：根是 1，1 的左孩子是 2、右孩子是 3，2 的左孩子是 4、右孩子是 5，3 没有孩子。一共五个结点。

请你写出它的先序、中序、后序、层序四个序列。

【停顿】对一下答案。先序是根左右，先访问根 1，再遍历左子树（2、4、5 的先序是 2 4 5），再遍历右子树 3，所以先序是 1 2 4 5 3。中序是左根右，先左子树（4 2 5），再根 1，再右子树 3，所以中序是 4 2 5 1 3。后序是左右根，先左子树（4 5 2），再右子树 3，再根 1，所以后序是 4 5 2 3 1。层序是一层一层，第一层 1，第二层 2 3，第三层 4 5，所以层序是 1 2 3 4 5。

你写的时候有没有发现一个窍门？递归地看，每个子树的序列都是"按同样的规则再走一遍"。比如求整棵树的中序，就是左子树中序、根、右子树中序拼起来；而左子树 2、4、5 的中序，又是 4、2、5。这种"大问题拆成同样的小问题"就是递归，也是遍历的本质。这棵树我们后面还要用，你先把它和这四个序列记在纸上。

## P6 递归遍历的调用栈展开（约3分钟）

刚才说递归遍历，那它在系统里到底是怎么跑的？我们把它在调用栈里的展开看一下，这跟非递归遍历直接相关。

以中序 InOrder(1) 为例。它第一步是调 InOrder(左孩子2)，于是 InOrder(2) 压栈；InOrder(2) 第一步又调 InOrder(它的左孩子4)，InOrder(4) 压栈；InOrder(4) 调 InOrder(4的左孩子)，4 没有左孩子，是 NULL，直接返回。这时候才轮到 visit(4)，访问 4；然后调 InOrder(4的右孩子)，也是 NULL，返回。InOrder(4) 结束，弹栈，回到 InOrder(2)。

回到 InOrder(2)，它左子树处理完了，接着 visit(2)，访问 2；再调 InOrder(2的右孩子5)……你看，这个过程是"一路往左压栈，压到底了（遇到 NULL）才开始回退、访问、再转向右子树"。

这个"一路往左压、到底再回退访问"的路线，就是非递归中序要用一个显式的栈去模拟的东西。你把这个调用栈的展开想清楚了，后面非递归中序的代码就不难懂。C 语言强化阶段我们画过函数调用的栈，这里是同一个机制用在树遍历上。

## P7 非递归先序（约4分钟）

那么递归靠系统栈，非递归就是我们自己拿一个栈来模拟。先看非递归先序。

看代码 PreOrder2。先判空，然后准备一个栈 s，这里栈里存的是结点指针 BiTree，不是 int，这就是约定4，答题时要说明一句。把根 T 压进栈，然后循环：只要栈不空，就弹出一个结点 p、立刻 visit(p) 访问它，然后把它的右孩子和左孩子依次压栈。

【停顿】这里有个关键点：为什么先压右孩子、再压左孩子？因为栈是后进先出，你先压右、后压左，那么左孩子在栈顶，会先被弹出来访问。弹出顺序就成了根、左、右，正好是先序。你要是先压左再压右，弹出的就是根、右、左，错了。所以"先压右再压左"是为了让左先出，这个次序要记牢。

非递归先序相对简单，因为它是"弹出即访问"，访问的时机就在弹出那一刻。中序和后序要复杂些，因为访问的时机不在弹出的第一时间。

## P8 非递归中序（约4分钟）

非递归中序是本节最重要、也最容易错的一段，我们仔细看。

看代码 InOrder2。判空之后准备栈 s，用一个指针 p 从根 T 开始。外层循环的条件是 !IsEmpty(s) || p != NULL，注意是两个条件用"或"连起来，缺一不可，等下解释。循环体里，内层先有一个 while(p != NULL)，一路把 p 压栈、p 往左孩子走，直到 p 为 NULL，也就是把从当前结点往左的一整条链全压进栈。压到底之后，如果栈不空，弹出一个结点 p、visit(p) 访问它，然后 p 转向它的右孩子 p->rchild。

这段代码在模拟什么？就是刚才 P6 那个调用栈的展开。内层 while"一路压左到底"，对应递归里一路往左调；弹出访问、转向右孩子，对应递归里左子树返回后访问根、再进右子树。

【停顿】再说外层那个双条件为什么要两个。如果只写 !IsEmpty(s)，会出什么问题？考虑一个结点的右子树还没处理，但栈这时候空了，如果只看栈空就退出循环，右子树就漏了。反过来，如果只写 p != NULL，当 p 走到 NULL、但栈里还压着没回退访问的结点时，只看 p 空就退出，那些结点也漏了。所以要"栈非空 或 p 非空"，两个条件只要有一个成立就得继续：p 非空说明还有左链要压，栈非空说明还有结点要回退访问。

## P9 过程页：非递归中序的栈变化（约5分钟）

这一页你拿纸跟着画，我们把 P5 那棵树用非递归中序走一遍，重点看栈怎么变。树还是：1 的左 2 右 3，2 的左 4 右 5。

第一步，p=1，进内层 while 一路压左：压 1，p 走到 2；压 2，p 走到 4；压 4，p 走到 4 的左孩子 NULL，停。现在栈里从底到顶是 1、2、4，p 是 NULL。

第二步，p 空了，内层 while 结束。栈不空，弹出栈顶 4，visit(4)，输出 4；p 转向 4 的右孩子，是 NULL。现在栈里是 1、2。

第三步，p 空、栈非空，外层继续。内层 while 因为 p 空不进。弹出栈顶 2，visit(2)，输出 2；p 转向 2 的右孩子 5。现在栈里是 1，输出序列是 4 2。

第四步，p=5 非空，内层 while 压 5，p 走到 5 的左孩子 NULL 停。弹出 5，visit(5)，输出 5；p 转 5 的右孩子 NULL。栈里剩 1，输出 4 2 5。

第五步，p 空、栈非空，弹出 1，visit(1)，输出 1；p 转向 1 的右孩子 3。然后 p=3，压 3、弹 3、visit(3)，输出 3。最终序列 4 2 5 1 3。

【停顿】你对一下，4 2 5 1 3，和 P5 递归中序的结果一模一样。这张图的价值在于，它把递归里那个你看不见的系统调用栈，变成了纸上这个你能一步步画的显式栈。非递归中序就是这个过程，你把它画熟，代码自然就会写了。

## P10 非递归后序（约2分钟）

非递归后序，我们用双栈逆序法，这个思路比"中序加标志位"那种写法清爽。

看代码 PostOrder2。第一句判空 if(T==NULL) return，这句材料里原本漏了，我们补上，否则空树会出问题。准备两个栈 s1 和 s2，把根压进 s1。然后循环：只要 s1 不空，从 s1 弹出一个结点 p，把它压进 s2，再把它的左孩子、右孩子依次压进 s1。等 s1 空了，再把 s2 里的结点一个个弹出、visit。

为什么这样能得到后序？我们理一下。s1 的弹出压 s2 这个过程，因为先压左再压右、弹出时右先出，所以从 s1 弹出、压进 s2 的顺序是"根、右、左"。s2 里存的就是根右左这个序列。然后从 s2 弹出，正好把它反过来，变成"左、右、根"，这就是后序。

说白了，双栈法是先用一个栈搞出后序的逆序（根右左），再用第二个栈把它逆回来（左右根）。你记住这个"逆两次"的思路，双栈后序就不会写错。

## P11 层序遍历（约2分钟）

最后是层序遍历，一层一层地访问，这次用的不是栈，是队列。

看代码 LevelOrder。判空之后准备一个队列 Q，同样里面存的是结点指针，约定4。把根入队，然后循环：只要队不空，就出队一个结点 p、visit(p)，再把它的左孩子、右孩子依次入队。

【停顿】为什么层序必须用队列、不能用栈？因为层序要的是先进先出：同一层的结点先入队的先被访问，这样才能保证一层一层地走。你想想，出队一个结点就把它的孩子入队，孩子排在队尾，等本层的结点都出队访问完了，才轮到下一层的孩子，天然就是按层的顺序。要是用栈，就变成后进先出，会一条路走到黑，那是深度优先，不是层序。

还有一个易错点：入队孩子之前要判孩子非空，if(p->lchild != NULL) 才入队。如果不判，把 NULL 也入队，等它出队的时候 visit(NULL) 就会崩。这个判空别漏。

## P12 由先序与中序建树（约4分钟）

那么遍历会了，反过来一个考点：给你遍历序列，能不能把这棵树建出来？这是 2026 年真题考的，10 分，我们重点讲。

先说结论：先序和中序两个序列，能唯一确定一棵树。为什么？先序的第一个元素一定是根（先序是根左右）；拿到根，去中序里找到它，中序是左根右，根左边的就是左子树的中序、右边的就是右子树的中序；数一下左子树有几个结点，就能把先序也切成"根、左子树先序、右子树先序"三段；然后对左右子树递归地做同样的事。

看代码 Build。参数 A 是先序数组、B 是中序数组，preL、preR 是当前子树在先序里的区间，inL、inR 是在中序里的区间。第一步，如果 preL > preR，区间空了，返回 NULL。第二步，建根结点，data 取 A[preL]，也就是先序区间的第一个。第三步，在中序里从 inL 开始找，找到等于根 A[preL] 的位置 k。第四步，算左子树结点个数 leftLen = k - inL，用它递归建左子树和右子树，注意四个区间的边界。

这里最容易错的就是边界。左子树在先序里是 preL+1 到 preL+leftLen，在中序里是 inL 到 k-1；右子树在先序里是 preL+leftLen+1 到 preR，在中序里是 k+1 到 inR。还有一个边界，判空要写 preL > preR，不能写 preL >= preR，因为 preL == preR 时区间里还有一个结点（就是叶子），写成 >= 会把它漏掉。下一页我们对着具体例子把区间走一遍。

## P13 过程页：建树的区间划分（约3分钟）

这一页你拿纸跟着标，我们用先序 1 2 4 5 3、中序 4 2 5 1 3 建这棵树，看四个下标怎么随递归缩小。

第一层，preL=0、preR=4（先序整个），inL=0、inR=4（中序整个）。根是先序第一个 A[0]=1。在中序 4 2 5 1 3 里找 1，位置 k=3。k 左边 4 2 5 是左子树的中序，3 个结点，所以 leftLen=3-0=3；k 右边 3 是右子树的中序，1 个结点。

第二层，先建左子树：先序区间是 preL+1 到 preL+leftLen，也就是 1 到 3，对应先序的 2 4 5；中序区间 inL 到 k-1，也就是 0 到 2，对应中序的 4 2 5。递归进去，根是先序第一个 2，在中序 4 2 5 里找 2，位置在中间，左边 4、右边 5，所以 2 的左孩子是 4、右孩子是 5，都是叶子。

再建右子树：先序区间 preL+leftLen+1 到 preR，也就是 4 到 4，对应先序的 3；中序区间 k+1 到 inR，4 到 4，对应中序的 3。根是 3，左右子树区间都空了（preL > preR），返回 NULL，所以 3 没有孩子。

【停顿】建出来的树，正是 P5 那棵：1 的左 2 右 3，2 的左 4 右 5。你把这四个下标 preL、preR、inL、inR 在纸上标着走一遍，就看懂区间是怎么一层层缩小的。建树的难点全在这四个边界，走一遍具体例子就通了。

## P14 小结（约2分钟）

这一节收一下。二叉树一般用二叉链表存，BiTree 是指向根的指针。

四种遍历：先序根左右、中序左根右、后序左右根、层序一层一层。递归版三个只差 visit 的位置；非递归版先序是弹出即访问、先压右再压左，中序是一路压左到底、弹出访问、转向右，后序用双栈逆序，层序用队列。时间和空间复杂度你看着表记：时间都是 O(n)，空间递归是 O(树高)、层序是队列最多一层的结点。

还有由先序和中序建树，先序定根、中序分左右、用 leftLen 切先序、递归建子树，四个下标边界是难点，2026 真题考过。

这些遍历是强化阶段所有树算法的基础，你现在把它们写熟、把栈的变化画熟，后面求高度、找路径那些就是在遍历上加几行。

## 附录一：课后题参考答案

跟练题：默写递归遍历、非递归中序、层序；先序 1 2 4 5 3 + 中序 4 2 5 1 3 建树。

```c
void PreOrder(BiTree T){ if(T==NULL) return; visit(T); PreOrder(T->lchild); PreOrder(T->rchild); }
void InOrder(BiTree T){ if(T==NULL) return; InOrder(T->lchild); visit(T); InOrder(T->rchild); }
void PostOrder(BiTree T){ if(T==NULL) return; PostOrder(T->lchild); PostOrder(T->rchild); visit(T); }

void InOrder2(BiTree T){                       // 非递归中序
    if(T==NULL) return;
    SqStack s; InitStack(s); BiTNode *p = T;
    while(!IsEmpty(s) || p != NULL){
        while(p != NULL){ Push(s, p); p = p->lchild; }
        if(!IsEmpty(s)){ Pop(s, p); visit(p); p = p->rchild; }
    }
}
void LevelOrder(BiTree T){                     // 层序
    if(T==NULL) return;
    SqQueue Q; InitQueue(Q); EnQueue(Q, T); BiTNode *p;
    while(!IsEmpty(Q)){ DeQueue(Q, p); visit(p);
        if(p->lchild) EnQueue(Q, p->lchild);
        if(p->rchild) EnQueue(Q, p->rchild); }
}
```

建树结果：根 1，左子树根 2（左 4、右 5），右子树 3（无孩子）。

模仿题（6答28 同类）：中序 + 后序建树。

- 后序的最后一个元素是根（后序是左右根）。
- 在中序里定位这个根，左边是左子树中序、右边是右子树中序。
- 用左子树结点个数把后序切成左、右两段（后序去掉最后的根，前 leftLen 个是左子树后序，剩下是右子树后序），递归建左右子树。
- 与先序+中序的唯一区别：定根的位置，先序看第一个、后序看最后一个，区间划分思路一样。

void PostOrder2(BiTree T){                     // 非递归后序（双栈逆序）
    if(T==NULL) return;
    SqStack s1, s2; InitStack(s1); InitStack(s2); BiTNode *p; Push(s1, T);
    while(!IsEmpty(s1)){ Pop(s1, p); Push(s2, p);
        if(p->lchild) Push(s1, p->lchild);
        if(p->rchild) Push(s1, p->rchild); }
    while(!IsEmpty(s2)){ Pop(s2, p); visit(p); }
}
BiTree Build(BiTree &T, int A[], int B[], int preL, int preR, int inL, int inR){
    if(preL > preR) return NULL;
    T = (BiTNode*)malloc(sizeof(BiTNode)); T->data = A[preL];
    int k = inL; while(B[k] != A[preL]) k++;
    int leftLen = k - inL;
    Build(T->lchild, A,B, preL+1, preL+leftLen, inL, k-1);
    Build(T->rchild, A,B, preL+leftLen+1, preR, k+1, inR);
