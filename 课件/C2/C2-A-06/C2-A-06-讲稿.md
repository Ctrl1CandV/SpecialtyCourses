## P3 串的三种存储与一个易错点（约3分钟）

那么先看串的存储。串有三种存储方式。第一种定长顺序存储，typedef struct，char ch[MaxSize] 是个数组，加一个 length，起名 SString。第二种堆分配存储，char 星号 ch 是个指针，要 malloc 出来，加 length，起名 String。第三种块链存储，一个结点存好几个字符，了解就行。本节讲的操作都基于堆分配这一种。

这里有一个必须记住的易错点：这两种定义不能混用。定长存储的 ch 是数组，数组名是个常量地址，你既不能对它 free，也不能给它赋 NULL。堆分配的 ch 是指针，才需要 malloc、才能 free、才能置 NULL。

怎么判断该用哪种？看代码里有没有给 ch 做 malloc 申请。凡是要 malloc 的，它的 ch 必须是指针那种定义；你要是拿着定长的数组定义去 malloc、去 free，就错了。程序阅读题爱在这里挖坑，给你一段有 malloc、free 的代码问你哪句错，往往就是混用了两种存储。

## P4 strassign：两个数字（约3分钟）

看堆分配的第一个操作 strassign，把一个 C 语言的字符串赋值给串。这段代码里有两个数字最关键，你一定要理解，别死记。

第一个数字，malloc 申请的是 len+1 个字符，不是 len 个。为什么要多一个？因为要在末尾存那个结束符 '\0'。C 语言的字符串靠 '\0' 标记结尾，你申请 len 个只够放有效字符，没地方放 '\0'，所以要多申请一个。

第二个数字，拷贝的循环写的是 i <= len，不是 i < len。为什么用小于等于？因为要把 '\0' 也一起拷过去。i 从 0 走到 len，一共拷 len+1 个字符，正好把有效字符加末尾的 '\0' 全拷进新空间。如果写成 i < len，就只拷了 len 个有效字符，漏了 '\0'，这个串就没有结束标记了。

【停顿】这两个数字是同一个原因的两面：len+1 是留位置给 '\0'，i<=len 是真正把 '\0' 放进去。你记住"多一个格子存结束符"，这两处就都不会写错。另外这段代码里，free 掉旧的 ch 之后要立刻置 NULL，返回值统一成成功 1、失败 0，这是我们对笔记里简写版本做的规范，你照这个写。

## P5 strcompare、concat、substring（约3分钟）

那么接着看另外三个操作，各有一个易错点。

strcompare，名字叫"比较"，但它实际做的是判等，不是比大小。看代码：从头逐个比 s1 和 s2 的字符，遇到第一个不相等的就返回 false；全比完了，再比长度，长度也相等才返回 true。所以它只告诉你两个串是不是一样，不告诉你谁大谁小。如果题目要的是字典序比较，得另写一个返回 int 的版本，用第一个不同字符决定正负。你别被 compare 这个名字骗了。

concat，拼接两个串。申请的空间是 str1.length + str2.length + 1，那个 +1 还是给 '\0'。拷贝用了两个循环，边界不一样：第一个循环拷 str1，条件是 i < str1.length，只拷有效字符、不拷 str1 自己的 '\0'；第二个循环拷 str2，条件是 j <= str2.length，多拷一个，把 str2 的 '\0' 一起拷过来当作结果的结束符。两个循环一个用小于、一个用小于等于，差别就在这。

substring，取子串。重点是合法性判断：pos 和 len 都不能是负的，pos 不能超出串长，pos+len 也不能超过串长，否则取的子串就越界了。这几条判断漏了，程序就可能访问到不该访问的内存。

## P6 BF 匹配：三个指针（约3分钟）

接下来是串匹配。先讲最简单的 BF，也叫暴力匹配。看代码 index，它有三个指针，分工要弄清楚。i 扫主串，指向主串当前在比的字符；j 扫模式串，指向模式串当前在比的字符；k 记住本轮匹配是从主串哪个位置开始的。

匹配过程是：如果 str.ch[i] 等于 substr.ch[j]，两个字符 match上了，i 和 j 都往后走一位；一旦失配，就 j 归 0（模式串退回开头）、i 回到 k+1（主串从本轮起点的下一位重新开始），同时 k 也加 1。这个"失配后主串指针往回退"的动作，就叫回溯。

匹配成功后返回什么？返回 k+1。为什么加 1？因为题目要的是位序，从 1 数起，而 k 是从 0 数起的下标，这和上一节 LocateElem 返回 i+1 是同一个道理。BF 最坏的时间复杂度是 O(nm)，n 是主串长、m 是模式串长。

## P7 过程页：BF 匹配走一趟（约3分钟）

这一页你拿纸跟着画，我们把 BF 匹配走一趟。主串是 ababcab，模式串是 abc。

第一轮，k=0，i 和 j 都从 0 开始。主串 a 对模式 a，相等，i、j 都到 1；主串 b 对模式 b，相等，i、j 都到 2；主串第 3 个是 a，模式第 3 个是 c，a 不等于 c，失配。

失配怎么处理？j 归 0，k 变成 1，i 回到 k 也就是 1。现在从主串第 2 个字符 b 开始，重新和模式串开头 a 比。

第二轮，主串 b 对模式 a，b 不等于 a，又失配。j 归 0，k 变 2，i 回到 2。从主串第 3 个字符 a 开始重比。

第三轮，主串 a 对模式 a，相等；主串 b 对模式 b，相等；主串 c 对模式 c，相等。j 走到了模式串长度 3，匹配成功。返回 k+1，k 现在是 2，返回 3，也就是模式串 abc 从主串第 3 个位置开始匹配上。

【停顿】你刚才看到 BF 的毛病了：每次失配，主串指针 i 都要退回到 k+1 重新来，前面已经比过的字符又被比了一遍。主串 ababcab 里，前面的 a、b 被反复比对。这就是 BF 慢的原因，也是 KMP 要解决的问题。

## P8 KMP 思想与 next 含义（约3分钟）

那么 KMP 就是来改进 BF 这个毛病的。它的核心思想一句话：让主串指针 i 永不回溯。失配的时候，i 不动，只把模式串的 j 退到一个合适的位置 next[j]，接着比。

为什么 i 可以不回溯？因为失配时，主串前面那些字符我们已经比过了，模式串自己内部有重复的信息可以利用，不用拿主串从头再来。这个"利用模式串自身重复信息"的东西，就存在 next 数组里。

next[j] 是什么含义？它是模式串前 j-1 个字符里，最长的那段"相等前后缀"的长度，再加 1。相等前后缀的意思是，这段字符的开头几个和结尾几个是一样的。比如模式串 aba，前面加一个位置，"a"这个前缀和"a"这个后缀相等，长度 1。

nextval 是 next 的优化。如果模式串第 j 个字符正好等于第 next[j] 个字符，那失配时退到 next[j] 还是会被同一个字符卡住、还是失配，白退一趟。所以这种情况干脆直接退到 nextval[next[j]]，跳过这次无用的比较。

要说明的是，802 只考 next 和 nextval 的手算，七年真题里没有一道要你写 KMP 的匹配代码。所以这一节我把思想讲透、把手算练熟，匹配代码不写。

## P9 检查页：手算 next 与 nextval（约4分钟）

这一页你先自己算，别急着看答案。模式串是 abaabc，六个字符，下标从 1 到 6。请你把它的 next 数组和 nextval 数组逐位算出来。

【停顿】对一下答案。先算 next。next[1] 规定是 0，next[2] 规定是 1。next[3]：看前 2 个字符 ab，前缀 a、后缀 b，没有相等的，长度 0，加 1 得 next[3]=1。next[4]：前 3 个 aba，最长相等前后缀是 a 对 a，长度 1，next[4]=2。next[5]：前 4 个 abaa，最长相等前后缀还是 a 对 a，长度 1，next[5]=2。next[6]：前 5 个 abaab，最长相等前后缀是 ab 对 ab，长度 2，next[6]=3。所以 next 是 0、1、1、2、2、3。

再算 nextval。nextval[1]=0。第 2 位字符 b，next[2]=1，第 1 位字符是 a，b 不等于 a，所以 nextval[2]=next[2]=1。第 3 位字符 a，next[3]=1，第 1 位是 a，相等，所以 nextval[3]=nextval[1]=0。第 4 位字符 a，next[4]=2，第 2 位是 b，不等，nextval[4]=next[4]=2。第 5 位字符 b，next[5]=2，第 2 位是 b，相等，nextval[5]=nextval[2]=1。第 6 位字符 c，next[6]=3，第 3 位是 a，不等，nextval[6]=next[6]=3。所以 nextval 是 0、1、0、2、1、3。

这套手算是填空题的固定考点，你多算几个模式串就熟了。关键就两条：next 看最长相等前后缀长度加 1，nextval 在字符撞上时往前跳。

## P10 数组的地址计算（约2分钟）

那么串讲完了，看数组。数组这块考的是地址计算，是填空题常考点。

二维数组存到内存里是一维的，有两种存法。行优先，一行一行存，C 语言用的就是这个；列优先，一列一列存。地址公式跟着存法走。行优先下，a[i][j] 的地址等于基址加上 (i 乘以列数 n 加 j) 再乘以每个元素的字节数，这里下标从 0 开始。列优先就把 i 和 j 的角色换过来，用行数去乘。

你要记的不是死公式，而是这个思路：a[i][j] 前面存了多少个元素，乘以每个元素多大，加上基址，就是它的地址。行优先时，前面是完整的 i 行、每行 n 个，再加本行的 j 个，所以是 i×n+j。如果题目下标从 1 开始，公式里的 i、j 各减 1。三维数组同理，多乘一层。

## P11 三对角矩阵压缩（约3分钟）

特殊矩阵的压缩存储也是每年爱考的，我们拿三对角矩阵做例子，重点是把下标公式推出来，不是背。

什么叫三对角矩阵？n 阶方阵里，非零元素只集中在主对角线和它上下各一条对角线上，也就是满足 |i-j| 小于等于 1 的位置，其余全是 0。这样的矩阵，非零元素一共 3n-2 个，把它们按行压缩存进一个一维数组，就不用存那些 0 了。

现在推 a[i][j]（下标从 1）压缩后在一维数组里的下标 k。思路是数它前面有多少个非零元素。第一行有 2 个非零元素；第 2 行到第 i-1 行，每行 3 个，一共 3(i-2) 个；到了第 i 行，本行从 a[i][i-1] 开始，a[i][j] 是本行第 j-i+2 个。把这几段加起来：k = 2 + 3(i-2) + (j-i+2)，化简就是 k = 2i + j - 2。

你验证一下，a[1][1] 代进去 k=2+1-2=1，是第一个；a[n][n] 代进去 k=2n+n-2=3n-2，正好是最后一个。对称矩阵、三角矩阵的推导是同一个套路，都是数前面有几个非零元素，考的就是这个推导过程。

## P12 广义表 head 与 tail（约2分钟）

最后是广义表。广义表是 n 个元素的有限序列，特别在它的元素可以是原子，也可以是一个子表，所以它是递归定义的。

它考的就两个操作，head 和 tail。head 取第一个元素，这个第一个元素可以是原子，也可以是一个子表。tail 取除第一个之外剩下的部分，而且 tail 的结果一定是一个表，哪怕只剩一个元素，也要带着括号。

举个例子，广义表 (a,(b,c))。head 取第一个元素，是 a。tail 取剩下的，是 ((b,c))，注意外面还有一层括号，它是一个只含一个元素 (b,c) 的表，不是 (b,c)。这个括号是最容易错的地方，很多人 tail 忘了加括号，就少了一层。head 和 tail 是填空题的固定考点，你抓住"tail 一定是表、带括号"就不会错。

## P13 小结（约2分钟）

这一节小结一下。

串：堆分配的 ch 是指针要 malloc，定长的 ch 是数组不能 free，两种不能混用；strassign 记 len+1 和 i<=len，都是为了 '\0'；strcompare 是判等不是比大小。BF 匹配三指针 i、j、k，失配主串回溯，返回位序 k+1；KMP 让主串指针不回溯，802 只考 next 和 nextval 手算。

数组：行优先地址 = 基址 + (i×列数+j)×字节数；三对角矩阵压缩下标 k=2i+j-2，靠数前面几个非零元素推出来。

广义表：head 取第一个元素，tail 取剩下的表、一定带括号。

这一节动手算的多、写代码的少，你把 next 手算、数组地址、广义表 head/tail 这几个固定考点练熟就够本了。

## 附录一：课后题参考答案

跟练题：模式串 ababaa 手算 next 与 nextval。

| j | 1 | 2 | 3 | 4 | 5 | 6 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| 字符 | a | b | a | b | a | a |
| next | 0 | 1 | 1 | 2 | 3 | 4 |
| nextval | 0 | 1 | 0 | 1 | 0 | 4 |

推导：next[1]=0、next[2]=1 规定；next[3] 前2位 ab 无相等前后缀得1；next[4] 前3位 aba 最长 a 得2；next[5] 前4位 abab 最长 ab 得3；next[6] 前5位 ababa 最长 aba 得4。nextval：第3位a=第1位a→nextval[3]=nextval[1]=0；第4位b=第2位b→nextval[4]=nextval[2]=1；第5位a=第3位a→nextval[5]=nextval[3]=0；第6位a≠第4位b→nextval[6]=next[6]=4。

模仿题（5答13 同类）：广义表 A = ((a,b),(c,(d,e)))。

- head(A) = (a,b)，取第一个元素，它本身是个子表。
- tail(A) = ((c,(d,e)))，取剩下的，外面要加括号，只剩一个元素也是表。
- head(tail(A)) = (c,(d,e))，先取 tail 得 ((c,(d,e)))，再取它的 head。

要点：tail 的结果一定是表、带括号；head 的结果可能是原子也可能是子表，看第一个元素是什么。

## 附录二：本节代码合集

串的堆分配存储与 strassign、BF 匹配，均用 `知识笔记/代码总结.md` 并按勘误 B6、B7 修正。

```c
typedef struct{ char *ch; int length; }String;   // 堆分配存储

int strassign(String &str, char *ch){
    if(str.ch){ free(str.ch); str.ch = NULL; }
    int len = 0;  char *c = ch;
    while(*c){ len++; c++; }
    str.ch = (char*)malloc(sizeof(char)*(len+1));   // +1 存 '\0'
    if(str.ch == NULL) return 0;
    c = ch;
    for(int i = 0; i <= len; i++) str.ch[i] = *c++;  // <= 拷到 '\0'
    str.length = len;  return 1;
}
int index(String str, String substr){             // BF 匹配
    if(str.length == 0 || substr.length == 0) return 0;
    int i = 0, j = 0, k = i;
    while(i < str.length && j < substr.length){
        if(str.ch[i] == substr.ch[j]) { i++; j++; }
        else { j = 0; i = ++k; }
    }
    if(j == substr.length) return k + 1;          // 返回位序
    return 0;
}
```
