## P2 2021 双调序列：题面（约3分钟）

第一道题，2021 年真题。屏幕上为题面：一个先递增后递减的序列称为双调序列，设计一个尽可能高效的算法，找到由 n 个数组成的双调序列中最大的关键值。

先按暂停自己写，给你两分钟。

【停顿】认结构：数组，先升后降，峰值唯一——"先递增后递减"这个形状就是全部信息。

题眼在"尽可能高效"四个字。扫一遍找最大值是 O(n)，谁都会，题目不会这么出；"尽可能高效"就是在说：要用 O(logn)。什么算法 O(logn)？折半。

选模板：模板9 折半框架改判定。序列不是整体有序的，但"先升后降"意味着站在任何一个位置，看它左右邻居就能判断峰在哪边——这就是判定条件。

## P3 2021 双调：判定条件怎么推（约4分钟）

这一页是本节的第一个核心：判定条件的推导。站在 mid 位置，三种处境。

处境一：A[mid-1] > A[mid]。左边邻居比它大，说明 mid 已经在下降段了——峰值在 mid 左边。【停顿】注意，right = mid，不是 mid-1。为什么？因为峰值可能就在 mid 与 mid-1 之间贴着，mid 自己虽然比左邻居小，但区间收缩时把它留着不影响正确性，而写 mid-1 在某些边界会跳过去。材料注释的原话是"其左侧元素可能是所求值故不+1"——保守起见把 mid 留在区间里。

处境二：A[mid+1] > A[mid]。右边邻居比它大，mid 在上升段——峰值在右边，而且 mid 自己一定不是峰值（右边还有更大的），所以 left = mid + 1，放心排除。

处境三：两边都不满足——左邻居不比它大、右邻居也不比它大，mid 自己就是峰值，直接返回 A[mid]。

【停顿】你看清这个不对称了吗：right = mid 与 left = mid + 1，一个含 mid 一个不含。道理一句话：mid 可能是答案时不能排除它，mid 一定不是答案时才排除。这是"折半框架改判定"这一类题的通用难点，旋转数组、第一个满足条件的位置，全在这上面栽跟头。

## P4 2021 双调：代码与边界（约4分钟）

代码屏幕上走。开头 n <= 0 返回 -1。left = 0、right = n-1，while left < right：算 mid，按三种处境分支——下降段 right = mid，上升段 left = mid + 1，都不是就返回 A[mid]。循环终止时 left == right，返回 A[left]。

两个边界判断藏在条件里：mid >= 1 才读 A[mid-1]，防止 mid=0 时读 A[-1]；mid < n-1 才读 A[mid+1]，防止 mid=n-1 时读 A[n]。【停顿】端点为什么也可能是峰值？纯递减序列（题目说先递增后递减，递增段可以退化到没有）峰值就在 A[0]，此时 mid=0，左邻居判断跳过、右邻居 A[1] < A[0] 也不满足上升段条件——落到处境三，返回 A[0]，正确。

复杂度：时间 O(logn) 每轮区间减半；空间 O(1)。理由各一句写进答案。

最容易丢的分：把 right = mid 写成 right = mid - 1。峰值恰好是 mid 的时候被排除掉，漏解。评分时思想段写清"用折半框架、判定条件改为比较 mid 与邻居"，不对称的理由写一句，就是采分点。

## P5 2020 逆序对：题面（约3分钟）

第二道题，2020 年真题。屏幕上为题面：一个序列由 n 个不大于 200 的正整数构成，n 不超过 30000，设计时间复杂度尽可能小的算法求逆序对个数。

认结构：数组；逆序对的定义——下标 i 小于 j 且 A[i] 大于 A[j] 的 (i,j) 对数。

【停顿】n ≤ 30000 这个数字不是随便给的，它在说话：双重循环 O(n²) 是九亿次操作，超时；O(nlogn) 是四十多万，轻松通过。题目给数据范围，就是在暗示复杂度下限。以后看到"n 不超过多少"，先算一下平方是多少，就知道出题人在排除什么。

"值不大于 200"也是个提示：可以用计数数组做，但归并法更通用、是模板10 的标准形态，主推归并。

选模板：模板10 归并加计数。完整推导强化阶段第10节讲过，这里直接用。

## P6 2020 逆序对：关键一行（约5分钟）

先按暂停，自己把代码写一遍——模板你背过，就看你能不能把它落到这道题上。

【停顿】改条件就一处：在 Merge 的 else 分支里加一行 count += mid - i + 1。

这一行为什么是 mid - i + 1，再推一遍：合并时右半的 temp[j] 被选中，说明 temp[j] 小于左半当前的 temp[i]；左半有序，所以从 i 到 mid 的所有元素都大于等于 temp[i]，也就都大于 temp[j]；这些元素的下标又都在 j 之前——每一个都与 temp[j] 构成一个逆序对。左半从 i 到 mid 共 mid - i + 1 个，一次全加上。

写成 count++ 是最常见的错：只算了 temp[i] 与 temp[j] 这一对，左半剩下的全漏了。一个符号的差别，答案差一半。

递归结构：MergeSort 返回左半的 count 加右半的 count 加合并的 count。每层只管跨段的那部分对，段内的对在更深层已经算过——不重不漏，这是分治计数的标准结构。

还有一个细节：合并前先把 A[left..right] 复制到 temp，从 temp 读、往 A 写，避免边合并边覆盖。

复杂度：时间 O(nlogn)，每层合并总代价 O(n)、共 logn 层；空间 O(n) 辅助表。

## P7 过程页：六元素归并加计数（约4分钟）

这一页拿纸跟着画。数组 3、1、4、2、6、5，屏幕上画出来了。先口算一下总共有几个逆序对：(3,1)、(3,2)、(4,2)、(6,5)，4 对。看代码算出来是不是 4。

递归拆：[3,1,4] 与 [2,6,5]，再拆到单元素，两两合并。

左半内部：[3] 与 [1,4] 合并——temp 是 [3,1,4]，i 指 3、j 指 1，3 > 1，走 else，count += mid-i+1 = 0-0+1 = 1，取 1；然后 3 <= 4 取 3；收尾取 4。左半内部 count = 1，段变成 [1,3,4]。

右半内部：[6,5] 合并，6 > 5，count += 1。然后 [2] 与 [5,6] 合并，2 最小直接取，无跨段对。右半内部 count = 1，段变成 [2,5,6]。

顶层合并 [1,3,4] 与 [2,5,6]：1 <= 2 取 1；3 > 2，走 else——左半从 i（指 3）到 mid 还剩 3 和 4 两个，count += 2，取 2；然后 3 <= 5 取 3，4 <= 5 取 4，收尾取 5、6。顶层 count = 2。

总计 1 + 1 + 2 = 4，与口算一致。你把每层的 i、j、count 标在纸上——每层只管跨段对，子层算好的直接加起来，这就是递归结构的价值。

## P8 Top-K 变式：两种解法（约3分钟）

顺带把 Top-K 讲了，它是这两道真题的邻居题型，题集勾画的 6算46 与 10答14 都在考。

解法一，小根堆：维护一个大小为 k 的小根堆，堆里是"目前最大的 k 个候选"。扫一遍数组，每个元素与堆顶比：比堆顶大，就换掉堆顶再下沉调整；不比堆顶大，跳过。扫完堆顶就是第 k 大。时间 O(nlogk)，空间 O(k)。

解法二，快排划分：Partition 之后看枢轴落在哪——正好是第 k 个位置就找到了；枢轴位置大于 k，只递归左半边；小于 k，只递归右半边。平均 O(n)（n + n/2 + n/4 + ... 收敛到 2n），最坏 O(n²)。

【停顿】选择依据一句话：数据一边来一边问（数据流），用堆——划分法要求数据一次给全；数组一次给全、要平均最快，用划分。还有一个易错：第 k 大用小根堆、第 k 小用大根堆，堆的类型别记反——小根堆的堆顶是候选里最小的，正好卡住第 k 大的门槛。

## P10 考法一：挖空补全的四步做法（约4分钟）

挖空补全四步。

第一步，读函数名、参数与返回值，猜整体功能。函数名里就写着答案的一半：DFSTree 就是 DFS 生成树，EnQueue 就是入队。猜出功能，你就知道每段代码"应该"在干什么。

第二步，标出所有变量并说出各自含义。每个指针指向什么、每个下标从几起、visited 记什么——变量含义标清楚了，空的候选范围就缩小了。

第三步，看空格的位置定候选。空在循环条件里，想终止条件；空在赋值语句，想指针移动或状态更新；空在函数调用，想递归参数怎么变。位置决定空的类型，类型决定候选。

第四步，回代验证。把答案代进去，拿一个小例子走一遍——三个结点的链表、两个元素的队列，跑通了才算完。这一步不能省，挖空补全的错误一半是"看着对、跑不通"。

常考的四类空再念一遍：循环边界（i < n 还是 i <= n）、指针移动（p = p->next 还是 p = p->prior）、递归调用的参数、返回条件。

## P11 考法二：片段排序的三步做法（约3分钟）

片段排序三步，比挖空简单。

第一步，找入口片段：含变量声明与初始化的那段一定在最前面——没有声明就用变量，代码跑不起来。

第二步，找依赖关系：哪一段用到了另一段定义的变量，被依赖的排前面。按数据流排：数据先被谁生产、再被谁消费。

第三步，验证：按排好的顺序走一遍小例子。还有一个位置线索——输出或返回的片段一定在最后。

口诀一句话：声明初始化在最前，输出返回在最后，中间按"谁用谁先"排。2024 年那道" s 插入 p 之前"就是这么排的：先存后继（声明与保存现场），再改指针（依赖前一段存的值），最后接回。

## P12 考法三：功能与复杂度分析的写法（约2分钟）

功能与复杂度分析，写法上有两个硬要求。

功能的写法：用"这个函数做什么"的完整句式。例如"把链表逆置并返回新表头""统计数组中负数的个数"。只写"处理链表""操作数组"不给分——功能要说清输入变成什么输出。

复杂度的写法：一句结论加一句理由。"双层循环，外层 n 次、内层平均 n/2 次，所以 O(n²)"。只写 O(n²) 不给理由会扣分——这与基础阶段第1节答题三件套的要求一致：结论加依据。

递归代码说功能有个固定读法：先看终止条件——n 为 0 或 1 时返回什么，这是功能的"底"；再看递归体——规模怎么缩小、返回值怎么合并。正是递归三件套倒着读。

## P13 三类考法各配一道真题（约3分钟）

屏幕上这道是 2026 年的阅读1，3 分，挖空补全。DFSTree 生成深度优先生成树，两个空。

按四步走。第一步猜功能：函数名 DFSTree，对每个连通分量生成 DFS 树。第二步标变量：p 是边表指针，visited 记访问过没有。第三步看位置：空①是赋值空，p 还没初始化，后面 while p != NULL 就要用——p 应该指向 v 的第一条边，答案是 G.vertices[v].firstarc；空②在 if (!visited[p->adjvex]) 里面，未访问的邻接点该干什么？递归进去，答案是 DFSTree(G, p->adjvex)——这条递归边就是生成树的树边。第四步回代：三个顶点的小图跑一遍，树边打印正确。

## 附录一：课后题参考答案

真题重写：2020 逆序对完整三件套。

思想段：分治计数。二路归并排序的过程中，合并两个有序半段时，若右半元素先于左半元素出队，说明左半从当前位置到 mid 的全部元素都大于该右半元素且下标在前，与它构成 mid-i+1 个逆序对，一次累加；每层递归只统计跨段对，段内对由更深层统计，总数为各层之和。n≤30000 排除 O(n²) 双重循环。

```c
int reverseCoupleCount(int A[], int n){
    int temp[MaxSize];
    for(int i=0;i<n;i++) temp[i]=0;
    return MergeSort(A, temp, 0, n-1);
}
int MergeSort(int A[], int temp[], int left, int right){
    if(left >= right) return 0;
    int mid=(left+right)/2, count=0;
    count += MergeSort(A, temp, left, mid);
    count += MergeSort(A, temp, mid+1, right);
    count += merge(A, temp, left, mid, right);
    return count;
}
int merge(int A[], int temp[], int left, int mid, int right){
    for(int k=left;k<=right;k++) temp[k]=A[k];
    int i=left, j=mid+1, k=left, count=0;
    while(i<=mid && j<=right){
        if(temp[i]<=temp[j]) A[k++]=temp[i++];
        else{ count += mid-i+1;  A[k++]=temp[j++]; }
    }
    while(i<=mid) A[k++]=temp[i++];
    while(j<=right) A[k++]=temp[j++];
    return count;
}
```

复杂度段：时间 O(nlogn)，每层合并 O(n)、共 logn 层；空间 O(n)，辅助表。

变式题答案要点：

1. 10算26 有序数组合并：二路归并 Merge，三指针 p、q、k 加两个收尾循环。
2. 6算46 数据流第 k 大：小根堆维护 k 个最大候选；新元素大于堆顶则替换堆顶并下沉调整；堆顶即第 k 大；O(nlogk)/O(k)。
3. 10答14 前 k 大最小比较次数：淘汰赛思路，n-k 次比较淘汰 n-k 个元素；结论按教材的说法写并给理由。

int binary_search(int A[], int n){
    if(n <= 0) return -1;
    int left = 0, right = n - 1, mid;
    while(left < right){
        mid = (left + right) / 2;
        if(mid>=1 && A[mid-1]>A[mid]) right = mid;         // 下降段，峰在左（含 mid）
        else if(mid<n-1 && A[mid+1]>A[mid]) left = mid+1;  // 上升段，峰在右
        else return A[mid];                                 // mid 就是峰
    }
    return A[left];
}
