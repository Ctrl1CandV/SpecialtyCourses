## P3 指针运算：p+1是往前走一格（约4分钟）

先做一个实验。int x = 10，int *p = &x。假设打印出来p是1000。现在我打印p + 1，你猜是多少？

【停顿】

很多人第一反应是1001。地址加1嘛，听起来很合理。但实际打印出来是1004。

为什么差4？因为p是int *，指向的是一个int的格子，一格int占4个字节。指针加1，意思是往前挪一格，一格就是4个字节。如果p是char *，指向的格子只有1个字节，那p+1才是真正的加1。

这里正好把上节课的一句话接上：类型决定盒子大小。盒子有多大，指针走一步的步子就有多大。int的盒子4格，走一步4格；double的盒子8格，走一步8格。指针不认识字节，它只认识格子。

你可以自己动手验证一下：声明一个double的变量，拿指针打印它和它加1的地址，会看到差8。类型不一样，步子不一样，自己验证一遍，比听我讲十遍都记得牢。

所以p+n的意思，就是从当前位置往前挪n格。注意是n格，不是n个字节。这个换算关系是今天后面所有内容的数学基础，你先把它记牢：指针的加减，永远按指向的类型缩放。

给你一个检验：int *p，p + 3的地址比p大多少？12。三格，每格4个字节。答对了，这一页你就过了。

把物理画面在脑子里建起来：内存是一片密密麻麻的字节，每个字节一个编号。int变量住进去，一次占四个连续字节。p指向的是这四字节的起点，p+1就是跳过这四字节，落在下一个int的起点上。你以后看指针运算，都用这个画面去套，不会错。

再补两个方向上的事。减法同理：p - 1往后挪一格，也是按类型缩放。还有一个常用运算：两个指向同一个数组的指针相减，得到的是它们之间隔了几格。比如q指向a[3]，p指向a[1]，q - p等于2。这个运算以后算"两个位置之间还差几个元素"时会用到，今天先有个印象。

## P4 i++与++i：先用再加，先加再用（约2分钟）

刚才代码里出现了p++，趁这个机会，把一个基础阶段留的小尾巴顺带说清：i++和++i到底什么区别。

看这两行。int i = 3，先打印i++，打出来是3，然后i才变成4；再打印++i，i先变成5，再打印5。区别就一句话：i++是先按现在的值办事，办完再加；++i是先加，再办事。

你不需要背什么前置后置的术语，读代码的时候，把i++理解成"这一轮先用，用完再加"，把++i理解成"先加好再用"，就够了。

实际写代码，绝大多数场景用的是先用再加的写法：for循环里的i++，遍历的p++，都是办完事再走一步。两种写法在循环里效果一样，你照着主流写法来就行，不用在这里花时间纠结。

给你一个易错点检验。int i = 3; printf("%d", i++ + 1); 打出来是几？

【停顿】

4。加法用的是i当时的值3，加1得4，打印完i才变4。这类"自增混在表达式里"的写法，读的时候只问一句：这一步用的是加之前还是加之后的值。考试和正经代码里都不鼓励这种写法，但你得读得懂。

## P5 数组名是首元素的地址（约4分钟）

指针的移动讲完了，回头看数组。

基础阶段说过，数组是一排带编号的盒子。现在加上地址的视角：这排盒子在内存里是连成一片的，一格挨着一格，中间不留空。

关键结论：数组名a，就是首元素a[0]的地址。你printf用%p打印a，打出来的就是第一格的门牌号。注意，这里不用写&a，数组名自己就是地址。

为什么不用写&？回想上节课那句话：地址就是格子的编号。数组名a本身代表的就是那片格子的起始编号，它已经是地址了，再用&反而是多此一举。这和变量不一样：变量x的名字指的是那个盒子，要用&x才能把编号拿出来；数组名a的名字直接就是编号。一个是盒子，一个是门牌号，这是两者最本质的区别。

有了地址，有了刚才的指针运算，一个等价关系就出来了。a[2]是什么意思？就是从a这个起点出发，往后数两格，取那一格的值。C语言里有个完全等价的写法：a[2]就是*(a+2)，星号外面套括号。a是起点，a+2是按int的格子往后挪两格的地址，取值，就是30。

我问你：a[4]等于*(a+几)？

【停顿】

*(a+4)。下标是几，括号里就是几，永远差不了。

再回头看遍历数组的for循环，i从0到n-1。现在你能看懂它的本质了：i每加一次，对应的就是指针往后挪一格，把整片格子从头走到尾。你基础阶段写的每一个数组遍历，骨子里都是指针在走路。今天把这层窗户纸捅破，数组对你来说就没有秘密了。

这个等价关系是双向的，反着也成立。既然a[i]能写成*(a+i)，那反过来，*(a+i)也能写成a[i]。延伸一步：指针p指向数组时，p[2]和*(p+2)也是一回事。换句话说，下标这套写法对指针同样有效，p[i]就是"从p当前位置往前数i格"。两套写法完全互通，你能自由翻译，才算真懂。

## P6 下标为什么从0：0表示起点自己（约3分钟）

现在正式回答第一个为什么：下标为什么从0开始。

你再看一遍刚才那个等价关系：a[i]就是*(a+i)。i在这里的真实身份，不是"第几个"，是"离起点几格"。a[1]是离起点1格的位置，a[2]是离起点2格的位置。那起点自己呢？离起点0格，所以是a[0]。

从0开始数，一切顺理成章：下标就是偏移量，0表示没挪动，还在起点。

反过来想，要是下标从1开始会怎样？起点自己得写成a[1]，而机器算地址还是从起点挪i格，每次都得先减个1再算。多一次换算，多一次出错的机会。从0开始，下标和地址偏移严丝合缝，一个字节都不浪费。

你还可以这么验证这个设计的好处：数组长度是n，下标从0开始时，合法下标是0到n-1，最后一个下标刚好是长度减1；循环条件写i < n，干干净净。要是从1开始，合法下标变成1到n，条件写i <= n，看起来也行，但每次算地址都得先减1，这个减1会出现在每一处用下标算地址的地方。省掉这个减1，就是从0计数换来的。

所以"下标从0"不是随便定的规矩，是地址运算的自然结果。你今天理解了这一层，以后看到任何从0计数的设计——循环从0到n-1，长度n最大下标n-1——全都串起来了。

打个生活里的比方。下标像地铁站的站号：0站就是始发站本身，不是"第1站"；1站是离始发站一站路的地方。你问"到0站要走多远"，答案是零，因为你已经在0站了。数组的下标就是这么数的：a[i]就是"从a出发走i站"，走0站，就是a[0]，起点自己。

## P7 数组名不是指针变量（约4分钟）

有一个容易混的地方，必须单独说清：数组名a是地址，但a不是指针变量。

看这段代码。int a[5]，int *p = a，这两行都没问题，p从a那里接过了首格地址。接下来，p++合法，因为p是个变量，它的格子里存的编号可以换。但你写a++，编译器不认。为什么？a代表的是那片内存的起点，这个位置是固定的，它没有一个自己的格子让你改。a像钉在地上的路标，p是拿着路标地址可以到处走的快递员。

这个区别还有一个实用的地方，就是sizeof。sizeof(a)算的是整个数组的大小：5个int，20个字节。sizeof(p)算的只是一个指针的大小，上节课说过，64位机器上8个字节。同一个sizeof，喂进去数组名和指针，结果完全不一样，就因为a是整片数组，p只是一个存地址的格子。

顺带给你一个常用技巧。想知道数组有多少个元素，不用手数，写sizeof(a)除以sizeof(a[0])：总大小除以一格的大小，就是格数。这个写法在正经代码里很常见，你看到别陌生。它只对还在原地的数组有效——数组一旦作为参数传进函数，情况会变，那是函数那一节的事，今天不展开。

给你一组易混的写法，正好把今天和上节课串起来。int a[5]，int *p = a。&a[0]、a、p，三个东西打印出来地址都一样，都指向首格。但身份不同：&a[0]是取第一格的地址，a是数组名自己就是地址，p是装了地址的变量。地址相同，身份不同，这个区分在板书和读代码时都会用到。

最后把a和p的关系收成一句话，这也是本节的易错点：a是地址，p是存地址的变量。所以int *p = a合法，把地址装进变量；p = a也合法，换个地址装；但a = p不合法，你没法给一个固定位置重新赋值。读代码看到谁等于谁，先问一句：等号左边是个能改的格子吗。

## P8 板书推演：用指针把数组走一遍（约6分钟）

【板书】

动手。今天画一张大一点的图：数组加指针。你拿纸跟着画。

第一步，横着画五个连在一起的格子，写上a[0]到a[4]，值填10、20、30、40、50。注意，五个格子中间不留空，这就是数组在内存里的样子。

第二步，画指针p，里面填a[0]的地址，箭头指向第一格。写一句int *p = a。

第三步，写指针版的遍历循环：for(p = a; p <= a + 4; p++)，打印*p。然后一轮一轮标p的位置：第一轮p在a[0]，打印10；p++挪到a[1]，第二轮打印20；一路走到a[4]打印50；再p++到了a+5，条件不成立，循环结束。你数一数，正好五轮，五个数。

第四步，在右边写下标版：for(i = 0; i < 5; i++)，打印a[i]。两行循环摆在一起看：左边的p就是右边的i干的事，一个挪格子，一个换下标，走的是同一条路。

【停顿】

检查一下你的图：五个格子连成一片，一个箭头从头走到尾，两行循环左右对照。这张图画顺了，指针遍历你就真懂了。课后把这张图自己再画一遍，尤其是p每一轮的位置，别偷懒。

画这张图有两个常见错法，你对着自查一下。一个是把五个格子画得分开，中间留空隙——数组的格子必须是连着的，留空隙就不是数组了。另一个是把箭头画在格子上方悬着，不落在具体格子上——箭头必须顶在具体某一格上，指针任何时刻都指向确定的格子，没有"悬在两格之间"的状态。

## P9 两种遍历：下标法与指针法（约4分钟）

板书里那两行循环，值得单独拿出来比一比。

下标法，i从0到4，打印a[i]。指针法，p从a走到a+4，打印*p。逻辑完全等价，打印结果一模一样。区别在两个地方：第一，下标法对人友好，一眼看懂在访问第几个；指针法贴近机器干活的方式，地址直接拿在手里走。第二，边界写法不同：下标版条件是i小于5，指针版条件是p小于等于a+4。

重点说边界。指针版的终点是a+4，也就是最后一格的地址。你要是手一抖写成p <= a+5，指针会多走一格，踩进数组外面的内存，把上节课刚讲的越界又演了一遍。两种写法互相翻译可以帮你检查：i < 5对应p <= a+4，5是长度，a+4是最后一格，两边都指向同一个边界。

再补一个观察。下标版里，i只是个计数器，跟数组本身没关系；指针版里，p自己就在内存里走路，起点、步长、终点全在它身上。所以读代码看到指针版循环，先把p的起点和终点标在图上，循环在干什么就一目了然了。

阅读题里经常考这一类循环边界：一段遍历代码，条件挖个空，问你填什么，或者问你循环跑几轮。这类题不用猜，把格子画出来，起点终点一标，数就出来了。

给你一个选择建议。平时写代码，两种都会，下标法可读性好，就用下标法；读别人的代码，两种都要认得。考试写算法题，两种都算对，挑你顺手的。

再给你看一个典型的边界事故，你就知道为什么边界值得单独讲。有人把指针版循环的条件写成p <= a + 5，多了一格。程序跑起来，最后一轮打印的是数组外面那格内存里的东西——可能是个莫名其妙的数，也可能恰好是个正常数，让你误以为没错。这种"看起来对"的越界，比当场报错的更难查。所以你写循环条件，写完多问一句：最后一轮，指针停在哪一格。

给你一个综合小例，看看指针遍历能干什么。打擂台求最大值，基础阶段用下标写过，现在看指针版：int *p = a + 1; max = *a; 然后while(p <= a + 4)循环里，如果*p大于max就更新max，p++。逻辑和下标版一模一样，只是把i换成了p，把a[i]换成了*p。你看，遍历不只是打印，边走边干点别的——求最值、求和、找目标——都是这个骨架。这个"遍历加加工"的模式，是后面很多算法的底子。

## P10 越界：踩进了别人的格子（约4分钟）

第二个为什么，也是今天最要紧的一个点。

看这段代码。int a[5]，五个格子，下标0到4。我在它旁边再声明一个int b = 100，b也住在内存里的某片格子。

然后我写一句：a[5] = 999。

你先猜猜，跑起来会发生什么？报错？崩溃？

【停顿】

多半什么都不发生。程序安安静静地跑完了。

注意，a[5]这个格子根本不存在。a只有五格，下标最大到4。那句话的真实含义，用今天学的东西翻译：从a的起点出发，往后挪5格，找到那一格，把999塞进去。那一格是谁的？不归你管。可能住着b，可能住着别的变量，也可能住着你完全不知道的东西。

这就是越界的真相：不是程序不让你访问，是那片内存不归你，你照样能踩进去。

更麻烦的是，这种错多半没有报错。编译器不拦你，程序照样往下跑，只是某个变量的值被悄悄改掉了。你打印b，可能发现它变成999了，也可能没变——取决于编译器怎么安排内存。错的地方和出问题的地方不在一起，这种bug查起来最折磨人。

所以规矩立住：写任何数组访问，先问一句，最大下标是多少。长度是n，最大下标就是n-1。这句话每次写循环边界的时候默念一遍。

越界踩出去的东西，可能是别的变量的值，可能是程序的关键数据，也可能直接让程序崩溃。最坏的情况不是当场崩，是当时没事，埋着埋着，换个环境、换个数据就炸了，查都没法查。所以别抱侥幸：编译器不报错，不代表你没错。

## P11 越界规矩：最大下标是n-1（约3分钟）

把越界的规矩整理成三条，你照着执行就行。

第一条，长度是n，下标范围就是0到n-1，多一步都是别人的地盘。这条是定义，今天你已经知道为什么了：下标是偏移量，最后一格离起点n-1格。

第二条，写循环之前，先回答一个问题：这个数组的最大下标是多少。想清楚了再写条件。很多越界不是不会，是写条件的时候压根没想过边界。i < n还是i <= n，p <= a+n-1还是p < a+n，差一个数就是事故。

这个习惯是怎么来的，说给你听。我当年写代码，总觉得越界是别人的事，直到有一次调一个程序调了一下午，最后发现是循环条件多写了一个等号。从那以后，每写一个边界，都问自己一句：最后一轮安全吗。这一句问话，省下的时间数不清。

第三条，指针遍历同样守这条边界：终点是a+n-1，条件写p <= a+n-1。和上节课的规矩合在一起，你现在有两条安全底线：指针不初始化不许用*；数组访问先确认最大下标。这两条能挡住初学者绝大多数的内存事故。

再给你一个自检动作。写完一段遍历代码，把起点和终点代入走一遍：第一轮访问的是哪一格，最后一轮是哪一格，有没有多走或者少走。十秒钟的事，能省你半小时的排查。

现场示范一次。假设数组长度n=5，你写的条件是i <= n。代入走一遍：i从0开始，最后一轮i等于5，访问a[5]——越界了，多走一格。改成i < n再走一遍：最后一轮i等于4，访问a[4]，正好是最后一格，停。自检就这么简单，关键是你得养成走完这一遍再交手的习惯。

## P12 scanf吃回车的救法（约3分钟）

最后一个坑，也是基础阶段留下的，今天填完。

场景是这样的：你先scanf("%d", &n)读一个数字，敲完数字要敲回车。这个回车不会消失，它留在输入缓冲区里。紧接着你再scanf("%c", &ch)，%c的脾气是不管三七二十一，收走缓冲区里的下一个字符——于是回车被它收走了。看起来就像你第二句输入被跳过，其实ch里存的就是那个回车。

你可以自己验证一次：打印ch的值，是10，就是回车的编号。

救法两种，记一种就够。第一种，在%c之前加一句ch = getchar()，专门把残留的回车收走，后面的scanf读到的就是你真正敲的字符。第二种，把格式写成" %c"，%c前面加一个空格，这个空格的意思是：先跳过所有空白字符再读。两种都灵，挑顺手的。

把第二种再拆开说一层。格式串里的空格和普通空格不一样，它不对应具体字符，是一个指令：把缓冲区里的空白字符——空格、Tab、回车——一直跳过，直到碰上第一个非空白字符才停。所以你写" %c"，哪怕缓冲区里堆了三个空白，也都能挡掉。理解了这一层，你以后看到格式串里莫名其妙的空格，就知道它在干什么了。规矩记住一条：只要前面读过数字，后面要读字符，先处理缓冲区。

## P13 本节小结（约2分钟）

今天的内容收一下，三件事。

第一，指针加减按指向的类型缩放：int *走一步4格，char *走一步1格；p+n就是往前n格。顺带把i++和++i说清了：先用再加，先加再用。

第二，数组名是首元素地址，a[i]就是*(a+i)。下标是偏移量，0表示起点自己——下标从0的原因，就在这。数组名是地址但不是变量，a不能挪，p能挪。

第三，越界是踩进别人的内存，而且多半不报错。最大下标n-1，写循环先问边界。

基础阶段留的三个问题——scanf的&、下标从0、越界——到这里全部解完了，用的都是同一套工具：地址和指针。工具齐了，下一节我们学一个新零件：结构体，把不同类型的数据装进一个格子里。数据结构的结点，就是拿它定义的。

最后把这张内存图完整地串一遍，你跟着默一遍：内存是带编号的格子；变量住格子，地址是编号；&取编号，*按编号找格子；指针是存编号的格子，加1按类型挪格子；数组是一片连续的格子，数组名是首格的固定编号。后面学的所有东西，都是在这张图上添加新家具。

## P14 课后任务（约2分钟）

老规矩，两道题。

跟练题：声明int a[5] = {10, 20, 30, 40, 50}，不用下标，只用指针p，从a走到a+4，依次打印五个数。要求把每一轮p的位置画出来：p在哪一格，打印的是几。这道题就是板书那张图，自己独立走一遍。常见错法两个：循环条件写成p <= a+5，多走一格；先p++再打印，第一个数被跳过。

模仿题：同一个数组，让p从a+4出发，用p--倒着走，把五个数倒序打印出来。这道题练的是反方向走路，原理一模一样，把加号换减号。打印出来应该是50、40、30、20、10，你预测一下，再上机验证。倒着走这个动作不是摆设，以后处理"反过来"的需求——把一个序列翻转、从尾往头检查——用的都是它。

要求：先在纸上预测打印结果，再上机跑，对照。合上资料，你能默写两个东西：*(a+i)，和指针遍历的边界p <= a+4。这两个默得出来，数组和指针这一关你就过了。

最后提醒一句：这两道题都不难，但都要求你动手画图。指针这一章，看懂和会用的分界线就在笔头上。画图的过程慢，但慢得值得。

## 附录一：课后题参考答案

跟练题：

```c
#include <stdio.h>
int main(){
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a;
    while(p <= a + 4){
        printf("%d ", *p);
        p++;
    }
    return 0;
}
```

要点：p从a出发，每轮打印*p后p++，走到a+4为止，共五轮。内存图上，箭头依次停在a[0]到a[4]五个格子上。对照检查两个坑：条件写成p <= a+5就多走一格；先p++再打印就跳过第一个数。

模仿题：

```c
#include <stdio.h>
int main(){
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a + 4;
    while(p >= a){
        printf("%d ", *p);
        p--;
    }
    return 0;
}
```

要点：起点是a+4，也就是最后一格；条件是p >= a，走到首格为止；每轮p--。倒序打印的关键就两条：起点换成终点，方向反过来。
