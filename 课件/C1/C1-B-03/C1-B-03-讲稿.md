## P2 引题：描述一个学生，一个变量不够用了（约2分钟）

先看一段代码。int age = 20，double score = 88.5。这两行没毛病，但你盯着它们看一会儿，会发现一个问题：这两个变量描述的是同一个学生，可在代码里，它们毫无关系。编译器不知道age和score属于同一个人，你自己过三天回头看，也未必记得它们是一对。

一个学生还好，眼睛能记住。学生多起来呢？age1、score1、age2、score2，一长串变量排下来，谁跟谁配对，全靠你脑子记。哪天你在循环里把下标写错一个，age3配上了score4，程序不报错，数据悄悄就错了。

你停下来想想：如果你是语言的设计者，你会怎么解决这个问题？加一种新类型，比如"学生型"？每个领域都有自己的对象，加不完的。更聪明的办法是给程序员一个模具：你自己声明每个对象由哪些属性组成，编译器按你的声明来安排。这个模具，就是接下来要学的东西。

问题的根源在哪？我们手里的类型，只能装一个值。int装一个整数，double装一个小数，数组装一排同类的数。但"一个学生"是年龄加成绩的组合，现有类型表达不了这种组合关系。

这种用几个平行数组硬配对的写法，有个专门的名字叫平行数组，是新手代码里最常见的坑之一。它的毛病不只是乱：任何一次插入、删除、排序，都得保证所有数组同步挪动，漏了一个数组，数据就错位了，而且编译器一个错都不报。你以后维护别人的代码碰到这种写法，就知道痛点在哪了。

所以需要一种新类型：能把不同类型的属性捆在一起，起个名字，当成一个整体来用。这个东西就是结构体。今天整节课，都围着它转。

## P3 struct：把属性打包成一个新类型（约4分钟）

结构体的关键字是struct，英文structure的缩写。看这个定义：

struct Student，花括号里列成员：int age，年龄；double score，成绩。花括号收尾，最后跟一个分号。

我拆开说三件事。第一，struct是关键字，Student是你起的名字，叫什么都行，起个好认的。花括号里的每一行就是一个成员，成员可以是任何类型，int、double，以后还能是数组、指针。第二，这段代码干的事，是画图纸。它告诉编译器：世界上有一种叫Student的类型，长这个样子。注意，此时还没有任何真正的变量被造出来，就像图纸画好了，房子还没盖。第三，花括号后面那个分号，是高频错点。函数体的花括号后不用分号，结构体的要用，漏了编译器直接报错。你第一次写几乎必漏，漏一次记住就行。

问你一个问题：定义完struct Student，内存里多了格子吗？

【停顿】

没有。类型只是图纸，描述了格子的规格，格子要等变量出现才会分配。这和基础阶段的道理一样：类型决定盒子怎么造，变量才是真正的盒子。

再补一个写法。成员清单里，每一行都是一个完整的变量声明，类型加名字加分号。你完全可以把成员想成"住在这个结构体里的变量"，它们各有各的类型，各有各的格子。顺便说一句，点号可以连着用：如果某个成员本身又是结构体，访问里面的成员就一路点下去，a.b.c，一层一层进去，这个写法以后会见到。

成员的类型很自由，这里多说一句。今天例子里是int和double，以后你还会见到成员是数组的、成员是指针的，甚至成员又是一个结构体的。结构体是类型的容器，什么类型都能往里装，这个能力是它强大的根源。今天你先用基本类型把规矩学扎实，容器怎么装东西，后面自然会遇到。

还有一个写法你会在代码里见到：定义结构体的同时顺手造变量，花括号后面直接跟变量名再分号。这和先画图纸再造房子是等价的，只是把两步并成一步。你自己写的时候，建议还是分开写，定义归定义，变量归变量，清楚。

## P4 定义结构体变量，用点号访问成员（约4分钟）

图纸有了，开始造房子。

struct Student stu = {20, 88.5};。这一行造了一个叫stu的变量，花括号里的值按成员声明的顺序对号入座：20给age，88.5给score。初始化列表的顺序必须和成员声明的顺序一致，顺序错了，值就配错了人。

怎么访问成员？用点号。stu.age，读作stu的age，取出来的就是20。点号的意思很直白：从这个整体里，把某个成员拿出来。拿出来之后，它就是普通变量，能打印、能改、能参与运算。stu.score = 90.0，改成员；stu.age + 1，算一算，都行。成员名写错了也不用怕，编译器当场报错，这类错误好查，不比漏分号难缠。

我考你一个：stu.age = stu.age + 1，执行完age是多少？

【停顿】

21。先取出20，加1，再放回去。和基础阶段对普通变量做的事一模一样，只是前面多了个stu.的前缀。

来个小综合运用。用成员算平均分？Student只有一个成员是成绩，算不了。换个场景：已知stu.age是20，写一句判断：如果age大于等于18就打印成年。if(stu.age >= 18)，成员直接进条件，没有任何特殊待遇。你慢慢体会这一点：点号取出来的成员，就是最普通的变量，之前学的所有操作都照旧能用。

再给你一个实用细节。造变量的时候可以不初始化：struct Student stu2;。这时候成员里是什么？是内存里原来的垃圾值，和基础阶段讲过的未初始化变量一个脾气。规矩不变：用完就初始化，别指望格子自己干净。

再强调一次初始化的顺序坑。{88.5, 20}这么写，编译器不会提醒你写反了，它只会老老实实地把88.5塞给age，把20塞给score——一个整数类型的成员收到小数，就截断成整数了。这类错误静默发生，数据错了你都不知道。所以初始化列表写之前，对着成员声明的顺序核一遍，十秒钟的事。

## P5 结构体在内存里：成员的盒子排成一排（约3分钟）

画图时间。结构体变量在内存里长什么样？

回忆一下成员的规格：age是int，4格；score是double，8格。造出stu的时候，编译器给它分配一片连续的格子：前面4格住age，紧跟着8格住score，连成一片，中间不留空。这就是stu住的地方。

结构体变量自己也有地址，用&stu取。这个地址用的是第一个成员的编号，和数组名用首格编号一个道理。格子是造变量时一次性分好的，成员不能自己挑地方住。

这里有个整体和部分的关系，你要分清楚。&stu指向的是整片格子，&stu.age指向的是开头那4格。两个地址打印出来数值相同，但含义不同：一个是"整片地盘的起点"，一个是"age那几格的起点"。就像小区的门牌号和某栋楼的门牌号可能写着一个号，说的范围不一样。

画图的时候，我建议这么画：一片大格子，内部用竖线分成两段，前半标age，后半标score，整片外面写stu的名字。整体和成员一图看清，后面所有结构体的内容都建在这张图上。

顺带把大小算一下。age四格，score八格，加起来就是12个字节。你用sizeof(stu)打印，主流编译器上就是这个数。这里先不讨论字节对齐那些细节，你记住大方向就行：结构体的大小是成员大小的总和，具体怎么排，编译器说了算。

## P6 结构体可以整体赋值：逐成员拷贝（约3分钟）

结构体有个数组没有的本事：可以整体赋值。

struct Student stu2; 然后一句stu2 = stu。合法。执行完，stu2的age是20，score也是20……不对，score是88.5。成员一个一个拷过去，就像把一张表格整行抄了一遍。

为什么说这是数组没有的本事？你写int a[5]，int b[5]，然后b = a，编译器不认。数组不能整体赋给数组，只能开个循环，一个元素一个元素地搬。结构体可以一句搞定，这是它在写法上的一个甜头。

但有个关键问题你要想清楚：拷贝完，stu2和stu是什么关系？

【停顿】

两份独立的数据。stu2有自己的格子，值是从stu抄来的，抄完各过各的。你改stu2的age，stu纹丝不动。这和上上节课讲的别名正好相反：别名是多个名字指同一格，这里是各自有格、值相同。

这个对比你记牢：指针指向同一个变量，改谁都一起变；结构体整体赋值，改谁都不影响谁。两种关系，两种图，别串了。

把今天学的两样东西放一起看，你会发现一个有趣的对称。数组不能整体赋值，结构体可以；数组名是固定地址不能改指向，结构体变量却能整个拷来拷去。数组的强项是批量同类型数据，结构体的强项是打包不同属性。两个工具各有所长，以后选谁，看你要装的是什么。

整体赋值什么时候用得上？举个实在的场景：备份。你要对一个结构体做一连串修改，又怕改坏，动手之前先来一句backup = stu，把现状拷一份。改砸了，stu = backup一句复原。两行代码，一个后悔药，这就是整体赋值在日常代码里最常见的用法。也要提醒一句，拷贝不是免费的，成员多的结构体每拷一次就多拷一片格子，所以大结构体在函数之间传递时，后面会学到传地址的办法，比整块拷轻便。

拷贝和共享的差别，建议在纸上画一张对比图：左边一片格子标stu，右边一片标stu2，值相同地盘不同；然后在stu上把age改成25，看stu2那片还是20。画完这张图，"同一块内存"和"两份拷贝"就彻底分清了。画图时还有个要点：成员必须连成一片，把age和score画得分开、中间隔空地，那不对，成员挨着住才叫一个整体。

## P7 结构体也有地址：&stu与指向它的指针（约4分钟）

指针前两节课练熟了，现在把它用在结构体上。

先说为什么要用指针操作结构体。今天这个例子，stu.age直接点着访问，好像用不上指针。但你想想以后：一批数据要在函数之间传来传去，拷来拷去成本很高，传个地址就轻便多了；再往后，格子还要在程序跑起来之后动态造出来，那时候你手里就只有地址。指针操作结构体，就是为这些场景准备的，今天先把写法学会。

struct Student *p = &stu。这行你逐段翻译：&stu取结构体变量的地址，装进指针p，p指向stu。规矩和之前完全一样，只是这次指向的格子是一片，不是一格。

顺着指针访问成员，第一个写法：(*p).age。先算括号里的*p，顺着p拿到它指向的整个结构体，再点age取成员。打印出来是20。

这里有个必须强调的坑：括号不能丢。你要是写成*p.age，编译器的理解完全变了。点号的优先级比*高，*p.age会被理解成*(p.age)，先去访问p的成员——可p是指针，哪来的成员，直接报错。所以规矩就一条：先取值再点成员，括号必须写。

这个写法正确，但啰嗦。你想想，结构体指针在代码里出现频率多高，每次都带一对括号，写着烦，看着乱。C语言给这个操作准备了专门的简写，下一页见。

在这之前，先把读这类代码的习惯立好：看到struct Student *p，先画图，一片格子标stu，一个箭头从p指过去。画图也给你个约定：结构体画成一片大格子，指针的箭头就指到这片大格子上。后面不管代码怎么绕，(*p)就是箭头尽头那片格子，点谁就取谁的成员。图在，心不慌。

## P8 p->age：箭头是括号点号的简写（约4分钟）

简写就是箭头：p->age。

一个减号一个大于号，连着写，读作"指向"。p->age的意思是：顺着p指过去，取那个结构体的age。它和(*p).age一字不差，就是写法短了。

为什么箭头长这样？你品一下这个符号：p，然后一个箭头指过去，然后是age。它把"从p出发、指向谁、取谁的成员"这三件事画成了一个符号。读代码的时候，你看到p->age，就在图上画一条从p出发的箭头，箭头落在结构体那片格子上，然后圈出age那几格。符号和图，严丝合缝。

把三种写法摆在一起：stu.age，变量自己点成员；(*p).age，指针先取值再点；p->age，箭头一步到位。三个写法，一个意思。用变量就点，用指针就箭头，这是惯例。

现在回到你以后会反复见到的场景。数据结构的代码里，箭头出现的频率极高，一行里三四个箭头是常态。你现在知道了，箭头不神秘，就是取值再点成员的糖。第一次见可能眼花，见多了就成肌肉记忆。

做个翻译练习。p->age = p->age + 1;。逐段翻：顺着p取出age的当前值，加1，再顺着p放回去。改的是p指向的那个结构体的年龄，其他什么都不动。箭头读熟了，这种句子跟读普通赋值没有区别。

再来一个检验。struct Student *p = &stu; p->score = 95.0;。这行改的是谁的score？

【停顿】

stu的。p指向stu，顺着箭头改的就是stu那片格子里的score。改完你打印stu.score，就是95。

箭头还能连着用，这里给个预告式的例子。假如结构体的某个成员自己也是个指针，那p->next->data这种连箭头写法就是顺理成章的：第一个箭头从p走到next指向的地方，第二个箭头再走一步取data。一行代码走两步。今天你的Student里还没有指针成员，这种写法先看懂意思就行，等你写链表的时候，它会变成你的日常。

## P9 typedef：给类型起别名（约3分钟）

结构体好用，但有个写法上的小麻烦。每次声明变量，都得写struct Student，一个关键字加一个名字，又长又容易漏。漏了struct，编译器就说不认识Student。

typedef就是来解决这个的。它的作用是给类型起别名。看这行：typedef struct Student Stu;。从这以后，Stu就是struct Student的另一个名字。声明变量写Stu stu2 = {21, 90.0};，干净利落。

别名和原名完全等价，就像一个人有大名有小名，喊哪个都是他。你用Stu声明的变量，和用struct Student声明的，是同一种类型，互相赋值没有任何障碍。

你品品typedef带来的变化：声明从struct Student stu变成Stu stu，四个词变两个。一行代码看不出什么，几十行代码里每行都省一截，可读性的提升就出来了。这也是为什么正经代码库都爱用typedef：把长类型名收成短名，代码看起来清爽。

为什么要专门讲这个？因为你以后读数据结构的代码，会大量见到这种别名写法：类型名看起来像个普通单词，前面没有struct。你现在知道了，那多半是typedef起的别名，它的背后还是一个结构体。看到陌生类型名别慌，先问一句：这是不是某个结构体的别名。

顺带把typedef的适用范围说全。它不是只能给结构体起别名，任何类型都行：typedef int Age;之后Age就是int。给int起别名意义不大，但这个能力你要知道，读代码时typedef后面跟什么类型都有可能。还有个常见写法：定义和起别名合在一行，typedef struct Student {...} Stu;，花括号后面直接跟别名，效果和先定义再typedef一样，读代码认得出来就行。

再补一个高频错点。用了typedef之后，有同学回头写原名，把struct漏了：Student stu4;。编译器说不认识Student。记住：原名永远带着struct，别名才是那个短名字。写的时候问自己一句：我现在用的是原名还是别名，前者带帽子，后者不带。

## P10 typedef与#define：一个是别名，一个是文本替换（约3分钟）

有同学会问：起别名这事，#define好像也能干？没错，#define PSTU struct Student，之后写PSTU stu3，看起来效果一样。但这两者的机制完全不同，值得说清楚。

#define是预处理阶段的文本替换。编译器动手之前，预处理器把代码里所有PSTU原样替换成struct Student，它不理解类型，只管抄写，跟查找替换一个性质。typedef不一样，它是编译器正式认可的类型别名，别名参与类型检查，编译器知道Stu是一种类型。

区别在复杂场景下才会显出来，比如声明指针的时候，文本替换容易出岔子。这个细节你现在不用深究，记住选择原则就行：声明类型别名，一律用typedef；#define的老本行是定义常量，比如#define MAX 100。各干各的活，别混用。

举个例子让你感受什么叫文本替换的坑。#define PSTU struct Student之后，写PSTU a, b;，预处理器替换完是struct Student a, b;——这个碰巧没事。但换个场景，比如给指针类型做替换，一行声明两个变量，替换完只有一个是指针，另一个不是。文本替换不懂类型，只管抄，坑就是这么来的。typedef没这个问题，别名就是完整的类型，声明几个变量都是同一种。

这也是你第一次正式接触预处理和编译的分工。#define属于预处理，动手最早，只动文本；typedef属于编译，理解语义。以后见到以#开头的指令，都知道它们是预处理的地盘，今天不展开，但这条分界线你先立住。

## P11 结构体的邻居：结构体数组、联合、枚举（约3分钟）

按老规矩，把这节课知识点的邻居点一遍，让你知道地图的完整形状。

第一个邻居，结构体数组。一个结构体装一个学生，那一个班的学生呢？把结构体排成数组：Stu list[10]，就是十个结构体挨个排成一排，list[0]是第一个学生，list[3]是第四个。数组和结构体一组合，批量数据就有了着落。这个写法以后管理一批同构数据时常用，今天会定义就够了。内存里它的样子，就是十片结构体格子排成一行，和基础阶段的数组一样连成一片，只是每片里面有自己的成员。

第二个邻居，联合，关键字union。它长得和结构体几乎一样，也是花括号列成员，但内存模型完全不同：所有成员共用同一片格子，同一时间里面只住着一个成员的值。空间省了，代价是你得自己记清楚当前住的是谁。我们这门课用不上它，你读代码碰到union，知道它是"多人合租一间屋"就行。

第三个邻居，枚举，关键字enum。它把一组相关的常量名字排成队，比如enum Week {MON, TUE, WED}，让代码里的取值有名字可依。再比如走迷宫表示方向，用枚举比用1、2、3、4好认得多。同样，知道它存在、长什么样就够了。

这三样都不展开，但它们的坐标你记下了：结构体管"打包"，联合管"共用"，枚举管"列名字"，结构体数组管"打包加批量"。

## P12 本节小结（约2分钟）

今天的内容收一下，三件事。

第一，struct把多个成员打包成新类型。定义是画图纸，变量才是格子；点号取成员；花括号后的分号不能丢。结构体在内存里是成员连成的一片格子，整体赋值是逐成员拷贝，拷完各自独立。

第二，结构体有地址，指针可以指向它。顺着指针取成员，(*p).age要带括号，p->age是它的简写。箭头在代码里出现频率极高，看到箭头就画格子上的箭头。

第三，typedef给类型起别名，让声明变干净；它和#define的文本替换是两套机制，起别名用typedef。

你把今天学的东西数一数：新类型、点号、箭头、别名，四样新工具。它们的共同点是什么？都是在给代码起更顺手的名字、找更方便的路。结构体把属性起名打包，点号和箭头是找成员的两条路，typedef是给类型起名。C语言走到这里，越来越像搭积木了。

下一节讲动态内存。今天造变量，格子都是编译器安排好的，下一节学一个更主动的玩法：程序跑起来之后，自己伸手向内存要格子。

## 附录一：课后题参考答案

跟练题：

```c
#include <stdio.h>
struct Book {
    int pages;
    double price;
};
int main(){
    struct Book bk = {320, 45.5};
    printf("%d\n", bk.pages);      // 320
    printf("%.1f\n", bk.price);    // 45.5
    return 0;
}
```

内存图：一片连续格子，前4格住pages（320），后8格住price（45.5），整片标bk。起点编号就是&bk的值。

模仿题：

```c
#include <stdio.h>
struct Book {
    int pages;
    double price;
};
int main(){
    struct Book bk = {320, 45.5};
    struct Book *p = &bk;
    printf("%d\n", (*p).pages);    // 320
    printf("%d\n", p->pages);      // 320
    return 0;
}
```

要点：两次打印结果必须相同，不同就说明括号或箭头写错了。常见错法：写成*p.pages，点号优先级更高，编译器直接报错；漏掉定义末尾的分号，报错位置还经常不在漏分号的那一行。

```c
struct Student {
    int age;

struct Student stu2;

struct Student *p = &stu;

typedef struct Student Stu;
Stu stu3 = {21, 90.0};          // 用别名声明
```
