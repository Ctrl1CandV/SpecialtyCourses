## P6 引题：三个为什么，一个答案（约2分钟）

进入正课。基础阶段留了三个为什么，我当时说好这个阶段讲，现在兑现。

第一个，scanf读数据，变量前面为什么非得写一个&？你基础阶段的作业里照抄了这个写法，抄得对不对？对。但为什么必须写，今天说原因。

第二个，数组下标为什么从0开始，不从1开始？你现在的回答多半是"规定就是这样"。你写了那么多次a[0]、a[i]，从来没怀疑过这个0。规定背后是有道理的，今天给你讲明白。

第三个，数组越界为什么危险？你可能会说，越界会报错。有意思的地方来了：很多时候它根本不报错。为什么错得无声无息，今天也讲清楚。

这三个问题看着不相干，答案其实是同一个东西：内存的地址。今天这节课，我们把地址这个东西彻底搞清楚，三个问题就全解开了。

这三个问题也是802爱考的地方。scanf的&出现在程序阅读的补空里，数组下标和越界出现在阅读题的挖坑里。你把它们的原理搞懂，这类题就是送分题；搞不懂，就是玄学题。今天我们就把它们一次讲透。

## P7 地址：内存格子的编号（约4分钟）

先说地址是什么。

基础阶段我讲过，内存是一长排小格子，一格接一格。当时留了个尾巴没说：每一格其实都有自己的编号，就像街道两边的门牌号。你的变量住进某一格，那一格的编号，就是这个变量的地址。

打个比方。你要让快递员上门修东西，光说"我家有台电脑坏了"没用，你得给地址。内存里的数据也一样，谁想动它，先得知道它住哪。

顺带把基础阶段的另一个知识点接上。int的盒子占4格，char占1格，double占8格。现在你能理解为什么了：类型决定盒子大小，盒子大，占的格子就多，门牌号用的是它第一格的编号。

地址怎么拿到？用&。&放在变量前面，意思是取这个变量的地址。看这段代码：int x = 10，然后printf用%p打印&x。%d是打整数的，%p就是专门打地址的。你跑一下，会看到一串类似0x7ffd开头的数，那就是x住的门牌号。你的机器和我的机器打出来不一样，甚至同一台机器跑两次也不一样，没关系，编号是编译的时候分配的，我们关心的是它有编号这件事，不是编号具体是几。

到这里，第一个为什么就可以解了。scanf("%d", &score)，为什么必须写&？scanf要把你敲的数字放进score住的那个格子，它必须知道格子的门牌号。你不给地址，它拿着数字不知道该往哪放。&score的意思就是：score的地址给你，放进去。

我再问你一个问题：基础阶段说变量是带名字的盒子，既然是带名字的，C语言为什么还要地址？因为名字是给人看的，编译器内部干活靠的是编号。函数之间传数据、scanf往回写数据、后面链表结点连来连去，靠的全是编号。名字只是你在代码里的便利贴。

还有一个细节。你打印&a和&x，两个地址不一样，这很正常，它们住不同的格子。但你同一个程序里多次打印&x，值是一样的，因为x一旦住进去，这间格子就不换了。变量搬家这种事不存在，搬的只是值。

一句话收住：变量是格子，地址是门牌号，&负责把门牌号取出来。

## P8 指针：专门存地址的变量（约4分钟）

地址能取出来，总得有地方存。存地址的变量，就是指针。

看这两行。int x = 10，然后int *p = &x。第二行读起来别扭，我拆开说。int *p是声明，意思是声明一个指针变量p，它专门用来存地址，而且存的是int变量的地址。p = &x是赋值，把x的门牌号放进p。以后p里装的不是10，是x住哪。

初学者最容易在这里犯糊涂：p里到底存的什么？不是10，是x的门牌号。你打印p，看到的是编号；你想看10，得用下一个知识点，马上讲。

习惯上我们说：p指向x。这个说法后面会一直用，你听到"指向"，就理解成"里面存着对方的门牌号"。802的代码里你会见到大量"让某个指针指向某个结点"的说法，全是这个意思。

再补一句。p自己也是个变量，也住在某个格子里，也有自己的门牌号。内存图里它就是一个普通格子，只是里面装的不是数据，是另一个格子的编号。这一点先有个印象，画图的时候你就不会懵。

顺便把写法说清楚。int *p，星号跟谁的问题，不用纠结，写int *p或者int* p编译器都认，802的伪代码里两种都会出现。你看的时候把int *当成一个整体，意思是"int指针类型"。还有一个点：指针也有类型。int *的指针存int的地址，char *存char的地址。类型的作用是告诉编译器，这个指针指向的盒子是多大规格的。现阶段你只需要记住，声明指针要写清楚它指向什么类型。读真题的时候也一样，看到LinkList、BiTree这类名字，先别慌，它们都是指针类型的别名，本质和int *p是一个东西。

从这节课开始，给你立一个贯穿整个强化阶段的规矩：凡是涉及指针，先画内存图。画法很简单，格子三样东西：名字、编号、值，指针画箭头，箭头从p指向x。图一画，指针怎么动你都能跟住；不画图硬想，越想越乱。802的链表题，最后拼的就是谁的图跟得上。

## P9 *p：顺着地址取值（约4分钟）

&是把门牌号取出来，那反过来呢？拿着门牌号找到格子、拿里面的东西，这个操作用星号。

还是刚才那个p。printf("%d", *p)，打印出来是10。*p读作取p指向的值：先看p里存的门牌号，找到那个格子，把里面的东西拿出来。&和*正好互逆：&x拿到地址，*(拿到地址的结果)又回到值。你绕一圈，拿回来的还是原来的值。

关键来了。我写一句*p = 20，会发生什么？顺着p的门牌号找到格子，把里面的10改成20。那个格子是谁的？是x的。所以你再去打印x，x也变成了20。

这里我问你：x和*p是两个变量吗？不是。从头到尾只有一格内存，*p和x是它的两个名字，改谁都是改它。这就是指针的价值：不用碰变量本身，顺着地址就能读它、改它。后面链表的插入删除、函数之间传出结果，全靠这个操作。

顺着这个想一步。如果再来一个指针q，也让它指向x，那q、p、x就是同一格内存的三个名字。这时候你写*q = 5，p和x看到的值都会变。多个名字指向同一块内存，这个现象叫别名。它是指针强大之处，也是链表代码最容易出bug的地方：你以为改的是一个东西，其实好几个指针都跟着变了。今天先记住这个词，等你写链表的时候，它会反复出现。

再说指针的移动。p++是什么意思？p里存的是地址，地址往后挪。注意，不是数值加1个字节，是往后挪一格，指向下一个int格子。你可以把内存想成一排等宽的格子，p++就是箭头往右移一格。

来个小的，你猜输出。int a[3] = {1, 2, 3}，int *p = a，然后p++，再printf("%d", *p)。输出是什么？

【停顿】

p一开始指向a[0]，p++挪到a[1]，*p取出2。答对的同学，指针移动你已经会了；答错的，倒回去把这一段的图自己画一遍。

这里顺带把一个细节说清。p++和++p，区别是先用再加还是先加再用：p++先按现在的值办事，办完再挪；++p先挪再办事。802的代码里，你几乎只会见到先用再加的写法，循环里的i++、遍历链表的p = p->next，都是办完事再走。知道有这回事就行，不用在这花时间。

给你一个读指针代码的笨办法，但是好用：见到&就念"取地址"，见到*就念"取值"，见到指针移动就想象箭头挪一格。三个动作翻译下来，再绕的代码也能拆成一步步的格子操作。读802的程序阅读题，就用这个法子。

## P11 数组名就是首元素的地址（约4分钟）

指针的工具齐了，我们回头看数组，第二个为什么要解了。

基础阶段说过，数组是一排带编号的盒子。现在加上地址的视角：这排盒子在内存里是连成一片的，一格挨着一格，中间不留空。

关键结论：数组名a，就是首元素a[0]的地址。你printf("%p", a)，打出来的就是第一格的门牌号。注意，这里不用写&a，数组名自己就是地址。

有了这个，下标的本质就清楚了。a[2]是什么意思？就是从a这个起点出发，往后数两格，取那一格的值。C语言里有个完全等价的写法：a[2]就是*(a+2)，星号外面套括号。a是起点，a+2是往后两格的地址，取值，就是30。

现在回答那个问题：下标为什么从0开始？因为下标表示的是离起点几格。a[0]就是起点自己，离起点0格；a[1]是离起点1格。从0数，一切顺理成章；要是从1开始，起点自己反而要写成a[1]，那才别扭。

再回头看遍历数组的for循环，i从0到n-1。现在你能看懂它的本质了：i每加一次，就是指针往后挪一格，把整片格子从头走到尾。你以后在802里写的每一个数组遍历，顺序表的循环、打擂台求最值，本质都是指针在走路。

你甚至可以把基础阶段的findMax改写成指针版：p从a出发，每轮比较*p和当前最大值，然后p++，一直走到最后一个格子。逻辑一模一样，只是走路的方式换了。下节课的结构体、以后的链表，全是这个走路套路的延伸。

给你一个检验标准：合上资料，你能把a[i]和*(a+i)互相翻译，这一页你就过关了。顺手考你一个：a[4]等于*(a+几)？对，*(a+4)。下标是几，括号里就是几，永远差不了。

## P12 越界：踩进别人的格子（约3分钟）

第三个为什么，也是今天最要紧的一个点。

看这段代码。int a[5]，五个格子，下标0到4，这个基础阶段就说过，a[5]这个格子不存在。现在我在后面再声明一个int b = 100，b也住在内存里，就住在某片格子里。

然后我写一句：a[5] = 999。

注意，a[5]这个格子根本不属于数组a，它是第六格。那句话的意思是什么？从a的起点出发，往后数五格，找到那一格，把999塞进去。那一格是谁的？不归你管，可能住着b，可能住着别的变量。

这就是越界的真相：不是程序不让你访问，是那片内存不归你，你照样能踩进去。

更麻烦的是，这种错多半没有报错。编译器不一定拦你，程序照样往下跑，只是某个变量的值被悄悄改掉了。你查半天查不出来，因为错的地方和出问题的地方根本不在一起。802的程序阅读题就喜欢在这里挖空考你，问你执行完某个值是多少。

给你归纳一下这类题的样子：一段代码，数组开得刚好，循环边界差一个数，问你最后某个变量是多少。你要是不知道越界踩的是谁的格子，这种题只能瞎猜；会画内存图的人，一格一格数就数出来了。

所以从这道题开始，把内存图当成你的常规武器。读代码先画图，格子里填上值，谁踩了谁的格子一目了然。这个习惯看着慢，实际上是最快的，因为你不用来回猜。

所以规矩立住：写数组访问，先问一句，最大下标是多少。长度是n，最大下标就是n-1，多一步都是别人的地盘。这句话你每次写循环边界的时候默念一遍，能少丢很多分。

## P13 scanf吃回车与野指针（约3分钟）

还有两个坑，今天一起给你填了。

第一个，scanf读字符吃回车。你先scanf("%d", &n)读一个数字，敲完数字要敲回车，这个回车会留在输入缓冲区里。紧接着你再scanf("%c", &ch)，%c不管三七二十一，把回车当字符收走了，看起来就像这行被跳过。你可以自己试一次：打印ch，会发现它既不是你敲的字符，看起来还像空的，其实它的值是10，就是回车的编号。救法两种，记一种就够：要么在%c之前加一句ch = getchar()，专门把残留的回车收走；要么把格式写成" %c"，%c前面加一个空格，它会先跳过所有空白字符再读。

第二个坑更狠，叫野指针。声明了一个指针，没初始化，里面存的是一个没人知道的地址。这时候你对它*p赋值，就是往一片不知道是谁的内存里写东西，比数组越界还危险，因为你连踩进了哪都不知道。规矩只有一条：指针没初始化，就不许用*。要么让它指向一个真实的变量，要么先赋成NULL，表示它现在不指向任何有效的东西，这是C语言里的标准写法。

这两个坑的共同点：出错的时候编译器不提醒你。C语言的风格就是这样，给你自由，也给你责任。802的程序阅读题经常就考这类边界，你心里得有数。

## P14 本节小结（约2分钟）

今天的内容收一下，就三件事。

第一，地址是内存格子的编号。&取地址，*顺着地址取值，两个操作互逆。scanf的&，就是把变量的门牌号交出去，让它找得到地方放数据。

第二，数组名是首元素的地址，a[i]就是*(a+i)。下标从0开始，因为0表示起点自己。越界危险，是因为你踩进了别人的内存，而且多半不报错。

第三，两条安全规矩：指针不初始化不许用；访问数组先确认最大下标是n-1。

今天这节课，是后面一切代码的地基。结构体的结点要靠指针连起来，链表的插入删除就是指针挪来挪去。今天这三件事你要是扎实了，后面会越走越顺；要是还有模糊的地方，别急着往下赶，把这节的内存图再画一遍，画通了再走。

下一节讲结构体和typedef。数据结构里那些结点，就是用这两个东西定义的，学完你就能看懂链表的结点定义长什么样。

## P15 课后任务（约1分钟）

老规矩，两道题。这两道题都不长，但都是后面链表操作的雏形，认真对待。

跟练题：声明int x = 10和一个指向x的指针p，用*p把x改成25并打印出来，然后把每一步的内存图画出来。这道题把今天的四个板书动作重走一遍。画图的时候检查三件事：p的格子里写的是x的门牌号不是10；箭头从p指向x；*p=25之后，被改的是x那一格，p的格子纹丝不动。三件都对，你才是真懂了。

模仿题：声明int a[4] = {1, 2, 3, 4}，不用下标，只用指针p，从a走到a+3，依次打印四个元素。这道题练的是指针走路。它和跟练题正好一对：跟练题练的是"顺着指针改一个格子"，模仿题练的是"让指针自己走起来"，这两个动作合起来，就是后面链表遍历的全部底子。

要求：两道题先写在纸上，再上机验证。合上资料，你能默写两行代码：int *p = &x; 和 *(a+i)。这两行默得出来，指针的入门你就过关了。

最后提醒一句，这个阶段开始的课后题，上机跑出来的结果和你纸上写的对不上时，别急着改纸上那版，先想想差在哪，差异本身就是你还没吃透的地方。纸上写代码的习惯从现在开始养，考场上才不慌。

## 附录一：课后题参考答案

跟练题：

```c
#include <stdio.h>
int main(){
    int x = 10;
    int *p = &x;
    *p = 25;
    printf("%d\n", x);      // 25
    return 0;
}
```

内存图：格子x（值10→25），格子p存x的地址，箭头p→x。*p=25作用在x所在的格子上。推演口诀：先找p里存的门牌号，再顺着门牌号找到格子，最后在格子里改值。三步走完，*p的任何读写你都不会再懵。

模仿题：

```c
#include <stdio.h>
int main(){
    int a[4] = {1, 2, 3, 4};
    int *p = a;
    while(p <= a + 3){
        printf("%d ", *p);
        p++;
    }
    return 0;
}
```

要点：p从a（首元素地址）出发，每轮打印*p后p++，走到a+3为止，共四格。常见错法有两个：一是循环条件写成p <= a + 4，多走一格就踩出去了；二是先p++再打印，第一个元素就被跳过了。对照这两个坑检查一下你写的版本。两个坑都躲开，说明你真的理解了"指针走路"是怎么回事。

## 附录二：本节代码合集

本节出现的代码都在下面，顺序和讲课顺序一致。默写的时候按"取地址、存指针、取值、移动、数组等价写法"这条线来，能串下来就说明结构清楚了。

```c
int x = 10;
printf("%p", &x);               // 打印地址，%p专门打地址

int *p = &x;                    // p指向x

*p = 20;                        // x也变成20，改的是同一格

int a[5] = {10, 20, 30, 40, 50};
printf("%p", a);                // 数组名就是首元素地址
printf("%d", *(a + 2));         // 30：a[i]就是*(a+i)

scanf("%d", &n);
ch = getchar();                 // 收走残留回车
```
