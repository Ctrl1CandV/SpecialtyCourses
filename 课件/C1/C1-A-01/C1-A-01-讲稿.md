## 课段导学部分（第1—6页，约5分钟）

## P1 封面页

大家好，我是牙膏学长。从这节课开始，我们正式进入C语言基础，这也是整个代码课程的第一讲，主题是初识C程序。开始之前先说一句：课程资料、答疑还有后面的更新，都在伴梦研途的QQ群里，需要的同学先加一下。

前面五分钟我先做个课段导学，把这门C语言基础到底教什么、怎么学、适不适合你，一次讲清楚，免得你学到一半才发现走错门。

## P2 课段定位页

先说这门课在802里到底值多少分。整张卷子里，程序阅读题大概20分，就是给你一段代码挖几个空、让你补出来或者分析功能；算法分析题30分，三道大题，直接让你写代码。这加起来五十分的东西，底子全在C语言——你连if、while、数组都读不顺，后面数据结构的代码根本无从谈起。所以这门课不是可有可无的前置，是地基。

我给这门课定的目标很实在：一共5讲、3小时左右，学完你能读懂一段最简单的C程序、能自己写出顺序结构的代码。指针我故意压后了，放到强化阶段专门讲，这节到第5讲都不碰它——零基础一上来碰指针，十个有九个被劝退，这个坑我替你们绕开。

## P3 课段目录页

五讲怎么排我给大家过一遍。第1讲就是今天，讲程序的骨架，main、printf、#define这些；第2讲讲数据类型、变量，还有怎么用scanf、printf做输入输出；第3讲讲运算符，重点是取模那个百分号，后面判断奇偶、取个位全靠它；第4讲讲分支和循环；第5讲讲函数和数组。

我的安排原则就一条：一讲只立一个核心概念，不贪多。每讲三四十分钟，跟得住。这五讲走完，才进指针和结构体的强化阶段，那块才是整个C语言真正的重头戏。

## P4 选课建议页

这门课不是所有人都得从头听。你对号入座：完全没写过代码、或者跨考过来的，老老实实从第1讲跟到底；学过C但忘得差不多的，翻目录挑生疏的那几讲补一补就行；要是你现在就能自己写出带if、带循环、带数组的小程序，那这门课你可以跳过，直接去强化阶段，别浪费时间。

我给你一个自测的办法：合上视频，能不能独立写一个读入两个数、判断大小再输出的程序。写得出来，就跳；卡壳了，就从头跟。

## P5 学习要求与衔接页

学法上我提四个要求，都是我自己当年走过来觉得真管用的。第一，跟练——我写一行你跟着敲一行，只用眼睛看不动手，等于没学，这是我踩过的最大的坑。第二，手撕——课后合上笔记，凭记忆把代码写一遍，写不出来再翻，翻完再写。第三，默写——基础的模板代码得能默出来，这是考场上的保底分。第四，每讲我都留一道跟练题、一道模仿题，答案在讲稿附录里，别嫌少，做完了这门课才算过关。

还有一件事我提前打个招呼：这五讲我只讲怎么用，不讲为什么。比如scanf为什么要加那个&号、函数里改了值为什么外面没变——这些背后全是地址和指针，我统一留到强化阶段一次说透。你现在遇到这类"为什么"，先别纠结，记住用法照着写就行，我埋的这些坑后面都会填。

## 正课：初识C程序（第7—15页，约30分钟）

## P7 引题页（约2分钟）

先看两行代码：

printf("你好，重邮802！\n");
printf("我是牙膏学长\n");

你不用是行内人，也能猜到它是往屏幕上打两行字。但我要问的是下一层：这两行字到底是怎么跑到屏幕上的？为什么非得写成这个样子，括号、双引号、分号，各自在干嘛，少一个行不行？

我当初自学的时候，就是看得懂、写不出——照着抄能跑，让我自己从空白写一个就卡壳。这一讲我带你把这两行拆到最细，讲完你不光看得懂，合上书自己也能敲出来。

## P8 思想先行页（约3分钟）

上来先建立一个最粗的框架：一个程序，说到底就三件事——输入、处理、输出。数据进来，按你写的指令一步步算，最后把结果吐出来给人看。这一讲我们只碰最后一环，输出，printf干的就是把结果打到屏幕上这件事。

那问题来了，我想让电脑打两行字，为什么不能直接跟它说，非得写C？因为电脑本质上只认0和1，你跟它说人话它听不懂。C语言就是中间那个翻译：你把想法写成C代码，有一个叫编译器的东西，把你这段代码翻译成电脑能执行的0和1，它才动。所以你写的.c文件，是要先编译、再运行的，这个过程后面第几讲用到编译器我再带你走一遍，这里先有个印象就行。

还有一句我必须提前跟你交代清楚，免得你后面纠结：802考场上写的是伪代码，不用写#include，也不用写main，一段函数就够了。但现在是打地基阶段，我要你先把一个完整的、能跑起来的程序从头写通，骨架长什么样心里有数，之后再谈简化。地基没打，直接学伪代码，你写出来的东西自己都不知道对不对。

## P9 程序骨架页（约4分钟）

来看第一个完整程序。别急着记代码，先跟我把它拆成五块，每一块干嘛你搞清楚，这个骨架你就拿下了。

第一块，头文件，#include <stdio.h>。你可以把它理解成"借工具"——printf这个打印工具不是你写的，是别人早写好放在stdio.h这个仓库里的。你要用它，就得在开头先把这个仓库搬进来。不搬，编译器不认识printf，直接报错。stdio就是standard input output，标准输入输出，管的就是屏幕打印和键盘读入这些事。

第二块，宏定义，#define MaxSize 1000。意思是给1000起个名字叫MaxSize，后面凡是写MaxSize的地方，编译器都当成1000。这个先眼熟一下，为什么有用第11页我专门讲。

第三块，主函数，int main()。这是整个程序的大门，不管你代码写了几百行，电脑一律从main这里开始执行。你以后拿到一段陌生代码，第一件事就是找main。

第四块，函数体，就是main后面那对花括号{}里包住的内容。里面的指令，从上往下一条一条执行，没有例外。

第五块，return 0。程序跑完了，跟操作系统报个信：我正常结束了，没出岔子。

这五块的名字先记住：头文件、宏定义、主函数、函数体、return 0。后面几讲会把它们一个一个拆开细讲，这节课你先建立"程序是分块的"这个感觉。

## P10 代码精讲页（约6分钟）

骨架拆完，现在一行一行抠，重点抠那几个初学最容易栽跟头的地方。

#include <stdio.h>，借工具，printf住在这。
#define MaxSize 1000，起名字，后面写MaxSize就是1000。
int main()，大门，从这开始跑。
printf("你好！\n");，打印，双引号里写啥屏幕就出啥，\n是换行。
return 0;，正常收工。

这里面有四个点我要你死死记住，考场上、平时敲代码，栽的都是这四个：

第一，main是入口，程序永远从它开始。这条我在骨架里说过，这里再钉一遍——看别人代码先找main，是习惯。

第二，printf是打印工具，双引号里是什么，屏幕就原样输出什么。注意"原样"两个字，你双引号里写空格它就打空格，写错别字它照打不误，电脑不帮你纠错。

第三，\n是换行符。它是一个整体，一个反斜杠加一个字母n，别写成斜杠。没有它，你printf两次的内容会挤在同一行连成一串。它自己不显示，作用只是让光标跳到下一行。

第四，分号。C语言里一条语句写完，末尾必须有分号，它相当于中文的句号。少一个，编译器就报错，而且报错位置常常还不在你漏的那行，初学者能找半天。所以从现在起，写完一句先补分号。

【板书】在代码旁把这四个要点圈出来：main、printf、\n、分号。

## P11 define与注释页（约3分钟）

再补两个小工具，都不难，但后面天天用。

第一个是#define。#define MaxSize 1000，给1000起名叫MaxSize；#define PI 3.14，以后写PI就是3.14。它好在哪？假设你程序里几十个地方用到1000，哪天要改成2000，你一个个找过去改，改漏一个就是bug；用了#define，只改开头这一行，全程序跟着变。

这里我顺便点一个考点，你先记着：802真题里顺序表的定义几乎必出#define MaxSize 100这种写法，数组开多大就是从这来的。到数据结构那块你会天天见它，现在混个脸熟。

第二个是注释。两条斜杠 // 后面到行尾，是单行注释；/* 和 */ 中间夹的，是多行注释。注释是写给人看的，编译器直接跳过，不影响程序运行。

那既然电脑不看，为什么还要写？两个原因。一是给你自己看，代码放两个月你自己都忘了当时怎么想的，注释就是给未来的你留的线索。二是给阅卷老师看——802答题要求写"算法思想"，说白了，就是把你脑子里的注释扩写成一段话。你平时写代码有注释习惯，考场上思路自然就顺出来了。所以这个习惯，从第一讲就得开始养。

## P12 板书推演页（约5分钟）

光听没用，代码是手艺活，得自己写。现在跟着我，从一张空白开始，一步一步把第一个程序敲出来。我写一行，你在纸上或者编辑器里跟一行，别只用眼睛看。

【板书】
第一步，先搬工具，写头文件：#include <stdio.h>
第二步，写大门，主函数开头：int main(){
第三步，写第一句输出：printf("第一行\n");
第四步，再来一句：printf("第二行\n");
第五步，收工：return 0;
第六步，别忘了把大门关上，补右花括号：}

写完先别急着往下，回头查三样东西，这也是我自己养成的习惯：每句末尾分号补了没、双引号是不是一对一对的、花括号有没有一开一闭。这三样是初学者报错的重灾区。

【停顿】给你半分钟，照这三条自己过一遍。

## P13 板书结论页（约2分钟）

对一下答案，你写出来的应该是这样：

#include <stdio.h>
int main(){
    printf("第一行\n");
    printf("第二行\n");
    return 0;
}

跑起来，屏幕上就是干干净净两行：

第一行
第二行

再强调一次那个最容易迷惑人的点：\n本身不会打在屏幕上，你看不到它。它干的活只有一个，让后面的内容换到下一行去。你要是把两个printf里的\n都删了，这两行就会连成"第一行第二行"挤在一块，自己动手试一下，印象最深。

## P14 总结页（约2分钟）

这一讲的东西不多，但都是地基：一个C程序从main进门，靠printf往外打字，每句话用分号收尾，这套骨架你得刻进肌肉里。

这节没有算法，所以不谈复杂度，那套东西从下一讲用到的时候我再带你算。

最后专门给你列四个坑，我保证你初学阶段一个都躲不过：忘写分号、大小写写混（main写成Main就不认了）、把英文双引号敲成了中文引号、花括号忘了配对。这四个错，人人都犯，不丢人，关键是养成写完扫一眼的习惯——分号、引号、花括号，过一遍再编译，能帮你省下大把找错的时间。

## P15 课后任务页（约1分钟）

留两道题，一道跟练一道模仿，都不难，但你一定要动手，光看不写这节课就白上了。

跟练题：自己写一个程序，分三行打印出你的名字、你的本科学校、你的考研目标。就照着课上的程序改，练的是把骨架默出来。

模仿题：把课上的程序改一改，只用一条printf，打印出三行诗。提示我给你：\n不是只能放句尾，放在字符串中间照样换行，你试试就懂了。

对你的要求就一条：合上笔记，能凭记忆把main那套骨架完整写出来。做不到就回看P12，多写两遍。

这一讲就到这，下一讲我们讲数据类型和变量，看看数据在电脑里到底是怎么存的。下次见。
