## P2 引题：代码越写越长，怎么管（约2分钟）

首先思考一个问题，前四节咱们写的程序，所有代码都挤在main函数里。十几行是没问题的，能看得过来，但802的程序代码，一个链表操作动辄几十行，要是全挤在一个main里，几百行代码堆在一起，显得很混乱。那么代码一长，就需要管理。怎么管？我们所用到的两个方法，正好是今天要学的两样。

第一个是函数，就是把一段干活的步骤打包，然后再起个名字，要用的时候喊名字就行。你去看802的伪代码，全是这个结构：InitList是初始化函数，ListInsert是插入函数，DFS是深度优先遍历函数。802的算法，本质上就是一个个函数，今天先把函数是怎么回事搞明白，后面读伪代码、写伪代码都会方便许多。

第二个是数组。前面咱们存数据，都是一个变量存一个数。可802里是一张顺序表存100个数、一个栈存一堆元素，这种"一批同类型的数据"，得有个东西批量装下，这就是数组。

我们分享一道真题，你感受下函数和数组的必要性。2026年那道约瑟夫环，题目说n个人围成一圈报数，要模拟这个过程的话，你首先得有一个东西把这n个人存起来，这就是数组或者链表；你得反复地报数、出列、继续，这就是循环加判断。一道8分的算法大题，拆开就是"存一批数据"加"反复处理"。数组和循环、函数，就是解这类题的基本零件。今天把零件配齐，后面才有得拼。函数的意义是"步骤打包"，数组则是"批量存数据"。这两样学习，你的C语言基础就齐了。

## P3 函数是什么：打包好的干活步骤（约2.5分钟）

先讲函数，那么函数是什么？我用做菜给你打比方，你就能懂了，先看这张表：

| 做菜    | 函数      |
| ----- | ------- |
| 菜谱名字  | 函数名     |
| 需要的食材 | 参数（输入）  |
| 做出来的菜 | 返回值（输出） |
| 做菜步骤  | 函数体     |

你做一道番茄炒蛋，菜谱有个名字，叫"番茄炒蛋"；你需要食材，番茄和鸡蛋；你按步骤做，最后端出一盘菜。这与函数一模一样：它有个名字；它需要原料，叫参数；它按步骤干活，这个步骤叫函数体；干完活交出一个结果，叫返回值。这个类比你要记牢，因为函数在802里太重要了。你以后写算法，本质上就是"写一道菜的菜谱"——把解题步骤打包成一个函数，题目给你什么参数，你按步骤加工，给出对应的返回值。函数最大的好处是**打包复用**。你把一段步骤打包起名之后，要用的时候喊一声名字就行，不用把步骤重写一遍。而且改的时候只改函数里那一处，所有调用它的地方全跟着变。

除了复用，函数还有第二个大好处：**让代码有层次**。你想想802的一道算法大题，如果你的答案是一坨从头到尾的流水账代码，阅卷老师要在几百行里找你的思路，很痛苦。但如果你按功能拆成几个函数——初始化一个、核心处理一个——每个函数就干一件事，代码就有了清晰的层次。阅卷看的舒服，你自己改起来也清楚。所以函数不光是省事，它是把代码组织起来的基本手段。

还有一个点你注意：你从第一节起就在用函数了——printf就是一个函数，scanf也是。你调用printf("你好")，就是在喊printf的名字、把"你好"这个原料交给它。前面四节你一直在调用别人写好的函数，从今天起，你学会自己**定义**函数了。从"用别人的"到"写自己的"，这是一个改变。

## P4 定义一个函数：四部分（约3分钟）

来看怎么定义一个函数，这里的代码是求两个数最大值的函数，一个函数定义，分为四个部分。

第一个，**返回类型**，就是最前面那个int。它说的是：这个函数结束后，交出来的东西是什么类型。这里的max是进行两个整数的比较，交出来的自然是一个整数，所以写int。

第二个，**函数名**，max就是函数的名称，跟变量命名一个规矩。

第三个，**参数**，括号里的 int a, int b。这是干活需要的原料。max需要两个数才能比大小，所以要两个参数。参数可以有多个，用逗号隔开，也可以一个都没有。

第四个，**函数体**，大括号里的干活步骤。max的活儿很简单：如果a大于b，把a交出去；否则把b交出去。

这里出现了一个新关键字，**return**。它的意思是上交结果。return a，就是把a这个值交出去，交给谁？交给调用max的那个地方。你把这四部分连起来看一遍：定义一个函数，名叫max，它接收两个int原料a和b，干完活交出一个int结果，结果就是俩数里大的那个。这里有个书写位置的问题，函数要么写在main的**前面**，要么先在前面声明、后面再定义。最省事的做法，就是像这样把函数整个写在main上面。你要是把函数写在main下面，又不提前声明，编译器读到main里的调用时还不认识这个函数，就会报错。所以养成习惯：**自己定义的函数，放在main上面**，今天板书我们就是这么干的。

## P5 调用函数：喊名字，交原料，收结果（约2.5分钟）

函数定义好了，那么要怎么调用呢。我们看这段代码，调用就是三个动作：**写函数名，把参数放进括号，然后取走返回值**。我喊max这个名字；括号里放3和8，这就是交给它的原料——3给了a，8给了b；max干完活，把结果8交出来；我用m把这个结果接住。最后打印m，打出8。

程序执行到这里，会发生什么？程序本来在main里一行行往下走，走到 max(3, 8)，**跳进max函数里**，从max的第一行开始干活，干到return，**带着结果跳回来**，回到刚才调用的地方，继续往下走。这里给你埋个悬念。我刚才说"3给了a，8给了b"，这个"给"到底是怎么给的？我在max里改了a，外面的3会变吗？这个问题，涉及参数传递的机制，是强化阶段的重点，今天先不展开。你现在只要会读、会写、知道"原料进、结果出"，就够了。

## P6 return 的两件事（约2分钟）

return这个关键字，我们再讲细的看一看，它干两件事。第一件是**交出结果**。return n / 2，把n除以2的结果交出去。第二件是，**立刻结束函数**。你看这个half，如果n小于0，它return -1，函数到此为止，后面的return n/2根本不执行。return就像函数的"出口"，走到return，函数立刻结束，后面的代码一行都不跑。

所以一个函数里可以有多个return，但**每次执行只会走一个**——走到哪个return，就从哪个出口出去。half有两个return，但n要么是负数走第一个，要么不是走第二个，一次只走一个。还有一种函数，返回类型写**void**。void的意思是"没有返回值"，这种函数只管干活，不交结果。比如打印一段话、遍历一张表，干完就完了，不需要交出什么。802里很多遍历函数就是void的，你后面会见到。

给你串一下802的实例，你就知道返回类型怎么选。InitList初始化顺序表，要报告"初始化成功还是失败"，所以它返回bool；LocateElem按值查找，要把"元素在表里第几个位置"告诉你，所以返回int；而层序遍历二叉树，它的活儿就是把结点一个个打印出来，不需要报告什么，所以是void。**函数交不交结果、交什么结果，取决于它干的活需要向外面报告什么**。你以后自己写函数，先想清楚这个问题，返回类型自然就定了。

## P7 数组登场：一排带编号的盒子（约2.5分钟）

函数讲完，现在讲数组。先思考一个问题，如果我要存5个同学的成绩，怎么办？按前面学的，那么我就要声明5个变量：score1、score2、score3、score4、score5。5个还能忍，那我要存100个呢？声明100个变量？而且这100个变量名字都不一样，你想用循环统一处理它们都做不到，数组就是来解决这个问题的。**数组就是一排带编号的盒子**，这一排盒子装的都是同一种类型的数据。

第一行的意思是，给我一排5个int盒子。注意，这5个盒子有编号，编号叫**下标**。然后关键来的是，**下标从0开始**。所以这5个盒子的下标是0、1、2、3、4。第一个盒子是score[0]，第二个是score[1]，最后一个是score[4]。

装东西、取东西，都用下标：score[0] = 85，就是往编号0的盒子里放85。

这里给你补一个初始化的细节。声明数组的时候，int score[5]; 这5个盒子里装的是什么？是不确定的值，不是0。你别想当然以为是0，没初始化的数组，里面是内存里残留的垃圾值。你要是想让它全变0，得用初始化：int score[5] = {0}; 这个写法会把所有盒子都置0。802伪代码里那个"把visited数组初始化为false"、"把data清零"，对应的就是这个动作——用之前先清零，是个好习惯。

为什么下标从0开始？这个跟内存地址的计算方式有关，是C语言的设计选择，你现在记住"从0开始"这个事实就行，原理强化阶段讲地址的时候一起说。这里通俗的说：数组名其实指向第一个盒子的位置，a[0]的意思就是"从第一个盒子出发，往后挪0格"，a[3]就是"往后挪3格"。从0开始数"挪几格"，比从1开始数"第几个"，在地址计算上更直接。

802里数组有多重要？顺序表的底层就是数组，栈的data是数组，队列的data也是数组。你后面学的线性结构，一大半都站在数组上。

## P8 本节难忘时刻：int a[5]，最大下标是几？（约2.5分钟）

好现在我们要讲一个重要的问题：int a[5]这个数组，最大下标是几？答案是4。a[5]是5个盒子，下标从0开始，是0、1、2、3、4。**最大下标是4，是长度减1**。根本没有a[5]这个盒子。那我要是写了 a[5] = 10，会怎样？

这就是**越界**——你伸手去拿一个不存在的盒子。最难理解的地方来了：这个错，**编译器依然不报错**。程序照样跑。但你访问的是不属于你的内存，可能把拿到别人的数据，程序行为就变得莫名其妙。这种不报错的错，比报错的错危险得多。

有条件的你真跑一遍，写个printf("%d", a[5])，你会发现编译器一声不吭。亲眼看到越界的输出，你才会真正敬畏数组的边界。记住一句话：**数组下标，最大是长度减1**。写循环遍历数组的时候，条件写 i < 长度，别写 i <= 长度——上一节讲的差一错误，在数组这里就是最典型的战场。802的程序阅读题，就爱考你这种边界判断。

## P9 初始化与遍历（约2.5分钟）

数组怎么装数据、怎么挨个处理？有两个标准动作。

第一个，**初始化**，声明的同时装好：

int a[5] = {3, 1, 4, 1, 5};花括号里把5个数写好，a[0]就是3，a[1]就是1，依次装进去。这比一个个赋值省事。

第二个，**遍历**，用for循环挨个访问：你看这个for，它感觉就是为数组量身定做的。i从0开始——因为下标从0开始；i < 5——因为最大下标是4，i取到4就停，绝不越界；每轮i++，下标往后挪一个。循环体里a[i]，i是几就访问几号盒子。

这个"for循环遍历数组"的写法，是编程里最最基础的模式之一，802里你会见到无数次。上一节学的for，到这一节才有了真正的用武之地——for和数组是天作之合，一个负责数下标，一个负责按下标取数据。

给你三个遍历的变体，都是802常见的，认个脸熟。第一种，求和：循环体里写 s += a[i]，把每个元素累进s。第二种，找最值：循环体里写 if(a[i] > m) m = a[i]。第三种，计数：循环体里写 if(条件) count++，数满足条件的有几个。你看，**遍历的框架一模一样，变的只是循环体里那一两句**。802的线性表算法，绝大多数就是"遍历框架+循环体里做点事"。把这个模式吃透，你读那些算法就是认字。你把这两个动作连起来：初始化把数据装进一排盒子，for循环按下标把盒子一个个打开。这就是处理一批数据的标准流程。

## P10 数组做函数参数（约2.5分钟）

现在把函数和数组合起来用——把一个数组交给函数处理。这是802算法函数的标准形态，你必须掌握。这个函数求数组所有元素的和。看它的参数：**int a[], int n**。a[]是数组，n是数组的长度。为什么要把长度n单独传进来？因为数组交给函数之后，**函数里不知道这个数组有多长**。a[]只告诉函数"这是一个int数组"，但不告诉它有几个元素。所以你得把长度n也传进去，函数才知道循环该转到哪。

这个"数组+长度"的参数搭配，在802里到处都是。你以后看到的算法函数，参数表几乎全是这个模式：一个数组，加一个表示长度或规模的数。比如折半查找，传数组、传low、传high；比如排序，传数组、传长度。调用也给你看一眼：sum(a, 5)，把数组a和它的长度5一起交进去。

这里藏着一个跟上一节呼应的点。你注意到没有，sum函数里那个 for(int i = 0; i < n; i++)，它用n来控边界，而不是写死5。为什么？因为这个函数要能处理**任意长度**的数组——今天传5个，明天传100个，函数都能接得住。这就是把长度当参数传的意义：**让函数变得通用**。你写802算法的时候也要有这个意识，边界永远用参数里的长度变量去控，别写死数字。写死数字的算法，换个数据规模就废了。

## P11 字符数组与字符串（约2分钟）

基础阶段最后一个知识点，是字符数组和字符串。这个点是给后面串章节铺路的，今天建立印象。我用一个字符串"hello"初始化一个字符数组。你猜这个数组里实际存了几个字符？不是5个，是**6个**。除了h、e、l、l、o这5个字符，结尾还偷偷多了一个字符，叫 **'\\0'**，读作"空字符"。

这个'\\0'是干嘛的？它是**结束标记**，告诉程序"字符串到此为止"。C语言的字符串没有专门记录长度，它靠这个'\\0'来知道哪里是结尾。你打印一个字符串，程序就是一个字符一个字符打，打到遇见'\\0'就停止。strlen求字符串长度，也是从头数到'\\0'之前。

所以记住这句话：**字符串 = 字符数组 + 结尾的'\\0'**。'\\0'不算在字符串的内容里，但它占一个格子，是字符串的"句号"。

这个概念为什么现在讲？因为你后面学数据结构，串这一章的BF匹配、KMP手算，全都建立在"字符串以'\\0'结尾"这个认知上，此外还有一些边界处理也要考虑到这个"\0"。]给你看一个'\\0'发挥作用的具体例子。strlen("hello")的结果是5，不是6——它从头数，数到'\\0'就停，'\\0'本身不算长度。再比如printf("%s", s)打印字符串，它也是一个字符一个字符往外吐，吐到遇见'\\0'为止。你看，strlen和printf都不需要别人告诉它们字符串多长，它们自己顺着数组找，找到'\\0'就知道到头了。这就是结束标记的意义：**长度信息藏在结尾里**。

## P12 板书推演：从零写，函数求数组最大值（约5分钟）

现在动手，收官板书。今天这个程序把函数和数组全用上了：定义一个函数处理数组，在main里调用它。

我写一行，你跟一行。

【板书】
第一步，头文件：#include <stdio.h>
第二步，先定义函数，写在main前面：
    int findMax(int a[], int n){
        int m = a[0];
        for(int i = 1; i < n; i++)
            if(a[i] > m) m = a[i];
        return m;
    }
第三步，写main大门：int main(){
第四步，声明数组：
    int a[4] = {3, 9, 2, 7};
第五步，调用函数并打印：
    printf("最大值：%d\n", findMax(a, 4));
第六步，收工：return 0; 补右花括号：}

这里有两个点你注意。第一，函数写在main**前面**。C语言要求函数先定义后使用，所以findMax放在main上面。第二，数组传参要**带长度**，findMax(a, 4)，数组和长度一起交。

我们用上一节学的列表格追踪法，把这个循环走一遍，你彻底吃透它。数组是{3, 9, 2, 7}，m一开始是a[0]，也就是3。第一轮，i=1，a[1]是9，9比m大，m更新成9；第二轮，i=2，a[2]是2，2不比9大，m不动，还是9；第三轮，i=3，a[3]是7，7不比9大，m还是9。循环结束，m是9。你看，每一步都清清楚楚，这就是打擂台。这个追踪能力，你读802任何带循环的算法都用得上。

写完检查。分号、引号、花括号，老规矩。今天加两条：函数定义四部分齐不齐，数组传参带没带长度。

## P13 板书结论（约1分钟）
