## P1 封面页（约0.5分钟）

大家好，我是牙膏学长。这节课是第二讲，讲数据类型、变量、输入输出。上一节咱们把程序的骨架认全了，这一节，往骨架里填装灵活可变的数据。

## P2 引题：硬编码的代码，应付不了真题（约2分钟）

先看上一节我们写的printf函数：printf("第一行\n");

它打出来的"第一行"这三个字，是咱们写代码的时候就写死在那的。跑一百遍，它都是这三个字，一个字都不会变。

但是802的题目不是这样的。你随便翻一道算法大题，题目会说：给定一个整数k，k是多少，题目说了算；给你一张顺序表，表里每个元素的值，是算出来的、是输入进来的。这些值，你写代码的时候根本不知道它是什么。那问题就来了——这些"活"的数据，从哪来往哪放？

这就是咱们这一节要解决的事，我先简单的把名字报给你：变量，存数据用的；数据类型，告诉编译器这个数据长什么样、占多大内存；printf和scanf，一个把数据输出到屏幕，一个把数据从键盘拿进来。这三样东西，从这节开始，一直到后面写链表、写树的算法，天天都用。说它是后面所有章节的地基，一点不夸张。

## P4 变量 = 带名字的盒子（约3分钟）

先讲变量。变量是什么？我给你打个比方，**变量，就是内存里一个带名字的盒子**。

首先内存是什么？内存就是一长排小格子，一格接一格，从0号一直排下去，多得你数不过来。程序要存数据，总得找个格子放进去。可格子那么多，编号那么长，怎么办？C语言就让你给某一个格子起个名字，然后去存放那个指定的数据。

你可能会问：直接用格子编号不就行了，为什么非得起名？两个原因。第一，编号是编译器分配的，你根本不知道它把数据放在了第几格，今天放这格、明天可能就换一格了；第二，名字有含义。你写score，一眼就知道这里存的是分数，只写个编号1024，别人和未来的自己都不知道它是干嘛的。**变量名是写给人看的，编号是给机器用的**，一个好的取名能方便自己，也方便老师。

比如我写这么一行：score = 125。这行的意思就是——找一个叫score的格子，把125塞进去。以后代码里只要我写score，编译器就去这个格子里，把125给我拿出来用。而且盒子是可以反复盖的：我再写一句 score = 130，原来的125就被盖掉了，盒子里只剩最新的那个值。这一点跟数学里的数不一样，数学里的数不变，变量是真的会"变"的——它是一个盒子，里面放什么是可以变化的。来，看这张表，有三种盒子：

| 盒子名   | 盒子规格   | 装的东西 |
| ----- | ------ | ---- |
| score | int    | 125  |
| level | char   | 'A'  |
| pi    | double | 3.14 |

score这个盒子，规格是int，里面装125；level规格是char，装一个字符A；pi规格是double，装小数3.14。我们可以发现，盒子名、盒子规格、装的东西，这三样，就是变量的全部。

再给你埋个悬念。这些格子，其实每一格都确实有一个编号，这个编号叫**地址**。地址有什么用、scanf为什么非得写那个&、指针为什么能指来指去——答案全在地址上。但这个我这节不讲，留到强化阶段讲指针的时候，一次给你说透。你现在就记住一件事：变量是带名字的盒子就够了。

## P5 802用得到的类型，就四种（约3分钟）

盒子有了，接下来看盒子的规格，也就是类型。C语言的类型其实挺多的，但是咱们这门课，只讲802真题里真用得上的，就四种，我一个个说。

第一个，**int**。装整数的，盒子大小4个字节。考研分数、题目给的整数参数，全是它。你去看802的代码，出现频率最高的就是int——顺序表的length是int，数组下标是int，真题里给你的那个k也是int。

第二个，**char**。装字符的，盒子最小，1个字节。注意，char装的是**一个**字符，用单引号括起来，比如'A'。你上一节见过的'\n'，它本质上也是一个char——一个特殊的、代表换行的字符。所以"字符"这个东西，比你想象的要宽一点。

这里顺带说一个有意思的事，PPT下面那行小字：'A'在电脑里存的，其实是数字65。字符和整数，底层是相通的——每一个字符背后，都对应一个整数编号。这个知识点你现在混个眼熟就行，后面802的手算题、还有讲字符比较的时候，会用到。

第三个，**double**。装包含小数的，8个字节。求平均数、圆周率这种带小数点的数就用它。

第四个，**bool**。装真假的。这个我放到最后单独讲，因为它太特殊了，802伪代码里出现频率高得离谱。

把这四个对应关系记一下：整数int、字符char、小数double、判断bool。就这四个，后面所有数据结构代码，元素类型翻来覆去也逃不出这四个。

哦对，还有一句话必须交代。你在真题和笔记里会看到一个词，叫ElemType。它是"元素类型"的占位写法，意思是"这里可以是任何类型"，别被它唬住。

## P6 先开盒子，再放东西（约3.5分钟）

类型认完了，看怎么用。四行代码，摆在这：

int score;            // 声明：先占一个盒子
score = 125;          // 赋值：把数据放进去
int target = 120;     // 声明的同时赋初值（初始化）
score = score + 5;    // 把右边算出的结果，放回左边的盒子

先看第一行，int score; 这句是在干嘛？是在跟编译器打招呼：给我准备一个int规格的盒子，名字叫score。这句执行完，内存里就有这个盒子了。注意，这时候盒子是**空的**，还没放东西。这个动作，叫**声明**。

第二行，score = 125; 这才是往盒子里放东西。这个动作，叫**赋值**。

第三行是一行同时干了两件事：开盒子、放东西，就是声明加初始化。

然后第四行是重点中的重点，初学者会对这一句很困惑：score = score + 5;

这在数学中完全行不通，一个数，怎么会等于自己加5？**但C语言里的等号，不是"等于"，是"赋值"**。

怎么读？从右往左读：先把右边的 score + 5 算出来，125加5，等于130，再把130塞回score这个盒子，把原来的125盖掉。盒子还是那个盒子，里面的东西换了。你看，同样一个等号，换个读法，这句就通了。这就是为什么我反复说：等号是赋值，不是等于。这句你记死了，后面讲判断的时候，你会少掉一个巨大的坑——那个坑咱们下一节填。

再补两条规则，都简单。第一，变量必须**先声明再使用**。你没声明就写score=125，编译器直接报错，因为它找不到这个盒子。第二，命名规则：字母、数字、下划线都行，但不能数字开头——score可以，score2可以，2score不行。另外C语言区分大小写，Score和score是两个盒子，别写混了。

## P7 int x = 3.9，x里是几？（约2.5分钟）

来，本节最好玩的一个点，也是你一定会踩的坑。我问你：

int x = 3.9; 然后打印x，出来是几？可能有同学心里答的是4。数学思维嘛，3.9四舍五入，不就是4吗？但是C语言**不四舍五入**，答案是**3**。

为什么？因为x这个盒子，规格是int，int是装整数的。你现在往里塞一个小数3.9，盒子装不下小数部分，怎么办？C语言的处理方式很干脆——小数点后面那部分，**直接切掉，扔掉**。学名叫截断。注意，是切掉，不是四舍五入。3.9变3，3.1也变3，3.9999还是变3。

为什么C语言要这么干脆地切掉，而不是帮你四舍五入？因为四舍五入是要额外算的，得判断小数部分够不够0.5，够才进位。C语言的设计哲学是"不为你没要求的事偷偷干活"，你既然声明的是int，它就直接把装不下的部分扔掉，后面很多不同类型的兼容也是遵循这个规范。

那我要真想装3.9怎么办？那就得用double盒子：double x = 3.9; 就完整存下了。所以记住一句话：**类型决定盒子能装什么**。装整数用int，装小数用double。802伪代码里写长度、写下标，全是int，不允许出现小数。

## P8 常量：不变的数，也给它起个名字（约1.5分钟）

跟变量相对的是常量——值不变的数据。两种写法。

第一种你上一节就见过了，#define：

#define MaxSize 1000
#define PI 3.14

给1000起名叫MaxSize，给3.14起名叫PI。好处就是改一处全变，而且看名字就知道它是干嘛的。

第二种，const：

const int DAYS = 365;意思是DAYS这个盒子里的东西，一旦放进去，就不许再改了。你再写 DAYS = 300，编译器直接报错。

还有一种最朴素的，叫字面常量：直接写在代码里的125、3.14、'A'。没有名字，值就是它自己。

跟上一节串一下：802真题的顺序表定义，几乎必出 #define MaxSize 100 或者1000，数组开多大就是从这来的。所以#define不是装饰品，是真考。

## P9 把盒子里的东西打出来（约2分钟）

上一节printf打的是写死的字，这一节要打盒子里的活数据，靠什么？靠占位符，官名叫转换说明。printf("分数：%d", score);

这行里，%d就是占位符。它先占住一个位置，意思是"待会儿这里要放一个整数"。后面逗号跟着的score，就是填进去的东西。运行结果：分数：125。

三个占位符对应三种类型，看表：%d配int，%c配char，%f配double。这个对应关系，跟前面那张类型表是同一套，你记一遍，用两处。占位符和后面的变量，**按顺序一一对应**。你写两个%d，后面就得跟两个变量，第一个%d吃第一个变量，第二个吃第二个。个数、顺序，都得对上。

给你举个对不上的例子。printf("%d %d", score); 我写了两个%d，后面只跟了一个变量。这个错跟刚才类型配错一样阴——有的编译器会给你一个警告，但很多情况下程序照跑，第二个位置打出来一个莫名其妙的数。所以写printf的习惯是：写完格式串，先数一遍里面有几个%，再数一遍后面有几个变量，两个数对上了才算完。

## P10 printf配错了，不报错，但结果全错（约2分钟）

这里有两个真实的坑，我必须提前给你打预防针。第一个坑，类型配错。你看这段：

double pi = 3.14;
printf("%d", pi);

我拿%d，去打印一个小数。它**不报错**，程序照跑，但是打出来的，是一串莫名其妙的数。所以你写printf的时候，占位符和变量类型，一定要对上。

第二个坑，%f默认打6位小数。你写 printf("%f", pi)，pi是3.14，打出来是多少？是3.140000。后面补了一串零。这不是bug，是%f的默认行为，它固定给你打6位小数。

## P11 板书推演（约4分钟）

现在动手。从空白开始，写一个完整的、带变量的程序。我写一行，你跟一行，别只用眼睛看。

【板书】
第一步，先搬工具，写头文件：#include <stdio.h>
第二步，写大门，主函数开头：int main(){
第三步，声明三个变量，顺便初始化：
    int target = 120;
    int score = 95;
    double pi = 3.14;
第四步，用printf打出来：
    printf("目标分：%d\n", target);
    printf("当前分：%d\n", score);
    printf("圆周率：%f\n", pi);
第五步，收工：return 0;
第六步，别忘了关门，补右花括号：}

写完先别急着往下，回头查。还是上一节那三样：分号补了没、双引号成对没、花括号一开一闭没。这一节多加一样——**每个printf的占位符，跟后面的变量对不对得上**。%d配int、%f配double。

## P12 板书结论（约1分钟）

对一下答案，你写出来的应该是这样：

#include <stdio.h>
int main(){
    int target = 120;
    int score = 95;
    double pi = 3.14;
    printf("目标分：%d\n", target);
    printf("当前分：%d\n", score);
    printf("圆周率：%f\n", pi);
    return 0;
}

## P13 scanf：让用户输入数据（约2.5分钟）

输出会了，补输入。数据不能总靠代码里写死，得让程序跑起来之后，停下来，等用户从键盘敲进来。scanf就是干这个的。

四行代码：

int score;
printf("请输入你的分数：");
scanf("%d", &score);
printf("你输入的是：%d\n", score);

第一行，先声明变量的数据类型。

第二行，先打一句提示，告诉用户该输入了。这行很重要——你不提示，程序就干等着，用户还以为它死机了。

第三行：scanf("%d", &score)。%d的意思是"我要收一个整数"，跟printf的%d一个道理。**&score**，变量前面这个&符号，为什么必须写？答案是地址，强化阶段揭晓。现在你只需要照做：**scanf收数据，变量前面加&**。

程序跑到scanf这一行，会**停下来等**。光标在那闪，等你敲数字、敲回车，它才往下走。我把这个过程给你过一遍：程序跑到scanf，停住；你在键盘上敲1、2、5，这时候数字还在输入队列里排队；你敲回车，scanf这才动手，按%d的格式，把队列里的125读出来，放进score这个盒子；然后程序才继续往下跑。所以回车是个信号，告诉scanf"我输完了，你可以来收了"。

所以我建议你亲手跑一遍：不跑一次，你不知道程序真的会停在那等你，也不知道回车原来是干这个用的。

scanf的占位符和printf大体一样：%d收整数、%c收字符。只有一个地方不一样，我提前给你说清楚：**就是scanf要读一个小数进double盒子，占位符写%lf**，比printf的%f多一个字母l。printf打double用%f，scanf读double用%lf，这一进一出长得像但不完全一样。802伪代码里很少读小数，你有个印象就行，要记得这个差别。

## P14 一次读两个数（约1.5分钟）

scanf还能一次收好几个数。看这个：

int a, b;
scanf("%d %d", &a, &b);
printf("和是：%d\n", a + b);

格式串里写两个%d，后面跟两个变量，各带各的&。程序跑到这，等你输入两个整数，中间用空格或者回车隔开都行，敲完回车，两个数分别进了a和b的盒子。

你以后写"读入两个数求平均""读入两个数比大小"这类程序，开头全是这一句。现在把套路记下来：**几个占位符，几个变量，几个&**，一一对应，一个都不能少。

## P15 scanf读字符，回车会捣乱（约1.5分钟）

这一页讲一个真实的坑，你写程序早晚会撞上，先给你打个预防针。

看这段代码：

int n;
char ch;
scanf("%d", &n);
scanf("%c", &ch);

先读一个整数n，再读一个字符ch。你心想这没问题啊，但是一跑，坏了——第二个scanf像是被跳过了一样，程序直接往下跑了，根本不给你输入字符的机会。

怎么回事？你敲数字、敲回车，那个**回车本身也是一个字符**，它就躺在输入队列里。第一个scanf把数字收走了，回车留下了。第二个scanf是收字符的，它一看，队列里躺着一个回车，直接把它收进ch就继续下一步了，所以你根本来不及敲你的A。

这个坑现在不用深究怎么救，等你真撞上的时候，知道"哦，是回车被收走了"就行，救法到后面讲字符处理的时候专门说。今天你就记住一件事：scanf读字符和读数字，待遇不一样。

## P16 bool：802伪代码里遍地都是（约2分钟）

最后单独讲bool。为什么给它一页？你往后看802伪代码就明白了——基本操作的返回值，几乎全是bool。

看一段你以后会反复见的代码：

bool InitList(SqList &L){
    L.length = 0;
    return true;
}

这是数据结构里顺序表的初始化，具体啥意思后面的课讲。你现在只看一件事：函数名前面写着bool，最后return true。

bool类型的变量，只有两个可能的值：true和false，真和假。它就干一件事——表示"成没成功""是还是不是"这种非黑即白的判断。

为什么802爱用它？因为数据结构的基本操作——初始化、插入、删除、入栈、出队——都有可能失败。表满了插不进去，表空了删不出来。操作做完了，得报告结果啊，成功就return true，失败就return false。所以你在802伪代码里见到的return true/false，没别的意思，就是在报告这事做成没做成。

声明也简单：bool flag = true; 跟int一模一样，就是把类型名换成bool。802伪代码里放心用，阅卷完全认。补一句上机的细节：你要是课后真在编译器里跑C代码，开头得加一句 #include <stdbool.h>，bool才能用。伪代码答题不用管这个，上机的时候记得就行。

## P17 总结（约0.5分钟）

这一节把数据进出程序的整条路打通了，就三件事：

变量是带名字的盒子，类型决定盒子能装什么——int装整数、char装字符、double装小数、bool装判断结果。记住那个截断：int装不下小数，3.9进去，3出来。

拿出去靠printf，占位符%d、%c、%f，按顺序、按类型跟后面的变量对应，配错不报错但结果全错。

拿进来靠scanf，占位符同一套，变量前面加&。&的道理，强化阶段讲指针揭晓，这节先照写。
