## P2 引题：函数为什么改不动外面的变量（约2分钟）

先把案发现场摆出来。

int a = 3，int b = 5。你想写一个函数swap，把a和b的值交换。你照着直觉写：swap(a, b)，函数里想办法换。程序跑完一看，a还是3，b还是5，纹丝不动。

你盯着函数里的代码看，逻辑没毛病啊：确实换了。为什么外面没变？

【停顿】

基础阶段你把这个疑问记了下来，今天揭开盖子。答案一句话就能说：函数收到的不是a和b本人，是它们的复印件。你改复印件改得再认真，原件也不会动。

这个坑几乎每个学编程的人都踩过，因为它反直觉。你写swap(a, b)，看起来就是把a和b交出去了，谁能想到交出去的是拷贝？语言的这个设计不是故意坑人，它有自己的道理，今天就讲明白。搞懂这个机制，两种改得动的写法自然就出来了。

给你个建议：答案揭晓之前，先按暂停，自己猜一下为什么。猜对了，说明你的直觉已经摸到门了；猜错了，记住这个错的感觉，听完解释就不容易忘。

## P3 传参的真相：参数收到的是副本（约3分钟）

看调用那一瞬间发生了什么。

你写swap(a, b)。这一行执行的真实动作是：a把自己的值3复印一份，交给参数x；b把自己的值5复印一份，交给参数y。注意，交出去的是值的复印件，不是变量本身。

x和y是什么身份？它们是swap函数自己的局部变量。上节课讲过，局部变量住栈上。函数开始执行，栈给x和y分出两个新格子，3和5分别住进去。

现在图景就清楚了：内存里有四个格子。外面两个，a装着3，b装着5；函数里两个，x装着3，y装着5。函数里所有的操作，x等于y也好，y等于x也好，动的都是里面那两个格子。外面那两个，从函数开始到结束，没人碰过。

问你一个检验：函数里把x改成100，外面的a会跟着变吗？

【停顿】

不会。x是a的复印件，不是a本人。你把复印件涂改了，原件还锁在抽屉里。

再问一个更细的：复印发生在什么时候？是调用函数的那一瞬间，参数还没进函数体，值已经拷好了。函数体里你写不写x，拷贝都已经发生。所以哪怕函数里一行都不用x，那次复印也照做不误。复印是传参机制的固定动作，不是你的选择。

这个机制有个正式名字，叫值传递：传的是值，是拷贝。它是C语言传参的默认行为，你之前写的每一个函数，参数都是这么进来的。

顺带把两个术语立住。调用时交出去的a和b，叫实参，实际参数；函数头上接收的x和y，叫形参，形式参数。值传递的本质就是：实参把值复印给形参。这两个词后面会一直用，今天先把名字对上。

再给你一层理解。值传递的这个复印动作，其实是好事。它让函数天然安全：函数里怎么折腾参数，都不会意外地改掉外面的数据，函数的影响范围被关在了自己的地盘里。副作用要显式地要，不是默认就送，这是语言设计里的一份谨慎。

## P4 swap失败版：换得热闹，白忙一场（约3分钟）

把失败版的代码完整看一遍。

void swap，参数int x、int y。函数体三行：int t = x，先把x的值存到临时变量t；x = y，把y的值给x；y = t，把t里存的原x值给y。三行走完，x和y确实交换了：x变成5，y变成3。

然后呢？函数执行完了。上节课说过，栈上的格子出函数就自动回收。x和y的格子被收走，里面的5和3跟着蒸发。这一通操作改的全是复印件，原件a和b从头到尾没被碰过，一个3一个5，安然无恙。

所以这个函数有没有干成事？站在函数内部看，干成了，x和y确实换了；站在调用者看，白干，a和b一点没变。失败的原因不在逻辑，在传参方式：值传递天生改不动外面的东西。

用内存图把这个失败钉在图上：a、b两格在外面，x、y两格在函数的地盘里，三行交换只在里面两格之间完成，外面的格子全程无人问津。函数一结束，里面两格被栈收回，一切痕迹消失。图一画，白忙一场这四个字就不用解释了。

这里要给你一个读代码的习惯。以后看到一个函数想修改传入的数据，先看参数表：参数是int x这种光杆写法，那它改不动外面；参数带星号或者带&，才有戏。一眼看穿函数的能力边界，这个本事今天就可以练起来。

补一句公平话。值传递不是永远办不成事，它还有一条路：不改原件，把结果用return送出来。比如求平方的函数，收一个数，return它的平方，调用者接住返回值赋给变量。传进来的是拷贝，送出去的是新值，全程没碰原件，事也办成了。所以准确的说法是：值传递改不动外面，但能用返回值把结果递出来。真正需要"直接改原件"的场景，才需要今天后面的两种写法。

## P5 第一种解法：指针传参（约4分钟）

知道了病根，药方就有了。改不动是因为函数拿不到原件的位置。那就把位置交进去。

看这个版本。void swap，参数变成int *px、int *py——两个指针。函数体：int t = *px，顺着px取出a的值；*px = *py，把b的值放进a的格子；*py = t，把原来的a值放进b的格子。

调用处写swap(&a, &b)。&a是a的地址，&b是b的地址。你交给函数的不再是复印件，是钥匙：a和b两间屋子的门牌号。

函数里改的是谁？*px顺着钥匙找到a的格子，改的就是a本人。第一节课学的隔空改物，在这里正式上岗。函数结束，px和py这两个指针变量自己消失了，没关系，它们只是钥匙的复印件；被改过的a和b，实实在在地换了值。

把调用那一瞬间也慢放一遍。swap(&a, &b)：先算&a和&b，拿到两把钥匙；钥匙各复印一份，分别交给px和py；函数开工，三句交换全顺着钥匙摸到外面的格子。你看，指针传参没有绕开复印，复印照样发生，只是这次复印的是钥匙，不是家具。

问你：交换为什么非要一个临时变量t？直接写*px = *py，再*py = *px不行吗？

【停顿】

不行。第一句*px = *py执行完，a原来的值已经被b的值盖掉了，找不回来了；第二句再把b的值赋过去，结果a和b都是b的值，一个数丢了。t的作用就是在覆盖之前，先把原值存起来。交换必须三步，这个结构以后会反复出现。

再给你一个高频错点。有人写指针版的时候，调用处忘了写&，写成swap(a, b)。这时代码也能编译过，但a和b的值会被当成地址传进去，函数顺着这两个假地址去写内存，大概率当场崩溃。参数是指针，调用处就必须交地址，这个对应关系写的时候多核一遍。

## P6 板书推演：两张图对比（约6分钟）

【板书】

动手。今天画两张并排的图，把两种传参摆在一起看。

左半边，值传递。外面画两个格子，a填3，b填5。下面画一条虚线框表示函数的地盘，框里再画两个格子，x填3，y填5。从a到x、从b到y各画一个带"复印"字样的箭头。函数里怎么折腾，都在框里面，框外面的a和b一个字符都不动。

右半边，指针传参。外面还是a、b两格。函数的框里画px、py两格，里面分别填a和b的门牌号，然后从px画箭头指向外面的a，从py画箭头指向外面的b。注意箭头是跨出函数框的：这就是函数的手伸到了外面。

【停顿】

对比着看。左边，函数框里发生的一切和外面无关，因为两边没有箭头相连；右边，箭头穿过函数框连到外面，函数里写*px，改的就是外面的格子。传参方式的差别，落到图上就是有没有那根跨出去的箭头。

这两张图你课后自己画一遍。画完你就彻底明白：改不改得动外面，不看函数体写了什么，看参数有没有拿到外面的地址。

画这两张图也有个常见错法，自查一下。有人把值传递的箭头画成从x指回a，那不对：值传递两边没有任何箭头相连，只有复印瞬间的示意，函数运行期间两个副本各过各的。箭头只出现在指针传参那半边，而且方向是从函数里的指针指向外面的变量，别画反了。

## P7 引用登场：变量的第二个名字（约3分钟）

指针传参能解决问题，但写起来有点绕：函数里满天飞的星号，调用处还得记着写&。有没有更顺手的写法？有，不过它不是C语言的，是C++的，叫引用。

看这三行。int x = 10，老规矩。int &r = x，注意&写在类型和名字中间，读作：r是x的引用。什么意思？r就是x的另一个名字，别名。最后一行r = 20，x也变成20——废话，改r就是改x，本来就是同一格内存。

第一节课讲别名现象的时候说过：多个名字指向同一格内存，改谁都一起变。当时那是指针造成的现象，今天引用把这件事变成了专门的语法：你声明一个引用，就是给现有变量起第二个名字，没有格子新增，没有地址存储，纯粹一个名字。两个名字地位完全平等，喊x和喊r，编译器都当成同一件事。

说明一句背景。引用是C++的语法，纯C语言没有它。但我们这门课的伪代码环境里它直接可用，后面的课程也会一直用。你把它当成"更顺手的别名工具"来用就行，C和C++的边界问题，不在这门课的范围内。

画图的时候，引用怎么表示？给你个约定：不画新格子，就在x的格子旁边多贴一张写着r的名字条。一个格子两个名字，这就是别名的全部。对比一下指针：指针要画自己的格子，里面存门牌号，再画箭头。引用在图上就是多一张标签，这个画法差别，正好对应两者的本质差别。

有同学会问：引用这么省心，为什么不都用引用，指针是不是多余的？不是。引用能干的，指针都能干，反过来不成立：指针能换指向，能在数组里走路，能指向动态内存，这些引用都做不到。引用是更安全的子集，指针是更灵活的超集。两个都学，不是重复，是互补。

## P8 引用的规矩：出生即绑定，从一而终（约3分钟）

引用好用，但有两条硬规矩。

第一条，出生的时候就必须绑定。int &r = x，等号右边的x必须在。你写int &r;光杆一个，不合法，编译器直接拒绝。道理也自然：别名是别人的别名，没有本尊，别名挂在哪？

第二条，绑定之后不能改绑。这点最容易和指针搞混，单独说清楚。r已经是x的别名了，你再写r = y，这行代码的意思不是"让r改指向y"，而是"把y的值赋给x"——r永远指x，r = y就是x = y。引用从一而终，出生绑了谁，一辈子就是谁的别名。

和指针放一起对比，差别就鲜明了。指针是个存地址的盒子，盒子里的编号随时能换，今天指x明天指y；引用不是盒子，就是个名字，贴给谁就一直是谁的。指针灵活，引用省心，各有各的脾气。

问你一个检验。int x = 3, y = 5; int &r = x; r = y;。执行完x是多少？

【停顿】

5。r是x的别名，r = y就是把y的值5赋给x。r从头到尾没换过人。

这两条规矩听着是限制，其实是保护。引用的世界没有野指针、没有换指向之后的意外，它天生绑定着一个真实存在的变量。你以后读代码看到引用，可以放心：这个名字永远代表着某个确定的变量，不会指空、不会指飞。自由的另一面是责任，引用把责任交给了编译器，这是它省心的根源。

## P9 第二种解法：引用传参（约4分钟）

引用拿来传参，就是今天的第二个解法。

看代码。void swap，参数int &x、int &y，每个参数类型后面跟一个&。函数体和失败版一模一样：t存x，y给x，t给y。调用处swap(a, b)，干干净净，不用写&。

神奇的地方来了。调用swap(a, b)的时候，x不是a的复印件，x就是a的别名；y就是b的别名。函数里改x，改的就是a本人。三行走完，a和b真的交换了。

你把三个版本并排看：失败版和引用版的函数体一字不差，区别只在参数表的两个&。就这两个符号，把"白忙一场"变成了"真换成功"。这也是今天最想让你记住的一幕：参数上有没有&，决定函数碰不碰得到外面的数据。

引用传参还有个顺带的好处：没有复印。值传递每次调用都要拷贝一份，传个int无所谓，传一个大结构体，每调用一次就复印一大块，费时费力。引用传参只起个别名，一个格子都不用拷。传大数据用引用，这个习惯以后会反复用到。

带你把引用版swap完整走一遍。调用swap(a, b)：x成为a的别名，y成为b的别名，此刻起函数里喊x就是喊a。第一句t = x，把a的值3存进t。第二句x = y，把b的值5放进a，a变成5。第三句y = t，把t里的3放进b，b变成3。三句走完，a和b互换，全程没出现&a，但改的就是a和b本人。这就是别名传参的威力。

## P10 三种传参：一套需求，三种写法（约3分钟）

把三种写法摆到一张表上，今天的内容就收口了。

值传递：参数收到值的副本，改不动外面，调用处写swap(a, b)。指针传参：参数收到地址，顺着*改得动外面，调用处写swap(&a, &b)。引用传参：参数收到别名，直接改得动外面，调用处写swap(a, b)。

三种写法对应三种心智模型。值传递是递复印件，安全但改不了原件；指针传参是交钥匙，拿着钥匙开门进去改；引用传参是给原件起个小名，喊小名就是喊本人。三个模型，你把哪个用顺了，另外两个也就通了。

这张表建议你记在顺手的地方。三种传参是这个阶段之后所有代码的基本盘：读代码要认，写代码要选，以后数据结构的每个函数头都在用它。现在把表背下来，是性价比最高的一件事。

给你一个读代码的口诀：先看参数表，再看函数体。参数是光杆类型，值传递，函数改不动外面；参数带星号，指针传参，见到*px就是顺着地址动手；参数带&，引用传参，函数里改参数就是改调用者的变量。三秒判断一个函数的能力边界，读代码的速度会上一个台阶。

现场练一次。你看到一个函数，头上写void process(int n, int *p, int &r)。三个参数，三种传参。不用看函数体你就能说：n是读进来的拷贝，改不动外面；p指向的东西可以被改；r的本尊可以被改。一个函数头读出三句话，这就是今天学的东西的直接回报。

判断的时候只认参数表，不认函数名。有人看见名字叫changeX，就以为它改得动外面——名字会骗人，参数表不会。一个叫modifyAll的函数，参数要是光杆的int x，照样改不动外面任何东西。以参数表为准，这个判断标准不会错。

## P11 什么时候用哪种（约3分钟）

会写三种，还要会挑。给你四条选择原则。

第一条，函数只读数据，不改：值传递。简单直接，不用想。比如传一个数进去算平方，值传递就够。

第二条，函数要改外面的变量：首选引用传参。写法干净，调用处不用记&，函数体里也不用满天飞的星号。

第三条，代码要兼容纯C环境：用指针传参。能力上指针和引用一样，都能改外面，只是调用处多写&，函数里多用*。纯C没有引用，这时候指针是唯一选择。

第四条，传大块数据：结构体、大数组这类，别用值传递。整块复印的成本太高，要么传地址，要么传引用。这条在传结构体的时候特别要紧，上节课那个Student，值传递一次拷12字节还行，成员多起来就是灾难。

拿上节课的Student举个具体的。你写一个函数给学生加分，参数要是struct Student stu，每次调用都把整个学生复印一份，改的是复印件，外面的学生分数纹丝不动，还白拷一次。正确写法是参数写struct Student &stu，直接改本人，零拷贝。你看，今天学的东西和上节课的结构体，正好接上了。

四条原则背后其实就一个判断：函数需要碰外面的数据吗？不需要，值传递；需要，地址或者别名。把这一问立住，选型不再纠结。

## P12 为什么伪代码的参数上常写&（约2分钟）

最后回到我们这门课的主线：为什么伪代码里到处都是引用传参。

你想一个场景。你写一个初始化函数，要把一个表清零、长度置0；写一个插入函数，要往表里添一个元素。这些函数干的活，都是直接修改传进来的那个结构。要是用值传递，函数改的是复印件，表本体一点没动，等于白干。所以这类函数的参数必须写&：把外面的表以别名的方式请进来，函数里改参数，就是改表本身。

这就给你一个读伪代码的信号：看到参数上带&，这个函数会动调用者的数据；看到不带，它多半只读。读函数先看参数表，功能猜个八九不离十。

反过来也用得上。你自己写函数的时候，先问一句：这个函数需要改传进来的东西吗？需要，参数加&；不需要，就不加。这个&加不加，等于你在函数头上挂了块牌子：进来的人能不能动屋里的东西。写清楚，读的人省心。

再把上节课的动态内存接进来，三种传参就全串起来了。函数里在堆上造了数据，怎么交出去？两条路：参数用引用，函数里把新地址写进参数；或者用返回值把地址递出来。造东西靠malloc，传东西靠传参，两节课的工具在同一个场景里会师了。

到这里，基础阶段那个"函数为什么改不动外面"的为什么，彻底解开了：值传递交的是复印件；想改得动，就把地址或别名交进去。

## P13 本节小结（约2分钟）

今天的内容收一下，三件事。

第一，值传递的机制。调用函数时，实参把值复印给形参，形参是栈上的新格子，改的是复印件。这就是函数改不动外面变量的原因，基础阶段的为什么，答案就在这。

第二，两种改得动的写法。指针传参：实参交&a，形参是int *，函数里用*px顺着地址改。引用传参：形参写int &x，它直接是实参的别名，函数里改x就是改a。

第三，引用的两条规矩：出生必须绑定，绑定不能更换。指针能换指向，引用从一而终。三种写法一句话串起来：复印件改不动，钥匙和别名改得动。

下一节是强化阶段的最后一节：递归与综合实战。我们要从零手写顺序表和单链表，今天学的传参、前几节课的指针、结构体、动态内存，全会用上。这是整个阶段的验收课，做好准备。

把六节课串一下你会发现一条线：地址和指针是看内存的眼睛，数组和结构体是内存里的家具，动态内存是自己造家具，传参是函数之间递家具的方式。下一节，把所有工具摆到同一张桌子上干活。

## 附录一：课后题参考答案

跟练题：

```c
#include <stdio.h>
void swapPtr(int *px, int *py){
    int t = *px;
    *px = *py;
    *py = t;
}
void swapRef(int &x, int &y){
    int t = x;
    x = y;
    y = t;
}
int main(){
    int a = 3, b = 5;
    swapPtr(&a, &b);
    printf("%d %d\n", a, b);   // 5 3
    swapRef(a, b);
    printf("%d %d\n", a, b);   // 3 5，换回来了
    return 0;
}
```

内存图要点：指针版中px、py在函数框内，箭头跨框指向外面的a、b，*px改的是a的格子；引用版中x直接标注为a的别名，没有新格子。

模仿题：

```c
#include <stdio.h>
void increment(int &n){
    n = n + 1;
}
int main(){
    int n = 10;
    increment(n);
    printf("%d\n", n);     // 11
    return 0;
}
```

要点：参数写int &n，调用处不写&；函数里改n就是改外面的n。若写成int n（值传递），打印出来还是10，正好对照验证两种传参的差别。

## 附录二：本节代码合集

本节出现的代码都在下面，顺序和讲课顺序一致。默写按"失败版、指针版、引用版"三个函数头来。

```c
void swap(int x, int y){       // 值传递：改不动外面
    int t = x; x = y; y = t;
}

void swap(int *px, int *py){   // 指针传参：顺着地址改
    int t = *px; *px = *py; *py = t;
}
swap(&a, &b);                  // 调用处交地址

void swap(int &x, int &y){     // 引用传参：别名直接改
    int t = x; x = y; y = t;
}
swap(a, b);                    // 调用处不用&

int x = 10;
int &r = x;                    // r是x的别名
r = 20;                        // x也变成20
```
