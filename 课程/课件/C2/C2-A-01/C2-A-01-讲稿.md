## 正课：答题格式与复杂度分析（第6—14页，约27分钟）

## P6 802代码题怎么写（约3分钟）

导学到这，下面进正课。正课讲两件所有算法题都通用的事：802的代码题用什么形式写，还有复杂度怎么算。

先看形式。802写的是伪代码，不是一个能在电脑上跑起来的完整程序。你在考场上不用写 #include，不用写 main，直接写一个函数就行。屏幕上这个 countNegative 就是例子，它统计一个数组里有多少个负数：开一个计数器 cnt，从头到尾扫一遍，遇到小于0的就加一，最后返回 cnt。你看，就这么一个光秃秃的函数，没有头文件，没有 main，这在802里完全合格。为什么能这么省？因为802考的是你会不会设计算法，不是考你会不会搭一个能编译的工程。所以它**重思路、轻语法**：思路对、边界全，就算漏个分号、拼错个单词，照样给分；反过来思路错了，语法再漂亮也没用。

但有三样东西不能省，省了要扣分：**结构体定义、函数签名、边界判断**。你用到的结构，它的类型定义要写出来，比如你用到顺序表，就得先把它的结构体写在这，不能假设阅卷老师知道你脑子里想的是哪一种；参数是什么、返回什么要写清楚；空表怎么办、下标越界怎么办、传进来的 n 合不合法，这些判断是算法严不严谨的体现，也是评分点。除这三样，头文件、main 都能省。

## P7 答题三件套（约3分钟）

再说一道算法题的完整答案长什么样，一般的标准是算法思想、伪代码和复杂度三件套。

第一件，算法思想。用文字说清楚你打算怎么做，分几步、每步干什么。这一件是让你先把思路理顺，也是给阅卷老师看的，他要看你有没有真想明白，并且边界情况是否思考清楚。

第二件，代码，也就是刚才说的伪代码。这一件是把思想落成一步步能执行的动作，结构体定义和边界判断要完整。

第三件，复杂度。时间和空间各给一个结论，而且每个结论后面都要配一句理由。这一点很多同学栽跟头：只写个 O(n) 就完了，不写为什么。阅卷是要看理由的，光有结论，这一件的分拿不全。

这三件是有分值的，**缺哪件就扣哪件的分**。非常多人答题，代码写了一大段，思想那栏空着，复杂度也空着，等于白丢了两件的分。反过来，思想这一件还能救你：万一代码写到一半卡住了，或者有个边界没处理干净，你把思想写清楚，阅卷老师看得出你是会做的，会酌情给分；要是卷子上只有一段跑不通的代码，那基本就是零分。所以从今天起养成习惯：一道算法题，思想、代码、复杂度，三件一起交。

## P8 三件套样例（约3分钟）

那么三件套写出来到底长什么样？我用一个最简单的例子给你看，求一个数组里的最大值。这个例子你早就会写，我们不看它难不难，只看三件套怎么排。

第一件思想，写在代码前面：先假定第一个元素最大，然后从第二个起逐个比较，遇到比当前最大值更大的就把它换掉，扫完一遍，剩下的就是最大值。思想不用写太长太复杂，但要把关键那一步点出来，这题的关键就是先假定第一个最大、边扫边更新，把这句说出来，阅卷老师就知道你想对了。

第二件代码：开一个变量 max 让它先等于 a[0]，一个 for 循环 i 从1到 n-1，每次拿 a[i] 和 max 比，a[i] 更大就更新 max，循环结束返回 max。你看，这就是刚才那段思想，一行行落成代码。

第三件复杂度，写在代码后面。时间 O(n)，为什么？每个元素都被拿出来比了一次，一共 n 个，所以是 O(n)。空间 O(1)，为什么？我从头到尾只额外用了一个变量 max，它不随 n 变大而变多，所以是 O(1)。

这就是一个能拿满分的三件套：思想在前、代码在中、复杂度在后，每件都带着理由。真实的考题会比求最大值难很多，但答题的骨架就是这个三段式，从这节课起你就照它练。

## P9 时间复杂度怎么数（约3分钟）

三件套里第三件是复杂度，这一件最容易丢分，我们单独花几页去讲一下。先说时间复杂度。

时间复杂度说到底就是去数**基本操作执行了多少次**。基本操作通常就是循环最里面那一句，它是整段代码里重复得最多的动作。数出来它跑了多少次，再只保留最高阶，把系数和低阶项都去掉，写成大 O，这就是时间复杂度。为什么要去掉系数和低阶项？因为大 O 描述的是 n 变大时的增长趋势，n 一大，最高阶那一项涨得最快，其余的跟它比起来小到可以忽略。

看屏幕这个例子：一个 for 循环，i 从0到 n-1，循环体里就一句 sum = sum + a[i]，这句就是基本操作。它跑了多少次？循环转 n 圈，它就执行 n 次，所以是 O(n)。再举一个常考的：如果循环里那个变量是翻着倍走的，比如 x 从1开始每圈乘2，一直到超过 n，那圈数就不是 n 而是 logn，因为2要乘 logn 次才够到 n，这种翻倍循环就是 O(logn)，等下的模仿题里就有一段是这样的。

这里提醒一个最常见的毛病：很多同学一看到循环就套公式，一层写 O(n)、两层写 O(n²)、三层写 O(n³)。这么套十有八九会错。正确的做法是先找到最里面那句基本操作，再看它到底跟着谁变、跑了多少次。**层数是表象，次数才是本质**。下一页用一个两层循环的例子，你就看清为什么不能光数层数。

## P10 内层跟着外层变，先求和（约4分钟）

看这个两层循环。外层 for i 从0到 n-1，内层 for j 从 i 到 n-1，最里面是 x++，这句 x++ 就是基本操作，我们来数它到底跑了多少次。

关键在这：内层 j 的起点是 i，不是固定的0，也就是说内层跑多少次是跟着外层的 i 变的。我们一趟一趟数。i 等于0时，内层 j 从0到 n-1，跑 n 次；i 等于1时，j 从1到 n-1，跑 n-1 次；i 等于2时跑 n-2 次；这样下去，到最后 i 等于 n-1 时，内层只跑1次。

【停顿】所以总次数不是简单的 n 乘 n，而是把每一趟加起来：n 加 n-1，加 n-2，一直加到1。这是个等差数列求和，首项1、末项 n、一共 n 项，结果是 n 乘 n+1 再除以2。展开以后最高阶是 n 的平方，系数二分之一和低阶项都去掉，所以是 O(n²)。

你回头看，这个例子确实是两层循环、确实算出 O(n²)，但这个 O(n²) 是求和求出来的，不是数层数数出来的。再给你一个反例：假设有三层循环，可最里面那层只执行固定的几次、根本不随 n 变，那这段代码可能还是 O(n)，甚至是 O(1)。所以记住，别数层数，要数最里面那句基本操作真正跑了多少次；一旦内层的范围跟着外层变，你就得先求和，再化简。这一步最容易被偷懒跳过，不少人嫌麻烦，直接拿两层的 n 一乘写成 n²，碰上内层不从0开始、或者内层次数跟外层不一样的，答案立马就错。

## P11 递归式怎么展开（约4分钟）

循环的会数了，再看递归的。递归函数的时间复杂度常常写成一个递归式，比如 T(n) 等于 2T(n/2) 加 O(n)。这个式子在说：要解决一个规模是 n 的问题，我先做 O(n) 这么多活，再把它拆成两个规模是 n/2 的子问题分别解决。这种带 T 自己的式子怎么算出大 O？办法是画一棵递归树，一层一层把代价加起来。这一页你拿纸跟着画。

【停顿】先画最上面一层，叫第0层。这层就一个问题，规模 n，它做的活是 O(n)。

往下画第1层。第0层那个问题拆成两个子问题，每个规模 n/2，各自做 O(n/2) 的活，两个加起来，2 乘 O(n/2)，还是 O(n)。所以第1层整层的代价还是 O(n)。

再往下第2层。每个 n/2 的问题又各拆成两个 n/4 的，一共四个，每个做 O(n/4)，加起来 4 乘 O(n/4)，仍然是 O(n)。

画到这规律就出来了：每往下一层，问题个数翻一倍，但每个问题的规模减半，一个乘2、一个除以2，正好抵消，所以每一层的总代价都是 O(n)，层层都一样。那这棵树一共有多少层？规模每次减半，从 n 减到1，要减 logn 次，所以一共 logn 层。每层 O(n)、一共 logn 层，加起来就是 O(n) 乘 logn，也就是 O(nlogn)。

这个逐层累加的办法比背公式靠谱得多。你只要记一句话：**算出每层的代价，再算出层数，两个一乘**。归并排序、快速排序的复杂度就是这么来的，到强化阶段讲这两个算法，这棵树还要再画一次，现在先把方法练熟。

## P12 空间复杂度（约3分钟）

说完时间说空间。空间复杂度数的定义是为了把这件事做完，你额外开了多少辅助空间。注意是“额外”两个字，输入数据本身占的那部分不算，算的是你为处理它另外开辟的空间。

额外空间一般来自两个地方。第一个是你开的辅助数组。新建了一个大小 n 的数组存中间结果，空间就是 O(n)，比如你要把一个数组逆序，图省事另开一个一样大的数组来存结果，那额外空间就是 O(n)；要是自始至终只用了固定的几个变量，不管 n 多大都是这几个，那就是 O(1)。这里澄清一个误解：说一个原地算法的空间是 O(1)，不是指它一点都不占内存，而是指它额外占的空间不随 n 增长，就固定那么几个变量。

第二个地方是递归调用压的栈，这个最容易漏。很多人以为一个递归函数只要没开数组，空间就是 O(1)，那么就错了。递归每调用一层，系统栈上就多压一帧，存着这一层的参数和返回地址，所以递归的空间至少要把栈的最大深度算进去。栈深度就是递归最深调到了第几层，比如一棵三层的树，递归最深压到第三层，栈上同时就压着三帧。举个例子，二叉树的递归遍历一个数组都没开，但栈的深度等于树的高度，空间就是 O(树高)；要是这棵树退化成一条链，树高等于结点数 n，空间最坏就是 O(n)。

所以答题时时间和空间都要给，各配一句理由。算空间别只盯着数组，**递归压的栈深度一定要算进去**。

## P13 小结（约2分钟）

这一讲结尾一下。今天是整个数据结构代码课的开篇，没讲具体结构，讲的是后面每道算法题都要会设计的两件事。

第一样，怎么作答。802写伪代码，可以省掉头文件和 main，直接写函数，但结构体定义、函数签名、边界判断这三样必须完整。一道算法题的答案是三件套：思想、代码、复杂度，缺一件扣一件的分，复杂度还要一句结论配一句理由。

第二样，怎么算复杂度。时间复杂度就是数基本操作跑了几次，只保留最高阶；内层次数跟着外层变的时候，先求和再化简；递归式就画一棵递归树，每层代价乘层数。空间复杂度数额外的辅助空间，包括辅助数组和递归栈的深度，特别记住递归的空间不是 O(1)。

这两样是通用的基础，后面每一节的算法都踩着它们走。802每道算法大题最后都要写复杂度，三件套的格式贯穿整张卷子，这两样练熟了，每道大题的格式分和复杂度分你就丢不了。至于每个结构具体怎么定义、书写上有哪些约定，讲到那个结构的时候再一条一条说，那时候你对着代码，才真的用得上。

## 附录一：课后题参考答案

跟练题：用三件套格式，统计数组里能被3整除的元素个数。

```c
// 思想：遍历数组，每个元素对3取余，余数为0就把计数加一
int count3(int a[], int n){
    int cnt = 0;
    for(int i = 0; i < n; i++)
        if(a[i] % 3 == 0) cnt++;
    return cnt;
}
// 复杂度：时间 O(n) 每个元素取余比较一次；空间 O(1) 只用了 cnt 一个变量
```

模仿题：三段程序的时间复杂度与理由。

```c
// (1) 嵌套循环，内层依赖外层
for(i=0;i<n;i++) for(j=i;j<n;j++) x++;
// (2) 循环变量翻倍
int i=0,x=1; while(x<n){ x*=2; i++; }
// (3) 递归函数
void f(int n){ if(n<=1) return; for(i=1;i<=3;i++) f(n/3); }
```

- (1) O(n²)。内层 j 从 i 到 n-1 共跑 n-i 次，总次数 n+(n-1)+…+1 = n(n+1)/2，最高阶是 n²。
- (2) O(logn)。x 从1每次翻倍，到 x≥n 停，循环次数是 logn 级。
- (3) O(n)。递归式 T(n)=3T(n/3)+O(1)，每层问题数乘3、规模除以3，共 logn 层，末层 n 个，逐层累加得 O(n)。

```c
int countNegative(int a[], int n){
    int cnt = 0;
    for(int i = 0; i < n; i++)
        if(a[i] < 0) cnt++;
    return cnt;
}
```

答题三件套样例，求数组最大值：

```c
// 思想：先假定第一个元素最大，从第二个起逐个比，遇到更大的就换掉
int findMax(int a[], int n){
    int max = a[0];
    for(int i = 1; i < n; i++)
        if(a[i] > max) max = a[i];
    return max;
}
// 复杂度：时间 O(n) 每个元素比一次；空间 O(1) 只用了 max 一个变量
```

时间复杂度，内层跟着外层变时先求和：

```c
for(int i = 0; i < n; i++)
    for(int j = i; j < n; j++)
        x++;                    // 总次数 n(n+1)/2，即 O(n²)
```
