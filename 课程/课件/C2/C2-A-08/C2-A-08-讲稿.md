## P2 引题：二叉链表有多少空链域（约2分钟）

那么先算一笔账，这笔账是线索化的出发点。一棵有 n 个结点的二叉树，用二叉链表存，一共有多少个链域？每个结点有左孩子、右孩子两个指针，所以是 2n 个链域。

这 2n 个里，有多少是非空的？非空的链域就是树的分支，一棵 n 个结点的树有多少条分支？除了根，每个结点都有一条边连到它的父结点，所以是 n-1 条分支，也就是 n-1 个非空链域。

那空链域就是 2n 减去 n-1，等于 n+1 个。你注意这个结果：空链域 n+1，比结点数 n 还多一个。也就是说，一棵二叉树里，一大半的指针是空的、指到 NULL，白白浪费。

【停顿】线索化的想法就从这来：这么多空链域闲着，能不能利用起来？中序遍历的时候，每个结点都有个前驱和后继，正好可以用这些空的左链域指前驱、空的右链域指后继。这样以后要找某个结点的前驱后继，直接顺着线索走，不用再从头遍历一遍。这就是线索二叉树。

## P3 线索化的想法与 ltag、rtag（约3分钟）

那么想法有了，要怎么落地呢？这里就要处理一个很关键的问题：一个链域，它到底是指着孩子，还是指着线索（前驱或后继），光看这个指针本身分不清，因为两种情况它都存在同一个地址中。

解决办法是再加两个标志位，ltag 和 rtag。看结构定义 BiThrNode：data、lchild、rchild 跟二叉链表一样，多了 int ltag 和 int rtag。规定是，ltag=0 表示 lchild 指向左孩子，ltag=1 表示 lchild 指向中序前驱（是线索）；rtag=0 表示 rchild 指向右孩子，rtag=1 表示 rchild 指向中序后继。

这样每个链域配一个 tag，一看 tag 就知道这个指针是孩子还是线索。你记的时候抓住一句：0 是孩子，1 是线索。这两个 tag 的 0 和 1 含义千万别记反，记反了后面找前驱后继的逻辑就全乱了。

加了 tag 之后，这个结构就叫线索二叉树。把空链域填成线索的过程，叫线索化。我们讲中序线索化，也就是按中序遍历的顺序，把空的左链域填成前驱、空的右链域填成后继。

## P4 中序线索化 InThread：pre 的作用（约5分钟）

中序线索化的代码是本节的核心，关键全在一个 pre 指针上，我们把它讲透。

看代码 InThread，它有两个参数，p 是当前处理的结点，pre 是一个引用，始终指向中序序列里刚刚访问过的那个结点，也就是 p 的中序前驱。函数体是：如果 p 不空，先递归线索化左子树 InThread(p->lchild, pre)；然后处理 p 自己；再 pre=p 让 pre 跟上；最后递归线索化右子树。

处理 p 自己是两个 if。第一个 if，如果 p 的左孩子为空，就把 p->lchild 指向 pre、ltag 设 1，这是给 p 建前驱线索。第二个 if，如果 pre 不空、并且 pre 的右孩子为空，就把 pre->rchild 指向 p、rtag 设 1，这是给 pre 回填后继线索。

【停顿】为什么是两个分开的 if？你想想线索化需要哪两类信息。第一类，当前结点 p 的前驱是谁？就是 pre，这个现在就知道，所以 p 的左线索能马上建。第二类，pre 的后继是谁？是 p，可是当初处理 pre 的时候，还没遍历到 p，那会儿不知道 pre 的后继是谁，只能等现在遍历到 p 了，回过头去把 pre 的右线索补上。这就是"回填"。所以前驱线索当场建、后继线索下一步回填，两个 if 分开写就是这个道理。

pre 用引用传参，是因为它要随着遍历一路往后挪，InThread 里 pre=p 这个更新必须让外面的调用也看到，所以传引用。这个 pre 一路跟着中序顺序往前走，是整段代码的线索。

## P5 过程页：中序线索化逐步（约5分钟）

这一页你拿纸跟着画，我们把一棵树中序线索化走一遍。树还是上一节那棵：根 1，左 2 右 3，2 的左 4 右 5。它的中序是 4 2 5 1 3。pre 一开始是 NULL。

按中序顺序，第一个访问 4。处理 4：4 没有左孩子，所以建前驱线索，4->lchild = pre，可 pre 现在是 NULL，所以 4->lchild 指向 NULL、ltag=1；再看回填，pre 是 NULL，不回填；然后 pre = 4。

第二个访问 2。处理 2：2 有左孩子 4，所以不建前驱线索（第一个 if 不进）；再看回填，pre 现在是 4，4 没有右孩子，所以回填 4->rchild = 2、rtag=1，4 的后继线索建好了；然后 pre = 2。你看，4 的后继是在访问 2 的时候才回填的。

第三个访问 5。处理 5：5 没有左孩子，建前驱线索 5->lchild = pre = 2、ltag=1，5 的前驱是 2；再看回填，pre 是 2，2 有右孩子 5，所以不回填（第二个 if 的条件 pre->rchild==NULL 不满足）；然后 pre = 5。

第四个访问 1。1 有左孩子 2，不建前驱线索；pre 是 5，5 没有右孩子，回填 5->rchild = 1、rtag=1；pre = 1。

第五个访问 3。3 没有左孩子，建前驱线索 3->lchild = pre = 1、ltag=1；pre 是 1，1 有右孩子 3，不回填；pre = 3。

【停顿】遍历结束，pre 停在最后一个结点 3。3 没有后继，可它的右链域还空着，这个要收尾单独处理，下一页讲。你回头看这一趟，前驱线索都是在访问当下建的，后继线索都是等到下一个结点访问时回填的，pre 就是把这两件事串起来的那根线。

## P6 CreateInThread：收尾处理 pre（约2分钟）

刚才留了个尾巴，遍历结束时 pre 指向中序最后一个结点，它的右链域还空着、也没有后继可指，怎么办？看 CreateInThread。

它先定义 pre = NULL，然后如果树非空，调 InThread(T, pre) 做整个线索化。InThread 回来之后，pre 已经停在了最后一个结点。这时候补一句：如果 pre 不空，就把 pre->rchild 置 NULL、rtag 设 1。

为什么这么处理？因为最后一个结点确实没有后继，它的右链域应该表示"后继为空"。我们把 rtag 设成 1，表示这是个线索（不是孩子），而线索指向 NULL，就代表没有后继。这跟前面的约定是一致的：rtag=1 时 rchild 是后继线索，只不过这里后继是空。这样整棵线索树就完整了，每个空链域都有了明确的含义。

## P7 线索树上找后继 Nextnode（约4分钟）

线索化建好了，怎么用？最常用的是找中序后继 Nextnode。看代码，它分两种情况。

第一种，如果 p->rtag == 1，说明 p 的右链域是线索，那它直接就指向 p 的中序后继，return p->rchild 就拿到了，一步到位，O(1)。这就是线索化的好处，后继早存好了。

第二种，如果 p->rtag == 0，说明 p 有右子树。那 p 的中序后继是谁？是中序遍历里 p 之后的第一个结点。p 访问完，接下来遍历它的右子树，而右子树的中序第一个结点，就是右子树里最左边、最下面的那个结点。所以代码是 q = p->rchild 进右子树，然后 while q->ltag==0 就一路往左下走 q = q->lchild，走到一个 ltag=1（没有左孩子了）的结点，那就是后继。这种情况最坏要走 O(树高)。

【停顿】你把两种情况对比着记：rtag=1，后继是现成的线索，直接拿；rtag=0，后继藏在右子树的最左下，要下去找。中序的后继要么是自己的右线索，要么是右子树的最左下结点，就这两种，没有别的。

## P8 Firstnode 与中序线索树遍历（约3分钟）

有了找后继，再配一个找中序第一个结点 Firstnode，就能遍历整棵线索树了。

Firstnode 很简单：中序第一个结点是整棵树最左下的那个，所以从根 T 开始，while T->ltag==0 就一路往左下走 T = T->lchild，走到 ltag=1 停下，返回它。这里注意一个常见笔误，返回的是结点指针 T，不是 0。

中序线索树的遍历就一行 for 循环：p 从 Firstnode(T) 开始，只要 p 不为 NULL，就 visit(p)，然后 p = Nextnode(p) 往后走。从第一个结点开始，一个一个 Nextnode，就把整棵树中序遍历完了。

【停顿】你体会一下这行代码的价值：它遍历一棵二叉树，不用栈、不用递归、不用任何额外的空间，空间复杂度是 O(1)。对比上一节的非递归中序，那个还要一个栈，空间 O(树高)。线索树把遍历的空间降到了 O(1)，这就是线索化存在的全部理由——用那些本来浪费的空链域，换来了不用栈的遍历。

## P9 树的孩子兄弟存储（约2分钟）

那么线索二叉树讲完了，看第二块，树和森林。这里的树是一般的树，每个结点的孩子数不定，不像二叉树最多两个。

一般的树怎么存？用孩子兄弟表示法。看定义 CSNode：data，加两个指针，firstchild 指向第一个孩子，nextbro 指向下一个兄弟。一个结点不管有几个孩子，都只用这两个指针：孩子里只记第一个，剩下的孩子靠"第一个孩子的兄弟链"串起来。

你发现没有，这个结构和上一节的二叉链表 BiTNode 形状一模一样，都是 data 加两个指针。这不是巧合。孩子兄弟表示法里，firstchild 相当于二叉树的左孩子，nextbro 相当于右孩子，所以一棵一般的树能唯一地对应一棵二叉树。这就是树能转成二叉树的结构基础，也是这一节两块内容共用同一个结构的地方。

## P10 树、森林转二叉树：三步画法（约3分钟）

树怎么转成二叉树？记住三步画法，考试画图题就考这个。

第一步，兄弟之间连线。把同一个父结点的孩子们，从左到右依次用线连起来，表示它们是兄弟。

第二步，只保留第一个孩子。每个结点，只留它和第一个孩子之间的那条线，把到其他孩子的线全抹掉。因为其他孩子已经通过第一步的兄弟链，从第一个孩子那里能走到了。

第三步，以根为轴，顺时针旋转 45 度。转完之后，你会发现每个结点的第一个孩子落在了它的左下方，成了左子树；它的兄弟落在了右下方，成了右子树。这正好对应 CSNode 的 firstchild 当左孩子、nextbro 当右孩子。

森林转二叉树也简单：先把森林里每棵树各自用这三步转成二叉树，然后把后一棵树的根，接到前一棵树根的右子树上，一棵接一棵连下去。因为森林里的各棵树互为"兄弟"，所以挂在右链上。

## P11 过程页：一棵三层的树转二叉树（约3分钟）

这一页你拿纸跟着画，我们把一棵具体的树转成二叉树。原树是这样：根 A 有三个孩子 B、C、D；B 有一个孩子 E。

第一步，兄弟连线。A 的孩子 B、C、D 是兄弟，把它们连起来 B—C—D。B 只有一个孩子 E，没有兄弟，不用连。

第二步，只留第一个孩子。A 只保留到第一个孩子 B 的线，抹掉到 C、D 的线；B 保留到 E 的线。现在结构是 A 连 B，B 连 E，而 C、D 通过兄弟链挂在 B 后面。

第三步，顺时针转 45 度。转完之后：A 的左孩子是 B；B 的左孩子是 E，B 的右孩子是 C（B 的兄弟）；C 的右孩子是 D（C 的兄弟）。

【停顿】你对一下结果这棵二叉树：A 往左是 B，B 往左是 E、往右是 C，C 往右是 D。原来的孩子 E 在左链上，原来的兄弟 C、D 在右链上。你抓住一句话就不会画错：第一个孩子往左、兄弟往右。原树的信息一点没丢，一一对应。

## P12 检查页：后根遍历对应二叉树的什么遍历（约2分钟）

这一页你先自己想，别急着看答案。树有两种遍历，先根遍历是先访问根再遍历各子树，后根遍历是先遍历各子树再访问根。问题是：树的后根遍历，对应到它转成的那棵二叉树，是哪种遍历？

【停顿】很多人第一反应是后序，因为"后根"和"后序"名字像。错了，答案是中序。

为什么？你想孩子兄弟表示法里，一个结点的兄弟全挂在它的右子树上。后根遍历是"先遍历孩子、再访问自己"，你注意位置：一个结点的所有孩子都在它的左子树里，第一个孩子是左孩子、其余孩子顺着右链挂在第一个孩子下面；而结点自己的右子树，才是它的兄弟。所以"先孩子后自己"落到二叉树上，就成了"先遍历左子树（第一个孩子）、再访问自己（根）、再遍历右子树（兄弟们）"，这正好是中序的"左根右"。

而先根遍历"先自己后孩子"，对应二叉树的"先根、再左子树、再右子树"，就是先序。所以你记这个对应：先根对先序，后根对中序。后根对中序是考试最爱挖的坑，别被名字骗了写成后序。

## P13 求树的度：孩子兄弟递归（约3分钟）

最后看一个用孩子兄弟结构写的算法，求树的度。树的度是所有结点里孩子数最多的那个数。看代码，写法很巧，我们逐行讲。

先有一个全局变量 degree，初始 0，用来记录目前见过的最大度。函数 Post(p)：如果 p 空返回 0。然后第一句 Post(p->firstchild)，递归进入 p 的子树——注意这句的返回值我们不要，它的任务只是让递归走到子树里去，把子树里的度也更新到全局 degree。

接着 int d = 1 + Post(p->nextbro)。这句是关键。1 是 p 自己，Post(p->nextbro) 返回的是 p 后面那条兄弟链的长度。p 和它后面的所有兄弟，是同一个父结点的孩子，所以 1 加上后面兄弟的个数，正好是那个父结点的孩子数，也就是那个父结点的度。然后 degree = max(degree, d)，用 d 去更新全局最大度，最后 return d。

【停顿】你把两件事分清楚。第一，Post(p->firstchild) 的返回值为什么能丢？因为它返回的是 p 的子树里某条兄弟链的长度，跟 p 所在这条链的度没关系，我们调它只是为了递归下去更新 degree。第二，1 + Post(p->nextbro) 为什么是度？因为一条兄弟链恰好对应一个父结点的全部孩子，链有多长，那个父结点的度就是多少。这个"递归里维护一个全局变量"的套路，强化阶段讲树的算法会反复用到，你在这里先吃透一个例子。

## P14 小结与课后任务（约2分钟）

线索二叉树：二叉链表有 n+1 个空链域，线索化就是把它们填成前驱后继，用 ltag、rtag 区分孩子和线索。中序线索化 InThread 靠一个 pre 指针，前驱线索当场建、后继线索下一步回填。建好之后用 Firstnode 找起点、Nextnode 找后继，遍历不用栈、空间 O(1)。

## 附录一：课后题参考答案

跟练题：默写 BiThrNode 定义与中序线索化；三层树的先根、后根序列与对应二叉树。

```c
typedef struct BiThrNode{ int data;
    struct BiThrNode *lchild, *rchild; int ltag, rtag; }BiThrNode, *BiThrTree;

void InThread(BiThrTree &p, BiThrTree &pre){
    if(p != NULL){
        InThread(p->lchild, pre);
        if(p->lchild == NULL){ p->lchild = pre; p->ltag = 1; }
        if(pre != NULL && pre->rchild == NULL){ pre->rchild = p; pre->rtag = 1; }
        pre = p;
        InThread(p->rchild, pre);
    }
}
void CreateInThread(BiThrTree &T){
    BiThrNode *pre = NULL;
    if(T){ InThread(T, pre); if(pre != NULL){ pre->rchild = NULL; pre->rtag = 1; } }
}
```

三层树（根 A 三孩子 B、C、D，B 一孩子 E）：先根序列 A B E C D，后根序列 E B C D A；对应二叉树按"第一个孩子往左、兄弟往右"画：A 左 B，B 左 E、右 C，C 右 D。

模仿题（6答21 同类）：二叉树还原成森林。

- 还原是转化的逆过程：从根沿左孩子往下走，遇到的每个结点，把它的右子树拆出来作为森林里的下一棵树。
- 判断依据：结点的右孩子如果是"兄弟"就属于同一棵树，如果一条右链走到头，就代表森林里树的边界。
- 相关结论：森林的叶数 = 对应二叉树里左指针为空的结点数（题集勾画 6选43）。

## 附录二：本节代码合集

线索二叉树以 `重邮数据结构.md` 为主（Firstnode 按批次一修正为 return p），求树的度用 `代码总结.md`。

```c
BiThrNode *Nextnode(BiThrNode *p){          // 找中序后继
    if(p->rtag == 1) return p->rchild;
    BiThrNode *q = p->rchild;
    while(q->ltag == 0) q = q->lchild;
    return q;
}
BiThrNode *Firstnode(BiThrNode *T){         // 中序第一个结点
    while(T->ltag == 0) T = T->lchild;
    return T;
}
// 中序线索树遍历：for(p=Firstnode(T); p!=NULL; p=Nextnode(p)) visit(p);

int degree = 0;                             // 求树的度
int Post(CSNode *p){
    if(p == NULL) return 0;
    Post(p->firstchild);                    // 递归进子树更新全局 degree，返回值丢弃
    int d = 1 + Post(p->nextbro);           // 自己+后面兄弟 = 父结点的孩子数
    degree = max(degree, d);
    return d;
}
```
