## P1 封面页（约2分钟）

前面三节课，我们造变量的方式只有一种：在代码里写死。int x，int a[5]，写代码的时候就要说清楚要几格。今天学一种新方式：程序跑起来之后，根据实际情况，自己向内存申请格子，用完再还回去。学完这节，你能说出程序内存的三个区，会写malloc和free的标准动作，还能认出内存泄漏和悬空指针这两个经典事故。这套东西是手写链表前的最后一块地基。今天的新词比前几节多：栈、堆、malloc、free、泄漏、悬空。词多，但道理都很朴素，全是借与还的事，拿生活里借东西的常识去套就能对上。

## P2 引题：局部数组的烦恼（约3分钟）

先看一个真实的麻烦。你要写一个程序：先读入一个n，再处理n个数据。数组总得有吧？int a[n]，能这么写吗？在C语言的约定里是不能的。数组声明的那个长度，得是写代码的时候就确定的数。可n是多少，要等程序跑起来、读到用户输入才知道。

那怎么办？土办法是开大一点：int a[1000]。够用吗？不一定。用户哪天输个1500，装不下，越界；用户只输3个，剩下997格全闲着浪费。写死一个数，两头不讨好。这个场景很常见。统计一批学生的成绩、处理一批订单、读一批数据——只要是"先读个数，再处理这么多个"的需求，全撞这个坎。靠猜一个足够大的数硬扛，迟早猜错。

问题的本质是什么？栈上的格子，大小在编译时就定了，运行时改不了。我们需要一种新的空间来源：大小可以等程序跑起来再定，要多少给多少，用完还能收回来。这个地方就是今天要讲的堆。这节课的内容，就是围着"怎么向堆要空间、怎么还"展开的。算笔账对比一下。写死a[1000]，容量固定一千格，用户输3个浪费997格，输1500个直接装不下。换成动态的方案，输3个就要3格，输1500就要1500格，空间永远刚刚好。这个"刚刚好"，就是动态内存的价值。

## P3 程序内存分三区：静态区、栈、堆（约3分钟）

在讲malloc之前，先把图画出来。程序跑起来之后，它能用的内存大致分成三个区。

第一个，静态区。全局变量住的地方，程序一开始运行就划好了，直到程序结束才收回。基础阶段我们写代码基本都在main里打转，没怎么碰过全局变量，这个区你先有个印象就行。它的特点是长寿：函数进进出出，它不受影响，谁都能去读它。长寿的代价是占着地方不放：全局变量多了，内存一直被占着，能用的就少了。

第二个，栈。这是你目前最熟的地方。你写的每一个局部变量，int x也好，数组a[5]也好，都是栈上的格子。它的特点是自动：进函数，格子自动分出来；出函数，格子自动收走，全程不用你管。

第三个，堆。一大片空地，不归任何函数自动管。你想要格子，得自己开口申请；用完了，得自己还回去。申请和归还，都是你亲手写代码完成的。

三区放在一起看，堆的特别之处就出来了：静态区和栈的空间，什么时候有、什么时候没，都是规矩定好的；只有堆，是程序运行到一半，你临时决定要多少就要多少。这个自由，就是动态内存四个字的来历。三个区的大小关系，这里说个大概。静态区通常最小，就住几个全局变量；栈中等，局部变量来来去去，占用不大；堆最大，程序能伸手要的空间基本都从这出。画图的时候，堆画得最大，不是随便画的，就是这个道理。

那么问你一个检验题：局部变量x住在哪个区？栈。函数一结束它就没了，这个现象你基础阶段就见过，今天知道它的机制了。

## P4 栈：自动管理的住所，快但做不了主（约3分钟）

把栈单独拿出来再看一眼，因为它和堆是今天的主对照组。栈的好处，前面说了，全自动。你声明一个变量，格子自动出现；函数返回，格子自动消失。你不写一行申请的代码，也不写一行归还的代码，编译器全替你办了。而且栈的分配速度很快，局部变量用起来几乎没有成本。但天下没有白吃的午餐。自动的代价，是你做不了主。格子多大，写代码的时候就得定死；格子活多久，函数的进出说了算，你想让它活得久一点都不行。

看个具体的例子。你在函数里声明int a[100]，函数一返回，这100格立刻收回，里面的数据跟着蒸发。你想把这100个数交给外面的函数用？做不到，地址还在，格子已经没了。这就是栈的限制：数据的寿命，被函数的寿命绑死了。今天引题里那个"长度运行时才知道"的需求，栈更是爱莫能助。大小和寿命都做不了主，这才需要堆出场。

栈上格子的寿命短到什么程度？短到一轮循环里就能完成一次创销。你在循环体里声明一个变量，每转一圈，它的格子都是重新分、重新收的。这个细节平时看不见，但它是栈自动管理的真实情形：位置一直在，里面的变量换了一轮又一轮。这里再接一下基础阶段的一个困惑。你可能碰到过：函数里算好的结果，函数一结束就带不出来了。当时只能说是规矩，现在你知道机制了：结果住的格子被自动收回了，地址还在，格子没了。

## P5 堆登场：malloc向堆要格子（约3分钟）

先看堆上怎么要空间。向堆申请空间的函数叫malloc，全称memory allocation，内存分配。看这行代码：int \*p = (int \*)malloc(sizeof(int));。信息量不小，我一段一段拆。malloc(sizeof(int))，括号里是要多少。malloc要的永远是字节数，一个int是4字节，所以这是要4个字节。sizeof(int)帮你算好，不用手写4，以后类型变了代码也不用改。

要到了，malloc交出来的是什么？地址。那片格子的起点编号。注意，堆上的格子没有名字，不像局部变量有x、有a，堆交出来的就是一块无名地盘，你手里只有一个地址。所以接住它的必须是指针：int \*p。那前面的(int \*)是干什么的？这叫强制类型转换。malloc交出来的地址是通用的，不带类型，你告诉它：这个地址我要当int的格子用。这个写法是惯例，你现在把它当成malloc的标准前缀就行，意思是"我要的地址，指向int"。

这里多说一层。malloc为什么交出一个不带类型的地址？因为它是通用的分配函数，谁来要空间都给，它不知道你要放int还是放结构体。类型是你自己的事：拿到地址之后，用强制类型转换告诉编译器按什么规格解读这片格子。问你一个问题：malloc完了，p指向的格子里是什么值？不知道。堆给你的格子不打扫，里面是原来残留的东西，和未初始化的局部变量一样。要求还是那条：用之前自己填值。还有一个上机才会碰到的坑，先说一句。malloc的声明在头文件stdlib.h里，你要在代码开头写#include <stdlib.h>。忘写的话，编译器不认识malloc，直接报错。这个头文件从今天起，凡是上机写动态内存，都要带上。

## P6 malloc三件套：申请、判空、使用（约4分钟）

malloc有一个必须配套的搭档动作：判空。为什么？内存不是无限的。你要的格子，堆上可能真没有——程序要多了，机器内存紧张了，malloc就要不到。要不到的时候，它不会报错，而是返回NULL，就是第一节说过的那个"明确的空"。

所以标准动作是三件套。第一步，申请：int \*p = (int \*)malloc(sizeof(int));。第二步，判空：if (p == NULL)，要不到地方，你得有个说法，打印一句话也好，结束程序也好，不能装没看见。第三步，使用：判空通过了，\*p = 100，和普通变量一样用。问你：省掉第二步会怎样？malloc要不到的时候，p就是NULL，你接着\*p = 100，就是往地址0那片谁都不许碰的地方写东西，程序当场崩溃。判空这一步，平时看着没用，但却是非常重要的判断。

顺带把NULL说完整。NULL的本质就是0，一个约定俗成的记号，表示"这个指针现在不指向任何有效的地方"。你写p == NULL和写p == 0，判断的是同一件事。正经代码里都写NULL，为的是读的人一眼看懂：这里查的是指针有没有要到地方。三件套写多了就成了肌肉记忆。你以后看别人代码，见到malloc后面紧跟着if判空，就知道这是标准姿势；见到malloc后面直接就用，你心里就该拉警报了。再问你一个串联前面知识的问题：p这个指针变量自己，住在哪个区，占多大地方？栈上，8个字节。p是局部变量，住栈上，和第一节说的一样：指针自己占的地方固定大小，装的是地址。堆上住的只有它指向的那片格子。两个位置，分清楚。

判空失败之后写什么？今天用最简单的处理：打印一句提示，return 1结束。return 1是"非正常退出"的意思，告诉外面：这次没干成。正经程序里的处理会更复杂，重试、换方案都有可能，但判空这个动作本身，什么场景都不能省。

## P8 malloc一片数组：指针当数组用（约4分钟）

刚才要了一格，真正干活经常要一整片。看这行：int n = 5; int \*arr = (int \*)malloc(sizeof(int) \* n);。括号里是sizeof(int)乘n，也就是20字节，五个int的地盘。malloc要的是字节数，这一点再强调一次：你要几个元素，就把单个大小乘上去。要到的这片格子是什么样的？连续的，和栈上的数组一模一样。所以第二节学的数组规律，这里原样适用：arr[0]到arr[4]，五个下标随便用。arr[i]就是\*(arr+i)，指针当数组名使，下标照常用。

这里有个和第二节连着的坑，必须说清：malloc要到的这片格子，不能用sizeof(arr)去算元素个数。arr是指针，sizeof(arr)算的是指针自己的大小，64位机器上永远是8，不是20。第二节那个sizeof(a)/sizeof(a[0])的算法只对真正的数组有效，对指针无效——这和当时说的"数组一旦作为参数传进函数，情况会变"是同一类问题：身份是指针，就只能拿到指针的大小。所以动态数组的长度，你得自己用一个变量记着，通常就是一个n。你那么到这里，引题里那个麻烦就里解决了。n可以运行时读进来：scanf读完n，malloc(sizeof(int) \* n)，要多长的数组就有多长。开小装不下的问题没了，开大浪费的问题也没了。

它和栈上数组的差别也分一下。用法上，arr[i]随便使，两者没区别；身份上，差别在两个字：归属。栈上数组的格子归编译器管，你只负责用；malloc这片格子归你管，什么时候要、什么时候还，都是你的账，这也是它和栈上数组最实质的区别。再补一个细节。malloc要一整片，失败是整片失败，不会给你一半。所以判空还是那一个if，不用一格一格检查。来个检验：malloc(sizeof(int) \* 10)要了多少字节？40字节，十个int。以后看到sizeof乘个n，就按这个路子算。

再解释一下为什么不直接写malloc(20)。写死数字能跑，但埋着隐雷：万一哪天换个环境，int不是4字节了，或者你把int改成double忘了同步改数字，格子就不够住了，越界悄悄发生。sizeof让字节数跟着类型走，类型变它跟着变，永远配得齐。记住这个习惯：要多少空间，用sizeof算，不手写数字。

## P9 free：借了要还，一对一配对（约3分钟）

有借有还。堆上的格子，用完要调free还回去。这个配对就是生活里借还的道理。图书馆借书，读完要还，没人天天催你，但你不还，图书馆就少一本书，下一个人借不到。malloc和free一样：借是主动的，还也靠自觉，系统只管出借和接收，不管催还。所以借的时候就要想好在哪还，别等想起来了再回头找。

free(p)，把p指向的格子交还给堆。还的规矩，三条。第一条，配对：一次malloc配一次free。要了不还，格子就一直占着，这叫泄漏，下一页细说；还了又还，同一块地方free两次，程序直接出事故。一对一，不多不少。

第二条，谁要谁还。malloc在谁手里申请的，free就该由对应的逻辑负责归还。这条现在听着抽象，落到代码上就一句话：格子在哪申请，就在哪安排归还，别让某次申请没人负责。举个具体例子。假设一个函数里malloc了一片格子，这片格子要给外面用很久，那free就不该写在这个函数里——数据还在用，不能提前还。该写在哪？写在真正用完它的那段逻辑之后。申请和归还中间隔多远不重要，重要的是每一次申请都有人负责归还。

第三条，free只还格子，不动指针。这条最容易出事，单独拎出来讲。free(p)执行完，堆上的格子收回去了，但p这个变量还在栈上住着，里面存的地址一个字没变。p还指着那片已经不属于你的地方。

还有一个常被问到的问题：free之后，那片格子里的数据还在吗？可能还在，系统不一定立刻抹掉，你侥幸读一把也许还能读出原值。但你不能赌这个：那片地盘已经易主，随时可能被新数据覆盖。free的语义是"不许再碰"，不是"数据消失"，这两件事分清楚。前面演示里那个画面记着：格子涂掉了，箭头还在。这个状态有个专门的名字，下一页讲。

## P10 内存泄漏：要了不还，地盘越积越多（约3分钟）

今天最重要的一个概念，内存泄漏。看这段代码。一个循环，每轮干一个任务，任务里需要临时空间：int \*p = (int \*)malloc(sizeof(int) \* 1000)，要1000格，干完活，进下一轮。毛病在哪？没有free。每一轮都要1000格，一格都不还。

推演一下后果。第一轮，堆上占了1000格；第二轮，又要1000格，第一轮的还占着，累计2000；第三轮，3000。循环跑一万轮，就是一千万格压在堆上，全是你借了不还的。

这种错误的阴险在哪？编译器不提醒，程序不报错，每一轮看起来都运行得好好的。只是内存悄悄见底，等操作系统发现你的程序吃光了配额，直接把它掐死。死的时候，你盯着代码看半天，找不到一行有毛病——因为毛病不在某一行，在"每一轮都漏一点"的积累。泄漏这个词很形象：一滴看不出来，滴一夜就成一滩。防的办法只有一条：见到malloc，马上问一句，它的free写在哪。找不到对应free的malloc，就是将来的泄漏。

泄漏的真实下场是这样的。程序跑着跑着越来越慢，因为能用的空间越来越少；然后某一次malloc要不到地方了——你判空了，程序正常退出；你没判空，当场崩溃。用户看到的只是"这软件用着用着就死了"，不会知道是三个月前某次忘了free。

再说一个写码习惯。写malloc的那一行，顺手把对应的free也写出来，哪怕中间逻辑还没写，先把归还的位置占上，再回头填使用过程。先写借和还，再写中间的事，账天生就是平的。这个顺序比"写完逻辑再补free"安全得多，因为补的东西最容易忘。

## P11 悬空指针：free之后，指针还指着老地方（约3分钟）

泄漏是要了不还，还有一个事故正好反过来：还了，手还伸着。这就是悬空指针。刚才说了，free(p)不碰p本身。还完之后，p里还是那个老地址，只是那片格子已经还给堆了。这时候的p，就叫悬空指针：悬在半空，指着一片不属于你的地盘。

悬空指针危险在哪？堆收回那片格子之后，随时可能把它分配给别人。你这时再来一句\*p = 5，改的就是别人的地盘，数据莫名其妙被改掉，又是一桩无头案。第一节讲的野指针是没初始化就乱指，悬空指针是曾经有效、现在失效，两者性质一样，都不许用\*。防的办法一句话：free之后紧跟一句p = NULL。第一节讲野指针的时候说过，NULL表示这个指针现在不指向任何有效内存。置成NULL之后，指针的状态是明确的，你误用它取值，程序当场报错提醒你，比悄悄改别人的数据好查得多。

到这里，指针的三种状态你集齐了，放一起对比一下。野指针：从来没初始化，指向一个没人知道的地方。悬空指针：曾经有效，free之后失效了，指向已经易主的地方。NULL指针：明确表示现在不指任何地方。三种里，只有NULL是安全的、明确的状态；前两种的共同点是"你以为它指着什么，其实那片地方不归你"。规矩合起来就一句：指针要么指向真实有效的格子，要么是NULL，中间状态不许存在。

把这两页收成一组对照：泄漏是要了不还，悬空是还了还想用。malloc和free之间把账记清，两个事故都躲开了。再补一个和它们同族的事故，叫重复释放：同一块格子free了两次。第一次还完，那块地方可能已经给了别人，第二次free还的是别人的地盘，堆的账本直接乱套，程序行为完全没法预测。防的办法和防悬空是同一招：free完立刻置NULL。对NULL再free，系统不当回事，不会出事；对老地址再free，就是事故。一句置NULL，两个事故一起堵。

## P12 malloc的邻居：calloc、realloc、new/delete（约2分钟）

第一个，calloc。它和malloc一样是向堆要空间，区别在申请的同时把格子清零：malloc要到的格子里是原来残留的值，calloc要到的格子全是0。写法是calloc(个数, 每个大小)，两个参数。需要一块全0的空间时，用calloc一步到位，省得自己写循环填零。

第二个，realloc。它的本事是改已申请空间的大小。要了10格不够用，realloc把它扩成20格，原来的数据也会一并搬过去。听着很美，但细节不少，我们这门课用不到，你读代码见到realloc，知道它是"扩容搬家"就行。

第三个，严格说不是C语言的，是C++的new和delete。它们干的事和malloc、free一样：new向堆要空间，delete归还。你以后读的代码两种风格都会见到，心里有个对应关系：new对malloc，delete对free，一套规矩，两种方言。

读代码时怎么快速区分malloc和calloc？看括号里的参数：只写一个字节数的是malloc，写两个数——个数加大小——的是calloc，而且要到的是清零的格子。认得出这两种写法就够了。这三样今天都不展开，但各自的用途你要记住：calloc管要清零的空间，realloc管改已申请空间的大小，new/delete是C++的另一套写法。

## P13 栈还是堆：按需求选（约2分钟）

学了两种空间来源，什么时候用哪个？选型表如下。

第一种场景：大小固定，函数里用完就扔。比如算几个数的平均，局部变量就够了，选栈。别没事找事上堆，栈自动管理，省心。

第二种场景：大小运行时才知道。引题里的例子，n要读进来才定，只能选堆，malloc。

第三种场景：数据的寿命要超过函数。函数里造的数据，要交给外面继续用，栈上的格子出函数就没了，只能选堆：堆上造好，把地址传出去，格子想活多久活多久。

第三种场景多说两句，因为后面经常这么用。初始化一个表、造一个结点，都是在函数里干活，造出来的东西要给外面用。标准写法就是：堆上malloc，把指针传出去，外面拿着地址用，用完负责free。今天先把这个写法记住。

总原则一句话：能用栈就别上堆。栈由编译器自动管理，堆要自己记账——每块格子都得清楚谁申请、谁归还，账多了总有记错的时候。读代码还有个视角。以后看到malloc，你就问三个问题：要了多少？判空了没有？free安排在哪？三个问题都有答案，这段内存代码就是健康的；缺一个，就大概率有问题。

这张选型表要记住。以后写程序碰到"要一块空间"的时候，先过一遍表：大小定不定？寿命多长？要不要传出函数？答案出来了，选谁就清楚了。别不动脑子全上堆，把自动管理的栈扔在一边。

## P14 本节小结（约2分钟）

今天内容密，收一下，三件事。

第一，内存三区。静态区住全局变量，从生到死；栈住局部变量，自动分配自动回收；堆是空地，自己申请自己还。动态内存的自由，来自堆。

第二，malloc三件套：申请、判空、使用。要字节数，用sizeof算；要不到返回NULL，判空不能省。一次malloc配一次free，谁要谁还，free后面跟一句置NULL。

第三，两大事故。泄漏是要了不还，空间越积越多，程序悄悄被掐死；悬空是还了还指，再碰就是动别人的地盘。两个事故都源于账没记清。

下一节讲引用与参数传递。今天你见过一个问题：栈上的数据出函数就没了，那函数之间怎么传出数据、怎么改外面的变量？下一节，把传参这件事一次说透。

最后用四句话收个尾：三区地图记心里，malloc三件套不离手，借一还一配好对，free置NULL不回头。这四句念顺了，今天的框架就记住了。

## 附录一：课后题参考答案

跟练题：

```c
#include <stdio.h>
#include <stdlib.h>
int main(){
    int *p = (int *)malloc(sizeof(int));
    if (p == NULL) {
        printf("内存不足");
        return 1;
    }
    *p = 88;
    printf("%d\n", *p);     // 88
    free(p);
    p = NULL;
    return 0;
}
```

内存图四步：① 栈上格子p，堆上四格，箭头相连；② 堆上格子填88；③ free后堆上格子涂掉，箭头还在（悬空状态）；④ p = NULL后箭头消失，指针明确为空。

模仿题：

```c
#include <stdio.h>
#include <stdlib.h>
int main(){
    int n;
    scanf("%d", &n);
    int *arr = (int *)malloc(sizeof(int) * n);
    if (arr == NULL) {
        return 1;
    }
    for(int i = 0; i < n; i++){
        arr[i] = i;
    }
    for(int i = 0; i < n; i++){
        printf("%d ", arr[i]);
    }
    free(arr);
    arr = NULL;
    return 0;
}
```

要点：字节数是sizeof(int)乘n，不是n；循环边界i小于n；用完free加置NULL。漏free这道题跑一次没事，但要养成"见到malloc找free"的反射。
