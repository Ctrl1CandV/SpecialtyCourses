## P2 引题：函数里明明改了，外面为什么没变（约2分钟）

先看一段代码。void swap，参数int x、int y，函数体三行：int t = x，x = y，y = t，三行交换写得没错。然后在main里，int a = 3，int b = 5，调用swap(a, b)，再打印a和b，但是会发现结果还是3和5，没有任何改变。这个问题几乎每个学编程的人都会碰到都会疑惑，因为它反直觉：你写swap(a, b)，看着就是把a和b交出去了。基础阶段碰到这个现象只能先记住，今天用上一节课的栈把它讲清。

先把失败版的三行走一遍。t存下x的值3，x拿到y的值5，y拿到t里的3。走完，x是5，y是3，确实换了。然后函数结束。上节课说过，栈上的格子出函数就自动回收，x和y的格子被收走，里面的5和3跟着没了。a和b的格子从头到尾没人碰过，所以还是3和5。这里先按暂停，自己答一个问题：函数里的x和y，跟外面的a和b，到底是什么关系？想清楚了再往下听，这一节就通了。

## P3 值传递：参数收到的是值的副本（约4分钟）

答案是：没有关系，它们是四个不同的格子。调用那一瞬间，栈给swap分了两个新格子x和y，a把值3复印一份交给x，b把值5复印一份交给y。内存里这时候有四个格子：外面两个，a装着3，b装着5；函数里两个，x装着3，y装着5。函数里所有操作动的都是里面那两个，外面那两个从函数开始到结束没人碰过。这就是改不动的原因，跟函数体写得对不对没关系。三行交换写得再漂亮，改的也是副本。复印发生在什么时候？就在调用那一瞬间，参数还没进函数体，值已经拷好了。所以哪怕函数里一行都不用x，那次复印也照做不误。复印是传参机制的固定动作，不是你能选择省掉的。

这个机制有个正式名字，叫值传递：传的是值，是副本。它是C语言传参的默认行为，你之前写的每一个函数，参数都是这么进来的。顺带把两个术语对上。调用时交出去的a和b，叫实参，实际参数；函数头上接收的x和y，叫形参，形式参数。值传递的本质就一句话：实参把值复印给形参。这两个词后面会一直用。检验一下：函数里把x改成100，外面的a会跟着变吗？答案是不会。x是a的副本，不是a本人。

还要说清楚一点，值传递不是失败的写法，它有正当用途。函数只读数据不改的时候，值传递最简单：传一个数进去算平方，return把结果递出来，全程不碰原件。而且它天然安全，函数里怎么折腾参数都不会意外改掉外面的数据；要产生副作用，得显式地传地址或引用，不会默认发生。所以准确的说法是：值传递改不动外面，但能用返回值把结果递出来。真需要直接改原件，才要用下面两种写法。

## P4 解法一：指针传参（约3分钟）

原因清楚了，办法就有了。改不动是因为函数拿到的只是一个拷贝，拿不到a和b的位置，那就把位置交进去。看这个版本。void swap，参数int \*px、int \*py，两个指针。函数体三行：int t = \*px，顺着px取出a的值；\*px = \*py，把b的值放进a的格子；\*py = t，把原来的a值放进b的格子。调用处写swap(&a, &b)，交出去的是a和b的地址。函数里改的是谁？\*px顺着地址找到a的格子，改的就是a本人。有一点要说准：px和py自己还是栈上的新格子，装的还是副本，只不过这次是地址，不是值。指针传参没有绕开复印，只是复印的东西换了。

内存图上和值传递的差别就一处。值传递的图上，函数里的格子和外面的a、b之间没有任何箭头；指针传参的图上，px、py的箭头跨出函数框，指到外面的a、b。改不改得动外面，落到图上就是有没有那根跨出去的箭头。这张图课后自己画一遍。

两个必须说的细节。第一，临时变量t不能省。有人想直接写\*px = \*py，再\*py = \*px：第一句执行完，a原来的值已经被b的值盖掉了，找不回来，第二句只是把b的值又赋了一遍，结果a和b都是5。交换必须三步。第二，调用处漏写&，写成swap(a, b)，代码能编译过，但a和b的值会被当成地址传进去，函数顺着这两个假地址去写内存，大概率当场崩溃。参数是指针，调用处就必须交地址。

指针传参还有一件返回值做不到的事：一次改多个变量。return只能递一个值出来，指针传参可以把两个、三个变量的地址都交进去，函数里一起改。上机的时候可以顺手验证一次：在函数内打印px，在main里打印&a，两个值一模一样；换成失败版，在函数内打印x的地址，和a的地址不一样。

## P5 解法二：引用，变量的第二个名字（约3分钟）

指针传参能解决问题，但写起来有点绕：函数里到处是星号，调用处还得记着写&。C++给出了一种更加简便的方法，就是引用。其本意就是规避复杂的指针操作，直接去使用指针变量的优点，此外他没有特殊的属性。看三行。int x = 10；int &r = x，注意&写在类型和名字中间，读作r是x的引用；最后一行r = 20，x也变成20。引用的意思就是别名：r和x是同一格内存的两个名字，没有新格子，改r就是改x。第一节课说的别名现象，到这里有了专门的语法。两条规矩要记住。第一，定义的时候必须初始化，int &r;单独一行不合法，别名得先有本尊。第二，绑定之后不能改绑。这条最容易和指针搞混：r已经是x的别名了，你再写r = y，意思不是让r改指向y，而是把y的值赋给x。

检验一下。int x = 3, y = 5; int &r = x; r = y;。执行完r和x分别是多少？都是5。r是x的别名，r = y就是把y的值5赋给x，r从头到尾没换过人。这一点和指针正好相反：指针随时能换指向，引用绑了谁就是谁。一个必须分清的写法问题：这里的&和取地址的&是同一个符号，两种含义。int \*p = &x里的&是取地址，算出一个地址；int &r = x里的&是声明别名，写在类型和名字中间。看位置区分就行。

背景说明一句：引用是C++的语法，纯C没有它，但我们这门课的伪代码环境里直接可用，C和C++的边界问题不在这门课范围内。画内存图的时候，引用不画新格子，就在x的格子旁边多写一个名字r；指针要画自己的格子，再画箭头。画法上的这个差别，对应的就是两者的本质差别。

## P6 引用传参：函数体和失败版一样（约2分钟）

引用拿来传参，就是第二种解法。void swap，参数int &x、int &y，函数体和失败版一模一样：t存x，y给x，t给y。调用处swap(a, b)，不用写&。

关键在这：调用swap(a, b)的时候，x不是a的副本，x就是a的别名。所以函数里改x，改的就是a本人。三个版本并排看，失败版和引用版的函数体一字不差，区别只在参数表的两个&。参数上有没有&，决定函数能不能改到外面的数据。

引用传参还有个实在的好处：没有复印。值传递每次调用都要拷一份，传个int无所谓，传一个大结构体，每调用一次就拷一整片。上节课那个Student，参数写struct Student stu，每次调用都把整个学生拷一遍，改的还是副本，外面的分数纹丝不动；写成struct Student &stu，直接改本人，一个格子都不拷。

## P7 三种传参：一张表与怎么选（约4分钟）

三种写法放到一张表上。值传递，参数收到值的副本，改不动外面，调用处写swap(a, b)；指针传参，参数收到地址，顺着星号改得动外面，调用处写swap(&a, &b)；引用传参，参数收到别名，直接改得动外面，调用处写swap(a, b)。PPT上就是这张表，你照着记。

读代码的口诀就一句：先看参数表，再看函数体。参数是光杆类型，值传递，改不动外面；带星号，指针传参；带&，引用传参。判断的时候只认参数表，不认函数名，名字叫changeX，参数要是光杆的int x，照样改不动外面。

我们可以现场写一个void process(int n, int \*p, int &r)，三个参数三种传参，不看函数体你就能说：n是读进来的副本，改不动外面；p指向的东西可以被改；r本人可以被改。一个函数头能读出三句话。再补一种情况：一个函数的参数有的带&有的不带，这时候逐个判断，别整体当成都能改或者都不能改。

怎么选，四条。第一，函数只读数据不改，用值传递，简单直接。第二，函数要改外面的变量，首选引用传参，写法干净；代码要兼容纯C环境，用指针传参，能力一样，只是调用处多写&、函数里多用星号。第三，传大块数据，结构体、大数组这类，别用值传递，整块复印成本太高。第四，数组做参数只能用指针传：函数头写int a[]和写int \*a是一回事，因为数组名传出去的就是首元素的地址，第二节和上节课都碰到过这一点。

第四条里藏着一个很容易混的地方，单独说一句。数组做参数的时候，函数里写arr[0] = 99，外面的数组真的被改了。这不是值传递失效了，而是因为传出去的是地址，函数拿到的本来就是外面那片格子。看着像值传递却能改外面，原因就在数组名交出去的是首元素地址，不是整片数组的副本。

再补一句引用和指针的分工。引用能干的指针都能干，反过来不成立：指针能换指向、能在数组里走、能指向动态内存，这些引用做不到。引用换来的是写法干净，代价是不能换指向，两个都得会。还有个常见写法顺带认一下：const int &r，表示这个别名只读不改，认识就行。

## P8 为什么伪代码的参数上常写&（约4分钟）

最后落到我们这门课的主线：为什么伪代码里到处都是引用传参。我们写一个初始化函数，要把一个表清零、长度置0；写一个插入函数，要往表里添一个元素。这些函数干的活都是直接修改传进来的那个结构。要是用值传递，函数改的是副本，表本体一点没动，等于白干。所以这类函数的参数必须写&：把外面的表以别名的方式请进来，函数里改参数，就是改表本身。

读伪代码的信号就是这个：看到参数上带&，这个函数会动调用者的数据；看到不带，它多半只读。反过来也成立，函数不碰外面数据的时候故意用值传递，副本干活，原件天然受保护。

这里有个读代码的细节要提醒：参数带&的函数，调用处是不写&的，和指针传参正好相反。你要是按指针的习惯去调用处找&，找不到就以为它改不动外面，那就判断错了。认参数表上的&，不认调用处的&。

自己写函数的时候也用得上。动手前先问一句：这个函数需要改传进来的东西吗？需要，参数加&；不需要，就不加。这个&加不加，等于在函数头上写明了进来的人能不能动屋里的东西，写清楚，读的人省心。上节课的动态内存也接得上。函数里在堆上造了数据，怎么交出去？两条路：参数用引用，函数里把新地址写进参数；或者用返回值把地址递出来。

这里还有一件相关的事必须说：函数不能返回局部变量的地址。局部变量住栈上，函数一返回格子就被收回了，你把它的地址递出去，外面拿到的是一个指向已回收内存的地址，也就是上节课说的悬空指针。这种错编译器不一定拦，跑起来可能没事，也可能随时出问题。所以数据要交到函数外面，只有两条路：堆上malloc之后把地址交出去，或者用引用参数把地址写进参数。到这里，基础阶段那个"函数为什么改不动外面"的问题彻底解开了：值传递交的是副本，想改得动，就把地址或别名交进去。

## P9 本节小结（约2分钟）

今天的内容收一下，三件事。

第一，值传递的机制。调用函数时，实参把值复印给形参，形参是栈上的新格子，函数改的是副本，所以改不动外面的变量。基础阶段那个为什么，答案就在这。

第二，两种改得动的写法。指针传参：实参交&a，形参是int \*，函数里顺着\*px改；引用传参：形参写int &x，x直接是a的别名，函数里改x就是改a。两种能力一样，区别在写法干净程度和是不是纯C环境。

第三，引用的两条规矩：定义时必须初始化，绑定之后不能改绑，r = y是改值不是改指向。

## 附录一：课后题参考答案

跟练题：

```c
#include <stdio.h>
void swapPtr(int *px, int *py){
    int t = *px;
    *px = *py;
    *py = t;
}
void swapRef(int &x, int &y){
    int t = x;
    x = y;
    y = t;
}
int main(){
    int a = 3, b = 5;
    swapPtr(&a, &b);
    printf("%d %d\n", a, b);   // 5 3
    swapRef(a, b);
    printf("%d %d\n", a, b);   // 3 5
    return 0;
}
```

内存图：指针版画函数内两个格子px、py，各存a、b的地址，箭头跨出函数框指到外面的a、b；引用版不画新格子，x、y直接标成a、b的第二个名字。两个版本都跑通之后，把失败版也跑一次，三种行为在一个程序里对比。

模仿题：

```c
#include <stdio.h>
void increment(int &n){
    n = n + 1;
}
int main(){
    int n = 10;
    increment(n);
    printf("%d\n", n);         // 11
    return 0;
}
```

对照实验：把参数改成void increment(int n)，函数体不变，调用后打印出来还是10，因为改的是副本。要点：参数带&时调用处不写&，函数里改n就是改外面的n；这个函数的结构和数据结构的初始化函数是一类，外面建东西，函数里修改，改完外面看得见。
