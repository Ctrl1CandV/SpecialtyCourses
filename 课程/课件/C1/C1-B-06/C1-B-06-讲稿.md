## P2 引题：函数调用自己，允许吗（约3分钟）

先看一段代码。void countdown，参数int n。函数体两行：先打印n，然后写了一句countdown(n - 1)。你看清楚最后那行了吗？countdown在调用countdown，函数在调用它自己。第一次见这个写法，多数人的反应是：这允许吗？不会乱套吗？这是允许的，而且叫递归，函数自己调用自己。C语言里调别人是调用，调自己也是调用，编译器一视同仁。但这段代码确实有问题，问题不在语法，在逻辑：它永远停不下来。你想，countdown(3)打印3，调countdown(2)；打印2，调countdown(1)；打印1，调countdown(0)；打印0，调countdown(-1)……负数一路打下去，没完没了。这叫无限递归，是递归的头号事故，后面专门讲。

怎么去进行补救呢？我们需要给它一个停止的出口，比如n到0就不调了。这个"停止的理由"即递归出口，是递归的第一要素，也是今天的第一块内容。加上停止条件之后，你再走一遍countdown(3)：打印3，调countdown(2)；打印2，调countdown(1)；打印1，调countdown(0)；打印0，n等于0，条件成立，不再调用，函数一层层回头。输出3、2、1、0，干净利落。同一个函数，一个条件的差别，从无限循环变成正常结束。递归的命门，就在这一个条件上。

先说一句：递归在树和图的代码里出现频率极高，你会大量见到"函数里又调了一遍自己"的写法。今天把机制搞懂，那些代码就不难读。生活里你其实见过递归的样子。两个镜子对着照，镜子里有镜子，镜子里的镜子里还有镜子，一层套一层；再比如剥洋葱，剥完一层，里面还是一个同样的洋葱，直到剥到芯。递归就是这个结构：大问题里套着长得一样的小问题，一层一层往里走，走到底，再一层一层退出来。有了这个画面，后面的机制就不抽象了。

## P3 递归三要素：终止、缩小、返回（约3分钟）

换一个正经的例子：阶乘。n的阶乘，就是从1乘到n，比如3的阶乘是6。用递归来写，看这三行。int fact，参数n。第一行：如果n等于0，返回1。第二行：返回n乘以fact(n - 1)。先说这个式子从哪来的。阶乘有个天然的递推关系：n的阶乘，等于n乘以n-1的阶乘。你验证一下：3的阶乘是6，3乘上2的阶乘——也就是2——正好是6。这个"大问题拆成同类小问题"的关系，就是递归能成立的前提：问题自己套着自己。写递归之前，先找到这个关系，找不到，就不适合用递归。

我把这三行拆成三个要素，你一个一个看。

第一个要素，终止条件：if (n == 0) return 1。这是递归的刹车。没有它，函数一层层调下去，永无止境。为什么0的阶乘返回1？这是数学约定，0的阶乘定义为1，你照用就行。终止条件的作用是给递归一个到底的楼层：降到这一层，不再往下调，开始回头。

第二个要素，缩小规模：fact(n - 1)，每次调用，问题都比上一层小一点。n变成n-1，离终止条件0就近了一步。这个要素保证递归能走到头：只要每一步都真的在缩小，迟早会撞上终止条件。你要是写了一个范围没有缩小的递归，那就跟countdown一样，变回无底洞。

第三个要素，返回值：return n \* fact(n - 1)。这一层干完自己的活，把结果交回给上一层。递归不是白跑一趟，每一层都要带着答案回来。

问你一个检验：fact(3)会调用几次fact？算上fact(3)自己。答案是四次：fact(3)、fact(2)、fact(1)、fact(0)。到fact(0)触发终止，不再往下调。

三要素你记住顺序：写递归，先写终止条件，再写缩小，最后写返回。这个顺序不是随便排的：终止条件是保命条件，再去考虑实际功能。这个阶乘的例子今天会贯穿始终，这三行代码你先拿稳了。拿刚才的countdown练一次三要素识别。终止条件是什么？n等于0不再调。缩小是什么？n减1，每次都离0近一步。返回呢？它只打印不返回东西，所以没有第三要素，这是个void的递归。你看，三要素是检查清单，不是每个都得填满，但前两个缺一就是事故。

## P4 调用栈：一层层展开，再一层层收回（约3分钟）

代码看懂了，机器是怎么执行它的？这里要引入一个关键概念：调用栈。上节课说过，函数一调用，栈上就给它分格子，放参数和局部变量；函数一返回，格子收回。递归就是这件事连续做了很多遍。

慢放fact(3)的全过程。第一步，main调用fact(3)，栈上压进一层，里面住着n = 3。这一层执行到return n \* fact(n - 1)，它要先算fact(2)，于是暂停自己，调用fact(2)。第二步，fact(2)压进来，住着n = 2。注意，这个n和上一层的n是两个不同的格子，各是各的，互不干扰。fact(2)也要算fact(1)，暂停，压fact(1)。第三步，fact(1)压进来，n = 1，它又要算fact(0)，压fact(0)。第四步，fact(0)压进来，n = 0，这回if条件成立，不再调用，直接返回1。到底了，开始回头。

收回的过程反着来。fact(0)把1交给fact(1)，fact(1)算1乘1等于1，交下去；fact(2)拿到1，算2乘1等于2，交下去；fact(3)拿到2，算3乘2等于6，交给main。每交一次，对应的格子就收回一次，栈一层层矮下去，最后只剩main。

把数字摆一排你更清楚：展开是3、2、1、0四层压进去，收回是1、1、2、6四个答案递回来。展开靠的是调用，收回靠的是返回值，两个方向，同一叠格子。问你：fact(2)和fact(1)里的n会打架吗？不会。每层调用都有自己的格子，参数各住各的。这是调用栈最重要的性质：同名不同格，层与层隔离。很多人想不通递归，就是以为只有一份n，其实每一层都自带一份。

再问你一个更细的：fact(3)自己的那层格子，什么时候被收回？不是调fact(2)的时候，是它拿到fact(2)的结果、算完3乘2、把6交出去之后。格子要等这层的活全干完才收。所以展开的过程中，四层格子是同时存在的，都在栈上叠着。这就是递归的空间代价：层数越深，同时占着的格子越多。

## P5 动画演示：fact(3)的调用栈（约5分钟）

这一页画调用栈，这张图是递归的标准画法。PPT会一步一步放，你拿纸跟着画。

第一步，竖着画一个框，写fact(3)，旁边标n = 3，这是第一层，先压进来。第二步，在它下面接着画fact(2)，标n = 2；再下面fact(1)，n = 1；最底下fact(0)，n = 0。四层框摞起来，像叠盘子，越往下压得越晚，你在每层之间画个向下的箭头，表示调用。

第三步，从最底下的fact(0)开始画回头箭头。fact(0)旁边写"返回1"，箭头指上去；fact(1)这层写1乘1，返回1；fact(2)写2乘1，返回2；fact(3)写3乘2，返回6，向上的箭头一路回到顶。第四步，在图右边写一行小字：展开是向下的，收回是向上的，每一层自带一个n。

检查你的图：四个框摞成一摞，每框一个n，向下箭头是调用，向上箭头是返回。这张图画顺了，递归运行的画面你就有了。

补一个常见错法：有人把四层的n都写成同一个，改一处全跟着改。不对。四层是四次独立的调用，四个独立的格子，fact(2)的n等于2，fact(1)的n等于1，谁也碰不着谁。叠盘子的比喻记着：盘子长得一样，装的东西各是各的。

画完这张图，再来一个自测动作。把图盖住，只看代码，自己在纸上重新画一遍fact(4)的栈：应该五层，最深到n等于0，最后返回24。画得出来，调用栈的模型就是你的了；画不出来，倒回P4再听一遍，不亏。

## P6 递归与迭代：一套问题，两种写法（约3分钟）

阶乘这个问题，你其实可以用基础阶段的循环去写。两种写法今天都要亲手写一遍，写顺了再上机，放一起对比一下。

迭代版：int result = 1，for循环i从1到n，每轮result乘i。一个变量从头跑到尾，格子只有一层。

递归版：三层函数体，靠调用展开成多层。两种写法算的是同一件事，结果一模一样，路子完全不同。

差在哪？迭代只用一层格子，从头用到尾，循环转多少圈，空间还是那一层，更省空间一些。递归是叠盘子，问题多深就叠多少层，每层都占格子，空间跟着层数走。阶乘这种问题，循环写起来又快又省，递归没有便宜可占。

顺带说一句实际限制：递归版的层数等于n，算fact(1000)就要在栈上同时叠一千层，栈有可能会撑不住崩溃，这个事故下一页就讲；迭代版不管n多大，栈上始终只有一层。所以平铺的问题优先用循环，除了省空间，还省掉了栈深度这个隐患。

拿具体数字算一下。算fact(100)：迭代版始终只用result和i两个变量，空间从头到尾不变；递归版要在栈上同时叠101层，每层一份n加返回地址。n越大，递归占的空间越深。这就是为什么平铺的问题优先选迭代：不是递归不能写，是账不划算。

那递归的价值在哪？在问题自带层次的时候。你以后会遇到这类问题：一棵树，处理完根，要对每棵子树做同样的事；一个迷宫，走完这一步，剩下的路还是一模一样的走法。这种"大问题里套着一模一样的小问题"的结构，用循环写能绕晕你，用递归写，三行就完。

所以结论不是"递归好还是迭代好"，是按问题选：平铺直叙的问题用循环，自带层次的问题用递归。两种写法你都要会认、会写。其实我还有一个判断的土办法，在写代码之前问自己一句：这个问题处理完一步之后，剩下的部分是不是和原问题长得一样？阶乘是：算完n这一层，剩下的是n-1的阶乘，长得一样，递归能写；但同样可以用循环一步步累，选循环更省。以后碰到那种"剩下的部分和原题一模一样"的问题，就可以考虑用递归。

## P7 递归的两大事故：无限递归与重复爆炸（约4分钟）

递归威力大，坑也实在，包含了两个经典事故。

第一个是无限递归。根源就一个：终止条件漏了，或者写了但永远够不着。countdown漏写是漏了；还有一种更隐蔽的：缩小方向错了，比如终止条件是n == 0，缩小却写成fact(n + 1)，越调越大，永远到不了0。后果是什么？每层调用都要占栈上的格子，一层层压下去，压到栈撑不住，程序崩溃——这个事故叫栈溢出，机制下面单独说。

只有一条要记住：写递归，第一行就写终止条件。先想清楚什么时候停，再想怎么调。检查的时候问一句：不管从什么输入出发，规模是不是真的在往终止条件靠？并且这个或这些终止条件是否真的能被百分之百触发？

把栈溢出的机制说透。栈的容量是有限的，不是无限大。每调用一层，栈上就多一个格子，存着这一层的参数和返回地址。无限递归就是一层一层只压不收，格子越叠越高，叠到栈顶，操作系统直接判定程序崩溃。你上机试的时候看到的"栈溢出"报错，就是这个现场。反过来想，正常的递归为什么会停？因为终止条件到了，开始只收不压，格子一层层退回去，栈永远高不到哪去。

第二个，重复爆炸。看斐波那契数列的递归写法：fib(n)等于fib(n - 1)加fib(n - 2)。写法三行，人畜无害，但它有个致命问题：重复计算。你算fib(5)，要算fib(4)和fib(3)；算fib(4)的时候，fib(3)又算了一遍。越往下，同一个子问题被算的次数越多，n稍微大一点，计算量像滚雪球一样爆炸，程序慢到像死机。

这个问题有更聪明的解法，核心思路是把算过的结果记下来，下次直接查，不重算。今天不展开，但你要记住两件事：见到递归代码，先扫一眼有没有重复的子问题；自己写递归，发现慢得离谱，先怀疑重复计算。

重复的量有多大，看一个数。这个写法算fib(40)，实际的调用次数是几亿次。不是四千次，是几亿次：每层都分裂成两个调用，层层翻倍，同一批小问题被翻来覆去算。而聪明的写法算fib(40)只要几十步。同一个思路，记不记账，差出天上地下。

递归和指针一样，画图也是硬道理。调用栈图就是递归的内存图，以后写递归卡住了，别盯着代码硬想，把展开和收回的过程画出来，一层一层标上参数和返回值，思路自然就顺了。

## P8 综合实战：把四样工具装进一个程序（约3分钟）

递归讲完，后半节课做一件事：把前面五节课的工具合起来，写一个能跑的程序。先把定位说清楚，免得你误会。等下我们会写一个记数的小表，还会用指针把几块内存串起来，这是在回顾C语言强化阶段的知识内容的同时，预习数据结构。顺序表和链表的正式内容——插入删除怎么做、头结点是什么、怎么查找、单向双向循环有什么区别——都在数据结构课里讲。今天借这两个壳，练的是四样工具：结构体、指针、动态内存、引用传参。

第一个组合：结构体里装数组。看定义，struct List，两个成员：int data[10]，数据放这里；int length，记当前存了几个数。为什么要多一个length？因为数组自己不知道里面存了几个数，开了10格，用了3格还是5格，数组不说，你得自己记一个。这就是结构体最直接的用法：把相关的数据和它的计数打包在一起。

第二个组合：引用传参改这个结构体。写一个初始化函数，void initList，参数struct List &L，函数体一行：L.length = 0。注意参数上的&：表是main里造的，函数要把它的length改成0，不带&改的就是副本，外面的表纹丝不动。上节课的内容，这里直接用上了。再写一个往里放数的函数，void insert，参数struct List &L和int x，两行：L.data[L.length] = x，然后L.length++。main里造一个表，initList，insert三次放5、8、2，再用for循环从0到length-1打印data[i]，输出5、8、2，一个能跑的程序就成了。

数一下这几行代码用了哪些东西：结构体和点号是第三节的，数组和下标是第二节的，引用传参是第五节的。这就是综合的意思：不是学新知识，是把学过的接起来。

## P9 结构体里装指针：自引用为什么合法（约3分钟）

换个组合：结构体里不装数组，装一个指向同类的指针。为什么要换？刚才那个表用的是数组，数组有两个硬约束：格子必须连成一片，大小在写代码的时候就定死了。要让几块分开申请的内存互相认识，只有一样东西能做到——指针，把对方的地址存下来。看定义。struct Node，两个成员：int data存数据；struct Node \*next，一个指针。这个指针有点特别，你仔细看它的类型：struct Node \*，指向struct Node的指针——指向的是自己的同类。

这种写法叫自引用。第一次见可能觉得绕：Node还没定义完，怎么就能用Node了？关键在那个星号：成员不是Node本身，是一个指针。指针只占固定的格子，装的是一个地址，它不需要知道Node内部长什么样，只需要知道指向的是Node这种类型。所以编译器认这个写法。

反过来看一个真不行的写法：成员直接写struct Node next，不带星号。那等于Node里套一个完整的Node，套下去没有尽头，编译器也算不出这个类型要占多大。记住一句：自引用必须隔一层指针。还有一处细节：定义里写的是struct Node \*next，struct不能省。因为此刻Node这个名字还没有别名，类型的全名就是struct Node。上节课学的typedef就是解决这个的，起了别名之后才能写短。

问你一个问题：next这个成员里装的是什么？一个地址，指向另一片同类型的内存。它自己不装数据，装的是"下一块在哪"。

## P10 malloc造、串、走、还（约3分钟）

定义好了，开始造。造在哪？堆上。两个原因：要几块是运行时才知道的事，而且造出来要活得比函数长。上节课那张选型表，这里直接对上。

造一块三行代码。struct Node \*p = (struct Node \*)malloc(sizeof(struct Node))，向堆要一块结点大小的内存，判空照旧不能省；p->data = 10，用箭头装数据；p->next = NULL，暂时没有下一块，先置空。

问你：next为什么要先置NULL？malloc到的内存不清零，next里是残留的垃圾地址。不置NULL就顺着它走，p = p->next会走到不知道哪里，轻则打印乱数，重则当场崩溃。还是那条规矩：指针要么指向确定的地方，要么是NULL。

串起来就一句：p->next = q，把q的地址放进p的next里。从此顺着p的next就能找到q。三块内存就是这么互相认识的。

走一遍也只用一句：struct Node \*p指向第一块，while(p != NULL)，循环里先打印p->data，再p = p->next，顺着箭头往前走一步。走到最后一块，它的next是NULL，p变成NULL，条件不成立，循环停。这就是第一节学的见箭头顺着走，加第二节的循环。

最后收尾：三块内存都要free，free完把指针置NULL。造、串、走、还，四步走完，动态内存的账才是平的。

这一页画这个阶段的收官图：一张图把四样工具全画上。PPT会一步一步放，你拿纸跟着画。

## P13 本节小结与课段收尾（约3分钟）

第一，递归。三要素：终止条件、缩小规模、返回值，写的时候先写终止条件。运行机制是调用栈：一层层展开，每层自带自己的参数，再一层层带着结果收回。两大事故：漏终止条件的无限递归，重复子问题的计算爆炸。

## 附录一：课后题参考答案

跟练题：

```c
#include <stdio.h>
int fact(int n){
    if (n == 0) return 1;      // 终止条件
    return n * fact(n - 1);    // 缩小规模并返回
}
int main(){
    printf("%d\n", fact(5));   // 120
    return 0;
}
```

迭代版：

```c
int result = 1;
for(int i = 1; i <= 5; i++)
    result = result * i;
```

调用栈图：fact(3)→fact(2)→fact(1)→fact(0)四层展开，返回依次为1、1、2、6。

模仿题：

```c
#include <stdio.h>
#include <stdlib.h>
struct Node {
    int data;
    struct Node *next;
};
int main(){
    struct Node *a = (struct Node *)malloc(sizeof(struct Node));
    struct Node *b = (struct Node *)malloc(sizeof(struct Node));
    struct Node *c = (struct Node *)malloc(sizeof(struct Node));
    a->data = 1; b->data = 2; c->data = 3;
    a->next = b;
    b->next = c;
    c->next = NULL;
    struct Node *p = a;
    while(p != NULL){
        printf("%d ", p->data);
        p = p->next;
    }
    free(a); free(b); free(c);
    return 0;
}
```

要点：三个结点各malloc一次，判空略写但真实代码不能省；串联就是前一个的next存后一个的地址；遍历走到NULL为止；三个结点都要free。
