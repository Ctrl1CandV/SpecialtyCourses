## P3 指针运算：p+1是往前走一格（约4分钟）

我们先做一个实验。int x = 10，int \*p = &x。假设打印出来p是1000。现在我打印p + 1，你猜是多少？很多人第一反应是1001。地址加1嘛，听起来很合理，但实际打印出来是1004。为什么差4？因为p是int \*，指向的是一个int的格子，一格int占4个字节。指针加1，意思是往前挪一格，一格就是4个字节。如果p是char \*，指向的格子只有1个字节，那p+1才是真正的加1。

这里正好把上节课的一句话接上：类型决定盒子大小。盒子有多大，指针走一步的步子就有多大。int的盒子4格，走一步4格；double的盒子8格，走一步8格。指针不认识字节，它只认识格子。你可以自己动手验证一下：声明一个double的变量，拿指针打印它和它加1的地址，会看到差8。类型不一样，步子不一样，自己验证一遍，比听我讲十遍都记得牢。

所以p+n的意思，就是从当前位置往前挪n格。注意是n格，不是n个字节。后面讲数组全靠这一条，先记牢：指针的加减，永远按指向的类型缩放。脑子里要有这么一幅图：内存是一片连续的字节，每个字节一个编号；int变量住进去，一次占四个连续字节；p指向的是这四字节的起点，p+1就是跳过这四字节，落在下一个int的起点上。以后看指针运算，都按这幅图想，不会错。

这里还有个读代码时容易混的地方：p+1算出来的是地址，\*(p+1)才是那个地址上的值。打印地址用%p，打印值用%d，两个转换说明不能混。读代码的时候先看有没有星号：没有星号，得到的是编号；有星号，拿到的才是内容。这两个一混，就会把地址当数据用。

再补两点。减法同理：p - 1往后挪一格，也按类型缩放。还有一个常用运算：两个指向同一个数组的指针相减，得到它们之间隔了几格。比如q指向a[3]，p指向a[1]，q - p等于2。这个运算以后算"两个位置之间还差几个元素"时会用到，今天先有个印象。

## P4 i++与++i：先用再加，先加再用（约2分钟）

刚才代码里出现了p++，趁这个机会，把基础阶段留下的一个问题顺带说清：i++和++i到底什么区别。看这两行。int i = 3，先打印i++，打出来是3，然后i才变成4；再打印++i，i先变成5，再打印5。区别就一句话：i++是先用当前的值，用完再加1；++i是先加1，再用。前置后置这两个术语不用背，读代码的时候把i++理解成"这一轮先用，用完再加"，把++i理解成"先加好再用"，就够了。

实际写代码，绝大多数场景用的是先用再加的写法：for循环里的i++，遍历里的p++，都是这一轮用完，下一轮用新值。两种写法在循环里效果一样，照着主流写法来就行，不用在这里纠结。这里来个易错点检验。int i = 3; printf("%d", i++ + 1); 打出来是几？4。加法用的是i当时的值3，加1得4，打印完i才变4。这类"自增混在表达式里"的写法，读的时候只问一句：这一步用的是加之前还是加之后的值。考试和正经代码里都不鼓励这种写法，但你得读得懂。回到指针上也是同一件事：p++之前，\*p是当前这一格的值；p++之后，p挪到下一格，\*p就变成下一个元素的值。等下写遍历循环，靠的就是这个先后顺序：先拿值，再挪格子。

## P5 数组名是首元素的地址（约5分钟）

指针的移动讲完了，回头看数组。基础阶段说过，数组是一排带编号的盒子。现在加上地址的视角：这排盒子在内存里是连成一片的，一格挨着一格，中间不留空。关键结论：数组名a，就是首元素a[0]的地址。你printf用%p打印a，打出来的就是第一格的门牌号。注意，这里不用写&a，数组名自己就是地址。

为什么不用写&？回想上节课那句话：地址就是格子的编号。数组名a本身代表的就是那片格子的起始编号，它已经是地址了，再用&反而是多此一举。这和变量不一样：变量x的名字指的是那个盒子，要用&x才能把编号拿出来；数组名a的名字直接就是编号。区别就在这：x是盒子本身，a直接就是门牌号。

有了地址，有了刚才的指针运算，一个等价关系就出来了。a[2]是什么意思？就是从a这个起点出发，往后数两格，取那一格的值。C语言里有个完全等价的写法：a[2]就是\*(a+2)，星号外面套括号。a是起点，a+2是按int的格子往后挪两格的地址，取值，就是30。我问你：a[4]等于\*(a+几)？\*(a+4)。下标是几，括号里就是几，永远差不了。

再回头看遍历数组的for循环，i从0到n-1。现在你能看懂它在干什么了：i每加一次，就是指针往后挪一格，把整片格子从头走到尾。基础阶段你写的每一个数组遍历，本质上都是指针在移动。

这个等价关系是双向的：a[i]能写成\*(a+i)，\*(a+i)也能写成a[i]。延伸一步，指针p指向数组时，p[2]和\*(p+2)也是一回事。下标这套写法对指针同样有效，p[i]就是"从p当前位置数i格"。两种写法你要能互相改写。

这里有两个可以自己动手验证的动作。第一个，打印a和a+4的地址，看差多少。a[5]是五个int，一格4字节，a+4应该比a大16。你上机跑一下，差值对得上，就说明这五格真是连成一片的，中间没有空隙。第二个，同一个元素用两种写法各打印一遍，a[2]和\*(a+2)，结果都是30。它们在编译器眼里就是同一个地址计算，下标只是写给人看的形式。顺带破一个说法：指针法比下标法快。早年某些编译器上也许有一点差别，现在基本没有，生成的代码是一样的。所以选哪种是可读性的问题，不是性能的问题，你不用为了快去找别扭的写法。

## P6 下标为什么从0：0表示起点自己（约3分钟）

现在正式回答第一个为什么：下标为什么从0开始。你再看一遍刚才那个等价关系：a[i]就是\*(a+i)。这里的i表示的是离起点几格：a[1]离起点1格，a[2]离起点2格。那起点自己呢？离起点0格，所以是a[0]。

从0开始数，一切顺理成章：下标就是偏移量，0表示没挪动，还在起点。

反过来想，要是下标从1开始会怎样？起点自己得写成a[1]，而机器算地址还是从起点挪i格，每次都得先减个1再算。多一次换算，就多一次出错的机会。从0开始，下标本身就是地址偏移量，不用换算。

还有一个直接的好处：数组长度是n，下标从0开始，合法下标就是0到n-1，最后一个下标刚好是长度减1，循环条件写i < n就行。要是从1开始，合法下标变成1到n，条件得写i <= n，而且每一处用下标算地址的地方都要先减1。

所以"下标从0"这条规矩来自地址运算本身。理解了这一层，以后看到从0计数的地方——循环从0到n-1、长度n最大下标n-1——你都知道为什么了。

顺带说一句，Java、Python的数组和列表下标也都从0开始。原因不完全一样，但根子是同一个：下标表示的是偏移量。这一点在C里体现得最彻底，因为下标直接参与地址计算，那个减1是实打实要做的一次运算。

你自己也能数一遍确认：a[5]是五个元素，下标0、1、2、3、4，最大下标4刚好是5减1。循环条件写i < 5，跑的就是这五轮，一轮不多一轮不少。

## P7 数组名不是指针变量（约4分钟）

有一个容易混的地方，必须单独说清：数组名a是地址，但a不是指针变量。看这段代码。int a[5]，int \*p = a，这两行都没问题，p从a那里接过了首格地址。接下来p++合法，因为p是变量，它格子里存的编号可以换；但你写a++，编译器不认。原因是a代表那片内存的起点，这个地址是固定的，它自己没有一个能重新赋值的格子。

这个区别还有一个实用的地方，就是sizeof。sizeof(a)算的是整个数组的大小：5个int，20个字节。sizeof(p)算的只是一个指针的大小，上节课说过，64位机器上8个字节。同一个sizeof，传数组名和传指针，结果完全不一样，就因为a是整片数组，p只是一个存地址的格子。还有个常用技巧。想知道数组有多少个元素，不用手数，写sizeof(a)除以sizeof(a[0])：总大小除以一格的大小，就是格数。这个写法在正经代码里很常见，你看到别陌生。它只在数组没被传进函数的时候有效——数组一旦作为参数传进函数，情况会变，那是讲函数那一节的内容，今天不展开。

数组名虽然不是指针变量，但它能参与指针运算。a+1就是第二格的地址，\*(a+1)就是第二个元素，打印出来是20；a+4是最后一格的地址。等下要写的for(p = a; p <= a + 4; p++)，起点那个a就是这么用的：数组名给出起点，指针变量负责往前走。区别在于，a这个起点你只能拿它算，不能改它。

再看一组易混的写法，正好把今天和上节课串起来。int a[5]，int \*p = a。&a[0]、a、p，三个东西打印出来地址都一样，都指向首格。但身份不同：&a[0]是取第一格的地址，a是数组名自己就是地址，p是装了地址的变量。地址相同，身份不同，这个区分在画图和读代码时都会用到。

最后把a和p的关系收成一句话，这也是本节的易错点：a是地址，p是存地址的变量。所以int \*p = a合法，把地址装进变量；p = a也合法，换个地址装；但a = p不合法，你没法给一个固定位置重新赋值。

## P8 两种遍历：下标法与指针法（约4分钟）

对比两种写法之前，先用图把指针走数组的过程过一遍。横着画五个连在一起的格子，标上a[0]到a[4]，值填10到50，中间不留空——数组在内存里就是这个样子。指针p指向第一格，循环写for(p = a; p <= a + 4; p++)，每轮打印\*p。一轮一轮标位置：p在a[0]打印10，p++到a[1]打印20，走到a[4]打印50，再p++到了a+5，条件不成立，结束。正好五轮五个数。旁边写下标版for(i = 0; i < 5; i++)打印a[i]：左边p干的就是右边i干的事，一个挪格子，一个换下标。这张图课后自己画一遍，重点画p每一轮停在哪一格；两个常见错法顺便自查，格子之间不能留空隙，箭头不能悬在两格中间。

下面把两种循环比一比。逻辑完全等价，打印结果一样，区别有两个。第一，下标法对人友好，一眼看出在访问第几个；指针法贴近机器干活的方式，地址拿在手里走。第二，边界写法不同：下标版是i < 5，指针版是p <= a + 4，5是长度，a+4是最后一格，指的是同一个边界。这里最容易手抖：写成p <= a + 5就多走一格，踩到数组外面去了。越界下一页专门讲，这里只提醒一句，写完条件先问自己：最后一轮指针停在哪一格。

阅读题常考这类循环边界：条件挖个空问你填什么，或者问循环跑了几轮。不用猜，格子画出来，起点终点一标，数就出来了。平时写代码用下标法，可读性好；读别人的代码两种都要认得；考试两种都算对，挑顺手的。

最后看指针遍历还能干什么。比如求最大最小值，基础阶段用下标写过，指针版是：int \*p = a + 1，max = \*a，while(p <= a + 4)里如果\*p大于max就更新max，再p++。逻辑一样，只是把i换成p，把a[i]换成\*p。遍历不只是打印，边走边做别的——求最值、求和、找目标——都是这个骨架，后面很多算法都需要用到这块内容。

## P9 越界：踩进了别人的格子（约4分钟）

第二个为什么，也是今天最要紧的一个点。看这段代码。int a[5]，五个格子，下标0到4。我在它旁边再声明一个int b = 100，b也住在内存里的某片格子。然后我写一句：a[5] = 999。你猜猜一下，跑起来会发生什么？是报错还是崩溃？多半什么都不发生。程序安安静静地跑完了。

实际上，a[5]这个格子根本不存在。a只有五格，下标最大到4。那句话的真实含义，用今天学的东西翻译：从a的起点出发，往后挪5格，找到那一格，把999塞进去。那一格是谁的？不归你管。可能住着b，可能住着别的变量，也可能住着你完全不知道的东西。这就是越界：那片内存不归你，可C语言不做检查，你照样能写进去。

有同学会问，编译器为什么不顺手检查一下下标？因为检查有代价：每访问一次数组就多一步判断，程序就慢一点。C语言把这个责任交给程序员，性能优先，安全自己负责。理解了这一点，你就知道为什么越界在C里这么常见，也知道画图检查这一步不能省。

更麻烦的是，这种错多半没有报错。编译器不拦你，程序照样往下跑，只是某个变量的值被悄悄改掉了。你打印b，可能发现它变成999了，也可能没变——取决于编译器怎么安排内存。错的地方和出问题的地方不在一起，这种bug查起来最折磨人。所以只有一条要记住：写任何数组访问，先问一句，最大下标是多少。长度是n，最大下标就是n-1。每次写循环边界的时候默念一遍。越界踩出去，改掉的可能是别的变量，可能是程序的关键数据，也可能直接让程序崩溃。最麻烦的是当时没事，换个环境、换组数据才出问题，查都没法查。所以别抱侥幸：编译器不报错，不代表你没错。

## P10 越界规矩：最大下标是n-1（约3分钟）

把越界的三条规矩整理一下，照着做就行。

第一条，长度是n，下标范围就是0到n-1，不能超出其长度。这条是定义，今天你已经知道为什么了：下标是偏移量，最后一格离起点n-1格。

第二条，写循环之前，先思考一个边界问题：这个数组的最大下标是多少。想清楚了再写条件。很多越界不是不会，是写条件的时候压根没想过边界。i < n还是i <= n，p <= a+n-1还是p < a+n，差一个数就是事故。写每一个边界的时候都问自己一句：最后一轮安全吗。

第三条，指针遍历同样守这条边界：终点是a+n-1，条件写p <= a+n-1。和上节课的规矩合在一起，你现在有两条安全底线：指针不初始化不许用\*；数组访问先确认最大下标。这两条能挡住初学者绝大多数的内存事故。

再补一个自检动作。写完一段遍历代码，把起点和终点代入走一遍：第一轮访问的是哪一格，最后一轮是哪一格，有没有多走或者少走。十秒钟的事，能省你半小时的排查。

现场示范一次。假设数组长度n=5，你写的条件是i <= n。代入走一遍：i从0开始，最后一轮i等于5，访问a[5]——越界了，多走一格。改成i < n再走一遍：最后一轮i等于4，访问a[4]，正好是最后一格，停。自检就这么简单，关键是养成习惯：写完边界，代入走一遍再往下做。

指针版同样代入一遍。n=5，条件写p <= a + n，起点p = a，最后一轮p走到a+5，访问的是第六格，越界。改成p <= a + n - 1，最后一轮p停在a[4]，正好是最后一格。

## P11 scanf吃回车的救法（约3分钟）

最后一个坑，也是基础阶段留下的，今天填完。场景是这样的：你先scanf("%d", &n)读一个数字，敲完数字要敲回车。这个回车不会消失，它留在输入缓冲区里。紧接着你再scanf("%c", &ch)，%c不做任何跳过，直接收走缓冲区里的下一个字符——于是回车被它收走了。看起来就像你第二句输入被跳过，其实ch里存的就是那个回车。这里要对比一句：%d读数字的时候会先跳过前面的空白字符，所以回车对它没影响；%c不跳，碰到什么收什么，这个差别就是坑的根源。

你可以自己验证一次：把ch的值用%d打印出来，是10，这是回车的ASCII码。

补救方法有两种，记住一种就够。第一种，在%c之前加一句ch = getchar()，专门把残留的回车收走，后面的scanf读到的就是你真正敲的字符。第二种，把格式写成" %c"，%c前面加一个空格，这个空格的意思是：先跳过所有空白字符再读。两种都灵，挑顺手的。

把第二种再拆开说一层。格式串里的空格和普通空格不一样，它不对应具体字符，是一个指令：把缓冲区里的空白字符——空格、Tab、回车——一直跳过，直到碰上第一个非空白字符才停。所以你写" %c"，哪怕缓冲区里堆了三个空白，也都能挡掉。理解了这一层，以后看到格式串里莫名其妙的空格，你就知道它在干什么了。记一条：只要前面读过数字，后面要读字符，先处理缓冲区。

顺便回答一个你可能会搜到的写法：fflush(stdin)。有些老代码拿它清缓冲区，在个别编译器上确实管用，但标准里fflush只保证对输出流有效，对输入流是未定义的，换个编译器就不灵。所以别用它，前面两种救法都是标准写法，走到哪都认。

## P12 本节小结（约2分钟）

今天的内容收一下，三件事。

第一，指针加减按指向的类型缩放：int \*走一步4格，char \*走一步1格；p+n就是往前n格。顺带把i++和++i说清了：先用再加，先加再用。

第二，数组名是首元素地址，a[i]就是\*(a+i)。下标是偏移量，0表示起点自己——下标从0的原因，就在这。数组名是地址但不是变量，a不能挪，p能挪。

第三，越界是踩进别人的内存，而且多半不报错。最大下标n-1，写循环先问边界。

基础阶段留下的三个问题——下标为什么从0、越界为什么危险、scanf吃回车——到这里都解完了，用的都是同一套工具：地址和指针。工具齐了，下一节我们学一个新东西：结构体，把不同类型的数据装进一个格子里。数据结构的结点，就是拿它定义的。

最后把这张内存图完整地串一遍，你跟着默一遍：内存是带编号的格子；变量住格子，地址是编号；&取编号，\*按编号找格子；指针是存编号的格子，加1按类型挪格子；数组是一片连续的格子，数组名是首格的固定编号。后面学的所有东西，都是往这张图上加内容。

## 附录一：课后题参考答案

跟练题：

```c
#include <stdio.h>
int main(){
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a;
    while(p <= a + 4){
        printf("%d ", *p);
        p++;
    }
    return 0;
}
```

输出10 20 30 40 50。p从a出发，每轮先打印\*p再p++，走到a+4为止，正好五轮，p依次停在a[0]到a[4]。

常见错法两个：条件写成p <= a + 5，多走一格，最后一轮打印的是数组外面那格内存里的值；先p++再打印，第一个数10被跳过，末尾还多打一个越界的值。

模仿题：

```c
#include <stdio.h>
int main(){
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a + 4;
    while(p >= a){
        printf("%d ", *p);
        p--;
    }
    return 0;
}
```

输出50 40 30 20 10。起点换成a+4，每轮p--，条件是p >= a，走到首格为止。

要点：条件写成p > a会漏掉第一个数10，少走一格。PPT答案页省略了头文件与main骨架，这里是完整版。
