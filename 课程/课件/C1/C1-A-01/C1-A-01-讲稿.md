## 正课：初识C程序（第7—17页，约30分钟）

## P7 引题页（约1.5分钟）

先看两行代码：

printf("你好，重邮802！\n");
printf("我是牙膏学长\n");

你不是科班生，也能猜到它是往屏幕上打两行字。但我要问的是：这两行字到底是怎么跑到屏幕上的？为什么非得写成这个样子，括号、双引号、分号，各自在干嘛，少一个行不行？

我当初自学的时候，就是看得懂、写不出——照着抄能跑，让我自己从空白写一个就卡壳。这一讲我带你把这两行拆到最细，讲完你不光看得懂，合上书自己也能敲出来。

## P8 程序是什么（约2.5分钟）

我们先给出一个最粗糙的框架：一个程序，说到底就三件事——输入、处理、输出。数据进来，按你写的指令一步步进行计算和处理，最后把结果吐出来给人看。这一讲我们先只介绍输出，就是printf把结果打到屏幕上这件事。

那问题来了，我想让电脑打两行字，为什么不能直接跟它说，非得写C？因为电脑本质上只认0和1，你跟它说人话它听不懂。C语言就是中间那个翻译：你把想法写成C代码，有一个叫编译器的东西，把你这段代码翻译成电脑能看懂、能执行的0和1序列，它才能照着去做。

还有一句我必须提前跟你们交代清楚，免得你后面纠结：802考场上写的是伪代码，不用写#include，也并不必须写main函数，有时一段函数就够了。但现在是打地基阶段，我要你先把一个完整的、能跑起来的程序从头到尾看懂，骨架长什么样心里有数，之后再谈简化。地基没打，直接学伪代码，你写出来的东西自己都不知道对不对。

## P9 程序怎么跑起来（约3分钟）

上一页我说"编译器把代码翻译成0和1"，这里把它展开，这是零基础最容易糊里糊涂的一环——很多同学以为代码一写完电脑就自动跑了，其实中间隔着两步。

你的代码一开始只是一个文本文件，我们叫它源代码，比如起名hello.c。这时候它跟一份记事本没有本质区别，电脑并不认识它。接下来要做一件事，叫编译——编译器读你这份源代码，逐行检查、翻译成电脑能直接执行的指令，产出一个新的文件，叫可执行文件，在Windows上就是hello.exe。到这一步，才是真正能被电脑跑起来的东西。最后你双击运行这个exe，电脑执行里面的指令，屏幕上就打出两行字。

所以完整的一条链是：写代码，得到.c源文件；编译，得到.exe可执行文件；运行，看到输出。

这里有两个结论你要记牢。第一，改了源代码必须重新编译。exe不会自己跟着你的.c变，你改了代码却发现运行结果没变，十有八九是忘了重新编译，这是新手最常懵的地方。第二，编译器很严格，你的代码少一个分号、拼错一个关键字，它就拒绝编译，一行都不让你跑——这跟考试改卷不一样，考试老师能看懂你的意思，编译器不行，差一个符号都不行。

## P10 C程序的骨架：五部分（约4分钟）

来看第一个完整程序，这是一个非常简单的程序，它由五个部分组成，我们一个一个认。

第一个部分，头文件，#include <stdio.h>。你可以把它理解成"借工具"——printf这个打印工具不是你写的，是别人早写好放在stdio.h这个仓库里的。你要用它，就得在开头先把这个仓库搬进来。不搬，编译器不认识printf，直接报错。stdio就是standard input output，标准输入输出，管的就是屏幕打印和键盘读入这些事。

第二个部分，宏定义，#define MaxSize 1000。意思是给1000起个名字叫MaxSize，后面凡是写MaxSize的地方，编译器都当成1000。

第三个部分，主函数，int main()。这是整个程序的大门，不管你代码写了几百行，电脑一律从main这里开始执行。你以后拿到一段陌生代码，第一件事就是找main。

第四个部分，函数体，就是main后面那对花括号{}里包住的内容。里面的指令，从上往下一条一条执行，没有例外。

第五个部分，return 0。程序跑完了，跟操作系统报个信，0表示我正常结束了，非0通常表示出了错。

这五块的名字先记住：头文件、宏定义、主函数、函数体、return。后面几讲会把它们一个一个拆开细讲，这节课你先建立"程序是分块的"这个感觉。

## P11 四个关键点（约4分钟）

骨架认完了，现在专门把初学者最容易栽跟头的四个点拎出来，一个个说清楚，这也是这一讲的重头。

第一，main是入口。程序永远从它开始执行。这条要变成你的本能——以后拿到任何一段陌生代码，第一眼先找main，找不到main你就不知道从哪读起。

第二，printf是原样输出。双引号里写什么，屏幕就打印什么，一个字不改。注意"原样"两个字，你写个空格它就打空格，你打了个错别字它照打不误，电脑不会帮你纠错。

第三，\n是一个整体，代表换行。它是反斜杠加字母n两个字符组成的一个转义符，别拆成两半，也别写成斜杠。它自己不会被打印出来，作用只有一个：让光标跳到下一行。你printf两次都不带\n，两行内容就会挤在同一行连成一串。

第四，分号收尾。C语言里每条语句写完，末尾必须有分号，它就是这句话的句号。少一个，编译器就报错，而且麻烦的是，报错的位置常常不在你漏写的那一行，新手能找半天。所以从现在起养成习惯：写完一句，先补分号。

## P12 #define与注释（约3分钟）

再补两个小工具，都不难，但后面天天用。

第一个是#define。#define MaxSize 1000，给1000起名叫MaxSize；#define PI 3.14，以后写PI就是3.14。它好在哪？假设你程序里几十个地方用到1000，哪天要改成2000，你一个个找过去改，改漏一个就是bug；用了#define，只改开头这一行，全程序跟着变。此外在伪代码里它还代表一个思路——你考虑到了数据规模的安全上限。这里我顺便提一嘴，802真题里顺序表的定义几乎必出#define MaxSize 100这种写法，数组开多大就是从这来的，到数据结构那块你会天天见它。

第二个是注释。两条斜杠 // 后面到行尾，是单行注释；/* 和 */ 中间夹的，是多行注释。注释是写给人看的，编译器直接跳过，不影响程序运行。那既然电脑不看，为什么还要写？两个原因。一是给未来的你自己看，代码放两个月你自己都忘了当时怎么想的，注释就是给未来的你留的线索。二是给阅卷老师看——802的考题很重视算法思想，也关注你的代码习惯，注释能让阅卷老师很清晰地看到你这段代码的思路，往往有比较好的效果。

## P13 亲眼看报错（约3分钟）

光说不练假把式，这一页我直接把初学者最常犯的四种错误摆出来，让你亲眼看看编译器会怎么"骂"你。

第一种，忘写分号。printf("你好") 后面没有分号，编译器直接报"expected ';'"，就是"这里该有个分号"。

第二种，大小写写混。把int main写成Int main，首字母大写了，编译器不认识Int，报错说找不到这个东西。C语言是区分大小写的，main、Main、MAIN在它眼里是三个不同的词。

第三种，中文引号。你输入法没切过来，把英文双引号敲成了中文双引号，长得几乎一样，编译器就是不认，报错说语法有问题。这个错最隐蔽，眼睛根本看不出来。

第四种，花括号不配对。你写了左花括号{，忘了写右花括号}，编译器报"expected '}'"。

这四种错，犯一个编译器报一个，报错信息是英文的，但翻来覆去就这四类。你现在不用背英文报错长什么样，只要记住：以后一看到编译报错，先扫一遍分号、引号、花括号这三样，绝大多数时候问题就在这。

## P14 板书推演（约4分钟）

光听没用，代码是手艺活，得自己写。现在跟着我，从一张空白开始，一步一步把第一个程序敲出来。我写一行，你在纸上或者编辑器里跟一行，别只用眼睛看。

【板书】
第一步，先搬工具，写头文件：#include <stdio.h>
第二步，写大门，主函数开头：int main(){
第三步，写第一句输出：printf("第一行\n");
第四步，再来一句：printf("第二行\n");
第五步，收工：return 0;
第六步，别忘了把大门关上，补右花括号：}

写完先别急着往下，回头查三样东西，这也是我自己养成的习惯：每句末尾分号补了没、双引号是不是一对一对的、花括号有没有一开一闭。这三样是初学者报错的重灾区。

【停顿】给你半分钟，照这三条自己过一遍。

## P15 板书结论（约1.5分钟）

对一下答案，你写出来的应该是这样：

#include <stdio.h>
int main(){
    printf("第一行\n");
    printf("第二行\n");
    return 0;
}

跑起来，屏幕上就是干干净净两行：

第一行
第二行

再强调一次那个最容易迷惑人的点：\n本身不会打在屏幕上，你看不到它。它干的活只有一个，让后面的内容换到下一行去。你要是把两个printf里的\n都删了，这两行就会连成"第一行第二行"挤在一块，自己动手试一下，印象最深。
