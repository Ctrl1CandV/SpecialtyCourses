## P3 2025 算法题：输出最长根叶路径（约2分钟）

回忆原题只写“路径长度”，本讲公开采用结点数，不暗中混用边数。若考试明确按边数，非空树结果减一即可，空树仍单独处理。先看最终答案要有结点序列和长度两项，只有树高函数还不完整。

## P4 题目要求决定函数必须交出的结果（约2分钟）

先把题面拆成能够检查的输出。只交treeHeight会得到长度，却没有路径，这是一份功能不完整的答案。把树高当作第二遍搜索的目标，可以避免边找边反复复制当前最优路径。这里函数分工由输出要求决定：treeHeight返回目标高度，deepest负责填数组并返回是否找到，包装函数把长度与输出连接起来。答题时应先写这一层关系，再展开递归。

## P5 把最长路径先定位到最深叶（约3分钟）

先让学生找两条最长路径，再说明并列任选带来的自由：搜索左子树先找到G就可以停，不必把所有最长路径都保存下来。树高为4，表示最长路径含4个结点；根的下标深度d从0开始，所以目标叶结点的d为3。第二次搜索负责把这4个结点填入数组。

## P6 高度从孩子返回到父结点（约2分钟）

【停顿】暂时遮住A和B的数，让学生从G开始向上补。递归函数进入时还不知道高度，它依赖两个子调用的返回值。D是叶结点，两个空孩子都返回0，所以D返回1；E从G得到1后返回2。这里必须取较大值，求和得到的是结点数类型的量，不能表示最长根叶路径。返回高度的递归不需要额外的全局层数变量。

## P7 两次遍历分别完成一个任务（约2分钟）

这里d用0起下标，目标层数h用结点数，所以终点检查d+1==h。数组当前前缀就是递归调用链对应的路径。失败支路留下的后部值没有意义，下一条候选路径会覆盖；最终只输出前h项。

## P8 路径数组与当前递归层一一对应（约2分钟）

前一次搜索D失败后，不必把path[2]清空。回到B，再进入E，程序会覆盖相同下标。path只承诺当前递归深度以内的前缀有效，后面的旧值不参与判断。找到G后短路返回，右子树不会再改动结果。与图中防止重复顶点的used不同，这里的数组用于记录输出，失败恢复的具体动作可以是下一分支覆盖，不能把所有递归状态都机械写成清零。

## P9 最长根叶路径的实现（1/3）（约2分钟）

第一遍每个结点收集左右高度后返回较大值加一。高度函数不承担输出职责，便于单独检查空树和单结点树。

## P10 最长根叶路径的实现（2/3）（约2分钟）

短路或让左边成功时不再搜索右边，结果数组保持已找到的路径。注意只有叶结点才能作为终点，不能把一个达到某个局部深度的内部结点误当作完整根叶路径。

## P11 最长根叶路径的实现（3/3）（约2分钟）

最后必须调用输出函数或明确把path交给调用者。打印循环只读len项，空树不读取path。课堂例子的字符标签可以换成对应整数，这不改变指针结构和搜索顺序。

## P12 最长路径的答案思想段怎样组织（约2分钟）

这一段可以直接作为本题思想说明的骨架。它交代先做什么、第二遍保存什么、何时成功以及最终输出什么。不要只写“利用递归求最长路径”，因为那没有解释路径如何保留下来。代码部分接着给三个辅助函数与调用入口，或将它们合理合并；复杂度写两遍各至多访问n个结点，打印h项，因此总时间O(n)，递归栈O(h)。题目已提供path时，它是输出空间；即使连同它计入，总量仍为O(h)。

## P13 复制路径会改变时间分析（约2分钟）

递归调用两遍仍然是线性，不是平方。相反，只遍历一遍却在每次更新时复制长路径，不能未经分析就断言线性。构造一侧不断产生更深叶的树，累计复制可能增长到平方量级；本题采用两遍方案避免这项成本。

## P14 反复复制更长路径可能累计到平方（约2分钟）

这张树用来区分遍历次数和实际工作量。先到X复制A、X，再到Y复制A、B、Y，再到Z复制A、B、C、Z。右侧D与Z一样深，若只在严格更优时复制，D不再触发更新。继续把右侧分支延长并在每层先安排一个叶结点，就会形成越来越长的一串复制。另一种写法可以正确，但其时间说明不能只数递归调用。本课两遍方案把每次进入结点的写入控制为一个数组位置。

## P15 模拟卷六：直接写出后序序列（约2分钟）

这个问题与2026先中序建树共享区间划分，但输出任务不同。我们保留先序定根和中序分左右，只把“申请结点、接孩子”改成“递归结束后写根”。条件标识互异保证根在当前中序段中位置唯一。

## P16 一个完整区间怎样划分（约3分钟）

要用中序左段的元素数量切开先序，不能拿根在先序中的位置去分左右。当前pre首元素A不属于任何子树；右先序起点要跳过根和整个左子树，所以偏移是left+1。

## P17 递归调用前写清三个区间（约2分钟）

每次调用收到的都是本子树自己的两个数组片段，变量left也是相对当前片段的偏移。用左链、右链各检查一次：左链右长度为0，右链left为0。这两种输入很容易暴露多加或少加1的问题。

## P18 后序输出的位置由递归完成次序决定（约2分钟）

把输出位置看作已经写完多少个结点。左调用返回时，D、E、B已经占据前三项；右调用从当前位置继续写F、C，最后根A落在下标5。这样才能解释out为什么要在调用之间共享。若每个子调用都拿自己的out副本，左调用写过的位置不会反馈给右调用，后续结果会覆盖它。这里图只解释序列来源，程序依然直接处理数组片段，没有创建这些树结点。

## P19 直接生成后序的实现（1/2）（约2分钟）

out按引用传递，所有子树共同推进同一个输出位置。根必须在两次递归之后写入；把写根移到前面会得到先序。输入已保证合法，线性寻找根不会越过当前段；如果题面不保证合法，必须额外做长度与元素一致性验证。

## P20 直接生成后序的实现（2/2）（约2分钟）

wrapper把out初始化为0，避免多次调用时复用旧输出位置。n=0时递归立即返回，post原内容保持不变。C语言可把引用换成指针，思想与下标划分不变。

## P21 扫描根位置使最坏时间达到平方（约2分钟）

树的每个结点只作为根处理一次，不代表总时间一定线性。根的位置寻找也在做工作。这里最坏左链会把根放在各中序段末端；右链的根在首端，扫描反而很快。复杂度结论要针对实际代码。

## P22 直接后序题的思想与复杂度怎样落笔（约2分钟）

这段答案应把划分依据、递归次序和写入方式连起来。若只说“先序找根，中序分左右”，仍没有说明后序结果何时写入。复杂度依据当前代码的while扫描，不借用另一个带哈希下标表的版本来声称线性。左链会依次扫描n、n−1直到1个位置，总和是平方量级；输出数组由题目提供，新增辅助空间来自调用栈。若主动提出更快版本，还需要给出查找结构、额外空间及实现条件。

### 最长根叶路径的实现
```cpp
#include <cstdio>
#include <cstddef>
struct TreeNode { int data; TreeNode *left, *right; };
int treeHeight(const TreeNode *t) {
    if (t == NULL) return 0;
    int a=treeHeight(t->left), b=treeHeight(t->right);
    return (a>b ? a:b)+1;
}
bool deepest(const TreeNode *t, int d, int h, int path[]) {
    if (t == NULL) return false;
    path[d] = t->data;
    if (t->left==NULL && t->right==NULL) return d+1==h;
    return deepest(t->left,d+1,h,path) ||
           deepest(t->right,d+1,h,path);
}
int longestPath(const TreeNode *root, int path[]) {
    int h=treeHeight(root);
    if (h!=0) deepest(root,0,h,path);
    return h;
}
void printLongest(const TreeNode *root, int path[]) {
    int len=longestPath(root,path);
    for (int i=0;i<len;++i) printf("%d ",path[i]);
    printf("length=%d\n",len);
}
```

### 直接生成后序的实现
```cpp
void fillPost(const int pre[], const int in[], int n,
              int post[], int &out) {
    if (n==0) return;
    int left=0;
    while (in[left]!=pre[0]) ++left;
    fillPost(pre+1,in,left,post,out);
    fillPost(pre+left+1,in+left+1,n-left-1,post,out);
    post[out++]=pre[0];
}
void toPost(const int pre[], const int in[], int n, int post[]) {
    int out=0;
    fillPost(pre,in,n,post,out);
}
```
