## P3 2026 算法题：验证给定拓扑序（约2分钟）

如果题面已经保证序列是顶点排列，合法性循环可简写；回忆原文未完整列出这项条件，本讲保留验证。只检查边不够：无边图上的重复序列也可能通过所有边检查。

## P4 无边图也需要检查顶点排列（约1分钟）

先让学生判断这张无边图的候选序列。弧检查循环一次都不执行，不能据此推出序列合法。pos初始为−1，首次看到顶点0后写入位置，再次看到0便可发现重复。长度已经等于V时，只要每项合法且互异，就自动包含全部顶点，不必再多写一次遗漏检查。这是合法性代码能够简短又完整的原因。

## P5 位置数组把先后关系变成比较（约3分钟）

序列下标和顶点编号都是整数，最常见错误是直接比较u<v。拓扑序关心它们出现在候选序列的哪个位置。填pos时用pos[order[i]]=i，把“第i个是谁”转换成“某顶点在第几位”。

## P6 比较弧两端在序列中的位置（约2分钟）

图中的顶点编号沿用题目，不能因为顺序变化就重新编号。序列第0位放顶点1，所以pos[1]=0；序列第1位放顶点0，所以pos[0]=1。接着拿弧1到2核对：需要比较0与3，不能比较顶点编号1与2。把这个逆向索引先写成表或标在图旁，再写赋值语句，可以减少把pos[i]误写成order[i]的错误。

## P7 验证拓扑序的实现（1/2）（约2分钟）

本题V≥1。pos初值−1表示尚未出现。先查x范围，再读pos[x]，依赖短路求值防止越界。长度V、编号合法且互异，三者合起来已经保证每个顶点都出现，不必再找遗漏顶点。

## P8 验证拓扑序的实现（2/2）（约2分钟）

一条弧逆序就足以否定候选排列。自环的两个位置相等，也会失败。有环图不可能让环上每条弧都严格向后，所以本判定不需要另写一次环检测。

## P9 验证题的完整答案应交代充分性（约2分钟）

思想段写清排列条件和边条件就足够，无须泛泛介绍拓扑排序定义。这里原图不一定无环，但如果输入有环，代码会返回假。与下一题不同，下一题把原图DAG和原序合法作为已知条件。

## P10 验证拓扑序的思想段与代码对应（约2分钟）

这里思想说明的顺序与代码一致，方便检查每个条件是否真正落实。最后一句返回真必须建立在排列与边条件全部通过之后，不能只说“没有发现环”。本题没有要求生成新序列，因此不用另外实现Kahn排序。若输入图含环，严格递增的位置条件不可能沿着环回到起点，边检查自然会否定它；答案中用这一句话解释充分性即可，不需要重复完整的拓扑排序证明。

## P11 模拟卷六：新增一条弧后三种状态（约2分钟）

先把三个结果写成互斥分支。原序失效不等于图成环，因此只有检查u、v相对位置还不够。题目只问分类，没要求重排；实现时不要多做一整套排序和输出工作。

## P12 原序失效仍可能找到另一个合法顺序（约2分钟）

这个反例专门拆开两个判断。旧序失效只说明新弧与这一个排列冲突，图可能还有其他合法排列。先看到1到0逆序，就直接返回CYCLE，会把需要重排的正常情况错判为成环。题目只要求三类状态，不要求把新顺序算出来；课堂写出1、0、2、3是为了证明本例无环，不必因此在最终代码额外增加重排函数。

## P13 新增弧成环的充要条件（约3分钟）

新出现的环一定包含新弧，因为原图没有环。把新弧拿掉后，环上剩余部分正好是一条从v回到u的原图路径。这个推导同时给出了必须搜索的方向；从u查v会把方向弄反。

## P14 新环去掉新增弧后留下反向路径（约2分钟）

证明分两边。若原图有v到u的路径，加上u到v就得到环。反过来，若新增后出现环，这个环必定包含新增弧，否则原图早就有环；拿掉新增弧，就得到v到u的原图路径。因此搜索方向由证明确定，不是凭记忆挑u或v。图中应从0搜索3，若误从3搜索0，原图找不到路径，反而会漏掉这个环。

## P15 同一原图演示三种结果（约3分钟）

对1到0这条新弧，重排后的合法顺序可取1、0、2、3，但题目不要求给出。让学生明确“需要重排”是第三类图结构状态里的正常情况，不应该作为失败或成环处理。

## P16 顺序一致的新增弧无需再搜索（约1分钟）

先假设位置较后的v还能走到较前的u。沿着这条原图路径，每一步的位置都应变大，最后却到了更小的位置，产生矛盾。因此顺序一致分支可以直接结束。这个推导解释了代码为什么把位置比较放在分配seen和DFS之前，省去不需要的搜索。自环应先单独判断，因为两个端点位置相等不会落入顺序一致分支。

## P17 只检查反向可达性（1/3）（约2分钟）

这次仅问能否到达target，没有必须经过其他点或指定长度的限制，所以seen不用回溯撤销。每个已访问顶点的后继可达性已经搜索过，其他前缀无须再展开。

## P18 只检查反向可达性（2/3）（约2分钟）

只查询u和v两个位置，可以扫描sigma用两个整数保存，而不必建整张pos数组。sigma合法与端点编号合法都由题目保证，这使pu和pv一定被赋值。

## P19 只检查反向可达性（3/3）（约2分钟）

搜索在原图上进行，方向从v到u；未真的插入新弧，也没有删除任何边。枚举三类返回前释放seen。与上一节路径回溯相比，这里每个顶点最多展开一次，复杂度重新回到线性。

## P20 加弧分类题的思想段按判定顺序写（约2分钟）

这段说明把三个输出、判断依据和查询对象都写清楚了。代码不要先插入新弧再随意搜索，否则读者需要额外确认你搜索的到底是哪张图。当前实现保持G不变，用reachable返回布尔结果即可。复杂度应写最坏位置扫描加一次DFS为O(V+E)，seen与递归栈为O(V)；若补充分支分析，自环是常数时间，顺序一致分支只需要扫描序列。

## P21 按分支写出时间与空间（约2分钟）

不能把整题时间只写成DFS，因为存在不搜索的分支；也不能只看位置扫描而漏掉搜索。最坏量级取完整可能执行路径。递归实现比迭代栈简短，但空间仍包含调用栈。

## P22 普通可达搜索的汇合点只需展开一次（约2分钟）

两条前缀虽然不同，但从x开始要查的都是能否到u，允许使用的后继也相同。第一次已经把x和y搜索完，第二次没有新的子问题，因此seen保持为1。上一课的简单路径枚举会受到当前路径已用顶点的限制，不能照搬这一结论。这里每个顶点只展开一次，每条邻接表弧只检查一次，所以时间可以写O(V+E)。用本例能说明复杂度来自什么工作被避免。

## P23 课堂检查：三类容易混淆的错误（约3分钟）

【停顿】第一问刻意使用非法序列：顶点2出现在0之前，违反0到2。但图中所有弧的编号都从小到大，错误地比较u<v会全部通过。第二问对应无环重排的反例。第三问要求根据新弧方向重新说出要查询的是原图0能否到3。每问必须指出实际违反的条件，不能只回答“应该比较位置”而不给输入上的证据。

## 附录二 完整代码

### 验证拓扑序的实现
```cpp
#include <cstddef>
#include <cstdlib>
struct Arc { int to; Arc *next; };
struct Graph { int V; Arc **head; };
bool isTopo(const Graph *G,const int order[]) {
    int *pos=(int*)malloc(G->V*sizeof(int));
    if (pos==NULL) abort();
    for (int i=0;i<G->V;++i) pos[i]=-1;
    for (int i=0;i<G->V;++i) {
        int x=order[i];
        if (x<0 || x>=G->V || pos[x]!=-1) { free(pos); return false; }
        pos[x]=i;
    }
    for (int u=0;u<G->V;++u)
        for (const Arc *e=G->head[u];e!=NULL;e=e->next)
            if (pos[u]>=pos[e->to]) { free(pos); return false; }
    free(pos); return true;
}
```

### 只检查反向可达性
```cpp
#include <cstddef>
#include <cstdlib>
// Arc、Graph 的定义与拓扑序验证题相同。
enum State { ORDER_OK, REORDER, CYCLE };
bool reachable(const Graph *G,int x,int target,unsigned char seen[]) {
    if (x==target) return true;
    seen[x]=1;
    for (const Arc *e=G->head[x];e!=NULL;e=e->next)
        if (!seen[e->to] && reachable(G,e->to,target,seen)) return true;
    return false;
}
State classifyArc(const Graph *G,const int sigma[],int u,int v) {
    if (u==v) return CYCLE;
    int pu=-1,pv=-1;
    for (int i=0;i<G->V;++i) {
        if (sigma[i]==u) pu=i;
        if (sigma[i]==v) pv=i;
    }
    if (pu<pv) return ORDER_OK;
    unsigned char *seen=(unsigned char*)calloc(G->V,1);
    if (seen==NULL) abort();
    bool back=reachable(G,v,u,seen);
    free(seen);
    return back ? CYCLE : REORDER;
}
```
