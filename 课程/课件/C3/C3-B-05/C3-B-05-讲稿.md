## P2 先判断题目究竟要求哪一种路径（约2分钟）

visited这一名字可以表示两种不同事情。普通遍历里表示这个顶点已完成或已发现；回溯里表示当前候选路径已经用到这个顶点。决定是否撤销标记的是语义，不是DFS这三个字母。

## P3 2024 题意整理：恰有 k 条边（约2分钟）

原题只要求判断，本讲增加路径输出用于观察搜索过程，交原题时只返回真假即可。边数k对应顶点数k+1。s=t且k>0不能靠绕一圈满足简单路径要求，因为起点将重复。

## P4 一条失败路径不能封死另一个分支（约3分钟）

如果第一次到x后永久标记，第二个分支就不能再进入x，正确答案被剪掉。两次到达x时已经走过的边数不同，而且路径中使用的其他结点也不同，不能把这两个状态合并成一次普通遍历。

## P5 恢复标记后才能尝试另一条路径（约2分钟）

沿第一条支路返回时，t、x、a依次撤销各自标记，s仍在当前路径。进入b、c以后才能再次进入x。若把第一次访问x永久记住，就会跳过这条正确答案。把两次状态并排写在纸上：第一次是当前顶点x、边数2、已用s与a；第二次是x、边数3、已用s、b、c。仅用顶点x不能概括这些限制，回溯必须保留候选路径上下文。

## P6 函数参数对应当前搜索状态（约2分钟）

初次调用d=0，因为只站在起点还没有经过边。对新邻点递归时d+1。used[u]必须在本层尝试不同邻点期间保持为1，防止子路径绕回u。某个子调用失败，只由那个子调用撤销它自己的标记；等本层所有邻点都失败，才撤销u并返回。成功时立即沿调用链返回，当前查询结束，不再清空或覆盖已找到的path。

## P7 回溯时恢复的是刚刚结束的调用（约2分钟）

【停顿】让学生指出表中哪一行允许撤销s：这些行里都不允许，因为最外层s尚未结束，它还要尝试b。把used[u]=0错误地放到每个邻点调用之后，会让父结点在尝试下一邻点时失去保护，后续搜索可能重新进入父结点。代码中的撤销位于for循环之后，表示本层所有选择已经用尽。这是从调用生命周期推出的位置，不靠背“DFS后面清零”的口诀。

## P8 定长简单路径的实现（1/2）（约2分钟）

先检查深度终止，再标记和扩展。终点那一层不再扩展，所以无需在该层设置used。成功返回会保留上一层的标记，但整个查询已经结束，wrapper随即释放它；若改成枚举全部答案，成功后也要继续并恢复。

## P9 定长简单路径的实现（2/2）（约2分钟）

这里内存不足直接终止程序，不把资源错误伪装成没有路径。考试伪代码可声明容量足够的辅助数组，但分析空间时要按V项计算。两个合法顶点参数由题目保证。

## P10 定长路径题的答案思想与边界（约2分钟）

这一题的思想段必须出现精确边数和路径内标记，普通“使用DFS查找s到t”没有表达约束。主函数应初始化used，检查k的范围并调用深度0的搜索。课堂增加path是为了展示结果，原题若仅要求判断，返回真假即可。成功检查放在d==k处，使边数不会超过题目要求；在小于k时偶然到达t也不能立即判成功。边数k对应k+1个顶点，这个换算适合在答案最后用小例子自查。

## P11 2025 题意整理：一条路径经过 w（约2分钟）

原回忆稿的“路径”用语没有进一步解释。这里公开采用简单路径，若考试明确允许重复顶点的游走，问题会不同。无向连通图也不保证任意三个指定顶点能按指定顺序落在一条简单路径上。

## P12 两段路径各自简单，拼接仍会重复（约3分钟）

把这张四结点图在纸上画出来。w是挂在x上的叶结点，若要经过它后再去t只能退回x，违反顶点不重复。因此两次独立DFS之间清空visited再拼接，只能在允许重复顶点的语义下作为游走使用。旧课堂相关简化讲法在这里修正。

## P13 在同一次回溯中维护经过状态（约2分钟）

hasW不需要全局反复清零，因为每次递归都有自己的副本。used数组是共享的，所以它的进入和退出动作必须对应。两种状态的生命周期不同，不能因为都表示信息就都用全局变量。

## P14 先到终点但尚未经过指定点（约2分钟）

这张图用于核对终点分支。到t时程序检查hasW，发现尚未经过w，所以返回失败。它不能把“已到终点”当成最终成功，也不能从t继续去绕w再回t。返回a后，a的调用还没有结束，因此a的标记应保持。需要恢复的是t这次调用设置的标记。把控制流和路径上的实际顶点对应，才能确定if分支中的清零语句属于谁。

## P15 返回父调用后继续尝试指定点（约2分钟）

a自己的hasW仍是false；进入w的子调用取得一个副本，再把它改为true。这个true继续沿w、b、t这一支传递。hasW按值传递，失败返回时父层的值没有被改写，所以无需手动改回false。used则是各调用共用的一份数组，需要显式恢复。成功后len保存顶点数5，对应边数4，不应把深度d直接当成输出数组长度。

## P16 经过指定点的实现（1/3）（约2分钟）

到达t却尚未经过w时不能继续越过t寻找w再回来，否则终点将重复。成功时len记录顶点数，不是边数。path的容量为V，简单路径不会越过此上界。

## P17 经过指定点的实现（2/3）（约2分钟）

递归分支失败后恢复used[u]，让其他前缀可以进入u。成功时沿调用链直接返回，保存当前path。把used标记在调用前的邻点上也可，但进入与恢复必须成对。

## P18 经过指定点的实现（3/3）（约2分钟）

输出包装见完整代码附录：成功依次打印path前len个顶点，失败打印−1。len在每次查询初始化，避免失败查询遗留上次成功路径长度。

## P19 经过指定点题的答案如何写完整（约2分钟）

思想段先写同一次搜索，再写经过条件和终止规则，能够直接排除两次独立DFS拼接的错误方法。代码末尾的包装调用和输出不能遗漏。只返回true不能满足原题输出路径的要求；只更新全局数组而不交代有效长度，也难以检查答案。空间说明可以写used数组、path与最深递归均为O(V)，总辅助量级O(V)，时间则按实际展开的候选状态和邻边检查计入。

## P20 回溯搜索不能套用普通遍历复杂度（约3分钟）

给出S的定义后，复杂度描述才可复核。对V个顶点的简单图，所有简单路径前缀的排列数量有限，但远大于顶点数；本课程无需背一个固定指数公式，必须明确不是线性DFS。限制k较小时，只搜索到k层，实际状态数会少很多。

## P21 永久标记与回溯标记依据的状态不同（约2分钟）

普通可达性把顶点视为搜索单位，因此一个顶点完成搜索后可以永久标记。约束路径中，先前用过哪些顶点会决定接下来哪些边还能走，已经走了几条边也会改变终止条件。这样同一个x对应多种待解决的问题。答案可设状态数为S，写时间不超过O(SV)，并说明简单路径前缀在最坏情况下增长很快；更精确时可按实际状态的邻接表长度求和。不要把这项枚举工作压成只访问V个顶点的O(V+E)。

## P22 课堂检查：回放一个成功分支（约3分钟）

【停顿】先试到t时hasW为假，t的used撤销；返回a后继续试w，不必取消a，因为a仍属于当前路径。成功路径s、a、w、b、t。hasW按值传递，失败调用的改变不会写回父调用。

## 附录二 完整代码

### 定长简单路径的实现
```cpp
#include <cstddef>
#include <cstdlib>
struct Arc { int to; Arc *next; };
struct Graph { int V; Arc **head; };
bool exactDFS(const Graph *G,int u,int t,int k,int d,
              unsigned char used[],int path[]) {
    path[d]=u;
    if (d==k) return u==t;
    used[u]=1;
    for (const Arc *e=G->head[u];e!=NULL;e=e->next)
        if (!used[e->to] &&
            exactDFS(G,e->to,t,k,d+1,used,path)) return true;
    used[u]=0;
    return false;
}
bool exactPath(const Graph *G,int s,int t,int k,int path[]) {
    if (k<0 || k>=G->V) return false;
    unsigned char *used=(unsigned char*)calloc(G->V,1);
    if (used==NULL) abort();
    bool ok=exactDFS(G,s,t,k,0,used,path);
    free(used);
    return ok;
}
```

### 经过指定点的实现
```cpp
#include <cstddef>
#include <cstdlib>
// Arc、Graph 的定义与定长路径题相同。
bool throughDFS(const Graph *G,int u,int t,int w,int d,
                bool hasW,unsigned char used[],int path[],int &len) {
    used[u]=1; path[d]=u; hasW=hasW || u==w;
    if (u==t) {
        if (hasW) { len=d+1; return true; }
        used[u]=0; return false;
    }
    for (const Arc *e=G->head[u];e!=NULL;e=e->next)
        if (!used[e->to] &&
            throughDFS(G,e->to,t,w,d+1,hasW,used,path,len)) return true;
    used[u]=0; return false;
}
bool pathThrough(const Graph *G,int s,int t,int w,int path[],int &len) {
    len=0;
    unsigned char *used=(unsigned char*)calloc(G->V,1);
    if (used==NULL) abort();
    bool ok=throughDFS(G,s,t,w,0,false,used,path,len);
    free(used); return ok;
}
```

### 路径输出包装
```cpp
#include <cstdio>
void printPathThrough(const Graph *G,int s,int t,int w,int path[]) {
    int len=0;
    if (!pathThrough(G,s,t,w,path,len)) { printf("-1\n"); return; }
    for (int i=0;i<len;++i) printf("%d ",path[i]);
    printf("\n");
}
```
