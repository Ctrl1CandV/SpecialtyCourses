## P2 先给指针和下标写清含义（约2分钟）

指针名不能代替定义。rear在循环链队列里是尾结点指针，顺序循环队列的rear可能是下一次插入位置；直接混用模板会错。共享栈两个top都指已占用位置，只是空时站在数组外。

## P3 2025 阅读题：只保留尾指针的队列（约2分钟）

原题出队返回指针，因此函数内部不能先free再return。虽然队列只存rear，仍可直接通过rear->next访问队首，这是循环结构节省一个指针的依据。

## P4 新结点入队前，rear的后继仍是原队首（约2分钟）

先看已有的三个next，a到b、b到c、c回到a。新结点d不属于任何一条旧边，题面保证它独立。要把d接到逻辑尾部，最终需要c到d、d到a。

为什么先写d到a？因为a的地址目前保存在旧尾c的next里。若先把c的next改为d，再用rear->next给d赋后继，取得的已经是d自身。

## P5 入队时保存原队首（约3分钟）

【停顿】先画队首a、尾结点c和新结点d。要保持原队首不变，新d的next应先指向a，即p->next=Q->rear->next。再让旧尾c指向d，最后把rear移到d。若先改rear->next，新结点就无法通过这一表达式取得原队首。

## P6 入队完成后，回边从新尾d指向a（约1分钟）

用同一组结点检查执行结果：队首仍是a，旧尾c后面多了d，新尾d的后继回到a，循环队列的表示约定恢复。连接操作和更新rear共同完成入队，漏掉最后一步会把新结点误当成下一次出队的队首。

【停顿】让学生从新rear出发先走一次next，再沿队列走一圈，确认逻辑顺序a、b、c、d。这个验证比只看一条赋值的语法更完整。

## P7 出队时区分一结点和多结点（约3分钟）

rear==p说明尾就是队首，即队列只有一个数据结点。此时必须rear=NULL，不能继续留下指向已出队结点的指针。原题不要求清空返回结点的next；调用者也不应把它误当作剩余队列的入口。

## P8 最后一个结点出队后，rear必须为空（约2分钟）

多结点删除通过rear->next=p->next跳过队首。只有一个结点时，p->next仍是p，做同一赋值会让rear保持原值，队列看起来仍非空。若调用者随后释放返回结点，队列就留下悬空指针。

因此唯一结点分支必须清空rear。返回的p仍是有效结点，函数没有释放它；“队列为空”与“返回结点已经销毁”不能混为一回事。

## P9 沿操作序列检查状态（约3分钟）

第一步故意连续入队，再删到空，再重新入队。很多程序正常处理多结点，却在空与非空之间转换失败。给学生在每一步画rear->next指向谁；最后一个e不能指向先前已移除的d。队首逻辑次序和循环中的回边分开表示。

## P10 队列题的完整作答（约2分钟）

题面若只问填空，直接给对应语句即可；若另外问复杂度，再给每次操作的量级。不要把调用者以后可能执行的遍历算进当前函数。两空已经由完整操作序列验证。

## P11 循环队列题的作答依据（约2分钟）

若阅读题只要求两空，直接按空号写p->next=Q->rear->next和Q->rear=NULL。若要求说明算法，就用本页的连接顺序组织语言：先说明空状态与非空表示，再说明插入或删除修改哪两条连接，最后交代返回什么。

返回原结点意味着其生命周期由调用者管理，不能在函数中free(p)再把地址交回去。这里的O(1)是单次操作的时间与额外空间，不包括调用者之后遍历或者销毁整个队列的工作。

## P12 2026 阅读题：两个栈共用一个数组（约2分钟）

先约定top表示当前栈顶，不是下一空位。这样左栈入栈要先向右移动，右栈入栈要先向左移动；出栈恰好相反。两个栈分享所有未占空间，不固定各用一半。

## P13 从占用区间推导判满（约2分钟）

让学生用m=6、top0=1、top1=4画六格。中间还空2和3两格，不能只检查top0==top1：那时两侧已经发生覆盖。判满是相邻，碰到同一个数组格之前就应拒绝入栈。

## P14 共享栈的空闲格正好位于两个top之间（约2分钟）

左栈当前栈顶是20，右栈当前栈顶是80。右栈的栈底在5号、栈顶在4号，因此从底到顶是90、80。确认这个方向后，再看出栈为何要让右top增加。

两个top之间严格夹着的格子才是空闲空间，数量为top[1]−top[0]−1。若两者相邻，这个数为零；等到两个top相等才判满，已经允许下一次写入覆盖另一个栈的元素。

## P15 入栈与出栈的五个空（约3分钟）

【停顿】不要立即把++和--作为口诀填上。要求学生先口述顺序：入栈先移动到空位再写，出栈先读当前元素再退回。②是++top0，③是--top1，④是top0++吗？出栈后左栈应缩短，所以是top0--；右栈则top1++。

## P16 前置与后置运算由一次操作推导（约2分钟）

拿左栈空状态top0=−1验证入栈：必须先变成0才能访问有效数组，若写成data[top0++]=x会先写−1号。拿右栈空状态top1=m验证，必须先减到m−1。

出栈则先取已经存在的栈顶。图中左top0=1，应读20后退到0；若先减再读就错误返回10。右侧同理先读80，再把top1从4增到5。通过具体下标推导即可消除对自增形式的猜测。

## P17 容量为6的混合操作（约3分钟）

用同一数组画出所有写入位置。最后一次失败必须保持原数组逻辑状态和top不变。数据格里有旧值不代表它仍在栈中，是否属于栈只由top界定。

## P18 满状态下失败入栈不改变两个top（约1分钟）

这就是上一张操作表最后一行的真实数组状态。左栈从底到顶是10、30，右栈从底到顶是90、80、70、60。再压40时先判满，尚未执行任何自增或者数组赋值，因此返回失败但结构保持正确。

统计操作次数时，这仍算一次入栈尝试，却不算成功入栈。后续输出必须沿失败后未变化的状态继续，不能为了“尝试过”就把top推进。

## P19 共享栈的结构和初始化（约2分钟）

假定1≤m≤CAP，栈号i只取0或1，这是本题调用契约。bot保留空栈时的下标，故出栈可统一判断top[i]==bot[i]。题目若给出另一种top定义，要重新推导表达式，不能强行搬用本页。

## P20 共享栈操作答案（1/2）（约2分钟）

把前置自增拆成先改top再访问数组，可以消除符号记忆负担。容量1时也应工作：左栈压入一个元素后top0=0、top1=1，右栈再入就被判满拦住。

## P21 共享栈操作答案（2/2）（约2分钟）

出栈读取的是移动之前的格子。空栈直接返回false且不改x，符合输出参数只在成功时有效的约定。每次操作常数时间；存储数组是给定结构，操作的辅助空间为常数。

## P22 单次操作与整段操作序列的复杂度（约2分钟）

复杂度的对象应与题目一致。问一次入栈，答案是O(1)；问给定r个操作全部执行，答案是O(r)。数组有m格不意味着每次都要检查m格，判满只读取两个top。

题目统计成功次数时，应按返回值计数；统计输出序列时，只记录成功Pop得到的x。失败Pop保持x旧值，不代表又输出了那个旧元素。这些区别要在读题时确定，不能到最后把调用次数、成功次数和输出个数混在一起。

## P23 课堂检查：输出和操作次数（约3分钟）

【停顿】学生自己画四个格子并跟踪两侧top。题目只统计API调用是否成功，不计内部比较次数。让学生在每一步同时记返回值和结构状态，失败操作不能改变top。

## 附录二 完整代码

### 循环链队列完整代码
```cpp
#include <cstddef>
struct LinkNode { int data; LinkNode *next; };
struct LinkQueue { LinkNode *rear; };
void EnQueue(LinkQueue *Q, LinkNode *p) {
    if (Q->rear == NULL) {
        Q->rear = p; p->next = p;
    } else {
        p->next = Q->rear->next;
        Q->rear->next = p; Q->rear = p;
    }
}
LinkNode *DeQueue(LinkQueue *Q) {
    if (Q->rear == NULL) return NULL;
    LinkNode *p = Q->rear->next;
    if (Q->rear == p) Q->rear = NULL;
    else Q->rear->next = p->next;
    return p;
}
```

### 共享栈操作答案
```cpp
const int CAP = 100;
struct TwStack { int data[CAP], top[2], bot[2], m; };
void InitStack(TwStack &S, int m) {
    S.m = m;
    S.bot[0] = S.top[0] = -1;
    S.bot[1] = S.top[1] = m;
}
bool Push(TwStack &S, int i, int x) {
    if (S.top[0] + 1 == S.top[1]) return false;
    if (i == 0) S.data[++S.top[0]] = x;
    else S.data[--S.top[1]] = x;
    return true;
}
bool Pop(TwStack &S, int i, int &x) {
    if (S.top[i] == S.bot[i]) return false;
    if (i == 0) x = S.data[S.top[0]--];
    else x = S.data[S.top[1]++];
    return true;
}
```
