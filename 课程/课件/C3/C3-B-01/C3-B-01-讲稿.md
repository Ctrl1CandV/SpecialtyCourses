## P3 2024 阅读题：归并成非递增链表（约2分钟）

原题给出完整函数，下面分段显示。先确认 La 和 Lb 本身就是数据结点指针，不能照带头结点模板写 La->next。非递增是输出要求，原结点复用使指针保存顺序成为关键。

## P4 先读已给出的收尾循环（约2分钟）

收尾先把 La 向后移动，再覆盖 p 的 next。看到 p->next=Lc 和 Lc=p，可以确认结果采用头插。既然每次放到最前面，要得到递减结果，取出的结点应从小到大。现在回到主循环就不需要凭模板名称猜测。

## P5 头插前，p与La分别保留当前结点和余链（约2分钟）

这一刻已经执行p=La和La=La->next，但还没有改p的后继。p仍连着5，La也指向5，所以接下来即使覆盖p->next，余链仍能从La找到。

若先执行p->next=Lc，再用La=La->next推进，由于La仍指p，读取到的是旧结果链的2，原表后面的5就丢失了。图中每个指针各保存哪一段，是判断更新顺序的依据。

## P6 头插后，3a成为新的结果首结点（约1分钟）

结果链从2、1变成3a、2、1，未处理的A仍是5。因为每次从两个有序余段中选较小值，取出序列非递减；头插把取出顺序反过来，结果因此非递增。

此时再看两条接链语句。第一条需要旧Lc的地址，第二条才更新Lc。若反过来，p->next会取到p自身，产生自环，同时原结果链失去入口。

## P7 主循环的四处填空（约3分钟）

【停顿】先让学生写①与②，再写接链语句。条件①必须让两个指针都可以安全取 data。条件②决定哪个较小。③和④不能互换：先更新 Lc 会令 p 的后继指向自己。原题相等时取任一侧都可，只要保持函数任务。

## P8 四个空分别受哪条已知条件约束（约2分钟）

学生写完四空后，用本页检查每一个答案的来源。①若写成或条件，一条链空时还会进入并访问空指针的data。②若取较大值，头插会破坏要求的结果次序，例如A为1、3，B为2，取出2再1后结果前两项为1、2，已经出现递增相邻项。

③④由旧结果链的保存关系决定。这种逐空验证适用于阅读题：利用已经给出的访问、收尾和返回约束答案，不需要凭记忆把另一套完整模板硬套进来。

## P9 用重复值区分结点和关键字（约3分钟）

输入 A 为1、3a、5，B为2、3b、7；a、b只是结点标记，比较时都按3。每轮取最小的未处理结点，放到前面。已经形成的结果始终递减，而未处理的两段仍各自递增。第5轮仍在主循环中取A的5，此后A为空，B的7才进入收尾循环头插。

## P10 归并逆序的答案（1/2）（约2分钟）

四空分别为 La!=NULL && Lb!=NULL、La->data<=Lb->data、p->next=Lc、Lc=p。比较处用严格小于也正确，仅改变同值结点相对顺序。代码中先推进原表游标，再改 p 的 next，确保剩余链不断。

## P11 归并逆序的答案（2/2）（约2分钟）

两个收尾循环在运行时至多一个处理非空余段。它们和主循环共享同一批 m+n 个结点，每个结点只被摘下和接入一次。辅助空间只有几个指针，结果链用原空间。

## P12 三个循环共同消耗m+n个结点（约1分钟）

把每个结点看成一次可消耗的输入：它进入结果链后不会回到La或Lb，因此不可能在另一个收尾循环里再处理一次。主循环结束时至少一个表为空，两个收尾循环也不会都处理非空余段。

空输入只有常数开销；一般长度下，功能要求复用全部结点，所以合计摘取m+n次。复杂度说明应写这一事实，单说“三个循环所以线性”仍然没有证明每个循环的工作量。

## P13 把功能与复杂度写完整（约2分钟）

优秀的功能说明应包括处理对象、顺序和结果。只写“合并链表”没有交代逆序和复用。时间复杂度不是看见三个 while 就把数量级相乘，它们消耗的是同一批结点。两链若共享结点，改链会破坏另一游标，这不在原题的通常独立输入模型内。

## P14 2025 阅读题：链表简单选择排序（约2分钟）

先找三个变量在程序里的角色。min 是结点指针，并非最小值本身。L是额外头结点，所以遍历数据必须从L->next开始。后面的三条交换语句都针对data，题目没有交换结点。

## P15 先读寻找最小值的一段（约2分钟）

min从p开始，保证余段只有一个结点时仍有合法候选。q从p的后继开始，意味着已经把p算入候选，不需要重复比较自己。每次外循环结束后，p以前的数据都已排好，本趟只改变p开始的余段。

## P16 第二趟扫描时，p之前的前缀已经确定（约2分钟）

前一趟已把1放到首数据位置。当前p在存4的结点，q扫描到存3的结点，min指向存2的结点。q未到空之前，min只保证是已经比较部分的最小值，不能提前交换并结束这一趟。

扫描完成后把p和min的数据互换，p所在的位置才最终确定。链的连接没有变，p下一趟仍应沿原next走到下一个位置。

## P17 交换与推进分别填什么（约3分钟）

【停顿】②可写 min!=p，③写 p=p->next。交换数据不会移动p这个结点本身。条件用 p->data>min->data 也能完成排序，但与原循环寻找最小结点的语义相比，min!=p最直接。若执行p=min，将跳过某些位置，外循环不再逐个确认排序位置。
## P18 p=min不能代替交换数据（约2分钟）
找到了min并不等于完成了本趟排序。指针赋值p=min只改变局部变量指向，链中任何数据都没动。如果随后再前进p，原来的4就被跳过，外循环的已排好前缀不再成立。

题目给出的交换语句作用在data上，因此填空要围绕同一语义补齐。若题目改为交换整个结点，必须另找前驱并处理连接，不能只改这个赋值就声称实现了结点交换。

## P19 同键记录的次序可能改变（约3分钟）

稳定性要追踪完整记录的身份。原题只有整数数据，我们增加a、b标记做性质检查，不更改原填空答案。比较条件用了严格小于仍不能保证稳定，因为较远的一次交换可以把相同关键字越过去。

## P20 选择排序的答案（1/2）（约2分钟）

把第一空放回函数整体，再对空表检查：L->next为空时主循环一次也不执行，没有访问数据。非空表的最后一趟q为空，但min仍指向p。

## P21 选择排序的答案（2/2）（约2分钟）

三空的表达式很短，完整验证需要看循环推进。每趟p向后移动一个结点，不受交换数据影响。不同题中同名变量角色可能不同，不要把第一题摘结点的做法带到这里。

## P22 工作量由每趟的扫描范围决定（约2分钟）

让学生先写前三趟比较次数，再补等差数列。这个过程比看到双循环直接写平方更稳，因为有些双循环的内层并不每次从头开始。原程序会访问最后一个p，但该趟没有关键字比较，不会给求和多出一项。

## P23 选择排序题的完整解释答案（约2分钟）

完整答案可以写：“以p依次指向各数据位置，每趟从p及其后继中寻找最小数据结点min，若min与p不同则交换二者数据，再将p后移。每趟结束后p所在位置之前的部分均已按升序确定。”

复杂度写每趟比较n−1、n−2直到0次，合计n(n−1)/2，因此即使输入已经有序也为O(n²)。只有固定个指针和一个临时数据，所以辅助空间O(1)。稳定性若被询问，可给2a、2b、1的一趟结果1、2b、2a作为证据，不把严格小于比较误当作稳定的充分条件。

## P24 课堂检查：哪些修改会破坏答案（约3分钟）

【停顿】给学生两分钟写具体输入。第一项任意首个结点就自环；第二项把头结点的数据也参与排序，破坏数据约定；第三项非空表的p不推进，死循环。回到原代码逐项核对后结束，不再追加同义总结。

## 附录二 完整代码

### 归并逆序的答案
```cpp
#include <cstddef>
struct Node { int data; Node *next; };
Node *mergeAndReverse(Node *La, Node *Lb) {
    Node *Lc = NULL;
    while (La != NULL && Lb != NULL) {
        Node *p;
        if (La->data <= Lb->data) {
            p = La; La = La->next;
        } else { p = Lb; Lb = Lb->next; }
        p->next = Lc;
        Lc = p;
    }
    while (La != NULL) {
        Node *p = La; La = La->next;
        p->next = Lc; Lc = p;
    }
    while (Lb != NULL) {
        Node *p = Lb; Lb = Lb->next;
        p->next = Lc; Lc = p;
    }
    return Lc;
}
```

### 选择排序的答案
```cpp
#include <cstddef>
struct SortNode { int data; SortNode *next; };
void SelectionSort(SortNode *L) {
    SortNode *p = L->next;
    while (p != NULL) {
        SortNode *min = p, *q = p->next;
        while (q != NULL) {
            if (q->data < min->data) min = q;
            q = q->next;
        }
        if (min != p) {
            int temp = p->data;
            p->data = min->data;
            min->data = temp;
        }
        p = p->next;
    }
}
```
