# deck.yaml 内容规格（内容生成规范）

> **架构分工**：
> - **内容生成**（本规格管辖）：负责把一节课的幻灯片内容写成结构化的 `deck.yaml`——页型、标题、文字、表格、代码。**只关心"讲什么"**，不写任何布局/颜色/字号。
> - **PPT 渲染**（`tools/render-pptx.js` 管辖）：读取 deck.yaml，套用统一版式生成 .pptx。**只关心"怎么摆"**，内容 AI 不得干预样式。
>
> 生成命令：`node tools/render-pptx.js <课件目录>/deck.yaml`（输出同名 .pptx）
>
> **自检命令**：`node tools/check.js`（检查全部课件）或 `node tools/check.js 课件/C1/C1-A-02`（检查单节）。检查项：YAML解析、渲染、页数对应、字数预算、违禁词、内部代号、image路径、前向引用重复、讲稿加粗密度。每节课交付前必须跑一遍。

---

## 一、文件位置与命名

```
课件/
├── C1/C1-A-01/
│   ├── deck.yaml              # 幻灯片内容（本文档规范）
│   ├── C1-A-01.pptx           # 渲染产物（不手改）
│   └── C1-A-01-讲稿.md        # 讲稿（另一份交付物）
```

每节课一个目录；deck.yaml 与讲稿内容逐页对应。

## 二、deck.yaml 结构

```yaml
meta:
  id: C1-A-01                    # 课段编号（渲染元数据，不上页面；正文禁止出现内部代号）
  title: 初识C程序               # 本节标题
  stage: A基础                   # 阶段标签
  instructor: 牙膏学长
  duration: 35min

slides:
  - type: cover                  # 页型，见下文
    title: ...
```

> 注意：**不设 footer 字段**——页脚只打印页码（渲染引擎内置），机构宣传由底图自带；封面 kicker 固定为"重邮802 数据结构代码课程"，不加机构名。

## 三、页型（type）

### 1. `cover` —— 封面（每课段首节课用）
字段：`kicker`（小字抬头）、`title`（大标题）、`subtitle`（副标题）、`meta`（阶段/主讲/时长一行）。

### 2. `content` —— 常规内容页（最常用）
字段：
- `kicker`：本页小字抬头（如"课段导学 · 这个课段管什么"）；
- `title`：本页标题（陈述式，见写作规范）；
- `badge`：可选右上角标（如"真题·2025""正课开始"）；
- `blocks`：内容块列表，按序渲染。

### 3. `board` —— 板书推演页
字段：`kicker`、`title`、`task`（板书任务描述），页面下半部自动留空白板书区。

### 4. `transition` —— 过渡页
字段：`kicker`、`title`、`subtitle`。用于导学结束进入正课等节点。

## 四、内容块（blocks）类型

| type | 字段 | 用途 |
| :--- | :--- | :--- |
| `bullets` | `items: [字符串]` | 要点列表（每条一行内说完） |
| `table` | `head: [列名]`、`rows: [[单元格]]`、`align` | 表格（目录、对比、数据） |
| `code` | `text: 代码字符串` | 代码块（保留换行；注释用 `//`） |
| `note` | `text` | 次要说明（灰字） |
| `text` | `text`、`size`、`bold`、`color`、`align` | 普通段落（`**词**` 会加粗） |
| `image` | `src`、`w`、`h`、`align`、`fit` | 图片块（C2起插图示用，见下方说明） |
| `gap` | `h` | 留白 |

**`image` 块说明**：
- `src`：图片路径，**相对于项目根目录**（如 `知识笔记/image/KMP.png`）；也支持绝对路径。
- `w`/`h`：宽/高（英寸），缺省时 w=内容宽×60%、h=w×0.66（约4:3）。C2 插图建议 `w: 8`、`h: 4.5` 左右。
- `align`：`center` 居中，缺省左对齐。
- `fit`：`contain`（完整显示不裁切，可能留白）或 `cover`（填满裁切），缺省 `cover`。笔记图建议 `contain`。
- 写法示例：

```yaml
- type: image
  src: 知识笔记/image/单链表插入.png
  w: 8
  h: 4.2
  align: center
  fit: contain
```

一页 blocks 总量控制：渲染器会自动缩字号防溢出，但**内容侧应主动控制密度**——一页 ≤6 条 bullets 或 ≤6 行表格或 ≤10 行代码，超了拆页。

> **YAML 写法注意**：以 `**` 开头的字符串必须用双引号包住（否则 `*` 被 YAML 当作锚点语法报错）；`**加粗**` 出现在句中则无需引号。代码块一律用 `text: |` 块写法。

## 五、写作规范（硬约束）

1. **禁止内部代号**：PPT与讲稿中不得出现 C0/C1-A/C2-B 等课段编号，一律用"C语言基础阶段""数据结构强化阶段""题型课"等面向学生的名称（deck.yaml 的 meta.id 是渲染元数据，不上页面，保留编号）；
2. **不打印机构标签**：底图自带机构宣传，页面不再打"伴梦研途"等机构/课程标签——页脚仅保留页码，封面 kicker 只写"重邮802 数据结构代码课程"（无机构名）；deck.yaml 不设 footer 字段；
3. **语气正式**：面向学生交付，用书面化表述；主讲录制时自行口语化发挥；
4. **课程开头引导**：每节课封面页 meta 行与讲稿开头含一句群引导（"资料答疑：伴梦研途QQ群"）；
5. **标题只陈述内容**：写"课段目录""802 试卷结构"，禁止口号式标题；不用营销腔与夸张语气；禁止"一句话总结"句式；目录/对比/数据一律用表格；代码注释克制。

### 去 AI 味补充（历史反馈沉淀）

- 不用"放心跟""稳稳拿下""跑不掉"等夸张表达；陈述事实、给数字、给判断标准；
- 目录/对比优先用表格而非卡片+箭头；列表结尾禁止加"一句话：……"式总结句；
- 导学页 kicker 用"课段导学 · ××"式平实表述。

## 六、讲稿对应关系

deck.yaml 的每一页对应讲稿的一个 `## P{n} 页名` 小节。页型决定讲稿节奏：
- cover/transition：20—30 秒口播；
- content：2—6 分钟，按 blocks 逐块讲；
- board：现场书写，讲稿只写板书步骤与停顿点。
